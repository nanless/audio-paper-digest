# Manual 论文解读写作要求

此模板用于单篇 Manual 教程正文。读者第一次接触该方向时，应能读懂论文的问题、方法、关键选择和实验，并说清哪些结论已经得到支持、哪些仍未验证。文章长度服务于解释，不作为质量证明。

```text
只处理当前这一篇论文。允许的输入包括论文基本信息、结构化全文、ArtifactIndex、原论文图表、已有事实记录、空白模板和质量要求。流程已保存并绑定 SHA 的 `official_project_evidence` 可以用于核对官方代码、权重、数据集入口及各自许可证；不能用未保存的临时网页内容扩写论文贡献。

不能读取或借用同批其他论文，也不能读取旧 `readerArticle`、任何 `article.md` 或 `post.md`、博客页面、历史分析正文和上一稿。每次写作都从本篇原始证据和空白模板开始，不能重排、润色、扩写、补段或仿写旧正文。收到审查意见后，只读取原始证据与结构化问题记录，从空白重新生成完整替换稿。这里的修正方式不允许沿用上一稿。

成品与结构

正文是一篇中文教学文章，长度为 6,000–40,000 个字符，按正文文本计数。通常使用 8–18 个本篇特有的三级标题。标题表达读者需要理解的问题或技术判断，不照搬“方法概述、核心创新、实验结果、细节、局限”等通用栏目。标题中不能包含“图 1”“表 2”“Figure 1”“Table 2”等编号；编号放在相关正文或图注中。

文章先解释领域任务和具体失败情形，再说明已有研究路线、本文要检验的问题及完整方法，随后展开数据、模型和目标组件，交代实验协议，再讨论主结果、诊断、消融、外部比较、能力范围和复现。背景、相关工作或方法还未解释清楚时，不直接公布重点结果。首次出现的关键术语要说明通俗含义、本文怎样实现，以及为何影响后续结论。

每段围绕一个主要问题展开，前后自然衔接，句子长短随内容变化。不要重复摘要、机械排比，或反复套用“不能外推”“需要核对”“证据边界”“复现者应当”等句式。标题和内容须对应，不能把小节写成换到其他论文也成立的通用段落。

页面中的题目、链接、两段评价、核心摘要、开源信息和文末评分证据由发布结构提供，`article.md` 不重复生成这些区域。开头将摘要结论变成读者可以检验的问题。页面另有会议或领域提示、导语及数字卡时，卡片只能采用本篇已验证且最有助于读者判断的事实，同时说明指标方向、比较对象和单位。卡片不能代替正文协议或完整结果表，也不在正文中再次拼装。

开头与相关工作

前 600 字内给出一个可以理解的反例或直觉冲突，解释至少两类已有路线及其具体失败点。先讲领域任务、输入查询、候选对象、训练配对、推理输出和基础评测含义。术语在首次出现的同一句或此前解释，不能用一张充满后文缩写的表代替说明。

用独立相关工作小节解释至少两条研究路线，分别说明监督来源、解决的问题和仍有的不足。不要先堆数据集名称或缩写，许多段之后才解释。相关工作之后，用一句可以被实验反驳的判断说明本文改变了什么、预期在哪些条件下有效、什么结果会推翻它。此处说明预测与反证条件，不提前给出结果答案。

在组件细节、公式和结果之前，先给完整方法流程表或合格原图。一次交代输入、数据或表示变换、音频与文本路径、训练目标和检索输出，并说明接下来要研究的数据监督、表征和训练目标等问题。系统论文可以先说明技术冲突、至少两种失败路线和已有工作的关键认识，再进入方法总览；相关工作不能只列名称。

方法与训练

数据论文解释原始来源怎样经过匹配、清洗或生成，如何控制质量、用于训练，以及输出存在什么风险。系统论文解释输入怎样变为表示、经过组件及训练或推理得到输出。先提供总览图或流程表，再分别说明模块，不让读者靠模块名称猜过程。

每个关键模块交代输入、输出、实际操作、设置它的理由，以及与相邻模块的分工。说明收益、代价和尚未验证的假设，不只评价“效果更好”。结果或消融会涉及的方法，应在实验协议前解释，不能展示多轮结果后才首次说明损失、层融合或训练变体。

训练部分覆盖数据构成、采样比例、阶段、损失、参数冻结与解冻、步数、批量大小、硬件、时长，以及论文未披露的项目。公式解释变量含义和对应的训练过程，不放无助于理解的公式。同节比较多个损失、目标或训练安排时，先用简短表格说明是否显式使用负例、直接优化什么、预期改善什么，以及代价或混杂因素，再解释公式。这张表用于理解差异，不作为性能排名。

行内公式只能用 `\(...\)`，独立公式只能用 `\[...\]`，不使用裸 `$...$` 或 `$$...$$`。加粗标记 `**...**` 必须成对，结束符后接正文时保留空格或标点。

原论文图表

ArtifactIndex 中的每张表、图和公式都要记录如何处理，不能默默省略结果表。核心结果表完整转录为 Markdown，保留设置、方法、所有指标、方向、数值和注释，转录结果应能逐格核对。

每张表前说明比较问题和评测协议，表后解释主要差异、绝对与相对变化、未胜出项、统计或自动评判风险，以及这张表尚不能支持的结论。宽表可以拆成内容连续的子表，但不能漏掉任何数值单元格，并保留原表编号和完整表入口。

原论文存在合格的架构、流程、训练动态或结果图时，嵌入原图。SVG 同样是论文图，不能因为不是 PNG 就丢弃；资助方标志和站点图标必须拒绝。图前说明该看什么，图后解释实际可见的结构、曲线或样例，再说明它与本文结论的关系，不只放图注。

图放在需要它解释问题的位置：总图介绍整体过程，局部图说明对应模块、注入位置或训练任务。不能只按图号另开可互换的小节。表格指标方向写成 `MRR↑`、`RMSE↓` 等可读形式，不保留 `\\uparrow`、`\\Delta`、`++`、`−-` 等转录残片，也不靠重复单元格模拟 HTML `colspan`。原文符号矛盾时保留数值并说明歧义，不自行推定方向。

实验与结论

先定义数据集、划分、任务和指标方向，让读者知道这组数字测量什么。第一张结果表之前，交代会改变比较含义的训练数据、指标、专用挑战或幻觉测试集、实现条件和基线选择。协议总览还要覆盖任务单位、数据划分及可能重叠、强基线、每组实验实际改变的变量，以及最终模型检查点和提前停止时怎样读取结果。

分别讨论主结果、公开数据上的泛化、相同骨干下的比较、消融、负结果和效率或部署；原文缺少相应内容时写“论文未报告”。每项核心贡献说明设计选择、预期机制、对应实验，以及替代解释或缺失的消融。整机性能提高不能自动证明某个组件有因果贡献。

精确数字说明设置、比较方法、强基线、指标、单位和方向，区分百分点、相对变化、绝对值和统计显著性。退化、平局、未胜出或无法直接比较的结果放在相应能力讨论中，不全部推到结尾。演示、案例图和定量评测分别说明，没有定量实验的展示只能说明可能的能力，不能写成已被系统验证的结论。

结尾与读者行动

提供一张说明能力、证据类型、判断和不能推出的结论的表，核对“第一”“领先”“强”等宽泛说法。对研究者，提炼可迁移的设计原则和下一步可检验的实验；对复现者，说明最小运行配置、风险最高的变量、公开资源、许可证和未披露项；对产品或部署者，列出当前实验尚不能回答的延迟、吞吐、成本、鲁棒性、安全和合规问题。

应用重要性应写成哪些用户、流程或风险条件值得进一步验证，不把潜在用途写成已经实现的部署能力。来源说明和免责声明不能代替事实核对。最后用 5–10 条互不重复的要点回答开篇问题，不把摘要换词重写。文末评分证据只引用正文已经解释的机制、实验、反证和复现事实，不在评分区首次引入精确数字，也不把“有 GitHub”当作可复现。

正文不能出现 `schema`、`manifest`、`SHA`、`evidenceLedger`、`sourceBindings`、`readerBindings` 或检查、审计、回放、字段等内部流程说明。不能只写“Table 1 表明”而不展示表，不能把完整表压成三行结论卡。不能将局部任务第一写成全面最佳结果，或把相关性和整机结果当成组件因果证明。摘要与正文首节不重复开场，连续三个以上段落不能套同一种先评价后否定的句式。

交稿前核对

独立阅读正文时，应能复述研究问题、完整数据或系统流程、模块分工、训练或生成过程，以及至少三组能力实验和各自的适用范围。检查每张图都有读图任务、可见内容解释和结论说明，每张核心表都有比较问题、协议、完整数值、主要发现与反证。每个精确数字都能辨认设置、比较对象、方向和单位，百分点与相对变化没有混淆。

渲染最终 Markdown，检查标题、表格、公式和图片是否可读。复杂多级表头、箭头、中文说明和数学符号不能只看源码判断。

提交文件与对应记录

`article.md` 只包含正文，三级标题按学习顺序排列。`quality.json` 使用 `version=2`，并记录 `readerPath.version=reader-tutorial-path-v1`。

以下 SHA-256 字段对应不同内容，不能互相替代：

| 字段 | 对应内容 |

| `freshAuthoring.articleFileSha256` | 刚写入磁盘的 `article.md` 原始文件字节。 |

不要使用写入前的中间字符串或上一稿哈希代替当前文件。`sectionPlan` 按下列顺序覆盖 15 种内容，字段名保持原样：

`field_background → related_work_map → paper_question → method_overview → data_component → model_component → objective_component → experiment_protocol → main_results → diagnostic_results → ablation_results → external_comparison → boundary_synthesis → reproduction → reader_closeout`
```
