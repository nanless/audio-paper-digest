## 目的与适用范围

本契约把高质量长篇论文解读中可复用的编辑决策，转成生产 Manual v6 的 `reader-longform-v2` 教程正文、质量记录与发布预检可共同执行的要求。目标读者是第一次接触该论文方向的研究生；目标不是把论文信息堆得更长，而是让读者能复述问题、数据/系统流程、训练或推理机制、实验结论及其边界。历史 Manual v5 只保留维护兼容，不再是新批次默认写作或发布契约；shadow v6 只用于显式审计，不能发布。

它只约束读者可见的 `editorial.readerArticle` 和相邻读者页，不替代受控全文、ArtifactIndex、`resultClaims`、评分或发布凭证的事实契约。所有精确事实仍必须来自当前论文的允许证据。

## 一、读者页固定信息顺序

发布器固定按以下顺序呈现正文前信息：中文题目、英文题目/arXiv 链接、标签、总分与八维分项、作者与机构、一句话概括、毒舌点评、核心摘要、开源与复现资源；随后才进入深度解读。正文之后呈现逐维评分依据与证据。本文同时规定深度解读内部与这些固定区之间的职责边界。

PaperTalk 的读前层级是值得复用的**展示顺序**：会议/领域 kicker → 读者标题 → 摘要式 lead → 三张数字卡 → 英文身份信息/关键词 → TL;DR。现有发布器若没有独立的 kicker 或数字卡槽位，不得把它们机械塞进 `readerArticle` 并重复标题或摘要；应将其映射到页面元信息、核心摘要或将来明确新增的展示组件。任何数字卡必须是本篇高信号、已在正文展开的精确事实，并写清指标方向、比较对象和单位；卡片不能替代完整结果表。

1. **身份与读前承诺**：题目、链接、标签、作者机构和评分让读者知道读什么；毒舌点评只说最强证据和最大缺口，不重写摘要。
2. **核心摘要**：用一段回答“问题、解法、最强结果、最大边界”，不抢走正文的推导任务。
3. **深度解读开头（前约 600 中文字）**：先用可感知的反例定义领域任务、输入、输出和基础术语，再用独立小节解释至少两条相关工作路线的监督来源、能力与缺口；随后才提出本文的可证伪判断。不要在读者尚未理解任务和已有工作时公布结果答案。
4. **论文特有教学正文**：按下节因果顺序展开，标题必须是读者问题或技术判断。
5. **开源与复现信息**：资源入口、许可证、实际可得内容、训练/数据缺口和最高风险变量。
6. **文末评分证据**：将评分逐维绑定到正文已经讲过的证据、反证和未披露项；不得另起一套未在正文解释的事实。

PaperTalk 的末段“key takeaways → 明确边界 → 应用重要性 → 论文信息/免责声明”也可映射为现有 Manual 的记忆点、能力—证据校准表、研究/产品行动和开源/来源信息。免责声明不能用于淡化事实错误；它只说明来源、评测或适用边界。

## 二、正文教学递进：先建模型，再给数字

正文通常使用 8–18 个论文特有的三级标题。可按论文类别改变标题，但教学依赖不可跳过。信息“出现过”不等于完成教学职责：背景、相关工作、论文问题和方法全貌必须是能独立承担职责的阶段，不能压缩进一个首节术语表后直接进入重点。

| 次序 | 必须回答的读者问题 | 系统/方法论文的典型内容 | 数据/资源论文的典型内容 |
|---|---|---|---|
| 1 | 这个领域任务到底输入什么、输出什么，真实失败是什么？ | 真实查询/输入、候选对象、正确输出、基础评价直觉 | 原始资料、目标监督单位和真实错配例 |
| 2 | 相关工作形成了哪些路线，各自解决什么、缺什么？ | 架构或监督路线谱系，首次出现即定义术语 | 标签、网页/RAG、评论或其他来源的能力与缺口 |
| 3 | 本文在研究地图上的位置和可证伪问题是什么？ | 改变的环节、应出现的结果、会推翻解释的反例 | 是替代已有资源、补充语域，还是改变数据质量控制 |
| 4 | 端到端整体如何流动，本文同时研究哪几条问题轴？ | 输入 → 表示 → 组件 → 训练目标 → 推理输出 | 原始来源 → 生成/质控 → 模型消费 → 训练目标 → 下游输出 |
| 5–7 | 每个关键数据、模型和目标组件做什么？ | 接口、共享/分工、公式、训练阶段与混杂因素 | 匹配、生成、覆盖—保真、采样、来源和许可 |
| 8 | 数字到底测什么？ | 任务单位、数据集、split/重叠、指标、强基线、变量轴、checkpoint 口径 | 同左，另说明抽样、人工/LLM 判定与数据泄漏风险 |
| 9–n | 每项能力的证据和反证是什么？ | 主结果 → 诊断 → 消融 → 外部比较 → 训练动态/效率 | 质量/覆盖 → 下游收益 → 误差/负例 → 外部比较 |
| n+1 | 已支持、未证明和不适用的结论分别是什么？ | 将整机证据、组件因果和部署缺口分开 | 区分数据量、生成器、筛选器、语域、许可证与获取边界 |
| n+2 | 如何复跑，三类读者如何行动？ | 最小配置、风险、未披露项、研究/复现/产品行动 | 同左，额外包括来源、版权、数据获取和清洗可复现性 |

每个段落只完成一个教学任务。反证应紧贴对应结果：例如一项宏平均提升，应在该小节说明逐数据集退化、误差条缺失或评测器限制，而不是在结尾集中“泼冷水”。

对 PaperTalk 式系统文章，方法中可采用“物理/技术冲突 → 两种失败路线 → prior work 与关键洞察 → 方法总览 → 子模块/自监督任务 → 层级注入 → 训练阶段”的具体路径。对 FireRedAudio 式复杂系统文章，允许进一步拆开长上下文长度、生成步、课程训练与各任务路由，但每一节都必须连接回最初的中心矛盾。

新教程质量记录使用 `reader-tutorial-path-v1`，并按正文顺序绑定 `field_background → related_work_map → paper_question → method_overview → data_component → model_component → objective_component → experiment_protocol → main_results → diagnostic_results → ablation_results → external_comparison → boundary_synthesis → reproduction → reader_closeout`。固定页首摘要可以预告结论，但正文的背景和方法不能以“摘要已经说过”为由跳过；方法、损失或层选择不得在结果之后首次定义。

## 三、图、表、公式和实验的编辑规则

### 图

- 每张被选中的原论文图必须有三段职责：图前的**读图任务**、图后的**可见结构/曲线/样例解释**、以及它支持和不支持的结论。
- 架构图优先服务全景数据流；训练阶段图或流程图优先服务训练组织；结果图只服务其对应能力问题。不得以漂亮插图替代证据。
- 图必须插在它承担论证任务的节点，而不是按“图 1、图 2”另开可交换小节。总图先帮助读者建立全景；局部放大只在解释对应模块、注入位置或训练任务时出现，并在前后文字中明确为何此处需要它。
- 原图与编辑性派生图必须明确区分。派生图只能重排已经核验的数字和关系，不能补造趋势、未给出的误差条或因果箭头。
- SVG 是合格原图；资助方 logo、网站图标和无研究信息的装饰图必须 reject。图片在移动端不可读、箭头方向错误、标题/数值错配时不得记录为完成。

### 表

- 核心结果表逐项完整转录：保留原表编号、设置/方法列、指标方向、所有数值、注释与可比性限制。宽表可以按语义连续的子表拆开，不能只留最佳三行。
- 表前固定回答“比较问题是什么、控制了什么、指标怎样读”；表后固定解释绝对或相对变化、未胜出项、统计/自动裁判风险和不能推出什么。
- Markdown 必须是实际可读的表，而非 HTML `colspan` 残片或重复伪单元格。多级表头使用表外 span label、独占分组行或拆表实现；不得出现裸露 `\uparrow`、`\Delta`、`++`、重复列标题或方向含混的符号。
- 对原论文本身的记号矛盾，正文要逐字说明歧义来源，保留数值但只给证据允许的解释；不能擅自修正代数方向。

### 公式

- 只重放推动读者理解设计、训练或评测的公式。公式前先说明它解决的冲突，公式后依次解释变量、输入/输出、训练语义和代价。
- 多目标或多损失论文，公式前必须有一张短导览：是否使用负例、直接优化对象、希望改善的能力、已知代价或混杂因素。导览不是结论排名。
- 不得为了“技术感”堆叠无后续作用的公式；无法从本篇证据重放的公式必须说明未重放原因。

### 实验

- 先定义能力问题，再给数字；按主结果、公开泛化、同主干比较、消融、负结果、效率/部署组织，而不是按表格编号机械串联。
- 每条精确比较至少就近写出：设置、方法、强基线、指标方向、数值、单位，以及绝对百分点或相对变化属于哪一种。
- “领先”“最好”“支持机制”都须配套边界：未胜出项目、自动裁判、数据重叠、单随机种子、样本量、置信区间或缺失消融。整机变好只能支持整机有效；组件因果必须有直接对照。
- 演示图、case study 和定量评测必须分开写。没有对应定量评测的展示，只能称为能力示意，不能扩写为系统验证。
- 在正文进入结果表前，先交代训练数据、指标、专用挑战/幻觉集、实现条件和基线选择中会改变比较含义的部分。PaperTalk 的五表结构和 FireRedAudio 的逐能力全表都说明：完整表不是附录装饰，而是让读者发现局部退化、平局和基线适用范围的证据入口。

## 四、标题、语气与评分禁则

### 标题禁则

- 禁用可任意交换的固定栏目标题，如“方法概述”“核心创新”“实验结果”“细节”“局限”。改写成论文特有的读者问题或判断，例如“为什么 6.25 Hz 的 LLM 输入仍能驱动 25 Hz 声学生成？”
- 禁用摘要复述式标题和没有对象的褒贬，例如“方法很新”“结果很好”“局限分析”。
- 禁用同一论文连续三个以上“主张—审计式否定”标题或段落。边界必须具体到设计、设置或证据，而非反复使用“不能外推”“需要核对”。
- 读者可见正文禁止出现 schema、manifest、SHA、evidenceLedger、sourceBindings、readerBindings、门禁、审计、回放、字段等内部流水线词。

### 评分证据

- 正文前必须同时显示总分与八个分项：创新（/2）、技术严谨（/1.5）、实验充分（/1.5）、清晰度（/1）、影响力（/1.5）、开源（/1.5）、可复现（/0.5）、工程/实践（/1.5）。任何一项为 0 也不得省略。
- 文末评分是证据索引，不是主观裁决页。每个维度都要指向正文的具体机制、实验组、负面证据或复现事实。
- 评分应区分：问题重要性、设计合理性/创新、实验广度、证明力度、可复现性、工程/部署价值等；项目可用既有维度，但不能凭“总分高”反向生成论据。
- 禁止把“有 GitHub”视作可复现；必须同时说明可获得的材料、许可证、训练数据与关键配置缺口。
- 局部任务第一不是全面 SOTA；自动模型裁判、无人工评测、无效率数据、无核心消融都必须影响对应维度的解释。

## 五、渲染验收与可恢复缓存

### 发布前可见性验收

1. 每页以最终 Markdown bytes 构造不可变 artifact；标题、正文、图片、表格、公式、评分证据从同一 artifact 检查。
2. 验证三级标题数量与编辑蓝图一致、标题均为论文特有标题、开头没有摘要重复、文末评分证据存在且不引入正文外数字。
3. 逐图目视检查：原图/派生图身份、中文说明、标题、箭头、并行关系、指标方向与数字；移动端裁图必须仍能读到关键结构。
4. 逐表渲染检查：列数、对齐、分组行、指标方向、数学字符与 Markdown 转义。含复杂 header 的表必须检查 HTML/Markdown 实际页面，而非只检查源文本。
5. 逐公式检查：行内/块公式不溢出、变量解释就在邻近段落、公式没有脱离实验或机制解释。
6. 正式 preview/Hugo gate 通过后再次哈希；任何字节漂移均使本轮 review 失效并要求重新检查。

### 提速但不降级的缓存边界

- **全文与 ArtifactIndex 缓存**：按当前论文 ID、来源 URL、字节 SHA、解析器版本、表格/公式/图像恢复状态缓存；来源、解析器或 bytes 变化只失效受影响资产及下游。
- **可读表缓存**：缓存确定性 Markdown 转录及其输入 artifact SHA；表格布局规则变化只重渲染表和关联段落，不重抓全文或重写无关小节。
- **事实证据缓存**：可缓存本篇局部原文块、图表 ID、确定性表格、公式、数值和 result claim 的事实核验；不得把任何模型生成段落、历史 `readerArticle`、旧质量包、博客页或 reviewer prose 作为新作者输入。事实 SHA 未变只能省去重新抓取和核数，不能让旧句子或旧文章结构获得 fresh 认证。
- **渲染/目视清单缓存**：以最终 page artifact SHA、图片 asset SHA、渲染协议版本为键。未改页面复用通过项；Markdown、图片或协议变化必须重新渲染和目视检查。
- **并行原则**：可并行解析图表、准备表格、检查公式和建立读图任务；最终正文合并、页面 hash 和发布 review 必须串行收口，避免不同 worker 检查不同版本。

缓存只能复用确定性解析或人工核验的**事实状态**，不能复用模型生成 prose。每个新作者任务必须声明 `fresh-authoring-v1`，其输入仅限本篇 metadata、source snapshot、结构化全文、ArtifactIndex、图表/公式/事实账本、固定 prompt/契约和空白 schema；`prohibitedProseInputs` 必须为空。缓存未命中或证据不完整时应停止，不能回退到修补、重排或扩写旧正文。

该声明必须由受控 `article.md` 的原始字节 SHA、trim+NFKC 正文 SHA 和逐文件 authority receipt 支撑；ArtifactIndex inventory 必须 complete。日期级官方项目证据存在时必须作为独立输入绑定 paperId、kind、HTTPS URL 与文件 SHA。只在旧 `readerArticle` 旁补一个正确 SHA 不构成冷启动凭证，spec、canonical 与 publisher 都必须重新读取真实文件。
