# 维护可续跑的生产流程

先读项目的执行规则、正常入口和完成条件。按用户已授权的范围处理数据、请求、提交和发布。本文提供判断方法，具体权限、默认值、锁和停止条件以项目为准。

## 何时使用与不适用

适合：

- 维护、清理或迁移带保存点、历史凭证、失败恢复或对外发布的批处理与发布流程。
- 统一内部格式、废弃旧入口、继续中断批次、核验上线，同时保留原始材料、记录和费用。
- 同一份材料被另一语言、进程、仓库或已发行客户端读取，需要一并核对。

不适合：

- 一次性、无保存点、无历史凭证也不对外发布的小脚本；直接写针对该任务的检查更合适。
- 代替项目自己的执行规则、权限、费用或发布授权。本文只给方法，实际范围以项目规则和实现为准。
- 为通过检查而改写历史记录、补造来源、手工填写完成状态或清零费用。
- 纯文案修改，或与流程状态、数据归属和发布无关的界面调整。

## 清理或迁移前查实际依赖

1. 查谁写入、谁读取、谁在中断后继续，以及谁从另一语言、进程、仓库或已发行客户端读取。同样检查命令别名、定时任务、动态加载、构建模板、测试和历史回放。文件名旧、搜索不到导入或仅能在旧数据中找到，都需要结合这些入口判断。
2. 分开处理现用内部格式、公开接口、正式发行号、原始凭证和已经退役的写入能力。经授权统一内部格式时，让当前写入使用稳定名称和明确的结构指纹。对需要保留的旧记录先验证原字节和原格式，再转成当前程序可用的视图。公开接口先对照实际消费者，决定保留边界转换还是协调一起迁移。
3. 历史声明指向旧提示词、源文件或程序时，保存可定位的原对象。逐字检查、字段兼容和继续执行是不同能力。原材料缺失时保留阻断，不能重算一份新摘要冒充原证明，也不能让旧记录重新获得写入、请求或发布资格。
4. 并行工作时分开写入范围，指定共享清单和跨边界接口的整合者。用独立目录跑夹具，检查时记录实际提交。最终在目标分支核对远端、合入状态和实际改动，保护用户未提交的文件。

至少检查新写后回读、真实旧记录读取以及关键拒绝路径。跨语言用同一材料核对两边的输出。依赖公开消费者时，用实际构建或读取入口检查。区分隔离夹具、明确绑定的真实旧记录回放和完整工程验收。只删除已查明无现行用途的入口与文件。

检查在哪里执行也要写清。某项检查退出持续集成后，最近一次集成通过不再覆盖它；此时只报告本机、哪个版本、哪条命令的结果，不沿用“集成通过”的说法。平台、运行时或环境不同时，另一环境的通过记录只说明那条路径，不证明本机行为。

## 运行失败时先保住已有结果

- 普通单项失败先保存，完成当轮其他项目，再收集全部剩余失败。认证、共同依赖、保存等运行级故障按项目规则停止新派发，妥善保存正在执行的结果。
- 来源缺失不一定能跳过。只有失败原因单一可判定（例如该篇全部官方下载地址都返回同一种“不存在”错误）、项目又给了硬上限时，才允许记录后跳过：把论文或对象编号、原始错误和跳过理由写入本次运行的独立记录，并绑定批次与来源运行。跳过的项不计为成功，不进入分析、产物和汇总，完成状态单列跳过数量。超时、认证错误、服务端错误、解析失败和格式不符都按整批停止处理；达到上限或上限为 0 时停止整批，不临时放宽。
- 身份不符、认证故障，以及不属于上一条情形的来源缺失，必须停止并报告实际错误：保留在途结果，不换来源重试，不把缺失材料补成新记录。
- 区分内容错误、来源缺损、格式不兼容、程序误判、原记录变化与服务故障。核对原来源、最新失败、待完成义务、候选、尝试与费用，再选恢复入口。
- 已保存的输出先用原输入和真实记录重新核验。内容合格、只差可验证的格式或状态时，优先复用原结果。程序误判用真实保存稿复现，配上应继续拒绝的反例，再修共同规则。遇到来源缺失或原稿变化时解决实际阻断。
- 局部修改应绑定准确的原句或数据位置、原稿摘要和修改依据。重建结果后确认范围外内容保持一致，再走正常校验。提交前持锁重读原稿和关键依赖，确认它们没有在准备期间变化。
- 重试保留旧失败、已发请求和真实费用。需要追加请求时按用户和项目授权登记新增消耗。请求预览、通过缓存、外层批次轮数和只读证明各有自己的用途。项目已有持续付费授权时，按项目规则登记必要的新窗口、清单和实际消耗后继续，不重复征求同意；授权只覆盖必要的执行与恢复，不改变来源、完成和发布资格的核验。

## 恢复入口按原因分开

同一流程常因不同原因需要继续：重新派发失败项、按外部审查意见维护已完成稿、或只补齐已完成的收尾阶段。实现上通常用互斥选项区分这些入口，它们不是同一条命令的不同写法。

- 入口只按它登记的原因授权。为“重新请求失败项”建立的清单或窗口，不能拿来承接审查意见或另一类失败；一项许可的额度、次数和费用范围不能外借。互斥选项同时出现时按报错处理，不自行挑一个执行。
- 新增窗口单独登记，绑定前序完整历史、真实稿件身份和实际费用。旧次数、旧稿和旧失败不清零，也不因新窗口重签为初次；中断后继续同一窗口，不平行登记同一批失败。
- 有些开关只减少动作：不请求模型、不放行重试、不聚合、只在锁内完成保存或暂存，失败稿原样保留。它们产出的结果不能当作“本轮已完成”，也不能据此跳过正常入口对完整失败集合的核验；不要把它与提权选项组合，实现通常会直接拒绝。
- 零请求修正（按审查意见改少量文字）只允许改动有明确上限的既有节点，每个节点绑定原稿摘要、原句范围和修改依据，不改动范围外的字符、图表或公式。原稿、原始请求次数和费用都要保留，改完仍走正常完整解析、来源核验与独立审查；不能手填成功、删失败或跳过检查。

## 发布后按同一份产物收尾

完成状态怎样划分，沿用 clear-technical-writing 中“写作时保住这些东西”的第 4 条“真实状态”；本节只补发布侧的步骤和证据。

1. 从审查结果确认目标文件和字节，发布时保护工作区里的其他改动。记录实际远端提交或发布对象；推送后核对远端 `main` 的 OID，确认它接受的差异恰是审查凭证允许的范围，没有夹带其他改动。
2. 绑定这次发布核对构建与部署。部署的 workflow 应属于发布提交，或属于保留该批已审页面字节的后续提交。旧提交成功、当前提交已推送和对应站点已部署分别记录。等待部署期间用阶段日志或服务状态观察，完整核验只在需要时运行。
3. 按发布清单核对目标网页或下载。按任务分别检查可访问性、最终地址、精确标题、页面结构或下载字节。先读工具实际判定条件，基础探测留下的缺口用相应检查补齐。
4. 与本次发布绑定的收尾登记（例如本项目的“不生图”记录）须能重新读取，其 SHA 与发布清单、审查凭证和远端发布提交对应，不能手填。
5. 状态汇报说清已完成的阶段、仍在等待的具体事项和验证范围。最终记录至少能找到发布对象、审查材料和外部验收结果。完成条件是数据、审查、远端发布、部署和网页核验全部通过，且第 4 条的登记有效；状态报告只反映读取时的状态，不能代替上线核验。

## 交付前检查清单

- [ ] 写入方、读取方、中断恢复、跨语言/进程/仓库/客户端消费者和命令别名已列全；删除前确认没有现行用途。
- [ ] 现用内部格式、公开接口、正式发行号、原始凭证和退役写入能力分开处理。
- [ ] 旧记录能定位原字节和原格式；材料缺失时保留阻断，没有用新摘要冒充原证明。
- [ ] 新写后回读、真实旧记录读取和关键拒绝路径都有实际结果；跨语言用同一材料核对。
- [ ] 失败批次先完成整轮并保存，再只续真实可重试的失败集合；原失败、尝试和费用没有被清零。
- [ ] 允许跳过的项只有单一可判定的原因，逐条记录了原始错误与理由，未计入成功、产物或汇总。
- [ ] 恢复入口的许可只用于它登记的原因，新窗口单独登记，旧次数、旧稿和旧失败未清零。
- [ ] 减权开关没有与提权选项混用，其结果没有被当成完成或发布资格。
- [ ] 零请求修正只改限定节点并绑定原稿摘要，改后仍通过正常完整解析与独立审查。
- [ ] 局部修改绑定原句或数据位置、原稿摘要和依据，范围外内容保持一致。
- [ ] 提交前持锁重读原稿和关键依赖；并行工作时只改分配的写入范围。
- [ ] 发布对象、对应构建与部署、目标页面或下载字节分别核验；状态汇报写明未验证的部分。
- [ ] 远端 `main` 的 OID 已核对，推送差异恰为审查凭证允许的范围；部署对应发布提交，或对应保留该批已审页面字节的后续提交。
- [ ] 与本次发布绑定的收尾登记可重读（如不生图记录），SHA 与生成清单、审查凭证和远端提交对应。
- [ ] 完成条件按数据、审查、远端发布、部署、网页核验和登记分别确认；状态报告不算上线核验。
- [ ] 身份不符、认证故障或不可跳过的来源缺失已停止并报告，没有换来源重试或补造记录。
- [ ] 验证范围写明在哪执行；已退出持续集成的检查单独说明，不沿用旧的集成通过结论。
- [ ] 新增或追加付费轮次按项目规则登记，持续授权范围内不重复征求同意。
