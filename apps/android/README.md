# 论文速递 Android

Android 原生应用读取网站已有的论文目录、图文导读、日更/会议汇总和说明页。你可以阅读原始 PDF、记笔记、保存离线资料，也可以主动发起自己的研究，或连接 Zotero 与坚果云。

功能说明、正常测试、模拟器操作和真实账户验收分别留证。当前包的范围与原失败见[验收记录](../../docs/android-validation.md)，逐项要求见[跨端验收表](../../docs/android-feature-parity.md)；debug 安装成功不等于正式发行，Android 结果也不能替代 Mac 验收。

## 从阅读开始

1. 正式资源通道首次是空目录。在“文献”同步网站来源，再打开论文；读取已有导读不会调用模型重分析。原 PDF 和图片按实际需要读取，来源或网络不可用时保留已有材料并说明缺项。
2. “阅读”页集中显示导读、原文、研究和笔记。手机一次显示一份主要内容；PDF 已打开且实际安全宽度足够时，才提供并排和专注布局。平板、折叠姿态和大字按实际可用区域排版，不把纸张强塞进手机两栏。
3. “网站汇总”在文献页进入。分类、搜索、保存版本、完整来源和离线状态各有入口。公式使用本地排版，图片只缓存实际打开页面所需的部分；缺图、旧目录或失败明确提示，不能称整站完整离线。普通网站说明也不会自动成为可分析的论文。
4. 新的个人研究先确认材料范围、问题、模型配置与预算。应用保留输入、回答、失败和实际用量；相同来源与输入可以复用原结果，明确重做另记历史。恢复资料或重新打开页面不会自动重发已派发的付费请求。
5. 在“任务”看真实进度、失败和取消结果；在设置中管理连接、资料与恢复。未知金额或未取得的结果保留未知，不能把界面已有内容当作本轮成功。

## Zotero 与坚果云分别做什么

Android 通过单独配置的 Zotero 官方 Web API 连接个人或群组文库，不继承 Mac 的本地许可。书目、完整来源、PDF、图文导读与所选研究/笔记逐项保存和回读；原映射、用户修改及失败断点受保护。Zotero Storage 和 WebDAV 是不同附件后端；当前 WebDAV 迁移支持的文库范围、目录要求与实际状态见[Zotero 说明](../../docs/android-zotero-research.md)。

Zotero 附件空间受限时，界面可要求你明确确认是否沿原归档改用本 App 已配置的坚果云连接。已有书目和原 Storage 记录保留，新目录中的材料须重新回读；更改连接或重启后需要再次确认，不能靠旧页面继续使用失效授权。其他 Zotero 客户端仍须独立配置并检查相同 WebDAV 同步，迁移完成不自动证明它们已下载打开。

“坚果云研究资料”保存完整研究空间的独立版本，提供上传续传、版本选择、校验与确认恢复；它与 Zotero 附件目录分开。两端使用共同备份与离线包合同，保留文章版本、原件、笔记、批注、研究回答、费用及恢复所需的业务完整性材料。登录凭据和模型 API 密钥由各端安全存储管理，不随研究备份迁移，也不会读取其他应用的密码。详见[备份合同](../../docs/android-cloud-contract.md)。

## 本机构建

需要满足根项目要求的 Node、JDK 17、Android SDK 平台 37、Build Tools 36.0.0、NDK 27.2.12479018、CMake 3.22.1，以及 Mac 子项目锁定的 KaTeX 依赖。版本来自当前 Gradle 配置；首次构建须下载锁定的工具和依赖。`build.sh` 使用已有 `JAVA_HOME` 与 `ANDROID_HOME`，也识别本机 Homebrew 路径，不修改全局设置。

```bash
./apps/android/build.sh :app:assembleDebug
./apps/android/test.sh
```

默认 debug APK 在 `apps/android/app/build/outputs/apk/debug/app-debug.apk`，仅用于开发验证。debug 的 `private-qa` 资源含固定公开 MiCLA 图文/PDF及目录小样；release 只带空目录引导、排版资源和完整许可。两通道输出和清单分开，正式 APK 不得混入样稿、私有验收 Activity、用户资料、生产 runtime 或 `.env`。

## 验证与发行

JVM、Lint、资源检查不替代系统文件选择器、原生 PDF 或实际文字可读性。原合成界面恢复、真实公开论文展示和真实账号流程须各自标注，不能互相借用“通过”。最新数据写在[验收记录](../../docs/android-validation.md)，本页不抄一份很快过时的测试总数。

设备测试只在自己创建的专用离线验收设备执行。先核对 `adb devices` 与实际 AVD 名称，把下列 `SERIAL` 替换为已选设备的序列号：

```bash
./apps/android/install.sh SERIAL
./apps/android/test.sh --device SERIAL
```

运行安装命令时明确传入 `SERIAL`；脚本定向该设备，并对模拟器核对 `PaperDigest_QA_API35` 或 `PaperDigest_QA_API28` 名称。它不负责替你确认该设备没有个人资料。测试入口还会检查指定设备就绪，并将运行目标限制为该序列号。不要改用用户现有手机、研究模拟器或向所有已连接设备派发。私有夹具、正常设备套件和真实账号验收分别保存证据。

正式发行还须核对固定源码、版本升级、APK签名、四ABI与16KiB对齐、包内许可、空目录资源及实际安装。签名私钥和口令不进入仓库。最终发行范围和下载资产以实际 Release 为准，不使用临时私有 QA APK 代替。
