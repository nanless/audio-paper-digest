# 客户端共享样稿与显示资源

[English](README.en.md)

本目录保存 Mac 和 Android 应用共同使用的固定论文样稿、原图准备脚本，以及显示正文所需的第三方资源。目录名来自早期交互原型；应用的安装和使用分别见 [Mac 说明](../../apps/macos/README.md)和 [Android 说明](../../apps/android/README.md)。

旧浏览器演示、独立网页服务和演示专用的 PDF.js 已退役。这里不再提供另一套应用入口。正式 Mac 使用 PDFKit 显示原文，Android 使用自身的 PDF 阅读组件；两端的测试和资源构建仍读取本目录中的必要材料。

## 各份材料的作用

| 路径 | 保存什么 | 实际用途 |
|---|---|---|
| `sample.json` | 固定 MiCLA 解读、书目、公式、表格、原图坐标及预期校验值 | 两端的科学排版、来源返回和打包隔离检查 |
| `assets/` | 本机准备的原始 PDF 和三张固定裁图 | 本地应用测试；原件和裁图不提交 Git，也不进入正式发行包 |
| `prepare_assets.py` | 按固定 PDF 页码和坐标重建裁图的准备程序 | 只读取明确指定的 PDF，核验后写入本机样稿目录 |
| `vendor/marked.esm.js` | Markdown 显示程序 | 两端构建时读取；保留对应 MIT 许可 |
| `vendor/lucide.min.js` | 界面图标程序 | Mac 网页显示层读取；保留对应许可 |

`sample.json` 不是全站同步接口。它不含模型配置、密钥、费用或内部请求，固定样稿的测试结果也不能用来证明全站同步、真实模型请求或 Zotero 写入已经通过。

## 准备本机样稿

从[原件说明](assets/README.md)取得指定 PDF。必须使用同一份公开原件；仅有相同文件名不能证明内容相同。准备程序会先比较整个 PDF 的 SHA-256 校验值，再检查页数，按固定页码、点坐标和三倍倍率裁出原图，最后核对每张图的校验值。

在本目录执行：

```bash
python3 -m pip install PyMuPDF==1.26.5
python3 prepare_assets.py --pdf /absolute/path/to/2610.27491v1.pdf
```

将示例路径替换为原始 PDF 的真实绝对路径。`2610.27491v1` 是 arXiv 原论文的正式身份，必须与样稿记录一致。PyMuPDF 的发行号规定裁图工具，不能随意换掉后仍声称产生相同字节。

程序不连接网络、不读取 `.env`、不搜索内部运行材料，也不改变交给它的原件。它先在临时目录中生成并核对所有结果，全部通过后才替换本机样稿文件。任一校验失败时，应检查原件和工具，不能修改预期校验值来消除错误。

## 构建和验证的边界

Mac 的 `build_resources.py` 与 Android 的 `prepare-assets.mjs` 读取这些共享材料。正式包只携带应用需要的显示程序；固定论文样稿、原 PDF、裁图和测试记录继续由打包检查排除。完整测试前的环境要求见各端 README。

SHA-256 是对文件字节计算的内容校验值。这里用它确认 PDF、裁图和样稿没有被替换；它不能代替论文事实审查，也不能让一份旧稿取得新的分析或发布资格。

第三方程序的原始许可与程序一并保留。论文及原图版权仍属于原作者。当前网站同步接口与后续数据设计见[Mac 数据说明](../../docs/mac-app-data.md)和[客户端数据设计](../../docs/desktop-data-contract.md)。
