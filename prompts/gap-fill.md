# 分析审校提示词

## 用途

对照原文检查主分析及资源扫描后的文本，纠正事实和评分问题，补充遗漏，输出可以完整替换已有分析的版本。这份结构化分析用于后续评分、修复和发布资料；默认博客正文由 API Reader 根据原文独立生成。

## 调用方式

代码通过 `loadPrompt()` 替换 `{title}`、`{arxivId}`、`{existingAnalysis}`、`{textForAnalysis}` 和 `{tagPromptText}`，分别提供标题、论文 ID、已有分析、本次论文证据和当前可用的标签定义。

## 提示词内容

~~~
请对照下方原文审校已有分析。核对研究问题、方法、数字、作者机构、实验结论和评分理由，纠正与原文不符的内容，补充重要遗漏，删除没有证据的推断。输出完整替换文本，直接从 `## 评分` 开始，不加前言、问候、其他开头标题或代码块围栏。

论文标题：{title}
arXiv ID：{arxivId}

已有分析：

{existingAnalysis}

论文原文：

{textForAnalysis}

当前可用的标签及其定义：

{tagPromptText}

### 输出结构

以下 13 个一级章节按顺序各出现一次：评分、机器摘要、标签、作者与机构、毒舌点评、核心摘要、方法概述和架构、核心创新点、实验结果、细节详述、评分理由、局限与问题、开源详情。标题使用 `## 章节名`。不要只输出修改片段，也不要增删或重复章节。

评分使用 `X.X/10`。机器摘要的 17 个键各出现一次，使用 `key: value` 纯文本格式，不加列表符号，不加粗，也不在值中使用其他 Markdown 标记：

```
document_type: 方法研究 / 系统技术报告 / 模型报告 / 数据集与基准 / 综述 / 理论研究 / 应用研究
rank_bucket: 前10% / 前25% / 前50% / 后50%
innovation: X.X
technical_rigor: X.X
experimental_sufficiency: X.X
clarity: X.X
impact: X.X
open_source: X.X
reproducibility: X.X
engineering_score: X.X
confidence: 高 / 中 / 低
primary_task_tag: #标签
primary_method_tag: #标签
sota_claim: 是 / 否 / 未说明
has_code: 是 / 否 / 未说明
has_model: 是 / 否 / 未说明
has_dataset: 是 / 否 / 未说明
```

文档类型按主要贡献选择一个，排名和置信度只能采用示例中的值。八个分项使用原始分数，必须是非负数字，最多一位小数，不能以文字代替。`sota_claim`、`has_code`、`has_model` 和 `has_dataset` 只能写“是”“否”或“未说明”，不留空。

标签严格写四行：第 1 行列出全部标签，第 2 行使用 `主任务标签：#具体任务标签`，第 3 行使用 `主方法标签：#具体方法标签`，第 4 行使用 `补充标签：#标签`。标签以 `#` 开头，用空格分隔，不用逗号、分号或顿号，共 3–5 个。

只使用当前提供的首选标签，状态为 `active`。主任务来自 `facet=task`，选择最具体的适用概念；主方法来自 `facet=method`，描述实际核心方法；补充标签可来自其他分类维度。不输出概念 ID、别名、已弃用名称、自造标签或 arXiv 类别，也不同时选择同一概念的别名或其上位和下位概念。

核对这些容易混淆的情况：识别或 ASR 只是社会语音学、韵律或发音评估的测量工具时，不标为语音识别。视频、参考音频、嵌入或到达方向用于指定目标时，选目标说话人提取；只有视觉用于盲分离时才选音视频语音分离。贡献是表示、量化、数据或协议时，不把骨干架构当主方法。没有训练的处理流程按实际信号处理方法选标签，对抗工作按实际机制选对抗训练或对抗鲁棒性，不因输入多模态就选多模态学习。

场景标签必须有实际研究或评测依据，不能只在局限或未来工作中出现。实时处理要有实测延迟或吞吐及其条件。基准、语料和数据集论文必须包含基准测试或数据集标签，它们在数量限制内优先于泛泛场景或模型族。补充任务必须有并列贡献或评测证据，仅使用 WER 等评测工具不构成另一个任务。

### 事实和正文

检查原文中已有分析遗漏的关键组件、训练细节、消融、与最佳基线的实际差距和作者报告的局限，补充到相应章节。所有补充信息都要有原文依据；未提供的信息写“未提及”或“未说明”，不按常见做法补造。

方法部分不少于 600 个中文字符。解释每个核心组件的名称、功能、内部结构或实现、输入与输出，以及组件间怎样传递数据。多个阶段分别说明，核心术语首次解释，设计动机有原文依据或明确标为有依据的推断。本轮没有图片网址；只有正文或图注明确写出的关系才能用文字说明，不插入或编造图片引用。

各节承担不同内容，前后自然衔接，不围绕同一组数字在摘要、方法、创新、实验、细节和局限中反复改写。精确实验量用阿拉伯数字，每组比较就近交代设置、基线、指标、数值、单位和方向。术语首次给中文解释和官方英文名或缩写，后文固定简称，中文与英文之间留空格。正文使用完整句子，不拼接编辑字段、不使用双重编号，也不堆叠防御性否定句。

保留已有合格的精简实验表，不恢复成原文全表。最多 2 张 Markdown 表格，每张最多 12 个数据行、8 个指标列，方法、模型和数据集等识别列不计入指标列数。实证论文的表格合计至少有 3 个数据行和 2 个可核对数字。优先保留本文方法、最强及代表性基线、汇总行、关键消融和负结果。

表头有识别列，方向性指标标 `↑/↓`，不以“结果”“观察”“含义”“说明”或“结论”代替指标。表前说明比较问题和为什么保留这些行列，表后解释主要差异、代价与适用范围。不要孤立放表、逐行复述、套用固定句首，或用“此处省略”“表格数据与论文一致”“详见原文”代替说明。负号用 ASCII `-`，百分号用半角 `%`，小数保留前导零。

数学公式使用 `$...$` 或 `$$...$$`，不写成普通文本。例如使用 `$RMS = \sqrt{\frac{1}{N} \sum y[n]^2}$`。`<S>`、`</S>`、`<E>`、`<task>` 和 `<perception>` 等文本标记用反引号包裹，避免被 Hugo 当作 HTML 标签。

### 评分核对

八个维度各出现一次，顺序为创新性、技术严谨性、实验充分性、清晰度、影响力、开源、可复现性、工程/实践价值，满分依次为 2、1.5、1.5、1、1.5、1.5、0.5、1.5。每项使用 `* 中文维度名 (得分/满分)：具体理由`，分数和理由在同一行。得分有限、非负、不超过分母且最多一位小数，不换算成十分制或百分制，不写总分计算过程。八项满分合计 11，总分封顶 10。

理由说明原文能支持的优点或缺陷。评分明显偏离实际贡献时，调整对应分项并写明证据。开源分与开源详情及相应核心材料一致，理论研究的证明材料不能仅用代码、模型和数据三个状态表达。已经公开核心代码、权重或数据时，开源通常应得 1.0 分以上；但仅有演示或未来开放承诺不能当成核心材料已公开。训练配置、超参数、硬件和复现步骤也充分时，才相应提高可复现性，不能仅凭链接加分。同步更新机器摘要中的资源状态，评分总分仍按统一规则计算。

按论文类型检查证据。方法研究看基线、消融、泛化和统计；系统及模型报告看质量、延迟、吞吐、成本、规模、压力测试、公平比较和失败案例；数据集与基准看覆盖、标注、泄漏、协议和基线；综述看检索、覆盖和综合分析；理论看证明、假设、边界和反例；应用看真实场景、外部验证和部署约束。不能因类型固定加分、保底或豁免。

没有传统消融不等于所有论文的验证都不足。只有声称某个组件带来提升而缺少对应证据时，才因这项缺失扣实验充分性。系统能力、软硬件协同或规模化工程有可检查证据时可以计入创新，宣传不能代替证据。

同一个缺陷只能扣一个主要维度。缺少核心材料归开源，缺少配置和步骤归可复现性，验证不足归实验充分性，表达问题归清晰度，推导或逻辑错误归技术严谨性。信息不足时降低 `confidence`，不把“无法验证”写成“技术错误”。

本分析面向语音、音乐和音频研究者。核心贡献在计算机视觉、自然语言处理、法律政策或通用机器学习等其他领域时，影响力通常不超过 0.5，不能因可能跨领域使用就给高分。

局限部分既核对作者报告的限制，也检查有证据支持的方法、实验或结论问题。把已确认的缺陷与待核查的推断区分，不以夸张评价代替具体依据。
~~~
