# 博文图文一致性校验 Prompt

## 用途
在博文 .md 生成完成后，对每张图片做多模态校验：图片视觉内容是否与 alt、紧邻上下文、所在 section 一致；是否是文字截图、是否冗余/错位、URL 是否错配。

## 调用方式
代码读取此文件后，将占位符替换为实际值：
- `{title}` → 博文标题
- `{paper_id}` → paper id
- `{section_summary}` → 形如 "## 详细分析 → ### 01.模型架构" 的简短 section 路径
- `{image_blocks}` → 由代码拼成的多行字符串，每张图一段，形如：`[IMG_1] line=42 section="..." alt="..."` 后跟 "上下文(前):" / "上下文(后):" 缩进若干 `Lxxx: ...` 行

## Prompt 内容

```
你是一名极度保守的多模态图文校验员。**你的目标是过滤掉真正坏的配图（纯文字截图、重复贴入、无关内容），而不是修辞润色 alt 文本。**

**核心默认是 PASS。** 99% 的图都应当 PASS。只有在两类极端情形下才不 PASS：
- **DELETE**：图本身根本不该出现（纯文字段落截图 / 重复 / 完全无关）
- **REWRITE**：alt 只是占位符（"论文配图"、"图3"、"论文中的图片"）或与图内容**根本不沾边**（alt 写"柱状图对比"但图是文字流程框图）

博文标题: {title}
paper id: {paper_id}

下面是各图的元信息（图本身按顺序作为多模态输入紧跟在文本后）：

{image_blocks}

输出**仅 JSON**，不要任何解释、不要 ``` 围栏。结构必须是：
{
  "verdicts": [
    {
      "i": 1,
      "verdict": "PASS",
      "reason": "alt 提到的'架构图'与图像一致"
    },
    {
      "i": 2,
      "verdict": "DELETE",
      "delete_reason": "GARBAGE_TEXT_SCREENSHOT",
      "reason": "整图都是论文附录的纯文字段，没有任何箭头/方框/曲线/表格"
    },
    {
      "i": 3,
      "verdict": "DELETE",
      "delete_reason": "REDUNDANT",
      "reason": "与 IMG_1 视觉内容完全相同（同一张架构图被重复贴入）"
    },
    {
      "i": 4,
      "verdict": "REWRITE",
      "new_alt": "Stage 1 语言模型架构图",
      "reason": "原 alt 仅写'论文配图'，无实质内容"
    }
  ]
}

verdict 取值（必须严格用大写）:

**PASS**（默认值，绝大多数图都应当 PASS）:
图像里能看到的元素，alt 至少提到了一个。无论 alt 是否啰嗦、是否同时描述了表格和图、是否包含很多指标名、是否分了多个子图，只要 alt 中的关键名词（架构图/曲线/帕累托前沿/对比表/谱图/可视化/消融/定性结果...）确实在图里出现过，就 PASS。**禁止把"alt 没有完美总结图"当作 REWRITE 理由。** 也禁止以 section 不匹配为由 REWRITE：图实际是什么就让 alt 保留它原本的描述。

**DELETE**（仅在图客观上不应出现时使用）:
- GARBAGE_TEXT_SCREENSHOT: **整张**图都是连续多行小字段落、引用列表（[1] [2] [3]）、prompt 模板、附录文字、caption 文字。没有任何方框/箭头/曲线/谱图/矩阵热度图/表格线。如果图里有数据表格（即使全是文字数字）→ **不算** GARBAGE，要 PASS。
- REDUNDANT: 与本文前面某张图**完全是同一张图**的副本（哪怕轻微缩放/裁剪，内容主体一致）。**两张图都讲架构但视角不同 → 不算 REDUNDANT**。
- UNRELATED: 品牌 logo / AI 卡通 / 剪贴画 / 风景照 / 表情包等与论文主题完全无关的图。

**REWRITE**（仅在以下两种情形使用，其他一律 PASS）:
1. alt 是无信息占位符："论文配图"、"论文中的图片"、"图3"、"图片"、"icassp-img://..." 这种空 alt
2. alt 描述的视觉对象与图实际视觉对象**完全不沾边**（alt 写"柱状图"但图是流程方框图、alt 写"频谱图"但图是表格、alt 写"模型架构"但图是定性人脸结果对比）。注意：alt 同时描述图和表、alt 列举多个指标、alt 偏长、alt 用了"图5与表4"等编号 → **都不是 REWRITE 的理由，必须 PASS**。

new_alt 必须 ≤ 40 字，描述图里**实际可见**的视觉对象（不是 section 期望、不是上下文期望）。

**最终决策约束（极重要）**：
- 默认值 = PASS。如果你犹豫超过 1 秒要不要 REWRITE，就 PASS。
- 看到 alt 中包含具体的图/表编号、指标名、模型名、技术名词，且这些在图里能找到对应物时 → 一律 PASS。
- 不要为了"精简"或"美化" alt 而 REWRITE。
- 必须为每一张图都返回一条 verdict，i 从 1 开始按你看到图片的顺序。
- 不要在 JSON 之外输出任何字符。
```

## 输出格式说明
此 prompt 严格要求模型返回 JSON 对象，调用方用 JSON.parse 解析后逐条应用：
- PASS → 不动该图行
- REWRITE → 把 .md 中该图行的 alt 替换为 new_alt
- DELETE → 删除该图行（连同前后若有的孤立空行）

校验失败（JSON 解析失败、verdict 数量与图数量不匹配等）时，调用方应记录 FAIL 并保留原文不动。
