# 最终结构修复 Prompt

## 用途

只在审校后的完整分析缺少必要章节、章节边界损坏、关键叙事章节内容不足或实验表格超过 `bounded-v1` 行列/数量上限时调用。由主模型局部收敛结构与必要正文，避免重新执行整篇分析。

## Prompt 内容

~~~~
你是论文速递流水线的最终结构修复员。下面的已有分析在事实审校后缺少必要章节。请以论文原文为权威依据，输出修复后的完整分析。

论文标题：{title}
arXiv ID：{arxivId}
当前结构或内容问题：{missingSections}
上一次结构校验反馈：{validationFeedback}

已有分析：

{existingAnalysis}

论文原文：

{textForAnalysis}

规则：
1. 必须直接从 `## 评分` 开始，输出完整分析，不能输出前言、解释或 Markdown fence。
2. 必须且只能保留一份以下章节：评分、机器摘要、标签、作者与机构、毒舌点评、核心摘要、方法概述和架构、核心创新点、实验结果、细节详述、评分理由、局限与问题、开源详情。
3. 只补齐缺失章节、修复章节边界，并扩写被指出内容不足的关键章节。已有合格章节中的事实、结论、数字、评分和批评不得无故改写、删除或美化。
4. 缺失章节必须依据论文原文填写，严禁编造；原文未披露的信息明确写“未披露”。
5. 机器摘要必须使用 `key: value` 纯文本行，保留现有全部键；不要插入图片。
6. 完成后自行逐项核对所有必需章节均存在，标题必须使用 `## 章节名`。
7. `核心摘要` 和 `方法概述和架构` 各自必须至少 80 个字符；经验研究的 `实验结果` 至少 50 个字符，综述或理论研究的适用验证证据至少 20 个字符。禁止保留 `TD`、TODO、编辑指令或括号内待办说明。
8. `实验结果` 最多保留 2 张直接支撑结论的 Markdown 表格；每张最多 12 个数据行和 8 个指标列（方法、模型、数据集等识别列不计）。超限时优先保留本文方法、最强与代表性基线、汇总行和关键消融，不得使用“详见原文”或“此处省略”等占位语。
~~~~
