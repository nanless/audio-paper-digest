# 论文处理提示词

[English](README.en.md) · [项目文档](../docs/README.md) · [Reader 写作说明](../docs/reader-writing.md)

`current/` 保存程序现用的 16 份提示词模板。模板规定模型接收哪些材料、完成什么任务、返回什么结构，以及材料不足或修复失败时不能做什么。它们不是依次运行的教程：程序根据实际流程、已保存的进度和当前错误选择需要的阶段。

本页供维护模板和排查模型输入的执行者阅读。只想学习怎样写论文解读，先读[把技术写清楚](../skills/clear-technical-writing/SKILL.md)、[项目写作约定](../docs/writing-guide.md)和 [Reader 写作说明](../docs/reader-writing.md)。运行日更、会议或历史更新，请从[项目操作规程](../SKILL.md)进入，不在目录里挑一个模板直接启动生产。

## 模板怎样进入一次请求

[JavaScript 提示词登记表](../scripts/lib/prompt-contracts.js)选择 13 份通用模板，包括筛选；另 3 份用于已经明确范围的事实或术语修复。Python 的[现用模板清单](../scripts/prompt_evidence.py)须与它一致。

加载器只读取模板的第一个围栏代码块，并把其中的 `{title}` 等占位符替换为本次材料。占位符是程序接口，不能随意改名。首围栏外的用途说明不发给模型，但整份文件也参与身份核验，因此不能把围栏外文字当作可直接润色的例外。

一次请求可能在模板之外增加当前数量要求、实际图片清单、反馈或受限操作说明。这些内容同样受输入身份和原请求记录约束；文档里出现字段示例或本地路径，不表示模型已经取得那份来源，也不增加修改权限。

## 写清楚，同时保住输出协议

面向初学者，先讲任务、对象和必要背景，再解释输入怎样经过关键步骤得到输出。术语要说明作用；普通中文足够时不强加英文，必要的正式名称、代码字段和缩写保持准确。比较附近交代对象、设置、指标、单位、数值方向和代价；公式解释实际运算，原图解释本次真正可见的内容。

段落按问题和解释顺序组织，转到新步骤、不同证据或推测时再分段。标题、正文、列表、表格与标记之间留空行；JSON 正文字符串用合法的 `\n\n` 转义表达空行。不要把检查要求、来源字段或编辑流程写进博客正文。

这些写作方法不改变机器输出。筛选仍返回固定结论，标签仍返回规定字段，评分仍返回结构化记录；受限修复只改当前获准目标。原表、TeX、逐字引文、字段、占位符与标记继续受各自协议保护。摘要选少量关键结果组时，每组仍保留可比较的双方数值、单位、精度、条件及必要成本，不能把组数当作数字个数上限。

## 表格材料与恢复材料分开使用

Reader 首次写作只依据本次提供的全文和实际收到的图像。可安全选择行列的原表使用 `selection`；需要整表时按 `completeTable` 的完整矩阵规则处理。普通全文中的连续结果句可用 `source_quotes` 绑定。具体输出形式和逐格来源要求见 [Reader 表格规则](../docs/reader-writing.md#表格和公式)。

只有本次受控恢复实际给出独立官方封存 PDF 的原字符全文，并明确允许相应引文操作时，`source_quotes` 才可增加 `pdfSourceQuotes`。路径、字段例子、图注、像素或先前的 PDF 证明都不替代本次材料和范围。`sealedPdfQuoteEvidence` 由程序核验生成，模型不得填写。不能通过换一种来源字段逃避数字、单位或比较条件检查。

日更 Reader 通过 Responses 修复普通已有字段时，程序还可生成带目标编号 `targetOrdinal` 和短标记 `requestToken` 的运行时提示词，再编译为按原字段 SHA 核验的补丁。特殊修复仍遵守各自规则。这类运行时提示词另记身份和真实请求，不增加目录模板数量，也不增加原窗口额度。

发布审查的页面输入由公共发布器生成，模型请求使用公共请求封装；它不是本目录中的另一份写作模板。旧稿从原保存进度和相应入口恢复，不能只因更换模板而重新取得内容额度。

## 修改模板与核验旧记录

现用模板使用 `current/` 下的稳定文件名，新请求使用不带编号的提示词合同，并记录实际内容指纹。文件名或合同名称不替代内容核验；历史记录仍按原路径、原声明和原 SHA 读取。

确需修改任何模板字节，包括围栏外说明时，先保全原 Git 对象及其整文件 SHA，再按[提示词修改规则](../docs/maintenance.md#prompt-修改)修改稳定路径中的现用模板。核对新旧占位符和输出结构，同步内容证据、共享登记和相关测试；不再通过增加文件编号表达变化。现有正确规则不为追求改动数量而更新。JavaScript、Python 和选定阶段重分析共用现用登记，历史格式和原预算由集中读取器核验，不能从旧稿重新取得请求额度。

旧模板不保存在工作树。[历史证据索引](../scripts/lib/git-prompt-evidence-index.json)保存原路径、Git 对象编号和整文件 SHA；读取器核对整文件及首围栏模板 SHA。旧对象缺失或字节不符时停止，不重建一份近似文本冒充原稿。原声明、论文来源、稿件、请求次数、费用和恢复范围继续保留；升级不能补签旧稿、删账或清零失败。

会议中尚未完成的旧 Reader，可在原请求、响应、用量与论文来源均核实后，沿用原模板声明只读重验。该入口禁止模型请求。旧 Manual 模板也只用于核验原记录，整批 Manual 生产入口已退役。

历史证据读取要求 Git 2.45 或更新版本及完整仓库历史，CI 使用完整检出。读取器只访问本地原对象，不自行联网补对象。浅克隆缺少原对象时，先同步完整历史，再重新核验；不把旧模板写回工作树。
