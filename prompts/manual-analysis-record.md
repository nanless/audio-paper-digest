# Manual 全文分析成稿规范

此模板只供 Codex/人工编辑在不调用项目 LLM API 时撰写 `manual_analysis_records`。它不由模型接口执行，但其 SHA-256 必须进入 Manual spec，使规则变化能够使旧 spec 失效。

```text
你正在基于受控的论文完整全文撰写一篇可直接发布的中文技术解读。Manual 不是摘要扩写，也不是把若干字段凑到长度门槛；最终成稿必须达到标准 API 深度分析的读者可见质量。

一、论证主线
- 核心摘要用 5–8 个完整句子回答：研究问题、既有缺口、方法主线、关键证据、实际意义、主要边界。句子之间必须有因果或转折推进，不能逐字段复述。
- 六个核心章节必须各司其职：摘要只保留 1–2 个主结果；方法只讲输入、组件、训练/求解与输出；创新解释为何不同和为何有效；实验展开比较；细节集中复现条件；局限统一收束外推边界。同一核心数字事实最多在摘要和实验各出现 1 次，禁止在方法、创新、细节和局限中换一种说法继续复述。
- 方法概述至少包含 5 个独立段落，依次讲清输入与表示、模块职责、数据流/并行分支、训练目标与阶段、推理输出及设计取舍。理论/数据集论文应使用与文档类型等价的对象、构造、证明或标注流程。
- `editorial.method` 与 `editorial.innovations` 是面向读者的最终完整章节，不是追加在短字段后的扩写。必须在一条连续叙事中吸收 `method/method2/method3/innovations` 的事实职责，但不要再次复述这些短字段；短字段仅用于证据审计和阶段 provenance。
- 核心创新写 3–5 项。每项都必须同时包含既有方法的具体限制、本文改变的机制、支持该机制的证据，以及不能外推到何处。禁止只列组件名。
- 实验结果必须绑定数据集、比较对象、指标方向、精确数字、消融或负结果和实验条件。全文有实验表时至少转写一张可读 Markdown 表；优先形成“主结果/效率”与“消融/失败案例”两层证据，而不是把论文压成三列结论卡。每张表至少有方法、数据集或设置识别列，指标名写明 `↑/↓`，单元格保留可核对数字；禁止用“结果、观察、含义、说明、结论”等叙述列冒充指标，也禁止把异构指标拼成总分。
- 表格必须嵌入论证：表前先提出该表要回答的具体比较问题并交代保留口径；表后只解释最关键的差异、原因或代价及不能外推的边界。不得孤立摆放数据卡，不得按行逐字复述表格。
- 每篇另写至少 3 条结构化 `resultClaims`，逐条给出 `datasetOrSetting`、`splitOrCondition`、`method`、`baseline`、`metric`、`value`、`unit`、`direction` 和全文连续 `sourceQuote`。每条还必须提供 `sourceBindings` 与 `readerBindings`：两者都必须且只能包含上述 8 个语义字段；值是人工选取的连续证据片段，至少 2 个非空白字符。`sourceBindings` 的每段必须存在于该条 `sourceQuote`，`readerBindings` 的 8 段必须共同落在实验结果的同一个自然段、句子或完整 Markdown 表中，不能靠数字在全章节别处偶然出现冒充本条证据。同一短片段最多供 3 个字段复用，禁止 8 字段机械复制整句。`direction` 只允许越高越好/越低越好（含 `↑`/`↓` 与等价英文）、描述性、绝对值关联强度或带理由的未报告。正文未报告的字段只能写成 `{ "notReported": true, "reason": "至少 8 个非空白字符的原因" }`，并为两套 binding 选取缺失、定性或负面证据；不能使用裸 `notReported`，也不能与推断数字混写。实证论文至少 1 条 claim 必须包含可核对数字；理论或纯定性论文若不足 3 条，必须用 `resultClaimsException` 绑定全文说明。
- 细节详述逐项覆盖数据/划分、目标或损失、优化与训练日程、关键超参数、硬件、推理/解码和稳定化技巧。论文未披露的项目明确写“未说明”，不得按常见实现补造。
- 局限分为“论文证据直接支持的边界”和“进一步审视”。前者只写作者或实验直接支持的限制；后者写审稿视角的缺失对照、统计、外推、复现或部署风险。

二、评分
- 八个维度各自给出论文特有证据和扣分边界。每条理由必须能脱离维度名称独立成立。
- 禁止“创新维度认可……”“方法维度有……”“综合维度体现……”等模板句。
- 清晰度只评价组织、符号、公式、图表与表达；可复现性只评价数据、配置、超参数、硬件与步骤；不得错位。
- 开源只计算本文直接交付的代码、模型、数据或 Demo，第三方依赖和未来口头承诺按固定锚点处理。

三、图片与技术表达
- 逐项审阅全文 manifest 中通过安全过滤的论文图。优先架构、流程、核心实验和关键失败案例；最多 4 张。资助方 logo、站点 chrome、作者头像、许可图标和无语义碎片必须拒绝。
- 只要选择图片，就必须在同篇 record 中显式给出与 `selectedImageUrls` 等长、同顺序的 `imageInsertions`；禁止省略选择后由代码自动生成邻文。每项包含 `url`、`section`、`anchorQuote`、`conclusionQuote`、`lead`、`explanation`。
- `anchorQuote` 必须唯一命中目标章节的一段正文；`lead` 承接该段具体命题并提出阅读任务（核对分支、比较曲线、追踪输入输出等），且复用至少一个论文特有术语。`conclusionQuote` 必须唯一命中同节中不早于锚点的后续论证或结论段；`explanation` 先写图中可见结构/曲线/色块/样例，再回扣该结论的条件或边界，并复用至少一个论文特有术语。
- 禁止“逐项对照”“不代表额外阶段”“不替代未报告配置”“只支持对应设置、不能外推”等跨论文模板。图片必须插入最相关正文段落之后，保留完整图注 alt；不得只把 URL 堆到章节末尾，也不得形成与前后段无逻辑关系的孤岛。
- 图前、图后和表前说明必须随论文内容自然改写；禁止把“关键比较问题是：”“下图用于核对”“证据边界在于”“下一段将解释”当作固定句首，禁止用“1. 是……”批量展开创新点。段落不得以分号结束，也不得出现“具有有”“尚尚”或“但……，但……”这类拼装痕迹。
- 若全文 manifest 有合格论文图，Manual 必须逐图明确选择或拒绝；不能省略 `selectedImageUrls` 让代码代选，也不能用空数组绕过审查。
- 源文中对理解方法或实验必要的公式，应使用 `$...$` 或 `$$...$$`；不需要公式的论文不得为了形式完整而编造。

四、事实与编辑质量
- 所有数字、方向、数据集、基线、资源状态、作者机构和限制均须由绑定全文或明确仓库证据支持。
- 所有实验数字、样本量、模型规模、时长、频率、百分比、比例、名次、超参数和置信区间统一使用阿拉伯数字；中文数词只用于序数、固定词组和不精确修辞数量。禁止先在表中写 `128`，再在正文写“一百二十八”复述。
- 每条结果句必须就近绑定数据集或设置、比较方法、基线、指标、数值、单位、方向和必要条件；不能让读者回到上一段或表格猜单位。术语首次出现写中文释义与官方英文/缩写，后文固定一种简称，并在中文与 ASCII 技术词之间保留空格。
- 不得出现人工审计、证据块、prompt、manual_complete、评分锚点等流程元话语。
- 不得在不同章节复制同一长句；相同事实再次出现时必须承担新的论证作用，并保留比较对象和条件。
- 同一章节也不得先用短字段概括一遍、再用长文把同一数据流或贡献重讲一遍；概览只能负责导航，不能成为正文的重复副本。
- 每个自然段只承担一个中心任务；段末必须推进、解释或限定下一段，而不是同义重启。避免连续使用“不能/不应/不足以”；证据边界集中放在结果结尾或局限章节一次说准。禁止 `1. 第一项` 双重编号和把“论文证据直接支持的边界”“进一步审视”作为无 Markdown 结构的裸行。
- 每篇必须附 `readabilityRubric`，逐项审查段内逻辑、段间承接、章节职责、事实局部性、术语与视角、句子节奏、去模板与文学性。每项 0–2 分并给出可定位证据，总分至少 12/14 且不得出现 0 分；rubric 不能替代正文确定性门禁。
- 最终逐页检查标题、作者、八维加总、表格列数、公式、图片 caption、URL、段落连续性和结论边界。
```
