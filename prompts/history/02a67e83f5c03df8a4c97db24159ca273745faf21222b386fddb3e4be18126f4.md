# 深度分析 Prompt — 单篇论文深度阅读理解（纯文本）

## 用途
双模型模式：主模型（纯文本）完成结构化分析，图片由独立的副模型（多模态）后续补充。
单模型模式：本 prompt 同时也是单模型模式的 prompt；未配置副模型时只做纯文本分析，图片仅保存为候选元数据，不会自动插入正文。

## 调用方式
代码读取此文件后，将占位符替换为实际值：
- `{hasFullText}` → "以下是论文全文，请仔细阅读所有技术细节。" 或 "以下是论文摘要。"
- `{textForAnalysis}` → 论文全文节选或摘要内容
- `{title}` → 论文标题
- `{authors}` → 作者列表（逗号分隔的字符串）
- `{categories}` → 论文类别（逗号分隔的字符串）
- `{arxivId}` → arXiv ID

## Prompt 内容

~~~
请对以下论文进行深度分析，以顶会审稿人（NeurIPS/ICML/ICLR 风格）的视角进行评审。{hasFullText}

论文标题: {title}
作者: {authors}
类别: {categories}
arXiv ID: {arxivId}
链接: https://arxiv.org/abs/{arxivId}

{textForAnalysis}

请按以下固定格式输出（用中文）。下列 13 个一级标题必须各出现且仅出现一次，不得增删、重复或将同名标题嵌入正文。缺失信息必须明确写"未说明"、"未提供"或"论文中未提及"，禁止根据常识、作者名气、单位名气、邮箱、外部网页或历史记忆猜测。

读者文本必须形成连续论证而不是字段拼装：摘要只负责问题—机制—1至2个主结果—主边界，方法只讲组件与数据流，创新解释机制差异，实验展开比较，细节集中复现条件，局限统一收束外推范围。同一核心数字事实最多在摘要和实验各出现一次，禁止在方法、创新、细节和局限中换说法复述。所有实验数值、样本量、模型规模、时长、频率、百分比、比例、名次、超参数和置信区间使用阿拉伯数字；中文数词只用于序数、固定词组和非精确修辞。术语首次出现写中文释义与官方英文/缩写，后文固定一种简称，并在中文与 ASCII 技术词之间留空格。不得批量复用“关键比较问题是”“下图用于核对”“证据边界在于”“下一段将解释”或“1. 是……”等写作脚手架；段落不得以分号收尾。

## 评分
先单独输出总分，格式必须是：X.X/10

## 机器摘要
**必须严格按照以下键值对格式输出，17 个键必须各出现且仅出现一次，不得增加额外键。每行一个键值对，键名必须与示例完全一致，禁止输出散文段落。如果某项信息无法确定，写"未说明"。**

**格式红线**：严禁在键值对中的任何位置使用 `**`、`*`、`__` 等 Markdown 格式标记。`**has_code:** 是` 和 `has_code: ** 是` 都是错误的，必须写纯文本 `has_code: 是`。**

```
document_type: 方法研究 / 系统技术报告 / 模型报告 / 数据集与基准 / 综述 / 理论研究 / 应用研究
rank_bucket: 前10% / 前25% / 前50% / 后50%
innovation: X.X
technical_rigor: X.X
experimental_sufficiency: X.X
clarity: X.X
impact: X.X
open_source: X.X
reproducibility: X.X
engineering_score: X.X
confidence: 高 / 中 / 低
primary_task_tag: #标签
primary_method_tag: #标签
sota_claim: 是 / 否 / 未说明
has_code: 是 / 否 / 未说明
has_model: 是 / 否 / 未说明
has_dataset: 是 / 否 / 未说明
```

**各字段说明**：
- `document_type`: 必须先判断文档的主要贡献形态，并且只能从 方法研究 / 系统技术报告 / 模型报告 / 数据集与基准 / 综述 / 理论研究 / 应用研究 中选择一个。类型只决定适用的证据标准，不直接加分或扣分
- `rank_bucket`: 只能从 前10% / 前25% / 前50% / 后50% 四档中选一档
- `innovation`: 创新性，范围 0-2
- `technical_rigor`: 技术严谨性，范围 0-1.5
- `experimental_sufficiency`: 实验充分性，范围 0-1.5
- `clarity`: 清晰度，范围 0-1
- `impact`: 影响力，范围 0-1.5
- `open_source`: 开源完整度，范围 0-1.5
- `reproducibility`: 可复现性（文档/细节充分度），范围 0-0.5
- `engineering_score`: 工程/实践价值，范围 0-1.5，评估论文的工程落地能力、pipeline 完整度、实际参考价值、工业界可复用性。对于 tech report、系统报告、benchmark 建设等工程型论文，此项必须严格评分；纯理论研究此项可为 0。
- `confidence`: 高 / 中 / 低
- `primary_task_tag`: 从标签中选择一个最主要的**任务**标签（以 `#` 开头，从【任务 — 语音】【任务 — 音频】【任务 — 音乐】【任务 — 多模态】标签表中选择）。**严禁**使用方法名、arXiv 类别或散文描述作为任务标签。
- `primary_method_tag`: 从标签中选择一个最主要的**方法**标签（以 `#` 开头，从【方法 — 神经网络架构】（含模型/架构类）或【方法 — 训练策略】标签表中选择）
- `sota_claim`: 论文是否明确声明达到 SOTA
- `has_code` / `has_model` / `has_dataset`: 是否提供代码/模型/数据集
- 八个分项必须是非负纯数字，最多一位小数；评分理由中的得分也必须使用同一归一化值。先将每个分项归一化到 0.1，再求和并封顶 10。
- `open_source` 只允许固定锚点 `0.0 / 0.2 / 0.5 / 1.0 / 1.2 / 1.5`，不得输出其他中间分。
- `sota_claim` / `has_code` / `has_model` / `has_dataset` 只能写 `是 / 否 / 未说明`，不得留空或写其他布尔表达。

【评分规则】
1. 先判断该论文在同期同方向工作中的相对位置，只能从前10% / 前25% / 前50% / 后50%四档中选一档。前10%对应领域突破性工作，前25%对应明显优秀，前50%对应合格到良好，后50%对应问题较多。
2. 各维度满分：创新性（0-2）+ 技术严谨性（0-1.5）+ 实验充分性（0-1.5）+ 清晰度（0-1）+ 影响力（0-1.5）+ 开源（0-1.5）+ 可复现性（0-0.5）+ 工程/实践价值（0-1.5）= 11 分。总分 = 各维度之和，但上限为 10 分（即超过 10 分按 10 分计），四舍五入到 0.1 分。
3. 评分必须有区分度，但不得故意压低分数。9.0 分以上只给真正具有里程碑潜力的工作；8.0-8.5 分给在重要问题上做出扎实贡献、有明确影响力的高水平工作；大多数扎实但非突破性论文应落在 6.0-7.5。不得因"这是组合已有技术"就压低工程型论文的创新性——关键看组合是否有新洞察、是否解决了真正的重要问题、是否带来了可验证的显著提升。
4. rank_bucket 必须与总分一致：≥9.0→前10%、≥7.5→前25%、≥5.5→前50%、<5.5→后50%。注意系统会从评分理由的八维分项重新计算总分并自动修正 rank_bucket，因此无需在评分理由中重复计算总分。
5. 不要因为任务小众就直接否定论文质量。小众、垂直、特殊人群、病理语音、动物声音等题材，在"创新性"和"技术严谨性"上应正常评分——只要问题定义清晰、方法有实质突破，就不能因其受众窄而压低创新分；但"影响力"必须打低分（通常不超过0.5），因为这类工作天然难以产生广泛的领域推动作用和后续研究价值。实验充分性中仅与数据集通用性相关的部分可以酌情扣分。
6. 采用"声明—证据匹配"原则：先列出论文的核心声明，再判断现有实验、证明、系统测试或数据分析能否支撑这些声明。只有当证据不足以支撑声明时，才在对应维度扣分；不能机械要求所有文档类型都具备同一种证据。
7. 采用"单一问题单一主维度扣分"原则。同一个事实只能归入一个主要扣分维度：缺少代码/模型/数据只扣开源；缺少超参数、训练配置和复现步骤只扣可复现性；缺少支撑声明的实验、对比或消融只扣实验充分性；写作、符号、图表和组织问题只扣清晰度；推导错误、不合理假设或算法逻辑漏洞才扣技术严谨性。严禁因同一处信息缺失在多个维度重复扣分。
8. "无法验证"不等于"已经证明错误"。公开信息不足时降低 `confidence`，并只在直接相关的开源、可复现性或实验充分性维度扣分；不得仅因闭源或细节未公开就认定技术逻辑不严谨。
9. 【领域相关性约束——最重要】本分析面向**语音/音乐/音频领域读者**。如果论文的核心贡献并非语音/音乐/音频（例如：纯计算机视觉、纯自然语言处理、纯法律/政策框架、纯通用机器学习理论、纯机器人/具身智能等），即使技术质量优秀，也必须在**"影响力"维度显著扣分（通常不超过0.5分）**，因为其对语音/音乐/音频领域读者的直接相关性和实用价值有限。此类论文不应因"跨领域通用性"或"方法理论上可被音频复用"而获得高分。只有当论文明确以语音/音乐/音频为核心实验对象、核心评测任务或核心应用场景时，影响力才可正常评分。
10. 文档类型决定实验充分性的适用证据：方法研究看代表性基线、消融、跨数据集与统计分析；系统技术报告/模型报告看端到端质量、延迟、吞吐、成本、规模、压力测试、竞品公平性和失败案例，只有在声称单个组件带来提升时才强制要求该组件消融；数据集与基准看覆盖范围、标注质量、泄漏控制、协议设计和基线；综述看检索方法、覆盖范围、分类体系和综合洞察；理论研究看证明、假设、边界条件和反例；应用研究看真实场景、外部验证、用户研究和部署约束。
11. 系统级创新、软硬件协同、规模化方法、工程组合产生的新能力均可计入创新性；不得因为没有新公式或因为组合已有技术就自动压低创新分。但只有产品功能描述、没有可检查证据的营销声明不能获得高创新分或高实验分。
12. 文档类型不提供固定加分、保底分或维度豁免。闭源系统报告仍须在开源和可复现性上如实失分；纯理论研究没有工程落地也可在工程价值上得 0 分。统一八维权重和总分规则始终不变。
13. 类型感知证据必须贯穿正文，而不只出现在评分理由：`核心摘要` 要说明主要贡献形态，`方法概述和架构` 要覆盖该文类的关键实现/论证链，`实验结果` 要呈现该文类适用的验证证据。原文未提供某类关键证据时明确写“论文未提供”，不得补造传统消融、系统指标、证明或用户研究。

【分项解释】
- 创新性（0-2）：问题是否新颖、方法是否有本质突破、insight是否深刻、与SOTA区分度是否清晰且有说服力。不要只因"组合已有技术"就低分，关键是组合是否有新洞察、是否解决了真正的问题。2分为真正突破性工作，1.5分为有明显创新，1分为小改进，0.5分为微小改进。
- 技术严谨性（0-1.5）：评价公开内容中的推导/证明是否正确、算法或系统逻辑有无漏洞、假设是否合理、边界条件是否讨论、数学表述是否严谨。闭源、未给超参数或未给源码本身不属于技术严谨性扣分理由。
- 实验充分性（0-1.5）：按 `document_type` 使用适配的证据标准，核心判断是证据是否充分支撑声明。消融只在论文做出组件级因果归因时强制要求，综述、理论研究、数据集和系统报告不得被机械套用方法论文模板。
- 清晰度（0-1）：只评价组织结构、符号定义、公式解释、图表质量和表达是否易于理解。实现细节不足导致无法复现应归入可复现性，不得在清晰度重复扣分；只有表达本身含混时才扣清晰度。
- 影响力（0-1.5）：对领域的推动作用、潜在后续工作价值、实际应用潜力、与音频/语音读者的相关性。评分时需综合考虑以下因素：
  - **研究成果本身**：在重要基准上取得SOTA、发布了大规模数据集/工具、解决了领域内长期存在的实际问题
  - **作者/机构信息使用边界**：只能使用论文文本中明确提供的作者、机构、资源发布、系统部署、数据规模等事实作为背景；不得根据外部记忆、作者名气、机构名气或单位刻板印象加分
  - narrowly applicable 的小改进或非音频核心工作只能得低分
- 开源（0-1.5）：论文核心内容是否公开可用。**注意：不同论文的核心内容不同**——模型论文的核心是代码+模型权重，数据集论文的核心是数据集，工具论文的核心是代码仓库，理论论文的核心是证明材料或实验代码。评分规则：
  - **1.5分**：论文核心内容已开源（含通过demo页面等间接提供链接的情况）且有完整文档
  - **1.2分**：核心内容已开源但文档不完整
  - **1.0分**：部分核心内容已开源（如仅有代码无模型，或仅有模型无代码）
  - **0.5分**：作者承诺开源但尚未发布
  - **0.2分**：仅提供demo但无开源核心内容
  - **0分**：完全不开源且无任何承诺
- 可复现性（0-0.5）：除开源外的文档充分度——训练细节、超参数、硬件环境、实验配置、复现步骤是否足够让他人不依赖作者就能复现。全部充分为0.5分，大部分充分但有少量缺失为0.3分，关键配置大量缺失为0.1分，核心方法和配置几乎都缺失为0分。
- **工程/实践价值（0-1.5）：评估论文的工程落地能力、实际参考价值、工业界可复用性。评分标准：**
  - **1.5分**：建立了完整的工业级 pipeline（如大规模系统报告、benchmark 建设、标准化流程、端到端生产方案），有大量可参考的工程细节和可复用组件，可直接指导实际落地。
  - **1.0分**：有明确的工程贡献（如详细的系统设计、组件化架构、完整的训练/部署流程文档），对工程实践有显著参考价值。
  - **0.5分**：有一定工程细节（如实现技巧、优化经验、工程 trade-off 分析），对复现有帮助但不够系统。
  - **0分**：纯理论或纯学术研究，无工程落地价值（此类论文正常，此项得 0 分即可）。
  - **注意**：对于 tech report、系统技术报告、benchmark 论文、工业界模型报告等工程型论文，此项必须认真评分；对于纯理论/方法论文，此项可为 0 分或低分。

【参考区间】
- 9.0-10.0：突破性贡献，领域里程碑候选，方法或结果具有范式转变潜力
- 8.0-8.5：高水平工作，在重要问题上做出扎实贡献，有明确影响力或显著性能提升，值得仔细阅读
- 6.5-7.5：有价值但不够突出，或有小硬伤，属于合格到良好，对特定方向研究者有参考意义
- 5.0-6.0：创新有限、实验薄弱、结论不够重要或存在明显缺陷，仅适合快速浏览
- 1.0-4.5：问题严重，推导错误、实验不支持结论或写作极差，不推荐投入时间

## 标签

**严格格式要求（必须遵守，不可省略任何一行）：**

```
#标签1 #标签2 #标签3 #标签4
主任务标签：#任务标签
主方法标签：#方法标签
补充标签：#标签 #标签
```

**示例（假设论文是关于语音识别的）：**

```
#语音识别 #语音大模型 #多语言 #低资源
主任务标签：#语音识别
主方法标签：#语音大模型
补充标签：#多语言 #低资源
```

**【极其重要】标签强制约束（违反将导致解析失败并强制修正）：**
1. **第一行**是所有标签的完整列表，每个标签必须以 `#` 开头，用空格分隔。禁止用逗号、分号或顿号分隔。
2. **第二行必须**以 `主任务标签：` 开头，后跟**一个**以 `#` 开头的任务标签。该标签**必须**从下方【任务 — 语音】【任务 — 音频】【任务 — 音乐】【任务 — 多模态】标签表中选择最具体的一个，**严禁**使用方法标签、arXiv 类别或散文描述作为主任务标签。
3. **第三行必须**以 `主方法标签：` 开头，后跟**一个**以 `#` 开头的方法标签。该标签**必须**从下方【方法 — 神经网络架构】【方法 — 训练策略】标签表中选择最核心的一种，**严禁**使用任务标签或自造方法名作为主方法标签。
4. 第四行以 `补充标签：` 开头，后跟剩余的标签，补充标签**也必须**从下方标签表中选择。
5. **严禁**使用 arXiv 类别作为标签（如 `#cs.CL`、`#cs.AI`、`#eess.AS` 等）。
6. **严禁**输出无 `#` 前缀的纯文本（如 `uncertainty_estimation`、`Speech Processing` 等）。
7. **严禁**一个标签包含多个用逗号/分号分隔的内容（如 `#语音情感识别；政治演讲分析` 是错误的，必须拆成两个独立标签）。
