# API 读者文章 Prompt — 面向刚入门研究者的论文解读

## 用途

在事实修复和最终评分完成后，生成博客真正展示的连续读者文章。机器摘要、标签、分数和评分理由仍由旧 canonical 结构承载，本阶段不重写这些字段。

## Prompt 内容

~~~
请为刚进入语音/音乐/音频领域的研究生写一篇可核对、能复述方法的中文技术解读。准确性、学习依赖和实验条件优先于修辞；用具体动作和自然段落讲清楚，不写营销式判断。

论文标题：{title}
arXiv ID：{arxivId}

默认从原文独立写作。事实来源只有下方论文原文证据与本次收到的官方原图像素；不继承其他生成分析的解释、评价或推断。若提供修复草稿，它只标示待修正文，事实仍须回到原文核对。

带 ID 的论文原文证据：

{sourceEvidence}

代码校验反馈：

{validationFeedback}

上一版完整 JSON 草稿（首次生成时为“无”）：

{previousDraft}

本次由代码提供的机械契约（数量与门槛以此为准）：

{mechanicalContract}

若上一版不是“无”，必须以它为底稿，优先精确修复校验反馈指出的局部问题，同时复核其他已通过结构，禁止无理由换标题、重排数字或重写全文。最终仍输出完整 JSON，不得只输出差异片段。

写作原则：

1. 开场先用简短段落说清“输入什么、想改变什么、必须保留什么、输出什么”，且范围限于论文实际研究和验证的任务。确有帮助时可用一个明确标为教学示例的场景，不强求比喻贯穿全文，也不能把自己的示例说成“论文通篇复用”的实验、产品或作者叙述。
2. 术语第一次出现时，先用一句白话解释，再给出官方英文名称或缩写；之后固定使用同一个简称。
   仅仅分别定义术语还不够：凡是论文把两个或多个名词组合成一个机制（例如“语义锚点 + 声学锚点”“门控 + 交叉注意力”），必须紧接着解释各自负责什么、为什么要搭配、组合后比单独使用多解决了什么。读者不应自行拼接这些含义。
3. 文章必须按学习依赖递进：任务与背景 → 相关路线与论文位置 → 方法全景 → 方法公式与关键组件 → 训练或确定性求解细节 → 数据集与实验协议 → 主结果与反证 → 边界/复现/收束。
4. 每个小节只承担一个教学任务，通常写 2–5 个自然段；长短段交替，短句可用于指出转折，技术段落通常 80–220 个汉字。小节标题优先写具体问题、操作或机制，避免让读者猜谜。段末自然推进到下一个问题，不要换句话重启摘要，也不要反复提示“接下来”。
4b. 遵守本次机械契约的节数与汉字范围，不以写满上限为目标。这里统计正文汉字，不是 JSON 字符数、英文长度或 token 数；标题、绑定记录与英文不能代替所需的中文解释。篇幅用于补足概念依赖、计算过程、对照条件和复现步骤；不要用重复结论、泛泛背景、连续反问或重复免责声明凑字数。后文重提同一结果时，必须增加新的机制、对照或适用条件。
5. 方法先讲完整的输入 → 表示 → 组件 → 目标 → 输出，再拆关键模块。给每个模块一个准确的动作描述，紧接正式术语和输入/输出，说明信息如何交给下一步。讲清哪些参数冻结、哪些参数更新、更新信号来自哪里。遇到跨帧、跨轮、测试时更新或重置，要跟着一个样本走完一次真实执行顺序，区分训练阶段和部署阶段，避免只有架构名词没有运行过程。
5b. 每个关键设计说明它解决的具体障碍，以及原文给出的安排理由和已验证对照。没有消融或原文论证时，不补写“拿掉后必然怎样”；有助于理解的未验证机制解释应简短标为推测。对性能或运行性质的判断，核对它成立的阶段、所用信息、参数状态和实际测量；不能从方法名称、初始化性质或参数冻结直接推定全程行为、监督来源或部署成本。
6. 实验不按 Table 1/2/3 翻译，而按问题组织：测什么 → 与谁比 → 指标方向 → 关键数字 → 支持什么 → 不能推出什么。至少就近呈现一个未胜出项、负结果或未评测边界。
   每张整理表前必须用 1–2 段提出它要回答的比较问题、统一的实验条件、基线与指标方向；表后必须用 2–4 段解释最公平的净收益、一个失败项/反例、以及哪些结论不能由这张表推出。禁止表格悬空，也禁止正文只是逐行复述数字。
7. 允许使用比喻，但只在它能减少理解成本时使用；紧接着把比喻中的每个角色对应到真实张量、组件、信号路径或实验条件，并指出类比不覆盖的部分。不要把“裁判”“记忆”“点火”等修辞直接当成优化性质、因果解释或稳定性证明，也不要给同一机制叠加多个比喻。
8. 文采来自准确的动词、自然的长短句和清晰转折，不是形容词堆叠。避免“本文提出”连续起句，避免“关键比较问题是”“下图用于核对”“证据边界在于”等流水线句式。
9. 不得编造数字、设置、因果关系或开源状态。每项事实保留完整身份：研究对象、划分与样本、比较条件、指标与单位、聚合方式、运行阶段和信息来源。原文定义不同的对象或指标不可互相替代；对总体趋势与全称结论分别检查反例。证据不足时具体指出缺少哪组对照或测量，不要反复写“不能外推”。
10. 不要输出分数、标签、机器摘要、评分理由、prompt、evidence ID 或流程元话语。直接讲图和方法，不能把“图后解释必须紧贴像素”“不擅自断言”“按反馈重写”等写作指令变成正文。首次术语解释使用自然句子或括号，不要把“白话是……”硬插进主谓之间；专有产品名保留原名，不机械直译品牌。
11. `READER_ARTIFACTS` 若给出公式，方法章节必须选择至多 5 条关键公式（只有 1 条时就选 1 条），但正文不要直接抄 `\[...\]`：用独占段落 `[[FORMULA_<ordinal>]]` 占位，并在 `formulaBindings` 绑定同一 ordinal。代码会从结构化原文注入原始 TeX；任何自行改写的展示公式都会被拒绝。
12. 表格优先服务核心比较：论文有定量主结果时，必须在 result/ablation 小节呈现数字结果表，包含必要基线和实际可运行的策略；不能只用数据集表、超参数表满足数量，更不能把主结果全部改成定性形容。原表行列可由代码逐字渲染；比较条件、指标方向和结论写在相邻正文。没有适合安全选择的原表时用 source_quotes 整理表，说明依据论文正文整理，不冒充原表，也不从柱高猜造精确数字。
13. 必须有专门段落解释数据集、样本构造、划分/采样、指标方向、基线、统计方法和硬件/训练预算。若论文没有训练可学习模型，要明确说明“没有训练阶段”，再解释复用模型、确定性求解和推理过程；不得用含糊的“模型完成评估”带过。
14. 只从本次实际收到像素的 Figure 编号中按教学价值选图，不要自行输出图片 Markdown 或改写 URL。方法图服务于数据流，结果图服务于紧邻比较，案例图服务于具体错误机制。每张图都要在同一小节中形成“独立导读段 → 独占 marker → 独立解释段”，字数遵守本次机械契约。没有收到像素时不选图；图注和原文仍可作为明确归因的文字事实，不得猜测图例、坐标轴、曲线、颜色或模块位置。
15. 把参考级深度作为下限：除核心结果外，还应按论文证据单独展开至少两类细节，例如数据构造、训练配置、消融机制、翻译器/数据规模失效条件、错误案例、部署成本或多语言扩展。不要为了控制篇幅把这些重新压成一段。
16. 按证据分别讨论数据与协议、主结果、关键消融/失败条件、训练或部署成本；不要把不同实验条件的数字挤成一张概览表。表格数量与宽表门槛以本次机械契约为准。选择原表时保留控制条件与必要基线，不为了凑宽度添加原文没有的列；需要整理表时每个数字与单位仍须有逐字 quote。
17. 图文互动不是“插图 + 图注”。图前正文先解释为什么现在看这张图；`focusPoints` 再给出 2–4 个按顺序可执行的观察点；有真实像素时，图后正文必须引用实际坐标轴、曲线、面板、图例、模块或案例，并说明它怎样改变当前判断。若一张图只能得到通用描述，就不要选它。
18. 每段写完都做一次“指代与依赖”检查：本段的“它/该模块/这一结果”必须能唯一回指；新概念依赖的前置概念必须已经解释；结论必须紧邻支撑它的公式、图、表或原文事实。若读者需要跨两节猜主语、比较对象或指标方向，就重写当前段，而不是补一句“综上所述”。
19. 区分三层事实：论文直接报告的事实、由这些事实作出的有限解释、作者未验证的推测。用“报告/显示”“说明/支持”“可能/尚不能判断”分别表达，禁止把相关性写成因果，也禁止用一串防御性否定淹没主要结论。
20. 读图先按图例确认完整实验对象、条件与时间范围，区分分布曲线和单样本标记，不能仅因同色就当成同一对象。再核对纵轴表示原始指标、相对改变量还是改善量，结合指标升降方向判断好坏；不能把曲线向下直接写成性能变差，也不能把初期趋势延伸到后期。只叙述收到像素中可核对的元素；图注或原文的补充说明要明确归因。没有像素的 Figure 不得加入 figurePlacements。
21. 每张表在 `tableBindings` 中按正文顺序绑定。只有 `TABLE_<ordinal>_SELECTION` 明示 `eligible:true` 的原表，才优先使用 `{tableIndex,selection:{sourceTableOrdinal,sourceRows,sourceColumns}}`：只选原表编号与零基行列，在正文独占一段写 `[[TABLE_<tableIndex>]]`；代码生成 Markdown、坐标映射和 SHA，你只写表前与表后的解释。`eligible:false` 表示含空源表头、未明确区分数据行、MathML/TeX 双写或不安全渲染内容，具体原因见 reasonCodes；不得对这张表反复尝试 selection，也不能猜表头或改写原始来源。此时使用已有 source_quotes 路线，以逐字连续全文原句绑定整理表，仍须通过全部数字与单位门禁；没有充分 quote 时明确报告无法完成该表，不能补造证据。第一条 sourceRows 必须是原表头行，后续必须是数据行；行列不可重复或越界。多级表头可选其完整的底层表头行。selection 项不得附带手写数据、cellBindings、sourceType 或 sourceQuotes。已有 artifact_table 全量逐格映射输入保持兼容。禁止自行填写 SHA 或 DOM 身份。
21b. 表内数字必须照抄原文写法：44,000 不得写成 44000，100% 不得写成 100，19.44 不得四舍五入成 19，年份 2025 不得加 s 写成 2025s；单位（%、dB、ms、Hz、GB）必须与原文一致。任何改写都会导致绑定失败。
21c. 发现原文转换中的数字或 TeX 双写粘连时，不能自行猜测新数值。选择模式保留来源单元格，由代码检验；无法安全渲染时改选同实验中可重放的表或用干净连续原句作 source_quotes，不得把绑定失败说成作者没有报告。叙述数字用阿拉伯数字，保留原文单位、千分位与精度，数字与拉丁单位之间留空格。
21d. 每张表严格三选一，不得混用正文形态或绑定字段：
   - selection：正文独占 `[[TABLE_<tableIndex>]]`，不写该表 Markdown；绑定项只含 `tableIndex` 和 `selection:{sourceTableOrdinal,sourceRows,sourceColumns}`，由代码生成所有单元格。marker 中的编号是正文表序号，不是原表 ordinal。
   - artifact_table（既有兼容模式）：在 `sections[].body` 写完整 Markdown 表，不使用 TABLE marker；绑定项恰含 `tableIndex,sourceType,sourceTableOrdinal,cellBindings,sourceQuotes`，`sourceType="artifact_table"`，`sourceQuotes=[]`，每个 cellBindings 项恰含 `renderedRow,renderedColumn,sourceRow,sourceColumn` 四个坐标。
   - source_quotes：在 `sections[].body` 写完整 Markdown 表，不使用 TABLE marker；绑定项恰含 `tableIndex,sourceType,sourceTableOrdinal,cellBindings,sourceQuotes`，`sourceType="source_quotes"`，`sourceTableOrdinal=null`，`cellBindings=[]` 必须为空，`sourceQuotes` 是逐字连续原句的字符串数组。不得发明 `value`、`quoteIndex`、`renderedText` 等单元格字段；quote 只负责验源，不负责生成表格。
   source_quotes 格式配对示例（方括号内容是格式占位，实际输出必须换成本篇证据；仍须满足本次表宽、数量和叙事门禁）：正文 body 中直接写 `| 条件 | 基线 | 本方法 | 指标 | 单位 |\n| --- | --- | --- | --- | --- |\n| [原文条件] | [原文基线值] | [原文方法值] | [原文指标名] | [原文单位] |`，相应绑定写 `{"tableIndex":1,"sourceType":"source_quotes","sourceTableOrdinal":null,"cellBindings":[],"sourceQuotes":["[覆盖这些数值与单位的原文连续句]"]}`。正文中不要再写 `[[TABLE_1]]`。
22. `tableBindings` 必须与正文表格一一对应，`formulaBindings` 必须与正文所有展示公式一一对应。论文确实没有原始表或公式时允许相应数组为空；但只要正文自己生成了表，就不能因原文无表而省略 quote 绑定。不得输出绑定之外的 Markdown 表或 `\[...\]` 公式。
23. 邻近方法按“是否接收相同输入、是否改变相同对象、是否使用相同监督、是否支持相同运行阶段”做有来源的对照，帮助读者看懂论文位置。没有同条件实验时，不得把不同方法类别的设计差异写成性能胜负，也不得用“以前没人做过”等宣传句替代相关工作证据。
24. 公式服务于计算过程：先解释符号对应哪种信号/分布/参数，再说明目标在拉近什么或惩罚什么、梯度经过哪里、哪些量被固定。明确区分原始目标、近似、停止梯度和实际实现；不能仅给公式后再用一句比喻跳过推导。
25. 结果讨论先交代基线和公平条件，再解释主要收益及一个未胜出项/代价。比较必须保留原文实际可运行的策略；昂贵的搜索、oracle 或事后最优值要另列，不能只挑最优列代替可部署收益。后续小节只有加入新对照、机制或适用条件才可重复同组数字。训练资源、推理开销、输出帧率与实际延迟分别表述。表内证据不能绑定时，应回查原文或按反馈重建表；禁止写入内部绑定/校验占位或假装论文未报告。
26. 结尾回答读者真正要做的决定：什么条件下值得尝试、复现先做哪一步、最需要补哪项验证。可在 reproduction/synthesis 的自然段中解决 2–3 个论文特有的常见误解，但不要另加通用 FAQ 清单或重复摘要。开源代码、可下载权重、可运行系统是三种不同状态，分别依证据说明。
27. 复现建议保留原文明示的关键超参数与信息条件。区分作者用于选模型、评估或展示的策略和读者实际可运行的策略；教学例子只演示执行顺序，不添加未经来源支持的数值或效果。观察偏离预期时提出待核对变量，不把未验证解释写成故障诊断。

只输出一个合法 JSON 对象，不要 Markdown fence、前言或结尾。字段必须精确如下：

`sections` 数量遵守本次机械契约，`kind` 只能按需要从以下集合中选择，并且总体按列表顺序递进：

background / related_work / problem / method_overview / component / training / experiment_setup / result / ablation / limitation / reproduction / synthesis

必须覆盖：background、related_work、method_overview、training、experiment_setup、result、limitation、reproduction、synthesis。`training` 不代表一定存在神经网络训练：没有训练时，该节必须明确说明没有训练阶段，并讲清 PCA/SVD、优化器、规则、检索、仿真或既有模型推理的真实计算过程。理论、综述、数据集论文可以用等价的构造、证明、检索或标注流程承担方法职责。

`conceptBridges` 数量遵守本次机械契约。每项的 `terms` 必须恰有 2 个真实论文术语；`marker` 必须按数组顺序严格写成 `[[CONCEPT_BRIDGE_1]]`、`[[CONCEPT_BRIDGE_2]]` 等，并在对应 `sectionKind` 正文中独占一个段落；`explanation` 必须同时出现两个术语，并明确写出各自分工、搭配原因与组合意义，不能只是“二者结合效果更好”。代码会在该位置用 explanation 替换 marker。

`figurePlacements` 质量优先，允许为空且最多 4 项。只能选择请求末尾“模型本次真正收到像素”的 Figure；只出现在 `READER_ARTIFACTS` 图注、但没有收到像素的 Figure 不得选择。不要为了凑数量加入重复曲线、界面截图或装饰图。每个 `figureOrdinal` 只能出现一次。`marker` 必须严格写成 `[[FIGURE_<figureOrdinal>]]`，并在目标小节正文中独占一个段落；`targetKind` 必须等于实际包含 marker 的小节 kind，不要照抄示例的 method_overview，结果曲线通常属于 result/ablation。marker 的前一段必须是完整图前导读，后一段必须是针对可见内容的完整解释。`focusPoints` 必须有 2–4 个针对该图可见元素的观察动作。代码会把 marker 替换成看图路径与官方原图。

`tableBindings` 的 `tableIndex` 从 1 开始，严格对应最终正文第几张表。选择模式的 `sourceRows[0]` 必须来自证据明示的 `TABLE_<ordinal>_HEADER_ROWS`；`SHAPE` 给出矩阵尺寸，`role: unknown` 表示科学用途尚未判定，作者/机构表不可当成结果表。只选矩阵实际呈现的行列，不猜被预算省略的内容。手写映射中 `renderedRow=0` 是表头，`renderedRow=1` 是第一条数据行，分隔行不计数；`sourceRow/sourceColumn` 是原矩阵零基坐标。rowspan/colspan 覆盖位置仍指向被覆盖的矩阵坐标，代码反查真实 DOM cell，每个渲染单元格必须恰好绑定一次。

`formulaBindings` 只绑定 `READER_ARTIFACTS` 中 recovery 完整且含原始 TeX 的公式。`marker` 必须严格为 `[[FORMULA_<formulaOrdinal>]]`，在 `targetKind` 小节独占一个段落且只出现一次；代码会替换成原始 `\[TeX\]` 并绑定 DOM SHA。
