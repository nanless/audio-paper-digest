# 表格补充 Prompt

用于深度分析后处理阶段。当 `## 实验结果` 引用了表格但缺少 Markdown 表格，或出现省略标记时，仅重写这一节。

```text
你是一位严谨的学术论文分析专家。请根据下面可见的论文原文，为"实验结果"部分补充 Markdown 表格数据。

论文标题: {title}
arXiv ID: {arxivId}

## 要求
1. 只输出"## 实验结果"这一个 section 的完整内容。
2. 只补充与当前结论直接相关的关键表格：最多 2 张，每张最多 12 个数据行和 8 个指标列（不含方法/数据集识别列），实证论文合计至少 3 个数据行、2 个可核对数字。优先保留本文方法、最强基线、代表性传统/开源基线、平均或汇总行、以及支撑关键消融和负结果的行列；原文同时有主结果和消融/效率证据时优先各保留一张。
3. 每张表必须有方法、数据集或设置识别列；需要优化方向的指标在表头显式写 `↑/↓`。禁止用“结果、数值、观察、说明、解释、含义、方向、结论”等叙述型列代替指标。表格及相邻解释中的精确数量、比例、名次、技术计数和参数一律使用阿拉伯数字，并统一使用 ASCII 负号、半角 `%`、小数前导零（例如 `p<0.001`，不能写 `p<.001`）。中文与 ASCII 技术词之间保留空格。
4. 表前必须提出该表要回答的具体比较问题，并说明保留主方法、最强基线、关键消融/失败项的口径；表后只解释最关键差异、原因或代价及证据边界，与前后段落自然衔接。禁止孤立数据卡、逐行朗读表格和表后重复整表，也不得逐篇复制“关键比较问题是：”等固定句首。
5. 严禁编造或插入任何 Markdown 图片、HTML 图片或图片 URL；本轮只补表格和文字。不可见或原文未给出的数据明确写“论文未给出具体数值”，严禁编造。

## 已有分析（供参考，但可能缺少表格）

{resultsSection}

## 论文原文（权威依据）

{textForAnalysis}

请直接输出"## 实验结果"及之后的完整内容：
```

## 调用方式

`deep-analyzer.js` 通过 `loadPrompt()` 注入：
- `{title}`：论文标题
- `{arxivId}`：论文 ID
- `{resultsSection}`：当前分析中的实验结果章节
- `{textForAnalysis}`：截断后的论文全文或摘要
