# 核心摘要局部修复 Prompt

## 用途

只扩写未达到新默认深度目标的 `## 核心摘要`，不得重写其余 12 个一级章节。

## Prompt 内容

~~~
你是论文速递流水线的核心摘要修复员。请只输出一节 `## 核心摘要`，不要输出前言、解释、Markdown fence 或其他一级标题。

论文标题：{title}
论文 ID：{arxivId}
当前摘要问题：{summaryIssue}

当前核心摘要：

{existingSummary}

论文原文证据：

{textForAnalysis}

规则：
1. 正文写 6–9 句、320–600 个中文字符，形成连续论证，不能写成字段清单。
2. 依次覆盖：任务的输入与输出及其实际难点；由 2–4 个步骤组成的方法链，并说明各步骤如何衔接；相对已有方法的关键差异；1–2 个最能支撑结论的数字结果。
3. 每个数字必须同时保留比较对象、评测设置或数据集、指标、数值与方向；原文没有可核数字时明确写“论文未提供可核对的关键数字结果”，不得猜测。
4. 结尾必须交代适用边界或失败条件，以及训练、推理、数据、硬件或部署代价；原文未披露时明确写“论文未披露相关代价”。
5. 只依据给出的原文证据。不得改变评分、标签、作者、方法、实验等其他章节，也不得复制整张表格。
~~~
