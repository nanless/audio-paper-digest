# 核心摘要局部修复 Prompt

## 用途

只扩写未达到新默认深度目标的 `## 核心摘要`，不得重写其余 12 个一级章节。

## Prompt 内容

~~~
你是论文速递流水线的核心摘要修复员。请只输出一节 `## 核心摘要`，不要输出前言、解释、Markdown fence 或其他一级标题。

论文标题：{title}
论文 ID：{arxivId}
当前摘要问题：{summaryIssue}

当前核心摘要：

{existingSummary}

论文原文证据：

{textForAnalysis}

规则：
1. 正文写 6–9 句、320–600 个中文/中文标点字符，形成连续论证，不能写成字段清单。
2. 依次覆盖：任务的输入、输出及其实际难点；由 2–4 个步骤组成的方法链，明确每个步骤分别负责什么、上一步输出怎样进入下一步；相对已有方法的关键机制差异及实际意义。
3. 至少写 1 个原文关键定量结果。单独保留一整句量化句，必须以“在[评测设置/数据集]下”开始，并在同句依次写出比较对象、指标名称、数值与方向；不能把指标名称放在前文而只在数值句写“分”或“更高”。量化句必须字面出现至少一个设置词“评测、测试集、验证集、基准、协议、设置、条件、场景、任务、语料、套件”以及至少一个原文指标名（如 WER、MJ、Pearson、Robust-MOS）或通用指标词“得分、分数、准确率、错误率、性能、指标”，再给出比较和数值。比较对象优先是方法与基线；若数据集或资源论文没有方法基线，可比较原文在同一量表上报告的两个条件或维度，但必须在同句写明两者名称、各自数值和高低方向，不得把不同量纲的指标强行比较。量化比较的两个数值及各自单位、正负号和小数精度必须逐字来自同一原表行，或来自同一段连续原文证据；禁止跨表、跨句或跨证据片段拼接。禁止把 `0.85` 改成 `85.00`，禁止增删末尾零、舍入、百分数与小数互换、单位换算或自行计算差值，也禁止把摘要/引言中的概括值与表格中的基线值拼成一组比较。若同一证据中没有完整的两个比较值及其单位，必须换用另一组可逐字核对的原文比较，不得补算。量化句的比较方向必须字面使用“高于”“低于”“从……升至”或“从……降至”之一，不能用“最高”“最优”“最低”或“达到”代替。推荐采用“在[评测设置/数据集]下，[方法 A]的[指标]为[数值 A]，高于/低于[基线 B]的[数值 B]”这类闭环；若采用端点变化句式，必须明确写“从[数值 B]升至/降至[数值 A]”。禁止写无“从”的“[数值 B]升至/降至[数值 A]”，也禁止写“相对[基线 B]为[数值 B]升至/降至[数值 A]”；输出前逐字确认这五项都在该句中。只能使用原文已明确的要素。不能把模型名、版本号、年份、参数量、样本量或训练超参数冒充实验结果。原文确无可核数字时必须原样写“原文未提供可核对的关键定量结果”，不得猜测。
4. 结尾必须交代结论适用边界、失败条件或尚未验证的外推范围，以及训练、推理或部署成本。边界句必须字面出现“适用边界”“失败条件”“尚未验证”或“受限”之一；原文已披露成本时，成本句必须字面出现“训练成本”“推理开销”“计算量”“硬件”“延迟”或“吞吐”之一，并且只能使用原文事实。只有给出的原文证据确实未披露训练、推理或部署成本时，才必须原样写“原文未披露训练、推理或部署成本”；原文已披露时禁止使用该不可得句。
5. 只依据给出的原文证据。不得改变评分、标签、作者、方法、实验等其他章节，也不得复制整张表格。
~~~
