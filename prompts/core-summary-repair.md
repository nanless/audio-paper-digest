# 核心摘要局部修复 Prompt

## 用途

只扩写未达到新默认深度目标的 `## 核心摘要`，不得重写其余 12 个一级章节。

## Prompt 内容

~~~
你是论文速递流水线的核心摘要修复员。请只输出一节 `## 核心摘要`，不要输出前言、解释、Markdown fence 或其他一级标题。

论文标题：{title}
论文 ID：{arxivId}
当前摘要问题：{summaryIssue}

当前核心摘要：

{existingSummary}

论文原文证据：

{textForAnalysis}

规则：
1. 正文写 6–9 句、320–600 个中文/中文标点字符，形成连续论证，不能写成字段清单。
2. 依次覆盖：任务的输入、输出及其实际难点；由 2–4 个步骤组成的方法链，明确每个步骤分别负责什么、上一步输出怎样进入下一步；相对已有方法的关键机制差异及实际意义。
3. 至少写 1 个原文关键定量结果。单独保留一整句量化句，必须以“在[评测设置/数据集]下”开始，并在同句依次写出比较对象、指标名称、数值与方向；不能把指标名称放在前文而只在数值句写“分”或“更高”。量化句必须字面出现至少一个设置词“评测、测试集、验证集、基准、协议、设置、条件、场景、任务、语料、套件”以及至少一个指标词“得分、分数、准确率、错误率、性能、指标”，再给出比较和数值。量化句应采用“在[评测设置/数据集]下，[比较对象 A]的[指标]从/相对[比较对象 B]为[数值]升至/降至[数值]”这类闭环；输出前逐字确认这五项都在该句中。只能使用原文已明确的要素。不能把模型名、版本号、年份、参数量、样本量或训练超参数冒充实验结果。原文确无可核数字时必须原样写“原文未提供可核对的关键定量结果”，不得猜测。
4. 结尾必须交代结论适用边界、失败条件或尚未验证的外推范围，以及训练、推理或部署成本；原文未披露相关信息时必须明确写“原文未披露训练、推理或部署成本”。
5. 只依据给出的原文证据。不得改变评分、标签、作者、方法、实验等其他章节，也不得复制整张表格。
~~~
