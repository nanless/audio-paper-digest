# Manual 研究生级超详细解读写作规范

此模板用于单篇 Manual 教程型正文。它不是摘要扩写、审计报告或字段拼装模板；作者必须把论文完整教给第一次接触该方向的研究生。

编辑目标是“先建立可复述的心智模型，再让每个数字承担判断责任”。高分篇幅不是目标；读者读完必须能说清问题、全景流程、关键选择、实验能证明什么以及尚不能证明什么。

```text
你只处理当前这一篇论文。输入只包括：论文 metadata、结构化全文、ArtifactIndex、原论文图表、已有事实记录、空白模板和质量契约；若本篇存在由流程保存并绑定 SHA 的 `official_project_evidence`，可用它核对当前官方代码、权重、数据集入口与各自许可证，但不能用未保存的临场网页内容扩写论文贡献。禁止读取或借用同批其他论文，也禁止读取任何旧 `readerArticle`、`article.md`、`post.md`、博客页面、历史 canonical 正文或 previous draft。每次新写作必须从受控论文证据冷启动；不能重排、润色、扩写、补段或仿写旧正文。review 后需要修正时，只读取原始证据和结构化 findings，从空白重新生成完整替换稿。

一、成品目标
- 正文是 6,000–40,000 个中文字符的连续教学文章，通常使用 8–18 个论文特有的三级标题。
- 标题必须表达读者问题或技术判断，禁止机械使用“方法概述、核心创新、实验结果、细节、局限”等固定栏目。
- 标题中不得包含“图 1”“表 2”“Figure 1”“Table 2”等资产编号；图表编号只在标题下的论证文字或 caption 中出现，标题本身必须先说明读者将判断什么。
- 面向入门研究生：关键术语第一次出现时依次给出白话定义、本文中的具体实现、它为何影响后续结论。
- 文章必须按入门学习依赖推进：领域任务与真实失败例 → 相关工作谱系 → 本文可证伪问题 → 方法端到端全貌 → 数据/模型/目标组件 → 完整实验协议 → 主结果 → 诊断与消融 → 外部比较 → 能力边界 → 复现和读者行动。不得在背景、相关工作或方法尚未讲清时直接进入重点结果。
- 不能用篇幅冒充质量。每段只承担一个教学任务，不重复摘要，不反复用“不能外推、需要核对、证据边界、复现者应当”等审计腔句式。
- 读者页既有的题目/链接、双向点评、核心摘要、开源信息和文末评分证据由发布结构提供；`article.md` 不重复这些固定区的职责。正文开头负责把摘要中的结论变成读者可检验的问题。
- 若页面容器提供会议/领域 kicker、摘要式 lead 或数字卡，数字卡只能选本篇最能建立读前承诺的已验证事实，并同时具备指标方向、比较对象和单位；它们不替代正文协议或完整结果表，也不应由 `article.md` 重复拼装。

二、开头必须先让读者知道为什么值得读
- 在前 600 字内给出一个可感知的反例或直觉冲突，解释已有路线至少两类及其具体失败点。
- 先定义领域任务、输入查询、候选对象、训练配对、推理输出和基础评测含义；术语首次进入正文时必须在同句或此前解释，不能用一张塞满后文缩写的表假装完成入门教学。
- 用独立相关工作小节建立至少两条路线的谱系；每条都说明监督来源、能解决什么、仍缺什么。数据集名称不是相关工作地图，不能先罗列缩写、数十行后才解释。
- 相关工作之后再给出一句可证伪的核心判断：这篇论文究竟改变了什么、在哪些条件下应该有效、什么结果会推翻它。此处只写预测和反证条件，不提前公布结果答案。
- 在任何组件细节、公式或实验结果之前，先给出方法全景流程表或合格原图；必须一次覆盖输入 → 数据/表示变换 → 音频与文本路径 → 训练目标 → 检索输出，并预告本文分别研究的数据监督、表征层和训练目标等问题轴。
- 对系统论文，可沿“核心冲突 → 至少两种失败路线 → prior work 与关键洞察 → 方法总览”搭建开头；不要把 prior work 写成无判断的相关工作清单。

三、方法必须成为可复述的心智模型
- 数据论文按“原始来源 → 匹配/清洗/生成 → 质量控制 → 训练使用 → 输出风险”展开；系统论文按“输入 → 表示 → 组件 → 训练/推理 → 输出”展开。
- 先给总览图或流程表，再逐模块解释。每个关键模块都回答：输入是什么、输出是什么、精确操作是什么、为什么需要它、与相邻模块怎样分工、收益是什么、代价或未验证假设是什么。
- 训练部分必须覆盖数据构成、采样比例、阶段、损失、冻结/解冻、步数、batch、硬件、时长和论文未披露项。公式出现时解释变量和训练语义；不需要的公式不硬塞。
- 行内公式只能使用 `\(...\)`，块级公式只能使用 `\[...\]`；禁止裸 `$...$` / `$$...$$`。加粗 `**...**` 必须成对，结束符后紧接正文时保留空格或标点。
- 当同一节比较多个损失、目标或训练配方时，先给一张短导览，至少说明“是否显式使用负例／直接优化什么／预期改善什么／代价或混杂因素”，再写公式；导览不是性能排名。
- 所有会在结果或消融中出现的关键方法必须在实验协议之前解释；禁止先展示三轮结果，再回头首次介绍损失函数、层融合或训练变体。

四、原论文图表必须完整进入论证
- ArtifactIndex 中每张表、图、公式都必须逐项处置。结果表不能静默省略；核心结果表应完整、确定性转录为 Markdown，保留设置列、方法列、所有指标、方向、数值和注释。
- 每张表前先写它回答的比较问题与评测协议；表后解释最关键差异、绝对/相对变化、未胜出项、统计或自动裁判风险，以及这张表不能证明什么。
- 原论文有合格的架构、流程、训练动态或结果图时，必须嵌入原图。SVG 是原论文图，不得因不是 PNG 而丢弃；资助方 logo、站点图标必须拒绝。
- 每幅图前说明读图任务，图后逐项解释可见结构、曲线或样例，再回扣它支持的主张和不支持的结论。禁止只放 caption。
- 图必须在需要它完成论证的节点出现：总图用于建立全景，局部放大用于解释对应模块、注入位置或训练任务；禁止仅按图号为图片另开可交换的小节。
- 如果原始表很宽，可拆成语义连续的子表，但不得漏掉任何数值单元格；必须保留原表编号和完整表入口。
- 表格必须在 Markdown 中实际可读：指标方向写为 `MRR↑`、`RMSE↓` 等，不保留 `\\uparrow`、`\\Delta`、`++`、`−-` 等转写残片；不得用重复单元格模拟 HTML colspan。原论文符号若自相矛盾，保留数值并如实说明歧义，不擅自推定方向。

五、实验要按能力问题教学，而不是只摘最好数字
- 先定义数据集、split、任务和指标方向，让读者知道“这组数字究竟在测什么”。
- 在第一张结果表前，交代会改变比较含义的训练数据、指标、专用挑战/幻觉集、实现条件和基线选择；读者不能在不知协议的情况下被数字卡或最佳项引导。
- 第一张结果表前的协议总览必须覆盖任务单位、数据划分与可能重叠、指标方向、强基线、每组实验实际改变的变量轴，以及最终 checkpoint/early-stop 的读数口径。
- 主结果、公开泛化、同主干比较、消融、负结果、效率/部署分别处理；论文没有提供时明确写“论文未报告”。
- 每个核心贡献建立四联：设计选择 → 预期机制 → 对应实验 → 替代解释或缺失消融。整机变好不能自动证明某个组件有因果贡献。
- 所有精确数字都带设置、比较方法、强基线、指标、单位和方向。明确区分百分点、相对变化、绝对值和统计显著性。
- 论文出现的退化、平局、未胜出项和无法直接比较的结果必须进入对应能力小节，不能全部塞到结尾。
- 演示、案例图与定量评测必须分开写：没有相应定量实验的展示只能称为能力示意，不能扩写成已被系统验证的结论。

六、结尾要让三类读者各有所得
- 给出“能力—证据类型—判断—不能推出什么”的校准表，纠正论文中的“第一、领先、强”等宽泛说法。
- 对研究者：提炼可迁移设计原则和可证伪的下一步实验。
- 对复现者：列最小复跑配置、最高风险变量、公开资源、许可证和未披露项。
- 对产品/部署者：列目前实验无法回答的延迟、吞吐、成本、鲁棒性、安全和合规问题。
- 需要说明应用重要性时，把它写成哪类用户、工作流或风险条件下值得进一步验证，而不是将潜在用途写成已经实现的部署能力；来源或免责声明只能说明边界，不能替代事实核验。
- 最后用 5–10 条互不重复的记忆点回扣开篇矛盾；不要把摘要换词再写一次。
- 文末评分证据只索引已经在正文解释过的机制、实验、反证和复现事实；不得在评分区首次引入精确数字，也不得把“有 GitHub”直接等同于可复现。

七、禁止项
- 禁止出现 schema、manifest、SHA、evidenceLedger、sourceBindings、readerBindings、门禁、审计、回放、字段等流水线内部词。
- 禁止只引用“Table 1 表明”而不展示表；禁止把完整表压成三行结论卡。
- 禁止把“有 GitHub”直接等同于可复现；必须写资源状态、许可证、训练数据和缺失配置。
- 禁止把局部任务第一写成全面 SOTA，或把相关性/整机结果写成组件因果证明。
- 禁止摘要与正文首节重复开场，禁止可任意交换的小节，禁止连续三个以上段落使用相同的“主张—泼冷水”句式。
- 禁止“方法概述、核心创新、实验结果、细节、局限”等可任意交换的固定标题；标题应表达论文特有的读者问题或技术判断。

八、交稿前读者视角自检
- 不看摘要，读者能否复述：问题矛盾、全景数据/系统流、关键模块分工、训练或生成过程、至少三组能力实验和各自边界？
- 每张图是否都有读图任务、可见内容解释、支持/不支持的判断？每张核心表是否都有比较问题、协议、完整数值、主发现和反证？
- 每个精确数字是否有设置、比较对象、指标方向和单位？“百分点”和“相对变化”是否明确区分？
- 以最终 Markdown 渲染检查标题、表格、公式和图片的可读性；复杂多级表头、箭头、中文说明或数学符号不能只靠源码目测。

九、提交物
- `article.md`：只含正文，三级标题按教学顺序排列。
- `quality.json`：新稿使用 version=2，并提交 `readerPath.version=reader-tutorial-path-v1`。`freshAuthoring.articleSha256` 绑定去除首尾空白并做 NFKC 规范化后的正文 SHA-256，`freshAuthoring.articleFileSha256` 与顶层 `articleSha256` 都必须绑定刚刚写入磁盘的 `article.md` 原始文件字节 SHA-256；禁止拿生成前的中间字符串或上一稿哈希填充。`sectionPlan` 必须按顺序覆盖 `field_background → related_work_map → paper_question → method_overview → data_component → model_component → objective_component → experiment_protocol → main_results → diagnostic_results → ablation_results → external_comparison → boundary_synthesis → reproduction → reader_closeout`；同时逐项列出背景定义、相关工作路线、可证伪问题、端到端方法全貌、完整实验协议、能力边界，以及每张表/图/公式处置、逐表问答、机制—结果桥、负面结果、复现路线、三类读者收束和九维 reviewer rubric 所绑定的正文 section ID。
- 所有原图 URL、表格矩阵和精确数字必须来自当前论文的 ArtifactIndex、全文或明确外部证据。
```
