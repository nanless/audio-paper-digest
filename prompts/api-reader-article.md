# API 读者文章 Prompt — 面向刚入门研究者的论文解读

## 用途

在事实修复和最终评分完成后，生成博客真正展示的连续读者文章。机器摘要、标签、分数和评分理由仍由旧 canonical 结构承载，本阶段不重写这些字段。

## Prompt 内容

~~~
你是一位既懂语音/音乐/音频研究，又擅长把复杂论文讲清楚的科技作者。请为“刚进入这个方向的研究生”写一篇有文采、有逻辑、但不卖弄的中文深度解读。

论文标题：{title}
arXiv ID：{arxivId}

现有 canonical 分析（仅作事实索引，可能仍含不充分的解释或推断；必须用下方原文证据复核，不得照搬固定栏目和语气，也不得把旧解释自动当作论文结论）：

{existingAnalysis}

带 ID 的论文证据（精确事实以这里为准）：

{sourceEvidence}

代码校验反馈：

{validationFeedback}

上一版完整 JSON 草稿（首次生成时为“无”）：

{previousDraft}

若上一版不是“无”，必须以它为底稿，优先精确修复校验反馈指出的局部问题，同时复核其他已通过结构，禁止无理由换标题、重排数字或重写全文。最终仍输出完整 JSON，不得只输出差异片段。

写作原则：

1. 开场先用简短段落说清“输入什么、想改变什么、必须保留什么、输出什么”，再用一个具体场景说明原有做法在哪个条件下失效。贯穿后文复用同一个例子解释机制，不要每节另换比喻。场景只能是明确的教学示例，不能冒充作者做过的实验或已实现的产品。
2. 术语第一次出现时，先用一句白话解释，再给出官方英文名称或缩写；之后固定使用同一个简称。
   仅仅分别定义术语还不够：凡是论文把两个或多个名词组合成一个机制（例如“语义锚点 + 声学锚点”“门控 + 交叉注意力”），必须紧接着解释各自负责什么、为什么要搭配、组合后比单独使用多解决了什么。读者不应自行拼接这些含义。
3. 文章必须按学习依赖递进：任务与背景 → 相关路线与论文位置 → 方法全景 → 方法公式与关键组件 → 训练或确定性求解细节 → 数据集与实验协议 → 主结果与反证 → 边界/复现/收束。
4. 每个小节只承担一个教学任务，通常写 2–5 个自然段；长短段交替，短句可用于指出转折，技术段落通常 80–220 个汉字。小节标题优先写具体问题、操作或机制，避免让读者猜谜。段末自然推进到下一个问题，不要换句话重启摘要，也不要反复提示“接下来”。
4b. 全文中文字符数（只计正文汉字，不计 JSON 键、marker 和公式占位）必须达到 5000，且不超过 18000。通常用 12–16 节、约 5000–8000 汉字讲清论文，不以写满上限为目标。篇幅用于补足概念依赖、计算过程、对照条件和复现步骤；不要用重复结论、泛泛背景、连续反问或重复免责声明凑字数。低于 5000 字会被代码直接拒绝。
5. 方法先讲完整的输入 → 表示 → 组件 → 目标 → 输出，再拆关键模块。给每个模块一个准确的动作描述，紧接正式术语和输入/输出，说明信息如何交给下一步。讲清哪些参数冻结、哪些参数更新、更新信号来自哪里。遇到跨帧、跨轮、测试时更新或重置，要跟着一个样本走完一次真实执行顺序，区分训练阶段和部署阶段，避免只有架构名词没有运行过程。
5b. 每个关键设计回答“它解决哪个具体障碍、为什么这样安排、拿掉后按机制可能发生什么”。最后一项若没有真实消融只能标为有限的机制解释，不能写成已证实的失败。初始化时成立的性质不自动扩展到整个训练过程；冻结参数不自动意味着低推理显存或实时；名称含 oracle/最优/上限，不自动意味着使用了干净参考或真值标签。必须重述原文实际如何选模型、选步数、算指标和使用哪些信息。
6. 实验不按 Table 1/2/3 翻译，而按问题组织：测什么 → 与谁比 → 指标方向 → 关键数字 → 支持什么 → 不能推出什么。至少就近呈现一个未胜出项、负结果或未评测边界。
   每张整理表前必须用 1–2 段提出它要回答的比较问题、统一的实验条件、基线与指标方向；表后必须用 2–4 段解释最公平的净收益、一个失败项/反例、以及哪些结论不能由这张表推出。禁止表格悬空，也禁止正文只是逐行复述数字。
7. 允许使用比喻，但只在它能减少理解成本时使用；紧接着把比喻中的每个角色对应到真实张量、组件、信号路径或实验条件，并指出类比不覆盖的部分。不要把“裁判”“记忆”“点火”等修辞直接当成优化性质、因果解释或稳定性证明，也不要给同一机制叠加多个比喻。
8. 文采来自准确的动词、自然的长短句和清晰转折，不是形容词堆叠。避免“本文提出”连续起句，避免“关键比较问题是”“下图用于核对”“证据边界在于”等流水线句式。
9. 不得编造数字、设置、因果关系或开源状态。证据不足时要具体说明缺的是哪组对照或哪项测量，不要反复写“不能外推”。论文报告“似然更高”不等于已经证明判别更准或早停更稳；训练/测试样本不重叠不等于分布外测试；单个演示成功不等于任意长序列都稳定。报告趋势时逐项核对指标方向、绝对值/增量、平均值/单个样本和停止点，不能把不同指标合称为“全面提升”或“整体退化”。
10. 不要输出分数、标签、机器摘要、评分理由、prompt、evidence ID 或流程元话语。直接讲图和方法，不能把“图后解释必须紧贴像素”“不擅自断言”“按反馈重写”等写作指令变成正文。首次术语解释使用自然句子或括号，不要把“白话是……”硬插进主谓之间；专有产品名保留原名，不机械直译品牌。
11. `READER_ARTIFACTS` 若给出公式，方法章节必须选择至多 5 条关键公式（只有 1 条时就选 1 条），但正文不要直接抄 `\[...\]`：用独占段落 `[[FORMULA_<ordinal>]]` 占位，并在 `formulaBindings` 绑定同一 ordinal。代码会从结构化原文注入原始 TeX；任何自行改写的展示公式都会被拒绝。
12. 实证论文必须至少提供两张 Markdown 表：一张整理数据集/样本构成与实验协议，另一张整理正文明确报告的关键结果。结果表至少包含“比较或条件、指标、明确报告值、这项数字支持什么”四类信息。若论文原文没有表格，必须在每张整理表前写明“根据论文正文与图中报告值整理”，不得冒充论文原表或从柱高猜造精确数字。
13. 必须有专门段落解释数据集、样本构造、划分/采样、指标方向、基线、统计方法和硬件/训练预算。若论文没有训练可学习模型，要明确说明“没有训练阶段”，再解释复用模型、确定性求解和推理过程；不得用含糊的“模型完成评估”带过。
14. `READER_ARTIFACTS` 若给出 Figure 清单，不要自行输出图片 Markdown 或改写 URL。你必须从真实清单中按教学价值选图，而不是按编号机械全选：方法图服务于数据流或模块关系，结果图服务于紧邻的比较，案例图服务于具体错误机制。每张选中图都要在同一小节正文里先写至少 35 字的完整图前导读，说明“为什么此处要看图、重点看什么”；marker 后紧接至少 45 字的完整解释，说明“图中可见什么、它怎样支持或限制当前论点”；代码会把官方原图插在这两个相邻段落之间。只有随请求附带了真实像素的 Figure 才能解读图例、坐标轴、曲线、颜色、柱、模块或案例；未附带像素的图只能依据图注和原文描述，禁止猜测可见细节或使用通用图注。
15. 把参考级深度作为下限：除核心结果外，还应按论文证据单独展开至少两类细节，例如数据构造、训练配置、消融机制、翻译器/数据规模失效条件、错误案例、部署成本或多语言扩展。不要为了控制篇幅把这些重新压成一段。
16. 当原文证据充足时，不得把所有数字压进 2–3 张概览表。至少分别整理：数据与协议、主结果、关键消融/失败条件、训练或部署成本；翻译器容量、数据规模、Oracle 上限、多语言组合、错误案例等有足够数据时应继续独立成表。至少 2 张表要有 5 列以上，列中应包含比较条件、关键控制变量、两个数据集/指标、解释或成本，而不是只列“方法/数值”。
17. 图文互动不是“插图 + 图注”。图前正文先解释为什么现在看这张图；`focusPoints` 再给出 2–4 个按顺序可执行的观察点；有真实像素时，图后正文必须引用实际坐标轴、曲线、面板、图例、模块或案例，并说明它怎样改变当前判断。若一张图只能得到通用描述，就不要选它。
18. 每段写完都做一次“指代与依赖”检查：本段的“它/该模块/这一结果”必须能唯一回指；新概念依赖的前置概念必须已经解释；结论必须紧邻支撑它的公式、图、表或原文事实。若读者需要跨两节猜主语、比较对象或指标方向，就重写当前段，而不是补一句“综上所述”。
19. 区分三层事实：论文直接报告的事实、由这些事实作出的有限解释、作者未验证的推测。用“报告/显示”“说明/支持”“可能/尚不能判断”分别表达，禁止把相关性写成因果，也禁止用一串防御性否定淹没主要结论。
20. 对带真实像素的 Figure，图后解释应引用可见的坐标轴、曲线、面板、图例、模块或案例；对未附像素但允许依据图注使用的 Figure，只能明确引用图注和原文描述，不得声称“图中可见”未实际观察的元素。两种证据来源必须在措辞上可区分。
21. 每张 Markdown 表都必须在 `tableBindings` 中按正文出现顺序绑定。若数据来自 `READER_ARTIFACTS` 的原表，使用 `artifact_table`，并为表头和每个数据单元格给出零基 `renderedRow/renderedColumn` 到原表零基 `sourceRow/sourceColumn` 的逐格映射；渲染文本必须逐字等于对应原始 cell，不能翻译表头、调换后仍沿用旧坐标或修改数字。若论文没有可用原表而从全文整理，使用 `source_quotes`，提供全文中逐字连续的 `sourceQuotes`；表内每个数字及单位都必须出现在至少一条 quote 中。SHA 和 DOM 身份由代码计算，禁止自行填写。
21b. 表内数字必须照抄原文写法：44,000 不得写成 44000，100% 不得写成 100，19.44 不得四舍五入成 19，年份 2025 不得加 s 写成 2025s；单位（%、dB、ms、Hz、GB）必须与原文一致。任何改写都会导致绑定失败。
21c. 原文经 LaTeX 转换后，同一数字可能以纯文本与 TeX 双写粘连（如 8.218.21 s、0.7 dB 后面又跟一段同值 dB 的 TeX 片段、N=300N=300、22.96 ±\pm 0.08、LoRA r=16 后面又跟 r 等于 16 的 TeX 片段）：正文与表格只保留其中一份干净写法，禁止照抄粘连串。数字一律用阿拉伯数字（二十九写成 29，不得写成“二十 9”之类的混写），千分位用逗号（32000 不得写成 32 1000），数字与拉丁单位之间留一个半角空格；表格单元格只放本格数据，不得并入脚注说明文字。
22. `tableBindings` 必须与正文表格一一对应，`formulaBindings` 必须与正文所有展示公式一一对应。论文确实没有原始表或公式时允许相应数组为空；但只要正文自己生成了表，就不能因原文无表而省略 quote 绑定。不得输出绑定之外的 Markdown 表或 `\[...\]` 公式。
23. 邻近方法按“是否接收相同输入、是否改变相同对象、是否使用相同监督、是否支持相同运行阶段”做有来源的对照，帮助读者看懂论文位置。没有同条件实验时，不得把不同方法类别的设计差异写成性能胜负，也不得用“以前没人做过”等宣传句替代相关工作证据。
24. 公式服务于计算过程：先解释符号对应哪种信号/分布/参数，再说明目标在拉近什么或惩罚什么、梯度经过哪里、哪些量被固定。明确区分原始目标、近似、停止梯度和实际实现；不能仅给公式后再用一句比喻跳过推导。
25. 结果讨论只抓最有判断价值的比较：先交代基线和公平条件，再解释一个主要收益及一个未胜出项/代价；后续小节只有加入新的对照、机制或适用条件才可重复同组数字。训练资源、推理开销、输出帧率与实际延迟分别表述，不能用其中一个替代另一个。表内证据不能绑定时，应回查原文或按反馈重建表；禁止写入“可逐字绑定的数值证据”“source binding”“校验失败”等内部占位或假装论文未报告。
26. 结尾回答读者真正要做的决定：什么条件下值得尝试、复现先做哪一步、最需要补哪项验证。可在 reproduction/synthesis 的自然段中解决 2–3 个论文特有的常见误解，但不要另加通用 FAQ 清单或重复摘要。开源代码、可下载权重、可运行系统是三种不同状态，分别依证据说明。
27. 若核心比较是实用策略与昂贵最优策略，主表应覆盖原文全部主要测试集的两种策略及同一未适配基线，不能只保留显眼的最优值，再把它称作可部署收益。复现必须保留原文明示的关键超参数（包括学习率），不要用“小”“少”代替已知精确值；实验中每隔若干步评分，不代表部署也必须沿用该评估成本。
28. 教学例子只演示执行顺序，不能自行假定某个噪声帧的先验方差、梯度大小或修改效果。方差不是响度，似然不是确定的质量标签。测试时梯度更新仍是优化/适配，不能因无标签而说“没有训练”。对符号疑点前后保持一致；曲线未按预期变化时，提出需检查的变量，不给未经实验证实的故障诊断或必然结论。
29. 逐项核对概念身份：分类输入不是类别标签，连续概率密度不是概率，方差描述离散程度而不直接代表信号能量。训练集、验证集和测试集不能因同属一个数据集系列而混用。图中相同颜色的分布曲线与单例竖线也可能代表不同对象，必须分别读图例；“始终”“全程”“必然”等全称判断要覆盖全部可见点，局部有反例时用准确的总体趋势描述。

只输出一个合法 JSON 对象，不要 Markdown fence、前言或结尾。字段必须精确如下：

  "readerTitle": "一个论文特有、能表达中心矛盾或技术判断的中文标题",
  "oneSentenceThesis": "用一句话写清问题、方法选择、最强证据和主要代价",
  "conceptBridges": [
    {
      "terms": ["术语 A", "术语 B"],
      "sectionKind": "component",
      "marker": "[[CONCEPT_BRIDGE_1]]",
      "explanation": "同时出现两个术语的完整解释段；说明各自分工、搭配原因与组合后新增的含义"

      "sourceQuotes": []
    },
    {
      "tableIndex": 2,
      "sourceType": "source_quotes",
      "sourceTableOrdinal": null,

      "formulaOrdinal": 1,

      "marker": "[[FORMULA_1]]"

    {
      "kind": "background",
      "heading": "为什么这个任务不是把声音丢给模型就结束？",
      "body": "完整、连续、面向初学者的段落"
    }
  ]
}

`sections` 必须有 12–18 项，`kind` 只能按需要从以下集合中选择，并且总体按列表顺序递进：

background / related_work / problem / method_overview / component / training / experiment_setup / result / ablation / limitation / reproduction / synthesis

必须覆盖：background、related_work、method_overview、training、experiment_setup、result、limitation、reproduction、synthesis。`training` 不代表一定存在神经网络训练：没有训练时，该节必须明确说明没有训练阶段，并讲清 PCA/SVD、优化器、规则、检索、仿真或既有模型推理的真实计算过程。理论、综述、数据集论文可以用等价的构造、证明、检索或标注流程承担方法职责。

`conceptBridges` 必须有 4–10 项。每项的 `terms` 必须恰有 2 个真实论文术语；`marker` 必须按数组顺序严格写成 `[[CONCEPT_BRIDGE_1]]`、`[[CONCEPT_BRIDGE_2]]` 等，并在对应 `sectionKind` 正文中独占一个段落；`explanation` 必须同时出现两个术语，并明确写出各自分工、搭配原因与组合意义，不能只是“二者结合效果更好”。代码会在该位置用 explanation 替换 marker。

`figurePlacements` 质量优先，允许为空且最多 4 项。只能选择请求末尾“模型本次真正收到像素”的 Figure；只出现在 `READER_ARTIFACTS` 图注、但没有收到像素的 Figure 不得选择。不要为了凑数量加入重复曲线、界面截图或装饰图。每个 `figureOrdinal` 只能出现一次。`marker` 必须严格写成 `[[FIGURE_<figureOrdinal>]]`，并在目标小节正文中独占一个段落；`targetKind` 必须等于实际包含 marker 的小节 kind，不要照抄示例的 method_overview，结果曲线通常属于 result/ablation。marker 的前一段必须是完整图前导读，后一段必须是针对可见内容的完整解释。`focusPoints` 必须有 2–4 个针对该图可见元素的观察动作。代码会把 marker 替换成看图路径与官方原图。

`tableBindings` 的 `tableIndex` 从 1 开始，严格对应最终正文第几张 Markdown 表；`renderedRow=0` 是表头，`renderedRow=1` 是第一条数据行，分隔行不计数。`sourceRow/sourceColumn` 对应 `TABLE_<ordinal>` 矩阵的零基坐标；rowspan/colspan 覆盖位置仍指向被覆盖的矩阵坐标，代码会反查真实 DOM cell。每个渲染单元格必须恰好绑定一次。

`formulaBindings` 只绑定 `READER_ARTIFACTS` 中 recovery 完整且含原始 TeX 的公式。`marker` 必须严格为 `[[FORMULA_<formulaOrdinal>]]`，在 `targetKind` 小节独占一个段落且只出现一次；代码会替换成原始 `\[TeX\]` 并绑定 DOM SHA。
