# API 论文解读写作要求

## 用途

本阶段在事实修复和评分完成后，为博客生成完整的论文解读。机器摘要、标签、分数和评分理由仍保存在已有分析记录中，本阶段不改写这些字段。

## 提示词内容

~~~
请为刚进入语音、音乐或音频领域的研究生写一篇中文论文解读。读者应能理解方法，复述关键步骤，并核对实验结论成立的条件。用准确的词语和自然的段落说明内容，不夸大论文价值。

论文标题：{title}
arXiv ID：{arxivId}

首次写作只依据下方论文原文和本次收到的官方原图，不沿用其他生成分析的解释、评价或推断。修复时可以读取提供的草稿，但它只是待修改的文字；其中的事实仍须回到原文核对。

带 ID 的论文原文证据：

{sourceEvidence}

代码校验反馈：

{validationFeedback}

上一版完整 JSON 草稿（首次生成时为“无”）：

{previousDraft}

本次代码检查的数量和长度要求：

{mechanicalContract}

如果上一版不是“无”，以它为底稿，优先修复反馈指出的局部问题，并检查修改是否影响其他已通过的部分。不要无故换标题、重排数字或重写全文。提交时仍输出完整 JSON，不能只输出修改片段。

文章如何展开

开场说明任务的输入、目标、必须保留的信息和输出。先讲任务和已有研究路线，再介绍方法整体流程、组件与计算、训练或构造过程，随后解释实验条件和结果，最后讨论复现与结论。只讲论文实际研究的任务。教学例子须明确标为例子，不能添加没有来源的数值或效果。

每节解决一个具体问题，标题说明读者要理解的问题、操作或机制。节数和正文汉字数遵守本次代码要求，不以写满上限为目标。这里统计汉字，不是 JSON 字符数、英文长度或 token 数。篇幅用于计算过程、比较条件和复现细节，不靠重复摘要、泛泛背景、反问或免责声明凑字数。再次讨论结果时，应增加新的对照、机制解释或适用条件。

句子长短随内容变化，段落之间要自然衔接。比喻确有帮助时才使用，并说明它对应的实际信号或组件；不能把比喻当作证明。正文不要出现分数、标签、机器摘要、评分理由、提示词、证据 ID 或内部检查状态，也不要叙述写作流程。不要写“本节同时出现两个术语”“表前需要”“为了满足表格列数要求”等自述。JSON 示例中的说明只是字段示意，不能照抄成正文。

相关工作应根据原文，在相同输入、目标、监督和运行阶段下比较，不能把类别差异写成同条件胜负。结尾回答何时值得尝试、复现首先做什么、还需补充哪项验证，保留关键超参数及信息条件。区分代码开源、权重可下载和系统可运行。用自然段解释本篇容易产生的误解，不再重复摘要或通用问答。

术语、方法与公式

首次使用术语时先用日常语言解释，再给出英文名或缩写；后文使用同一种简称。介绍组合机制时，紧接着说明两个术语各自指什么、怎样分工、为什么搭配，以及组合后增加了什么作用。先沿一个样本说明输入怎样经过各组件得到输出，再展开公式。代词应有明确对象，解释结论前先讲清它依赖的概念。

方法部分应说明原文给出的安排理由和已验证对照。参数如何冻结或更新、梯度经过哪里、监督来自哪里、何时重置，都只能按证据说明；未报告时指出具体缺项，不从模型名称猜实现，也不补写“拿掉后必然怎样”。没有训练的论文应说明本研究未训练哪些模型，再解释实际的调用、搜索、标注、仿真或计算。不能把无训练等同于确定性求解，也不能从参数冻结推定系统输出确定。

介绍公式时，先说明符号和输入，再解释计算目标及原文明确的实现。区分原始目标、近似、停止梯度和优化步骤，不猜原文未说明的梯度路径。如果 `READER_ARTIFACTS` 提供了完整的原始 TeX，在方法部分选择至多 5 条关键公式；只有 1 条时就选 1 条。每条公式用独占一段的 `[[FORMULA_<ordinal>]]` 表示，并在 `formulaBindings` 中记录对应关系。代码会显示原式，不要自行写展示公式。

实验结果与结论范围

实验部分按要回答的问题组织，交代测量对象、比较方法、条件是否一致、指标方向和关键数字，再解释结果支持什么判断、有什么限制。有证据时分别说明数据与协议、主结果、消融或失败条件、训练与部署成本，并在核心结果之外展开至少两类本篇特有的细节。原文报告定量主结果时，`result` 或 `ablation` 小节必须展示包含必要基线和实际可运行策略的数字表，数据或配置表不能替代。比较必须保留原文实际可运行的策略。通过搜索选出的最优值、已知答案条件下的 oracle 结果和事后最优值要另行标明，不能把它们当作可部署收益。

按原文交代数据、划分、采样、指标、聚合方式、统计方法及硬件预算。核对表格数字时，同时检查数据集、模型或基线、实验阶段、指标、单位和聚合对象；数值相同不是同一指标的证据。百分点和相对百分比也不同。不要把不同指标的差值放到模型列下，或把自动指标当成人工评价。原文表头、图注或算术互相冲突时明确标注冲突，不编造划分或统计方式来解释矛盾。

每张表前后都要有相邻的独立段落。表前说明比较问题、公平条件和指标方向，表后解释主要收益、具体代价或反例；字数遵守本次代码要求，但不强求固定段落数，也不逐行复述。至少在相应结果附近说明一个未胜出项、负结果或尚未评测的范围。表格数量和宽度须符合要求，不能为凑列数制造无来源的列、混放不同条件或删除不利基线。

写清论文直接报告了什么、证据支持怎样的有限解释、哪些仍是推测。可分别使用“报告”“显示”“支持”“可能”或“待验证”等词，但不要每段套同一句式。缺失证据不是技术错误，相关性不是因果。没有测量误判率、延迟或成本时，不能承诺它们得到改善。训练资源、推理开销、输出帧率和实际延迟应分别讨论；总体趋势不能推广到每组结果或每个步骤。

原图的选择与解释

只选择本次实际收到像素且有教学价值的论文图，最多 4 张，也可以不选。在同一小节先写独立的读图说明，再放独占一段的图片占位符，之后用独立段落解释可见内容。`focusPoints` 给出 2–4 个针对该图的观察动作，段落长度遵守本次代码要求。不要自行输出图片 Markdown 或网址。没有像素时，只能说明来源后引用图注或正文，不能猜坐标、颜色、曲线或模块位置。

先根据图例确认对象、条件和时间范围，区分分布曲线和单样本标记；颜色相同不代表对象相同。检查纵轴表示原始指标、相对改变量还是改善量，再结合指标方向判断好坏。不能把曲线向下直接写成性能变差，也不能把末步结果推广到全程。图中不能精确辨别的数值或步数不要硬写；引用原文补充说明时要交代来源。

表格的来源与数字

`tableBindings` 按最终正文的表格顺序逐项对应。使用 `selection` 时，`sourceTableOrdinal` 只能取 `TABLE_ORDINALS_AVAILABLE` 中明确列出的值，且对应的 `TABLE_<ordinal>_SELECTION` 必须标明 `eligible:true`。清单为 `[]` 时，不得输出 `TABLE` 占位符或 `selection` 记录。正文表只要使用了该 `TABLE_<ordinal>` 矩阵中的一个数字，就必须直接选择原表行列；不能把 DOM 表格数字抄入手写 Markdown，再用 `source_quotes` 说明来源。展平的全文未必包含 DOM 单元格，不能代替原表记录，也不能据此自行计算原表数字的差值、百分比、四舍五入值或添加单位。`eligible:false` 的 `reasonCodes` 说明空表头、行身份不明或 TeX 重复等问题，不要反复选择不合格原表或猜表头。如果无法安全选择，只能用全文连续原句中实际出现的数字制作 `source_quotes` 表。缺少充分原句时删去无证据的表，改选另一张合格原表或说明具体缺项，不能造证据，也不能把来源匹配失败写成作者没有报告。

表格数字和单位保留原文写法、千分位和精度：44,000 不改成 44000，100% 不改成 100，19.44 不四舍五入成 19。叙述数量使用阿拉伯数字，数字与拉丁单位之间留空格。原文转换后出现字符粘连或 TeX 重复时，不猜新数值，应改用能核验来源的同实验表或清楚的连续原句。

三种表格记录方式

每张表只能使用以下一种结构，不混用正文形式或字段：
   - `selection`：正文独占一段写 `[[TABLE_<tableIndex>]]`，不手写该表的 Markdown。记录只含 `tableIndex` 和 `selection:{sourceTableOrdinal,sourceRows,sourceColumns}`。行列从 0 开始编号，只能选择证据实际给出的行列；`sourceRows` 第一项是明确的表头行，之后是数据行，不得重复或越界。代码生成原表、坐标对应关系和 SHA。占位符编号是正文表序，不是原表编号；不要附带手写值、`sourceType`、`cellBindings` 或 `sourceQuotes`。
   - `artifact_table` 是既有兼容模式。在 `sections[].body` 中写完整 Markdown 表，不使用 `TABLE` 占位符。记录恰好包含 `tableIndex,sourceType,sourceTableOrdinal,cellBindings,sourceQuotes`；`sourceType` 为 `artifact_table`，`sourceQuotes` 为空数组。每个 `cellBindings` 项恰好包含 `renderedRow,renderedColumn,sourceRow,sourceColumn` 四个坐标，逐格记录完整对应关系。
   - `source_quotes` 用于直接整理原文句子。在 `sections[].body` 中写完整 Markdown 表，不使用 `TABLE` 占位符。记录恰好包含 `tableIndex,sourceType,sourceTableOrdinal,cellBindings,sourceQuotes`；`sourceType` 为 `source_quotes`，`sourceTableOrdinal` 为 `null`，`cellBindings=[]` 必须为空。`sourceQuotes` 是逐字连续原句的字符串数组。不得发明 `value`、`quoteIndex`、`renderedText` 等字段；引用只用于核验来源，不生成表格。
   `source_quotes` 中的原句必须覆盖每个数字单元格的全部数字和单位。原文数值带单位时，单位留在同一单元格，不能拆成独立列再跨列补全；原文是裸数值时不擅自添单位，指标单位按原文在表头或相邻说明中交代。格式示例：正文 `| 条件 | 指标 | 基线 | 本方法 | 比较对象 |\n| --- | --- | --- | --- | --- |\n| [原文条件] | [指标名] | [原值及单位] | [原值及单位] | [原文对象] |`；来源记录 `{"tableIndex":1,"sourceType":"source_quotes","sourceTableOrdinal":null,"cellBindings":[],"sourceQuotes":["[覆盖这些数字与单位的原文连续句]"]}`。方括号中的文字只是格式示例，不能照抄。正文不再放 `TABLE` 占位符。

记录与正文的对应关系

每张正文表都要有 `tableBindings` 记录，每条展示公式都要有 `formulaBindings` 记录，不要自行填写 SHA 或 DOM 身份。原文确实没有相应证据时，数组可以为空；自行整理的表仍须用原句说明来源。保留正确的图和公式编号、概念解释占位符及对应关系。修正一处事实时，不要重排无关章节或重新编号。

只输出一个合法 JSON 对象，不加 Markdown 代码块、前言或结尾。字段必须精确如下。示例标题和看图步骤只是说明写法；只有论文确实研究相应任务、本次原图确实包含相应路径时才能采用，其他论文应按自己的内容填写：

{

  "readerTitle": "语音与文本如何共同支持音频检索",
  "oneSentenceThesis": "用一句话写清问题、方法选择、最强证据和主要代价",
  "conceptBridges": [
    {
      "terms": ["术语 A", "术语 B"],
      "sectionKind": "component",
      "marker": "[[CONCEPT_BRIDGE_1]]",
      "explanation": "[直接解释术语A与术语B的分工、搭配理由和组合机制，不照抄此占位说明]"
    }

  "figurePlacements": [

      "figureOrdinal": 1,

      "focusPoints": [
        "先沿输入到输出的箭头看主路径",

      ]
    }
  ],
  "tableBindings": [
    {
      "tableIndex": 1,
      "selection": {
        "sourceTableOrdinal": 1,
        "sourceRows": [0, 1, 2],
        "sourceColumns": [0, 1, 2, 3, 4]

    {
      "kind": "background",

`sections` 数量遵守本次代码要求，`kind` 只能按需要从以下集合中选择，整体按列表顺序展开：

background / related_work / problem / method_overview / component / training / experiment_setup / result / ablation / limitation / reproduction / synthesis

必须覆盖 `background`、`related_work`、`method_overview`、`training`、`experiment_setup`、`result`、`limitation`、`reproduction` 和 `synthesis`。`training` 不代表一定存在神经网络训练。没有训练时，应在该节明确说明，并讲清 PCA/SVD、优化器、规则、检索、仿真或已有模型推理的实际计算过程。理论、综述和数据集论文可以解释相应的构造、证明、检索或标注流程。

`conceptBridges` 数量遵守本次代码要求，每项 `terms` 恰好包含 2 个真实论文术语。`marker` 按数组顺序写成 `[[CONCEPT_BRIDGE_1]]`、`[[CONCEPT_BRIDGE_2]]` 等，在对应 `sectionKind` 正文中独占一段。`explanation` 必须出现两个术语，说明各自分工、搭配原因和组合意义，不能只写“二者结合效果更好”。代码会在占位符处显示这段解释。

`figurePlacements` 允许为空，最多 4 项。只能选择请求末尾“模型本次真正收到像素”的论文图；只有 `READER_ARTIFACTS` 图注而未收到像素的图不能选择。不要为凑数量加入重复曲线、界面截图或装饰图。每个 `figureOrdinal` 只能出现一次。`marker` 必须写成 `[[FIGURE_<figureOrdinal>]]`，在目标小节正文中独占一段。`targetKind` 等于实际包含占位符的小节 `kind`；不要照抄示例的 `method_overview`，结果曲线通常放在 `result` 或 `ablation`。占位符前一段是完整的读图说明，后一段解释实际可见的内容。`focusPoints` 给出 2–4 个针对可见元素的观察动作。代码会在占位符处显示看图步骤与官方原图。

`tableBindings.tableIndex` 从 1 开始，对应最终正文的表序。原表可用性及三种结构遵守上方要求。选择模式的 `sourceRows[0]` 必须来自 `TABLE_<ordinal>_HEADER_ROWS` 明确列出的表头行；`SHAPE` 给出矩阵尺寸，`role: unknown` 表示尚未判断其科学用途。作者或机构表不能当作结果表，只选实际呈现的行列，不猜因预算省略的内容。手写坐标记录中，`renderedRow=0` 是表头，`renderedRow=1` 是第一条数据行，分隔行不计数；`sourceRow/sourceColumn` 是原矩阵从 0 开始的坐标。`rowspan/colspan` 覆盖的位置仍使用被覆盖的矩阵坐标，代码会找到真实 DOM 单元格。每个显示单元格必须恰好对应一次。

`formulaBindings` 只能选择 `READER_ARTIFACTS` 的 `FORMULA_ORDINALS_AVAILABLE` 中明确列出、完整恢复且带有原始 TeX 的公式。清单为 `[]` 时，正文不能有 `FORMULA` 占位符，并须输出 `"formulaBindings": []`。`marker` 必须是 `[[FORMULA_<formulaOrdinal>]]`，在 `targetKind` 小节独占一段且只出现一次。代码会显示原始 `\[TeX\]` 并记录 DOM SHA。
