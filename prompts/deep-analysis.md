# 深度分析 Prompt — 单篇论文深度阅读理解

## 用途
用于深度分析阶段，让 LLM 阅读论文全文（+ 可选图片）后输出结构化分析报告。

## 调用方式
代码读取此文件后，将占位符替换为实际值：
- `{hasFullText}` → "以下是论文全文，请仔细阅读所有技术细节。" 或 "以下是论文摘要。"
- `{textForAnalysis}` → 论文全文节选或摘要内容
- `{title}` → 论文标题
- `{authors}` → 作者列表（逗号分隔的字符串）
- `{categories}` → 论文类别（逗号分隔的字符串）
- `{paperInfo}` → 论文信息（arXiv ID 或本地 PDF 信息）

## Prompt 内容

```
请对以下论文进行深度分析，以顶会审稿人（NeurIPS/ICML/ICLR 风格）的视角进行评审。{hasFullText}

论文标题: {title}
作者: {authors}
类别: {categories}
{paperInfo}

{textForAnalysis}

请按以下固定格式输出（用中文），不要增删一级标题，缺失信息必须明确写"未说明"、"未提供"或"论文中未提及"，禁止根据常识、作者名气、单位名气、邮箱、外部网页或历史记忆猜测。

## 评分
先单独输出总分，格式必须是：X.X/10

## 机器摘要
**必须严格按照以下键值对格式输出，每行一个键值对，键名必须与示例完全一致，禁止输出散文段落。如果某项信息无法确定，写"未说明"。**

```
rank_bucket: 前10% / 前25% / 前50% / 后50%
quality_score: X.X
value_score: X.X
reproducibility_bonus: X.X
confidence: 高 / 中 / 低
primary_task_tag: #标签
primary_method_tag: #标签
sota_claim: 是 / 否 / 未说明
has_code: 是 / 否 / 未说明
has_model: 是 / 否 / 未说明
has_dataset: 是 / 否 / 未说明
```

**各字段说明**：
- `rank_bucket`: 只能从 前10% / 前25% / 前50% / 后50% 四档中选一档
- `quality_score`: 综合学术质量（创新性+技术严谨性+实验充分性+清晰度），范围 0-7
- `value_score`: 影响力与重要性，范围 0-2
- `reproducibility_bonus`: 可复现性综合（开源完整度 0-1.5 + 文档/细节充分度 0-0.5），合计范围 0-2
- `confidence`: 高 / 中 / 低
- `primary_task_tag`: 从标签中选择一个最主要的**任务**标签（以 `#` 开头，如 `#语音识别`、`#语音合成`、`#音频生成`、`#音乐生成`、`#音频降噪`、`#语音情感识别` 等）。**严禁**使用方法名、arXiv 类别或散文描述作为任务标签。
- `primary_method_tag`: 从标签中选择一个最主要的**方法**标签（以 `#` 开头，如 `#扩散模型`、`#预训练`、`#对比学习`、`#自监督学习` 等）
- `sota_claim`: 论文是否明确声明达到 SOTA
- `has_code` / `has_model` / `has_dataset`: 是否提供代码/模型/数据集

【评分规则】
1. 先判断该论文在同期同方向工作中的相对位置，只能从前10% / 前25% / 前50% / 后50%四档中选一档。前10%对应领域突破性工作，前25%对应明显优秀，前50%对应合格到良好，后50%对应问题较多。
2. 总分 = 创新性（0-3）+ 技术严谨性（0-1.5）+ 实验充分性（0-1.5）+ 清晰度（0-1）+ 影响力（0-2）+ 开源（0-1.5）+ 可复现性（0-0.5），四舍五入到 0.1 分，满分 10 分。
3. 评分必须有区分度，但不得故意压低分数。9.0 分以上只给真正具有里程碑潜力的工作；8.0-8.5 分给在重要问题上做出扎实贡献、有明确影响力的高水平工作；大多数扎实但非突破性论文应落在 6.0-7.5。不得因"这是组合已有技术"就压低工程型论文的创新性——关键看组合是否有新洞察、是否解决了真正的重要问题、是否带来了可验证的显著提升。
4. rank_bucket 必须与总分一致：总分 ≥ 9.0 必须是前10%；总分 8.0-8.5 必须是前25%；总分 6.5-7.5 应为前50%或前25%（视具体质量而定）；总分 < 6.0 一般为后50%。
5. 不要因为任务小众就直接否定论文质量。小众、垂直、特殊人群、病理语音、动物声音等题材，在"创新性"和"技术严谨性"上应正常评分——只要问题定义清晰、方法有实质突破，就不能因其受众窄而压低创新分；但"影响力"必须打低分（通常不超过0.5），因为这类工作天然难以产生广泛的领域推动作用和后续研究价值。实验充分性中仅与数据集通用性相关的部分可以酌情扣分。
6. 如果论文缺少关键实验、对比不充分、结论跳跃，必须在"实验充分性"中显著扣分；如果复现信息模糊、训练细节缺失，必须在"可复现性"中扣分；如果只给GitHub链接但无README或文档，必须在"开源"中扣分。
7. 如果论文写作混乱、符号不统一、关键细节缺失导致无法复现，必须在"清晰度"中扣分。
8. 如果论文方法推导有明显错误、证明不严谨、算法逻辑有漏洞，必须在"技术严谨性"中显著扣分。
9. 【领域相关性约束——最重要】本分析面向**语音/音乐/音频领域读者**。如果论文的核心贡献并非语音/音乐/音频（例如：纯计算机视觉、纯自然语言处理、纯法律/政策框架、纯通用机器学习理论、纯机器人/具身智能等），即使技术质量优秀，也必须在**"影响力"维度显著扣分（通常不超过0.5分）**，因为其对语音/音乐/音频领域读者的直接相关性和实用价值有限。此类论文不应因"跨领域通用性"或"方法理论上可被音频复用"而获得高分。只有当论文明确以语音/音乐/音频为核心实验对象、核心评测任务或核心应用场景时，影响力才可正常评分。

【分项解释】
- 创新性（0-3）：问题是否新颖、方法是否有本质突破、insight是否深刻、与SOTA区分度是否清晰且有说服力。不要只因"组合已有技术"就低分，关键是组合是否有新洞察、是否解决了真正的问题。
- 技术严谨性（0-1.5）：推导/证明是否正确、算法逻辑有无漏洞、假设是否合理、边界条件是否讨论、数学表述是否严谨、有无过度简化。
- 实验充分性（0-1.5）：基线是否充分且有代表性、消融实验是否完整、数据集覆盖是否足够、结果是否真正支撑结论、有无显著性检验或误差分析、是否存在过拟合嫌疑。
- 清晰度（0-1）：组织结构、符号定义、公式解释、图表质量。读者能否不读源码就理解核心方法并复现。写作混乱或关键细节缺失要扣分。
- 影响力（0-2）：对领域的推动作用、潜在后续工作价值、实际应用潜力、与音频/语音读者的相关性。如果论文在重要基准上取得SOTA、发布了大规模数据集/工具、或解决了领域内长期存在的实际问题，应给高分； narrowly applicable 的小改进只能得低分。
- 开源（0-1.5）：代码/模型/数据/检查点是否公开可用。1.5分要求代码+模型+数据全部开源且有完整README和文档；1.0分要求代码开源但缺模型或缺文档；0.5分仅提供部分资源或无文档链接；0分完全不开源。
- 可复现性（0-0.5）：除开源外的文档充分度——训练细节、超参数、硬件环境、实验配置、复现步骤是否足够让他人不依赖作者就能复现。0.5分要求所有细节完整；0.25分信息部分缺失；0分关键细节完全缺失。

【参考区间】
- 9.0-10.0：突破性贡献，领域里程碑候选，方法或结果具有范式转变潜力
- 8.0-8.5：高水平工作，在重要问题上做出扎实贡献，有明确影响力或显著性能提升，值得仔细阅读
- 6.5-7.5：有价值但不够突出，或有小硬伤，属于合格到良好，对特定方向研究者有参考意义
- 5.0-6.0：创新有限、实验薄弱、结论不够重要或存在明显缺陷，仅适合快速浏览
- 1.0-4.5：问题严重，推导错误、实验不支持结论或写作极差，不推荐投入时间

## 标签

**严格格式要求（必须遵守，不可省略任何一行）：**

```
#标签1 #标签2 #标签3 #标签4
主任务标签：#任务标签
主方法标签：#方法标签
补充标签：#标签 #标签
```

**示例（假设论文是关于语音识别的）：**

```
#语音识别 #语音大模型 #多语言 #低资源
主任务标签：#语音识别
主方法标签：#语音大模型
补充标签：#多语言 #低资源
```

**格式规则（违反将导致解析失败）：**
1. 第一行是所有标签的完整列表，每个标签必须以 `#` 开头，用空格分隔。禁止用逗号、分号或顿号分隔。
2. **第二行必须**以 `主任务标签：` 开头，后跟一个以 `#` 开头的任务标签（从下方标签表中选择最具体的一个任务标签）。
3. **第三行必须**以 `主方法标签：` 开头，后跟一个以 `#` 开头的方法标签（从下方标签表中选择最核心的一种方法标签）。
4. 第四行以 `补充标签：` 开头，后跟剩余的标签。
5. **严禁**使用 arXiv 类别作为标签（如 `#cs.CL`、`#cs.AI`、`#eess.AS` 等）。
6. **严禁**输出无 `#` 前缀的纯文本（如 `uncertainty_estimation`、`Speech Processing` 等）。
7. **严禁**一个标签包含多个用逗号/分号分隔的内容（如 `#语音情感识别；政治演讲分析` 是错误的，必须拆成两个独立标签）。
8. 所有标签必须从下方标签表中选择，禁止自造新标签。

【标签规则】
1. 总数 3-5 个，必须严格从下方标签表选择，禁止自造新标签。
2. 必须包含至少 1 个【任务】标签，至少 1 个【方法】或【模型/架构】标签。
3. 优先用最具体的标签，避免宽泛上位词。
4. 只有当论文核心贡献就是多模态建模，或语音/音乐/音频与其他模态同等重要时，才使用 #多模态模型。
5. 已使用 #多模态模型 时，通常不要再用 #音视频，除非论文重点就是音视频场景本身。
6. #音频大模型 与 #语音大模型 二选一，按论文核心对象决定。
7. 若已标 #扩散模型 或 #流匹配，一般不要再标 #生成模型，除非论文确实讨论更广义的生成框架。

## 作者与机构
请基于当前提供的论文内容尽量完整提取作者与机构信息，要求：
1. 明确标注第一作者（如论文可判断），否则写"未说明"
2. 明确标注通讯作者（如论文可判断），否则写"未说明"
3. 列出能确认的作者姓名及其所属机构（大学、实验室、公司）
4. 机构信息尽量具体到实验室或部门；如果文本里没有，就写到能确认的层级
5. 禁止猜测机构信息；无法确认时明确写"未说明"

输出格式示例：
- 第一作者：张三（清华大学计算机系）
- 通讯作者：李四（Google DeepMind）
- 作者列表：张三（清华大学计算机系）、李四（Google DeepMind）、王五（未说明）

## 毒舌点评
用 2-3 句话做有信息量的点评，必须同时包含至少 1 个亮点和 1 个短板。可以犀利，但不要空泛嘲讽，不要只喊"很强"或"很水"。点评应像资深审稿人的 final comment，一针见血。

## 核心摘要
用 5-8 句话总结这篇论文，必须覆盖：
1. 要解决什么问题
2. 方法核心是什么
3. 与已有方法相比新在哪里
4. 主要实验结果如何（尽量带数字；没有就写未提供）。如果论文中有实验结果表格，必须用 Markdown 表格完整列出关键数据；如果有实验结果相关图表，描述图表内容
5. 实际意义是什么
6. 主要局限性是什么

## 方法概述和架构
**必须详细描述**论文的核心方法及其实现架构。本部分是整篇分析的技术核心，要求内容充实、层次清晰、细节充分。

**字数要求**：方法概述和架构部分不少于 600 个中文字符（约 400-500 个英文单词等效长度）。若论文方法复杂或模块较多，应显著超过此下限。

**必须覆盖的要素（缺一不可）**：
1. **整体流程概述**：用 2-3 句话描述完整的输入→处理→输出流程，说明这是一个端到端系统、多阶段流水线、还是某种框架/方法论。
2. **主要组件/模块详解**：逐一说明每个核心组件的：
   - **名称**：论文中使用的正式名称
   - **功能**：该组件解决什么子问题、承担什么职责
   - **内部结构/实现**：使用了什么网络结构（如 Transformer、CNN、RNN、Diffusion 等）、什么算法原理、什么数学工具；若论文给出具体公式，用文字解释公式含义
   - **输入输出**：接收什么数据/特征，输出什么结果
3. **组件间的数据流与交互**：组件之间如何连接？数据以什么形式传递？是否有循环/反馈机制？是否有条件分支？
4. **关键设计选择及动机**：为什么选用这种架构而非其他？论文中明确提到或可以推断的设计取舍（如精度 vs 速度、端到端 vs 模块化、自监督 vs 有监督等）
5. **多阶段/多模块逐层展开**：若论文方法分多个阶段（如预处理→编码→解码→后处理），每个阶段都要独立展开描述，不要一笔带过
6. **架构图/流程图**：若论文中有架构图或流程图（可能有多张），**每张图都必须用标准 Markdown 图片语法 `![描述](图片URL)` 贴到输出中**，并在图片下方用 3-5 句话详细说明图中各模块的关系和数据流向。
```
