# 论文解读的按目标局部修复

~~~
修复论文解读中明确列出的错误，只输出获准修改项。正确事实、数字单位、方法归属、比较条件、原文引文及已有标记保持准确。正文只讲论文，不复制检查要求。术语组合可以包含2–4个不同概念，各项为2–48字符，解释全部概念的分工、搭配原因和新增作用。
用平和朴实的中文说明具体对象和处理过程，不写宣传语，不生硬直译（如把 nuisance parameter 译成“讨厌参数”，应译为“干扰参数”或“无关参数”；不要把 ViSQOL 生硬译成“虚拟语音质量客观听众”，标准指标与硬件缩写如 ViSQOL、STOI、PESQ、WER、CER、MOS、RTF、GPU、CPU、FFT、MDCT 保留原名并首次括号解释；logit 译为“对数几率”，严禁误译为“对数值”），严禁在中文正文或小节标题中夹杂裸英文普通虚词、形容词、动词或通用概念词（如 alone、over、abstain、noisy、without、embodied、grounding、pending、backchannel、scaling、alignment、rollout、tradeoff、lookahead、pipeline、baseline 等），严禁使用“记住这个顺序”“务必记住”“不要忘记”等说教式口吻，严禁使用“这张图确实可见”“从像素可见”“比较问题是：”“这张表支撑的判断是”“本表数值与单位依据论文 PDF”等二代校验套话，也严禁在正文中复述“该式的三层含义”“可分三层理解”“三层读法”“怎样进入下一步”“可写作者”“本次核验返回 200”“资源清单未标明”等提示词与核验口癖。中文与英文或阿拉伯数字之间留一个半角空格（例如“185 个样本”“35B-A3B”“84.0%”），数学与统计专名及自然中文序数、逐指词、构词短语保留纯正汉字（如最小二乘、一阶/二阶、二维频谱、一对一、置信区间半宽、第一个/第二步、每一帧/每一维、两阶段/三阶段、两段式、哪一帧/两者/任何一级，绝不写成“最小 2 乘”“1/2 宽”“第 3 个”“每 1 帧”“2 者之间”或“哪 1 帧”）。critic 按实际任务称为价值评估模型或辅助分数模型，严禁译成“评论家”“评论更新”或“评论与学生”；声称某方法/数值在表内“最优/最低/最高/第一/SOTA”前，必须逐格核对同表同列其他方法行及指标方向（`↑/↓`），绝不把同列存在更优值的条目写成最优，也绝不混淆 `↓` 与 `↑` 方向。只使用原文涉及的概念，不能把这些写作规则抄入正文。
在本次获准目标内，把读者缺少的解释补清：讲清概念处理的对象、模块间的数据与因果衔接、公式背后的数学动机/极端取值行为/下游作用（严禁顺着符号硬念文字绕口令或套用“该式的三层含义”模板，行内数学用规范 \(...\)），以及比较条件和指标含义。扩写时只能补充原文尚未展开的机制、条件或实验细节，严禁换词重复前文已交代的语料规模、样本数或方法步骤，严禁整节反复套用“……为何……”“前一步……后一步……”的机械句式凑字数。以当前错误和原文证据为限，不补造维度、梯度、数值、消融或因果，不硬塞“建议做网格搜索”，不改无关正确解释。术语和符号沿用本篇已核准的含义，原表、公式、标记、引用及来源字段保持原协议约束。
正文或解释目标包含多个自然段时，每段围绕一个具体问题展开，保持 120–320 汉字（硬上限 420 字）的舒适自然段，散文超过 950 汉字的小节须使用 `####` 子标题或结构化列表（至少 2 项）建立层次，段间留一行空白，JSON 字符串用合法 \n\n 转义。转到新步骤或不同证据再分段，不要一遇分号或每两三句就碎切，不机械重复句首和段尾免责句。术语叶子、原句等窄目标不得借此扩写成段落或越过授权；任何标题不得包含“图 1/Figure 1/表 1/Table 1”编号，且不得连续 3 节及以上套用“问题本质：/方法全景：/核心机制：/主实验验证：”等模板化前缀；`figurePlacements` 的 `chineseCaption` 须为 12–120 字单行自然中文图注（不含“图 N / Figure N”前缀）并保持图-节语义就位；`implementationSpecs` 须保留六个必填单行纯文本来源核实字段（`trainingData`/`computeHardware`/`keyHyperparams`/`inferenceCost`/`openSourceArtifacts`/`appendixHighlights`）及可选 `audioSignalSpecs`（不含换行/Markdown/HTML/内部核验话术，行内公式统一用 `\(...\)`，无训练阶段标明无模型训练阶段，真正缺失再写“原文未披露”）；章节、表格、公式和图片的数量及位置只按本轮明确操作协议修改。
表格修正须保留真实方法、条件、指标、单位及对应数值，按原表真实列数呈现，不为固定宽度补解释列；同一原表（相同 `sourceTableOrdinal`）不得重复展示相同完整表或数据格重合 >= 50% 的重叠子集，严禁把消融表冒充主结果表放进 `result` 小节（主结果原表 DOM 不可编译时须改用 `source_quotes` 逐字引文构建主结果表）；使用 `selection` 时 `sourceRows[0]` 须为含具体指标列名的真实表头行（严禁选取仅含分区标题的空列分隔行），且表前表后表述须与实际保留的行列数量严格一致，不对精简子表宣称“列出全部 N 项”；表后评述须提炼跨行规律、代价权衡与明显未胜出项而非逐行复述数字。禁止把引文中的任意数字或参考文献编号、年份、页码拼成“来源证据／来源句一／量化值一”占位结果表；sourceQuotes 须对应实际实验的条件、方法、指标和原结果，逐字数字存在不代表结果归属成立。它只核验来源，不生成或搬动表格，也不能靠几个相同数字选择原表。只在已授权正文及绑定节点内按同一原表或完整连续结果句恢复语义行列，缺证据时保留失败，不补造对应关系。构造或修订 source_quotes 表时，列头单位（如 %、s、GiB）须在对应来源行有逐字单位证据；原文只写裸数字而未逐行重复单位时优先绑定原表，或不在 source_quotes 列头加括号单位符号，同时守住最低表数要求（可用原表不少于 4 张时至少保留 4 张表），并确保每张表紧邻的表后评述只对应本表行列与数值。描述图例颜色、柱体实心或斜纹填充（如 p <= 0.05 实心与 p > 0.05 斜纹）及子图行列轴向时，使用“全部”“所有”“只有”“唯一”前须逐组核对无例外，不把条件图例颜色同方法行名混为一谈。

没有明确的原子操作时，只输出下面的JSON结构，不输出完整文章：

只提交1–8个授权目标，目标类型保持一致，父子路径不同时修改。修改后必须实际消除当前问题；不要逐字回传仍有错误的旧值。其他字段由程序保留。正文目标回传完整正文，术语解释目标回传完整对象，数组数量只在本轮明确授权时才可改变。来源证据不足时不能补造事实，也不能用占位文字或重复内容凑长度。
