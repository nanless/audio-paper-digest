# 单篇论文分析提示词

## 用途

主模型依据文本完成结构化分析。配置了副模型时，后续由副模型根据实际图像补充说明；未配置时，图片只保留候选信息，不自动插入正文。

## 调用方式

代码通过 `loadPrompt()` 读取第一个代码块，把占位符替换成论文标题、作者、类别、arXiv ID、本次可用的原文和标签选项。`{hasFullText}` 说明本次输入是全文证据还是摘要；`{tagPromptText}` 提供当前可用的标签及其定义。

## 提示词内容

~~~
中文讲解与术语用法

【以下仅为写作规则和术语对照，不得复制到文章；只使用本篇原文涉及的条目】
- 讲清论文解决的具体问题、各部分分工、输入处理过程及作用和代价；按实际内容自然展开，避免固定栏目、反复总结和宣传语。
- 术语首次出现时解释实际作用，之后保持称呼一致。critic 按原文任务命名：价值估计用“价值评估模型”，学生分布分数估计用“辅助分数模型”；分类判别任务中的 discriminator 可称“判别器”。不得套用论文未涉及的角色。
- 术语对照：score＝对数密度对输入的梯度（适用于原文采用此定义时）；FID＝生成图像与参考样本的特征分布差异指标（参考集以原文为准）；patch FID＝在图像块上计算的 FID。Inception、Fréchet、KL、梯度和模型专名保持准确名称。
- 普通概念用自然中文，写出具体对象、处理过程和统计方式；必要专业术语可保留，首次说明含义。
- 正文只讲论文内容和有证据的结论。结构、来源校验、字数与修复权限仅供执行，不写进正文。事实、公式、数字、单位、指标方向、方法归属及逐字引文保持准确。

请依据下方文本分析这篇论文，核对研究问题、方法、证据和结论，并按后面的格式用中文输出。{hasFullText}

论文标题：{title}
作者：{authors}
类别：{categories}
arXiv ID：{arxivId}
链接：https://arxiv.org/abs/{arxivId}

{textForAnalysis}

以下 13 个一级标题必须按顺序各出现一次，不增删、重复，也不把同名标题嵌入正文。输出直接从 `## 评分` 开始，不加问候、前言或任务说明。无法从输入确认的信息，写“未说明”“未提供”或“论文中未提及”，不根据常识、作者或机构声望、邮箱、外部网页和历史记忆猜测。

正文使用完整句子和自然段落，句子长短可以变化。核心摘要作为全景导读摘要完整交代问题瓶颈、方法架构、主基准对比与核心代价及适用边界，方法解释组件与数据流，创新说明与已有方法的差异。实验展开比较，细节说明复现条件，局限集中讨论尚不能成立的结论。核心实验数字主要集中在摘要与实验结果中，不在其他章节换说法反复堆砌。

先说明读者需要理解的对象、困难和处理过程，再给术语名称。一个尚未解释的术语不能用另一个陌生术语代替定义。沿一个样本说明输入怎样表示、经过什么变换、生成什么中间结果、交给哪个组件以及最终输出；分清并行与串行、训练与推理、冻结与更新。形状、梯度、近似和实现细节只按原文披露的范围解释，不能为了写得完整补造。每个自然段围绕一个问题，话题转到下一步骤、证据或推测时另起一段；Markdown 段落、标题、列表、表格与公式之间留一行空白，不把每句话都拆成段落。

公式先说明计算目标，再解释关键变量、下标、范围和单位，沿运算顺序说明结果怎样用于方法；不能只列原式或翻译字母。比较先说明任务、数据划分、对象、条件、预算和指标方向，结果附近解释分母或聚合方式、实际收益与代价。观察、作者解释和编辑推测区分开，跨指标或不同条件不能拼成同一次胜负。教学例子必须明确标示，不增加无来源的实验数值、公式、效果或未做过的消融。

精确实验数值、样本量、模型规模、时长、频率、百分比、比例、名次、超参数和置信区间使用阿拉伯数字。中文数词只用于序数、固定词组或非精确描述。术语首次出现时先用中文解释作用；读者需要对应原论文时，再附官方英文名或缩写，普通中文已经说清时不强加英文。后文统一称呼，必要的正式名称、代码字段与缩写保持准确，中文与英文或阿拉伯数字之间留一个半角空格（例如“185 个样本”“35B-A3B”“84.0%”），数学专名与自然序数保留纯正汉字（如一阶、二维、第一步、每一帧）。遇到混合专家总参/激活参简写（如 35B-A3B）、采样率或帧率记号时须按原文定义准确展开，绝不曲解字母含义。不要重复套用“关键比较问题是”“下图用于核对”“证据边界在于”“下一段将解释”等通用句首，不把字段串拼成正文，不使用双重编号或以分号结束的段落。

以下写作要求适用于正文所有章节。面向第一次接触这个方向的读者，用平实的中文写清事实、条件和依据，不预设他们熟悉术语或研究惯例。

不要这样写：

* 八股连接词。“首先、其次、最后、总之”反复出现，“不是 A，而是 B”“这就是……的本质”。有真实的先后顺序就直接写出来，没有顺序关系就不要连接词。
* 固定口头标签。给每节加“人话版”“一句话总结”“看什么”“记住”这类固定的口头标签。直接写事实或写清两段之间的关系。
* 工作流话术。“本轮、排期、交付、后续迭代、闭环验收”。只写读者需要理解或核对的内容，编辑过程不进入正文。
* 产品与咨询黑话。“拉通链路、推动落地、赛道红利、能力底座、核心抓手、组合拳、性能天花板、方案兜底”。改写成具体的模块、指标、限制，或失败之后要做的处理。
* 过度拟人和伪口语。“算法把频谱吃进去”“把掩码喂给”“网络接管”“系统翻车”“掉链子”。改写成“网络输入语谱图”“用掩码估计协方差”“条件数增大后求逆误差上升”。
* 夸张口语与竞技化标签。“踩坑、命门、崩塌、通吃、露馅、打榜”。直接写失效条件、响应变化或公开评测目标。专业含义明确的“秩亏”“零陷”不属于这一类。
* 营销式断言。“工业默认、唯一正确、彻底消除、任何场景都适用、直接碾压”。写明数据集、条件、假设和比较对象；证据不够就降低结论强度。
* 命令读者。“记死、不许质疑、照抄”。改成说明建议、适用条件和出错后果。
* 不必要的中英混杂。“调 trade-off”“跑 baseline”“pipeline 已 ready”。需要对照原文时给官方英文全称或缩写；普通叙述用自然中文，后文统一称呼。

可以保留的用法。真实步骤里的“先、再、最后”，单个“总之”用来收束一段也可以；已经给出中文名和英文全称之后的专业缩写；代码、命令、API 名称和没有稳定中译名的正式术语；由公式或标准给出数值的“上限”，表示可复现对照的“基线”；表示信号或数据依次经过哪些模块的“链路”。“不是 A，而是 B”、类比和提问句可以偶尔用，但如果删掉不损失信息，或者在相邻段落里重复出现，就改写。

定量结论要写清实验条件、比较对象、指标和数值，精确值与近似值按原文区分，不用“显著提升”代替具体结果。解释因果关系时给出论文实际支持的依据，不把相关现象写成因果结论。句式随内容自然变化，不反复套用固定模板。用类比时说明它只解释哪一部分、边界在哪里，不让类比代替机制说明。

## 评分
单独写总分，格式为 `X.X/10`。

## 机器摘要
以下 18 个键必须各出现一次，不能增加其他键。每行使用 `key: value` 纯文本格式，不加列表符号，不在键或值中使用加粗等 Markdown 标记。

```
rubric_version: type-aware-v2
document_type: 方法研究 / 系统技术报告 / 模型报告 / 数据集与基准 / 综述 / 理论研究 / 应用研究
rank_bucket: 前10% / 前25% / 前50% / 后50%
innovation: X.X
technical_rigor: X.X
experimental_sufficiency: X.X
clarity: X.X
impact: X.X
open_source: X.X
reproducibility: X.X
engineering_score: X.X
confidence: 高 / 中 / 低
primary_task_tag: #标签
primary_method_tag: #标签
sota_claim: 是 / 否 / 未说明
has_code: 是 / 否 / 未说明
has_model: 是 / 否 / 未说明
has_dataset: 是 / 否 / 未说明
```

`rubric_version` 固定写 `type-aware-v2`。`document_type` 按论文主要贡献选择示例中的一个类型。`rank_bucket` 只能使用示例中的四档，`confidence` 只能写“高”“中”或“低”。`sota_claim` 表示论文是否明确声称达到当前最佳结果；它与 `has_code`、`has_model`、`has_dataset` 都只能写“是”“否”或“未说明”。

八个分项分别是创新性、技术严谨性、实验充分性、清晰度、影响力、开源、可复现性和工程/实践价值，**全部采用 0.0–10.0 统一量表**（四舍五入保留一位小数）。评分理由使用完全相同的分值，分母统一写 `/10`。总分由代码按文档类型加权计算：`总分 = min(10.0, round1(七项核心加权分 + (open_source / 10) × 开源上限加分 B_t))`。

开源分只允许 `0.0 / 1.5 / 3.0 / 6.0 / 8.0 / 10.0`。主任务和主方法标签分别从下方标签选项中的 `facet=task` 和 `facet=method` 选择，使用状态为 `active` 的首选名称，不能用方法名、arXiv 类别或一段描述代替任务标签。

### 评分依据

先判断论文在同期同方向工作中的位置。前10%对应里程碑或显著领先工作，前25%对应明显优秀，前50%对应扎实良好，后50%对应短板明显。排序档位与总分保持一致：总分至少 8.5 为前10%，至少 7.5 为前25%，至少 6.0 为前50%，低于 6.0 为后50%。代码会根据评分理由按文档类型权重重算总分和档位，不在理由中重复计算。

七项核心维度严格按统一 10 分制五档行为锚定拉开区分度，禁止习惯性集中打在 6.8–8.0：
- 9.0–10.0：里程碑/突破级水准（同方向前 5%，近乎无短板）；
- 7.5–8.9：明显优秀（清晰创新或跨规模显著跃升、强基线领先、证据扎实）；
- 6.0–7.4：扎实良好（方法成立、实验可核对，但属稳健渐进或存在范围局限）；
- 4.0–5.9：存在明显短板（核心主张与验证脱节、常规模块拼装、表文算术矛盾、窄受众无外溢或关键基线/消融/复现披露缺口显著）；
- 0.0–3.9：严重缺陷或不适用（存在实质逻辑漏洞、缺乏基本支撑或该维度不适用）。

反通胀校准：普通可读论文清晰度给 6.5–7.2，存在表文数字或算术矛盾不超过 5.8；教科书常规流水线加立论脱节时技术严谨性给 4.5–5.8；商用模块拼装或纯目录综述创新性给 4.5–5.8；窄地域/单语种/小众应用无泛化或复用产物时影响力给 4.0–5.5；跨规模显著领先的全模态音视频基础模型按核心音频影响正常给 8.2–9.2。

不同文档类型适用不同的证据重点与核心权重：方法研究重创新（24%）、实验（22%）与严谨（18%）；系统技术报告重工程（20%）与实验（20%）；模型报告重实验（22%）、创新（18%）与影响（18%）；数据集与基准重影响（20%）、实验（18%）、复现（12%）且开源上限加分最高（`B_t = 0.8`，按核心数据集核验）；综述重影响（22%）与清晰度（20%）；理论研究重严谨（30%）与创新（26%），工程权重为 0% 且开源上限加分仅 `B_t = 0.2`；应用研究重实验（20%）与工程（18%）。

同一个缺陷只用于一个主要维度的扣分。缺少代码、模型、数据或其他核心材料归开源；缺少超参数、训练配置、硬件和复现步骤归可复现性；缺少支持结论的对比、消融或其他验证归实验充分性；写作、符号、图表和组织问题归清晰度；推导错误、不合理假设或算法逻辑漏洞归技术严谨性。不能因一处信息缺失在多个维度重复扣分。“无法验证”不等于“已经证明错误”；信息不足时降低 `confidence`，只在直接相关的维度扣分。

本分析面向语音、音乐和音频研究者。核心贡献不属于这些领域时，即使技术优秀，影响力通常不超过 4.0。全模态音视频基础模型若在原生音频理解、语音交互或音视频联合基准上系统评测并取得代表性成果，按真实音频领域影响正常评定。小众、垂直、特殊人群、病理语音和动物声音等题材的创新性、技术严谨性正常评分，影响力按实际受众和推动力如实评定。

开源按对应类型核心产物评分：核心材料完整开放且文档完整为 10.0；完整开放但文档不完整为 8.0；部分开放为 6.0；明确承诺未来开放但尚未发布为 3.0；只有可访问的在线演示、没有核心材料为 1.5；完全关闭且无承诺为 0.0。理论研究仅公开推导与证明而无代码/数据仓库时最高计 3.0。可复现性只看论文对架构、训练数据、超参数、硬件、评测和步骤的披露是否充分（8.5–10.0 详尽可复现；6.5–8.4 大部分充分；3.5–6.4 关键配置缺失较多；0.0–3.4 几乎未披露）。工程/实践价值看真实延迟/吞吐/成本测量、可复用训练推理管线或公开基准工具，纯理论研究无工程落地时可为 0.0。

## 标签

严格输出四行，第一行列出全部标签，第二行指定主任务，第三行指定主方法，第四行列出补充标签。所有标签以 `#` 开头，用空格分隔，不用逗号、分号或顿号。

```
#标签1 #标签2 #标签3 #标签4
主任务标签：#任务标签
主方法标签：#方法标签
补充标签：#标签 #标签
```

共选择 3–5 个标签，至少包含一个任务和一个方法，其中任务标签（`facet=task`）最多 3 个。标签必须逐字采用下方提供的首选名称，状态为 `active`，不输出概念 ID、别名、已弃用名称或自行翻译的名称。找不到完全对应的概念时，选择可用且最接近的上位概念，不自造标签。主任务选择最具体的适用概念，主方法描述论文实际的核心研究方法，补充标签可以来自其他分类维度。

同一概念及其别名不能重复，已经选择具体概念时不再选它的上位概念。相关性相近时，补充标签优先覆盖不同分类维度。选择时阅读 `definition` 和 `scopeNote`，不能只看名称相似。arXiv 类别如 `#cs.CL`、没有 `#` 的文字，以及把多个标签拼在一起的写法都不合格。

这四行只记录本篇有原文证据的直接标签。网站按同一词表的九个分类维度和上下级关系展示路径；父级导航由程序补出，不计入直接标签数量。不要输出整套目录、同级其他方向、未命中的分类维度或自行编造的层级名称。

根据以下事实区分容易混淆的标签：

- 识别或 ASR 只是测量工具时，社会语音学、韵律统计或发音评估研究不能因此标为 `#语音识别`。选择 `#语音属性识别` 或适用的科学主题。
- 用视频、参考音频、说话人嵌入或到达方向（DOA）指定目标时，选择 `#目标说话人提取`；有视觉输入时可以补充 `#音视频`。只有视觉用于盲分离、没有指定目标时，才选择 `#音视频语音分离`。
- 核心贡献是表示、量化、数据或协议时，主方法不选 `#CNN`、`#RNN`、`#Transformer`、`#注意力机制` 或 `#状态空间模型` 等骨干架构。架构可以作为补充。数据集、基准、综述和理论论文按实际采用的研究方法选择。
- 多模态输入不等于核心方法是多模态学习。没有训练的处理流程优先选择适用的信号处理或系统方法；对抗工作按实际机制选择对抗训练或对抗鲁棒性。词表没有对应概念时选择合适的上位概念，不为凑数贴标签。
- 应用场景必须是论文实际研究或评测的场景，不能只出现在局限或未来工作中。`#实时处理` 必须有实测延迟或吞吐及其条件，作者自称实时不能作为依据。
- 标题或正文明确表明构建基准、语料或数据集时，必须包含 `#基准测试` 或 `#数据集`。在 3–5 个标签的限制内，它们优先于泛泛的场景或模型族标签。
- 补充任务必须有与主任务并列的贡献或评测证据。仅用 WER 等指标评测其他任务，不意味着识别也是本文的研究任务。

## 作者与机构

只从提供的论文内容提取作者及其机构。能判断第一作者和通讯作者时分别注明，否则写“未说明”。列出能确认的姓名及对应大学、实验室或公司，机构具体到输入能支持的层级，不猜部门或归属。

格式示例：

## 论文评价

用 2–3 句话评价最有依据的贡献和最重要的限制，说明判断来自什么证据。不空泛赞美、嘲讽或表演犀利，也不为凑齐正反意见编造缺陷。没有发现明确问题时，如实说明。

## 核心摘要

撰写信息饱满、结构清晰的全景导读摘要，让读者只读一遍即可完整把握整篇论文。正文写 10–26 句，汉字与中文标点合计 700–1400 个（起草目标 850–1150 个），分成 3–4 个自然段，段落之间只用一个空行分隔，段内不拆行或列点。严禁在核心摘要内使用 `#`、`##`、`###` 等 Markdown 标题、独立编号粗体标题行（如 `1. **...**`）或水平分隔线；统一采用段首粗体引导词直接顶格开启以下 4 段式（或紧凑 3 段式）自然段落（段首不加 `-`、`*` 或 `1.` 等列表编号）：

- `**问题与瓶颈：**` 说明具体任务的输入与输出信号规格，直指现有主流路线在物理、统计或架构上的根本失效因果（如频谱混叠、长序列注意力开销、音色与内容耦合），拒绝空泛套话“难以兼顾”。
- `**核心思路与方法架构：**` 先用一句话点破核心设计直觉，再沿一个具体输入样本的表征流自然讲清关键模块分工、码率/帧率/维度/模型规模、冻结与更新边界、离线或流式约束，以及这套机制为什么能直击前述根因。方法机制单句不超过 520 字，跨句自然衔接，不要写成生硬的“先…输出…送入…”流水账或连续堆砌“称为…”。
- `**关键实验与核心代价：**` 给出主基准对最强可比基线的核心定量对比，写清评测数据集或设置、原文指标名称与方向、本文与基线的具体数值——允许在同一自然段内跨 1–3 句自然展开比较条件与多组关键指标，不必把所有要素硬塞进同一个长句；不能用模型名、版本号、年份、参数量、样本量或训练超参数代替实验结果（原文确无可核对的定量结果时，原样写“原文未提供可核对的关键定量结果”）。同时交代主导收益的关键消融发现及付出的最显著代价（如某子集指标回升、参数/显存开销、实时率 RTF 或推理时延）；若为纯理论、诊断或免训练评测论文，如实说明计算方式即可，无需机械背诵“原文未披露训练、推理或部署成本”。凡写出的实验与成本数值均须在原文有据可查，严格保持原文精度、正负号与百分号，绝不编造或四舍五入。
- `**适用边界与深读导览：**` 点明结论成立的具体前提与尚未覆盖的失效或部署场景，并用一句话指明读者若想深究哪部分公式推导、核心机制或消融表可查阅下方长文对应章节。须用凝练概括语言独立撰写摘要，严禁从长文直接整段复制 80 字及以上的相同文字，也不在摘要中嵌入 Markdown 表格。

## 方法概述和架构

正文不少于 600 个中文字符，解释核心方法怎样工作。先用 2–3 句话说明输入、处理和输出，再展开核心组件。每个组件要说明论文采用的名称、功能、内部结构或算法，以及输入和输出。原文有公式时解释其含义，不仅列符号。

写清组件怎样连接、传递什么数据，是否存在循环、反馈或条件分支。说明设计动机和精度、速度、训练方式等取舍；推断的理由明确标为推断，并给出依据。多个阶段分别解释，不省略论文明确报告的组件。首次出现的核心术语应让不熟悉该方向的读者也能理解。

数据集、基准、理论和综述等工作按实际内容解释构建过程、评估流程、论证或综合分析，不强行套用模型架构。不要只列组件名、用“详见原文”代替实现，或把方法压成 1–2 段短文字。

## 核心创新点

说明 3–5 个最重要的创新点。每项解释新的内容、已有方法的局限、作用机制，以及原文提供的收益或证据，不写空泛评价。

## 实验结果

写清主要基准、数据集、指标和数值，以及与最强基线或当前最佳结果的差距。原文没有直接比较时明确说明。原文提供了关键消融、负结果或不同条件、语言、场景的细分结果时，保留相关证据和数值。

正文明确报告的数字可以直接使用。正文没有复述图表数字时，只能从输入中可见的原始表格单元格或明确图注提取，不能根据曲线、柱高、颜色或像素位置估算。拿不到具体数字时写“论文未给出具体数值”。每组结果就近说明数据划分或设置、方法、基线、指标、数值、单位、方向和必要条件，不让读者猜测数字对应什么。

最多嵌入 2 张关键 Markdown 表格，每张最多 12 个数据行和 8 个指标列，方法、模型和数据集等识别列不计入指标列数。实证论文的表格合计至少有 3 个数据行和 2 个可核对数字。表头有识别列；指标有优化方向时标出 `↑/↓`。不使用“结果”“观察”“含义”“说明”或“结论”等叙述列代替指标。

大表优先保留本文方法、最强基线、代表性传统或开源基线、平均或汇总行，以及关键消融和负结果。表前说明比较问题和选取这些行列的理由，表后解释主要差异、代价与适用范围。不要套用固定句首、逐行复述或用“此处省略”“详见原文”代替数据。负号用 ASCII `-`，百分号用半角 `%`，小数保留前导零。

## 细节详述

解释复现所需的技术细节，包括训练数据的来源、规模、预处理和增强，损失函数及其权重，学习率、预热、批量大小、优化器、步数或轮数及调度策略。再说明模型规模、层数、隐藏维度、码本大小、训练设备型号和数量、训练时长，以及解码、温度、束搜索宽度和流式设置。原文提供了正则化或稳定训练方法时也应说明。缺失的项目写“未说明”，不按惯例补写。

## 评分理由

八个维度各写一条，顺序为创新性、技术严谨性、实验充分性、清晰度、影响力、开源、可复现性、工程/实践价值。每条严格使用 `* 中文维度名 (得分/10)：具体理由`，分数和理由不拆成两行。理由说明具体证据及其优点或缺陷，不写占位评价，也不重复总分计算。

得分采用统一的 0.0–10.0 量表，分母统一为 `10`，得分必须有限、非负、不超过 `10.0` 且最多一位小数。开源分采用 `0.0 / 1.5 / 3.0 / 6.0 / 8.0 / 10.0`。缺项、重复、错误分母和无有效理由都会被程序拒绝。同一个缺陷只用于一个维度，按 `document_type` 选择适用证据，不能仅因类型保底。

* 创新性 (X.X/10)：解释问题、方法或关键认识的新颖程度，与已有最佳方法的区别，以及论文声称的创新能否成立。
* 技术严谨性 (X.X/10)：解释推导、证明、算法、假设和边界是否可靠，只指出有依据的技术问题。
* 实验充分性 (X.X/10)：评价基线、消融、覆盖范围和统计等适用证据能否支持结论，指出不公平比较或过度解读。
* 清晰度 (X.X/10)：评价组织、符号、公式、图表和文字；训练配置、硬件和复现步骤的缺失归可复现性。
* 影响力 (X.X/10)：说明对语音、音乐或音频研究的实际贡献、后续价值和适用范围。非音频核心贡献或范围很窄的小改进按前述政策评分。
* 开源 (X.X/10)：根据论文类型判断相应核心材料是否公开、文档是否完整，与开源详情保持一致。有演示页面时，可以据输入中提供的链接说明是否存在资源入口，不能假装已经访问网页。
* 可复现性 (X.X/10)：说明训练细节、超参数、硬件、实验设置和步骤是否足以复现。只有仓库或演示链接不代表这些说明充分。
* 工程/实践价值 (X.X/10)：根据系统流程、真实测量、可复用组件和部署资料评价实际参考价值。系统、模型和基准工作应具体核对；纯理论工作可以为 0.0。

## 局限与问题

区分论文明确承认的局限与根据证据发现的潜在问题。前者概括作者报告的限制、假设和未来工作；后者说明方法、实验设计或结论中需要进一步核查的具体问题及依据。推测不能写成已确认错误，某方面没有发现明显问题时如实说明，不为凑数编造。

## 开源详情

只根据输入论文和提供的链接说明资源情况，不编造仓库、收藏数量或平台热度。分别说明代码仓库、模型权重、数据集及获取方式、在线演示、训练配置和检查点、附录及其他复现材料，必要时注明论文使用的开源工具或模型。没有相应信息时写“未提及”；没有代码链接时写“论文中未提及代码链接”，没有开源计划时写“论文中未提及开源计划”。

### 输出注意事项

关键实验表格放在实验结果中，其他结果用有依据的文字说明。特殊文本标记如 `<S>`、`</S>`、`<E>`、`<task>`、`<perception>`、`<interrupt>` 和 `<backchannel>` 必须用反引号包裹，避免被当作 HTML 标签。

数学公式使用 `$...$` 表示行内公式、`$$...$$` 表示独立公式，不用普通文本代替。例如应写 `$RMS = \sqrt{\frac{1}{N} \sum y[n]^2}$`。可能被误解析的符号放在公式环境或代码格式中。

所有章节完整输出，不留下截断句子。篇幅过长时精简重复描述，输出仍会写到全部章节结束。
