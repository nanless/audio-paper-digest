# 核心摘要修复提示词

## 用途

根据校验反馈修复 `## 核心摘要`。只修改这一节，其他 12 个一级章节保持不变。

## 提示词内容

~~~
中文讲解与术语用法

【以下仅为写作规则和术语对照，不得复制到文章；只使用本篇原文涉及的条目】
- 讲清论文解决的具体问题、各部分分工、输入处理过程及作用和代价；按实际内容自然展开，避免固定栏目、反复总结和宣传语。
- 术语首次出现时解释实际作用，之后保持称呼一致。critic 按原文任务命名：价值估计用“价值评估模型”，学生分布分数估计用“辅助分数模型”；分类判别任务中的 discriminator 可称“判别器”。不得套用论文未涉及的角色。
- 术语对照：score＝对数密度对输入的梯度（适用于原文采用此定义时）；FID＝生成图像与参考样本的特征分布差异指标（参考集以原文为准）；patch FID＝在图像块上计算的 FID。Inception、Fréchet、KL、梯度和模型专名保持准确名称。
- 普通概念用自然中文，写出具体对象、处理过程和统计方式；必要专业术语可保留，首次说明含义。
- 正文只讲论文内容和有证据的结论。结构、来源校验、字数与修复权限仅供执行，不写进正文。事实、公式、数字、单位、指标方向、方法归属及逐字引文保持准确。

本规则不扩大本次获准修改范围。

请根据下方论文证据和校验反馈修复核心摘要。只输出 `## 核心摘要` 及其正文，不加前言、代码块围栏或其他标题。

论文标题：{title}
论文 ID：{arxivId}
当前摘要问题：{summaryIssue}

当前核心摘要：

{existingSummary}

论文原文证据：

{textForAnalysis}

摘要正文写 10–26 句，汉字与中文标点合计 700–1400 个。起草时以 850–1150 个中文字符为目标，将核心摘要写成信息饱满、结构清晰的全景导读摘要，让读者只读一遍就能完整把握整篇论文；最终按 700–1400 个汉字与中文标点、10–26 句、3–4 个自然段检查。段落之间严格使用一个空行分隔，段内写成连贯散文，不拆行或列点。严禁在核心摘要内使用 `#`、`##`、`###` 等 Markdown 标题、独立编号标题行（如 `1. **...**`）或水平分隔线；统一使用段首粗体引导词直接顶格组织 4 段式（或紧凑 3 段式）自然段落（段首不加 `-`、`*` 或 `1.` 等列表编号）：

1. `**问题与瓶颈：**` 交代具体任务输入与输出信号规格，指出现有主流路线在物理、统计或架构上的真实失效症结，拒绝空泛“难以兼顾”。
2. `**核心思路与方法架构：**` 一句话点破核心洞察，再顺着信号或表征流讲清关键模块分工、码率/帧率/维度/模型规模、训练与冻结边界，以及为什么这样设计能解决瓶颈。方法机制单句不超过 520 字，允许跨句自然表达信号传递与相互作用，不必生硬堆砌“先…输出…送入…”或连写多个“称为…”。
3. `**关键实验与核心代价：**` 给出主基准对最强可比基线的核心定量对比（含评测设置/数据集、原文指标名与方向、本文与基线具体数值），允许在同一自然段内跨 1–3 句自然展开比较条件与多组关键指标；同时交代关键消融发现与付出的具体代价（如指标回升、参数开销、实时率 RTF 等）。纯理论、诊断或免训练评测论文如实说明实际计算方式即可，不再强求机械背诵“原文未披露训练、推理或部署成本”。
4. `**适用边界与深读导览：**` 点明结论成立条件或未覆盖场景，并用一句话指明读者若想深究哪部分公式推导、架构细节或消融分析可阅读下方长文对应部分。请用凝练概括语言撰写摘要，严禁从长文直接整段复制 80 字及以上的相同段落。

修复缺项时优先替换已有不完整或重复的说明，不把每个补充说明机械附在末尾。保护已经正确的事实、比较对象、条件、指标、数字、单位、方向、边界和代价；若纠错反馈明确要求某句逐字保留，则该句必须原样保留。不要修改评分、标签、作者、方法、实验等其他章节，也不要复制整张表格。

### 定量结果

原文提供了关键定量结果时，必须给出主基准对最强可比基线的核心定量对比。允许在同一段内跨 1–3 句自然展开评测设置或数据集、比较对象、原文指标名称、双方具体数值与高低或变化方向，不必把五个要素硬塞进同一个超长单句。写出原文指标名称，不用“分”“更高”或“多项指标”代替指标。

比较通常采用本文方法与最强可比基线。数据集或资源论文没有方法基线时，可以使用原文在同一量表上报告的两个条件或维度。写清双方名称、各自数值及高低或变化方向，不能比较不同量纲或不同指标。方向可以用“高于”“低于”“超过”等符合原意的词表达，也可以明确说明数值从何值变为何值。“最高”“最优”“最低”或“达到”不能独立说明与谁比较。

两个数值及各自单位、正负号和小数精度必须逐字来自同一原表中明确可比的记录，或来自同一段连续原文证据。比较不同方法时，数值可以位于不同方法行，但必须沿完整表头定位同一指标列，并逐项核对评测设置、行名、单位和聚合方式。比较不同条件时，只采用原表明确设置的条件对照，且除被比较因素外其余评测条件一致；原表转置时，按真实行列角色核对同一指标，不能把不同指标当成两种方法。禁止把不同数据集、评测协议、指标或不连续证据片段拼成同条件比较。PDF 表格被拆成多行时，先恢复可核对的表头、对象与数值对应关系；无法唯一对应就换用另一组完整证据，不猜测单元格归属。

不要把 `0.85` 写成 `85.00` 或 `85%`。也不要增删末尾的零、舍入、把百分数与小数互换、换算单位或自己算差值。摘要和引言里的概括值不能和表格里的基线值拼成一组比较。同一处证据没有完整的比较值和单位时，换用另一组可以逐字核对的原文比较，不补算缺失结果。

模型名、版本号、年份、参数量、样本量和训练超参数不能充当实验效果。摘要只有这些数字时，应换成原文有明确指标名称的结果。速度或压缩结果也要写清原文的测量口径，不能把速度、实时率、压缩率和文件大小混为同一指标。

原文确实没有可核对的定量结果时，原样写“原文未提供可核对的关键定量结果”，不猜测数字。

### 核心代价、适用边界与深读导览

说明结论在哪些条件下成立、哪些条件可能退化或失效，或哪些范围尚未验证，写明具体条件而不只笼统写“仍有局限”，并用一句话自然引导读者按需查阅下方长文中的核心推导、架构细节或消融分析。

如实交代关键消融发现以及方法付出的具体代价或资源开销（例如硬件、计算量、参数量、显存、延迟、吞吐、实时率 RTF 或特定指标回落）；若为纯理论、诊断或免训练评测工作，直接说明其闭式求解、统计检验或冻结推理方式即可，不必机械背诵“原文未披露训练、推理或部署成本”，但凡写出的真实开销数值必须在原文中有据可查且精度一致。

提交前核对段数（3–4 段，空行分隔，段首粗体引导词，无 `#` 标题）、字数（700–1400 个汉字与中文标点，目标 850–1150 个）、句数（10–26 句）以及每组比较的对象、设置、指标、数字精度、百分号与方向是否严格对应原文证据。
~~~
