# 核心摘要修复提示词

## 用途

根据校验反馈修复 `## 核心摘要`。只修改这一节，其他 12 个一级章节保持不变。

## 提示词内容

~~~
请根据文末 `<paper_input>` 中的论文证据和校验反馈修复核心摘要。只输出 `## 核心摘要` 及其正文，不加前言、代码块围栏或其他标题，不要修改评分、标签、作者、方法、实验等其他章节，也不复制整张表格。

### 写作与自洽规则（仅用于执行，不写入正文）
- 面向音频研究读者，用平实自然的中文讲清对象、处理过程与证据；首次出现的术语说明作用，音频与声学指标保留标准缩写并首次括号解释（WER/CER/EER/LSD/MCD/FAD/RTF ↓，PESQ/STOI/UTMOS/DNSMOS/ViSQOL/SI-SDR/CLAP/MOS ↑），硬件保留 GPU/CPU/TPU/MACs 原名；`logit` 译为“对数几率”（非“对数值”），`critic` 按任务称“价值评估模型”或“辅助分数模型”（不译“评论家”）。
- 声称“最优/最低/最高”前逐格核对同表同列全部可比行及指标方向（`↑/↓`）；摘要量纲（小数 vs 百分制）、术语译名与开源状态须与原文和后续章节一致，深读导览指向下方真实存在的模块主题。
- 中文与英文或阿拉伯数字之间留一个半角空格（如“185 个样本”“35B-A3B”“84.0%”），数学专名与自然序数保留纯正汉字（一阶、二维、第一步、每一帧），混合专家总参/激活参简写（如 35B-A3B）按原文定义准确展开。

### 篇幅与段落结构

摘要正文写 10–26 句，汉字与中文标点合计 700–1400 个（起草目标 850–1150 个），分成 3–4 个自然段，段间留一个空行，段内写成连贯散文不拆行或列点。严禁使用 `#`/`##`/`###` 标题、独立编号标题行（如 `1. **...**`）或水平分隔线；顶格以段首粗体引导词组织 4 段式（或紧凑 3 段式）自然段（段首不加列表符号或编号）：

1. `**问题与瓶颈：**` 交代任务输入输出信号规格，直指现有主流路线在物理、统计或架构上的根本失效因果（如频谱混叠、长序列注意力开销、音色与内容耦合），不用空泛“难以兼顾”。
2. `**核心思路与方法架构：**` 一句话点破核心设计直觉，沿具体输入样本的表征流讲清关键模块分工、码率/帧率/维度/规模、冻结与更新边界、离线或流式约束及如何直击根因。方法机制单句不超过 520 字，跨句自然衔接，不写成“先…输出…送入…”流水账。
3. `**关键实验与核心代价：**` 给出主基准对最强可比基线的核心定量对比（见下节规则），同时交代主导收益的关键消融与最显著代价。
4. `**适用边界与深读导览：**` 点明结论成立前提与未覆盖失效/部署场景，并用一句话指引深读下方长文对应章节。须凝练独立撰写，严禁整段复制长文 80 字及以上文字。

修复缺项时优先替换已有不完整或重复说明，不把补充内容机械附在末尾；保护已正确的事实、条件、指标、数字、单位、方向、边界与代价；反馈要求逐字保留的句子原样保留。

### 定量结果

原文提供关键定量结果时，须给出主基准对最强可比基线的核心定量对比，允许同段跨 1–3 句自然展开评测设置或数据集、比较对象、原文指标名、双方具体数值及高低或变化方向，不用“分/更高/多项指标”代指标。数据集或资源论文无方法基线时，可用同一量表上的两个条件或维度。写清双方名称、数值与方向（“高于/低于/超过”或“从 A 变为 B”），不跨量纲或跨指标比较；“最高/最优/最低/达到”不能独立说明与谁比较。

两个数值及各自单位、正负号和小数精度必须逐字来自同一原表中明确可比的记录，或来自同一段连续原文证据。比较不同方法时，数值可以位于不同方法行，但必须沿完整表头定位同一指标列，并逐项核对评测设置、行名、单位和聚合方式。比较不同条件时，只采用原表明确设置的条件对照，且除被比较因素外其余评测条件一致；原表转置时，按真实行列角色核对同一指标，不能把不同指标当成两种方法。禁止把不同数据集、评测协议、指标或不连续证据片段拼成同条件比较。PDF 表格被拆成多行时，先恢复可核对的表头、对象与数值对应关系；无法唯一对应就换用另一组完整证据，不猜测单元格归属。

不要把 `0.85` 写成 `85.00` 或 `85%`。也不要增删末尾的零、舍入、把百分数与小数互换、换算单位或自己算差值。摘要引言概括值不与表格基线值混拼；单处证据缺完整数值或单位时换另一组可逐字核对的原文比较，不补算缺失结果。模型名、版本号、年份、参数量、样本量和训练超参数不能充当实验效果；速度或压缩结果须写清原文测量口径。原文确实没有可核对定量结果时，原样写“原文未提供可核对的关键定量结果”。

### 核心代价、适用边界与深读导览

如实交代关键消融与具体代价或资源开销（硬件、计算量、参数量、显存、延迟、吞吐、RTF 或指标回落）；纯理论、诊断或免训练评测工作直接说明闭式求解、统计检验或冻结推理方式即可，不必机械背诵“原文未披露训练、推理或部署成本”，凡写出的真实开销数值须在原文有据可查且精度一致。适用边界须写明具体成立条件与退化/未验证场景，不笼统写“仍有局限”，并自然引导读者查阅下方长文对应推导、架构或消融章节。
