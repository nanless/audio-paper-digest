# 按论文类型复核评分的提示词

## 用途

先完成正文审校、表格核对和方法补充，再以盲审方式复核评分。只返回结构化评分，不改正文，也不处理插图。

## 提示词内容

~~~~
请以独立盲审方式复核文末 `<paper_input>` 中论文的文档类型、证据画像、八个维度的分数和理由。代码已移除初稿中的旧总分、旧分档、旧置信度、旧八维数值、旧论文评价和旧评分理由；请完全依据正文事实与编号证据账本重新评定，按不同类型适用的证据评价，不因论文类型保底或跨维度重复扣分。

### 一、先定文档类型与证据画像，再打分

1. 先从 `方法研究`、`系统技术报告`、`模型报告`、`数据集与基准`、`综述`、`理论研究`、`应用研究` 中选择一个主要类型。
2. 打分前先在 `evidenceProfile` 中如实列出：
   - `primaryStrengths`（1–3 条，每条不少于 12 字并引用 `[证据编号]`）：最扎实、有原文支撑的核心强项。
   - `primaryDefects`（0–3 条，每条不少于 12 字并引用 `[证据编号]`）：最关键的方法漏洞、主张与验证脱节、基线/消融缺口、表文算术矛盾或复现缺口；确无实质短板可填 `[]`，不凑数编造。

### 二、盲权统一 10 分制五档锚定与音频标尺卡（`type-aware`）

八个维度分别是 `innovation`（创新性）、`technicalRigor`（技术严谨性）、`experimentalSufficiency`（实验充分性）、`clarity`（清晰度）、`impact`（影响力）、`openSource`（开源）、`reproducibility`（可复现性）、`engineering`（工程/实践价值），全部采用 **0.0–10.0 统一量表**（保留一位小数）。

代码会在 `type-aware` 规则下按你判定的文档类型自动计算加权总分与分档（`≥ 8.5` 前10%、`≥ 7.5` 前25%、`≥ 6.0` 前50%、`< 6.0` 后50%），本提示刻意隐藏各类型百分比权重与开源加分系数：请独立客观在 **0.0–10.0 统一量表** 上评定每项维度，严禁猜测权重或凑总分。七项核心维度须充分拉开区分度，禁止扎堆 `6.8–8.0`；按以下五档音频校准标尺对齐尺度（严重推导/逻辑硬伤或维度不适用则落在 `0.0–3.9`，如纯理论研究无工程落地时 `engineering` 可给 `0.0`）：

- **标尺 `5.2`（`4.0–5.9`，存在明显短板 / 后50%）**：常规商用硬件或现成开源声学模块拼装用于单一窄场景，宣称“低功耗/实时”却零功耗与延迟实测、缺少强基线或组件消融，或表文存在算术/口径自相矛盾；核心维度典型 `4.5–5.8`。
- **标尺 `6.5`（`6.0–7.4`，扎实良好 / 稳健渐进，前50%）**：在已有语音识别、增强或音乐分析框架上引入合理损失项或特征前端微调，在 1–2 个标准公开集上小幅可核对提升，但原创幅度有限、基线偏旧或缺少跨噪声/跨语种/跨设备泛化验证；核心维度典型 `6.0–7.0`。
- **标尺 `7.5`（`7.5–8.9` 下段，明显优秀 / 细分扎实推进，前25% 门槛）**：针对流式神经音频编解码器、零样本语音合成、声源分离或声学表征中的明确瓶颈提出清晰可验证的机制或训练方案，具备公平强基线、直接组件消融及规范主观听测或真实部署延迟实测，单一细分赛道优势明确但跨任务外溢有限；核心维度典型 `7.2–8.0`。
- **标尺 `8.5`（`7.5–8.9` 上段，强旗舰 / 顶级水准，前10% 门槛）**：在全模态音视频基础模型、原生语音交互、大规模高质量音频基准或高压缩低延迟编解码上实现显著能力或跨规模效率跃升（如小模型在多项公开权威基准超越数倍参数开源前沿），防泄漏、统计检验、消融、硬件吞吐/延迟实测与核心产物开放度俱佳；核心维度典型 `8.0–9.0`。
- **标尺 `9.2`（`9.0–10.0`，里程碑 / 范式级突破，同期前 5%）**：开辟语音、音乐或通用音频建模/生成/评测新范式的基础模型、核心算法或决定性基准，在严格公平的广泛公开评测中压倒性领先，理论/系统与消融无短板，兼备端到端实测部署效率与完整开源复现生态；核心维度典型 `8.8–9.6`。

### 三、各维度反通胀红线与音频专项红线

1. **`clarity`（清晰度）**：普通结构完整、文通字顺仅给 **`6.5–7.2`**（勿随手给 `7.8–8.2`）；出现**表文数字矛盾、表内算术错误、摘要与结论口径冲突、关键符号或单位混乱**时**不得超过 `5.8`**；仅符号严谨、图表教学价值高且全文零矛盾者给 `8.0–9.0`。
2. **`technicalRigor`（技术严谨性）**：“常规公式（STFT/Mel/标准微调）没算错”不等于 `7.8`！常规模块拼装且**核心方法与立论脱节**（标榜低功耗却无功耗建模测量、用替代物种音频声称检测另一物种、综述缺系统检索去重协议或表内算术冲突）给 **`4.5–5.8`**；标准自洽设计给 `6.5–7.4`；非平凡理论证明、严密统计检验与防泄漏/因果控制才给 `7.8–9.2`。
3. **`innovation`（创新性）**：现成模块/商用硬件拼装或纯目录综述给 **`4.5–5.8`**；稳健渐进改进给 `6.0–7.2`；通过系统级架构/多阶段训练/交互范式整合取得显著跨规模能力或效率跃升（如 9B 超越 30B 级前沿、17×–30× 实时突破）给 **`7.5–8.5`**；开辟新范式或核心数学/架构突破给 `8.5–9.5`。
4. **`impact`（影响力）**：面向语音、音乐与音频研究者。音频仅作附带模态或核心贡献属他领域时**不超过 `4.0`**；**窄地域/单语种资源盘点、小众硬件原型且缺乏跨场景泛化或复用产物**给 **`4.0–5.5`**；细分方向扎实方法给 `6.5–7.5`；全模态音视频基础模型在原生音频理解、语音交互或音视频联合基准刷新开源 SOTA 或逼近专有前沿（且开放权重/评测）属音频核心推进，正常给 **`8.2–9.2`**，不因含视觉压低。
5. **音频领域四项专项红线（逐条核查）**：
   - **主观听测协议红线（MOS/CMOS/SMOS/ABX）**：严禁跨不同听测人群或不同论文横向对比绝对 `MOS`；主张主观音质/自然度/相似度领先时须核查**听测人数、样本量、置信区间/方差与盲测协议**，缺失关键协议或跨论文照搬旧 MOS 时扣 `experimentalSufficiency` 并记入 `primaryDefects`。
   - **客观代理指标与人类感知区分红线**：严格区分自动代理（`UTMOS`、`DNSMOS`、`PESQ`、易受小样本偏差影响的 `FAD`、易受转写失真影响的 `Whisper-as-a-Judge`）与真人主观听测；仅凭窄范围代理指标宣称人类感知更优而无真人盲测支撑时，在 `primaryDefects` 标出并扣 `experimentalSufficiency`。
   - **实时/流式/因果声明实测红线**：宣称“实时”“流式”“低延迟”或因果架构却未给实测 `RTF`、算法前瞻（lookahead）、帧/块延迟及测试硬件规格时，一律设 `deploymentMeasured=false`、`engineeringEvidence="claim_only"`（触发 `engineering ≤ 5.5`）并记入 `primaryDefects`。
   - **开源产物自动探测核验红线（`[A_ARTIFACT_PROBE]`）**：若账本 `[A_ARTIFACT_PROBE]` 显示 HTTP 200 仓库实为无代码/无权重占位框架，或权重受控访问（gated）且无公开许可证，该事实**仅反映于 `openSource`**，严禁跨维度扣减其余七项。

### 四、单次扣分、开源与可复现标准

每条理由须引用至少一个 `[证据编号]`（如 `[A_METHOD]`、`[A_RESULTS]`、`[A_ARTIFACT_PROBE]`、`[SCORING_SOURCE_3/20]`），原文证据优先于转述，不美化或反转事实；“无法验证”不等于“技术错误”，信息不足时降 `confidence`。同一缺陷只归一个主要维度，严禁跨维度重复扣分：
- 缺代码/权重/数据集或占位仓库/受控权重 → 仅归 `openSource`；
- 缺超参/训练配置/硬件/数据配比/复现步骤 → 仅归 `reproducibility`；
- 缺基线/消融/统计检验/听测协议/压力测试/公平控制 → 仅归 `experimentalSufficiency`；
- 结构、表达、符号、表文矛盾或图表可读性问题 → 仅归 `clarity`；
- 推导错误、立论脱节、不合理假设、检索去重缺陷或逻辑漏洞 → 仅归 `technicalRigor`。
闭源与无法复现绝不得用于扣减其他六维；`openSource` 不扣复现步骤，`reproducibility` 不重复扣闭源。

`openSource` 仅允许六个离散锚点：`10.0`（核心产物完整公开且官方文档完整）、`8.0`（核心产物完整但文档不全）、`6.0`（部分核心产物公开）、`3.0`（原文明确承诺未来公开但未发布）、`1.5`（仅可访问在线演示，不能给 `3.0`）、`0.0`（闭源无承诺）。模型/系统/方法/应用看代码与权重；`数据集与基准` 看数据集及评测代码；`理论研究` 仅公开证明无代码/数据仓库最高 `3.0`。

`reproducibility` 仅看论文披露充分度（架构、训练数据与预处理、超参、硬件时长、评测与解码设置）：详尽可复现 `8.5–10.0`、大部充分 `6.5–8.4`、关键配置缺失较多 `3.5–6.4`、几乎未披露 `0.0–3.4`；仅有链接不自动抬高本项。

### 五、证据画像与代码硬上限

在 `evidenceProfile` 中如实填写：
- `ablationStatus`：`direct`（直接消融）、`partial`（部分消融，含模型/系统报告配对对照但缺后训练分阶段消融）、`none`（无受控对照）、`not_applicable`（仅 `multiComponentClaimed=false` 时必选；为 `true` 时禁用）。
- `targetEvaluation`：`public`、`internal`、`mixed`、`not_applicable`（仅理论研究或综述可用）。
- `engineeringEvidence`：
  - `measured_deployment`：含真实端到端延迟/吞吐/帧率/RTF/显存/功耗实测（仅此时 `deploymentMeasured=true`）；
  - `reusable_pipeline`：提供可核对的完整算法/训练/评测软件管线或公开脚手架（商用硬件 BOM、架构框图、离线固定网格模拟或仪表盘截图若无实测与公开软件实现，一律填 `claim_only`）；
  - `public_artifact_or_benchmark`：已公开可用工具、模型或基准；
  - `claim_only`：仅口头声称工程价值、缺实测 RTF/延迟与硬件的实时声明、商用 BOM 或仅离线模拟；
  - `not_applicable`：不适用。
- `evidenceBoundary`：至少 20 个字，且至少直接引用一个包含在 `evidenceIds`（1–12 个不重复 ID）中的 `[证据编号]`。

代码硬上限（超限自动裁剪或拒绝）：
- `multiComponentClaimed=true` 且 `ablationStatus=none`：一般类型 `experimentalSufficiency ≤ 6.5`；模型/系统报告公开或混合评测且含公开泛化时 `≤ 7.5`；
- `multiComponentClaimed=true` 且 `ablationStatus=partial`：一般类型 `≤ 7.8`；模型/系统报告公开或混合评测且含公开泛化时 `≤ 8.5`；
- 仅内部评测且未报样本规模：`experimentalSufficiency ≤ 6.0`；
- `engineeringEvidence=claim_only`，或系统/应用类 `deploymentMeasured=false && targetEvaluation=internal`：`engineering ≤ 5.5`；
- 总分硬红线（超限直接拒绝）：`confidence` 非“高”时总分不得超过 `8.4`；`multiComponentClaimed=true` 且 `ablationStatus=none` 且 `targetEvaluation=internal` 时总分不得超过 `7.2`。

校验反馈指出具体错误时，针对该错误修正，不重复上次无效理由。
