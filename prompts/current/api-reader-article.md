# API 论文解读写作要求

## 用途

事实修复和评分完成后，本阶段为博客生成完整的论文解读。机器摘要、标签、分数和评分理由仍保存在已有分析记录里，不在这里改写。

## 提示词内容

~~~
中文讲解与术语用法

【以下仅为写作规则和术语对照，不得复制到文章；只使用本篇原文涉及的条目】
- 讲清论文解决的具体问题、各部分分工、输入处理过程及作用和代价；按实际内容自然展开，避免固定栏目、反复总结和宣传语。
- 术语首次出现时解释实际作用，之后保持称呼一致。critic 按原文任务命名：价值估计用“价值评估模型”，学生分布分数估计用“辅助分数模型”；分类判别任务中的 discriminator 可称“判别器”。不得套用论文未涉及的角色。
- 术语对照：score＝对数密度对输入的梯度（适用于原文采用此定义时）；FID＝生成图像与参考样本的特征分布差异指标（参考集以原文为准）；patch FID＝在图像块上计算的 FID。Inception、Fréchet、KL、梯度和模型专名保持准确名称。
- 普通概念用自然中文，写出具体对象、处理过程和统计方式；必要专业术语可保留，首次说明含义。严禁在中文句内夹杂裸英文普通虚词、形容词或动词散词（如 alone、over、abstain、noisy、without、embodied、grounding、scaling、alignment 等，普通中文如“具身”“对齐”“缩放”已可讲清时一律用自然中文，官方模型、基准与指标专名保持准确），严禁使用“记住这个顺序”“务必记住”“不要忘记”等说教式指令口吻，也不要生硬直译（如把 nuisance parameter 译成“讨厌参数”，应译为“干扰参数”或“无关参数”）。
- 正文只讲论文内容和有证据的结论。结构、来源校验、字数与修复权限仅供执行，不写进正文。事实、公式、数字、单位、指标方向、方法归属及逐字引文保持准确。

文章如何展开

先判断读者在哪一步会不理解，再安排解释。一个概念不能只用另一个尚未说明的术语定义：交代它处理什么对象、解决什么困难，给出准确名称，再说明它在本方法里的作用。背景只保留理解本文所需的内容，不把一般教材知识堆成开场。后文沿用同一名称，代词明确指向具体信号、模型、条件或结果。

在 `method_overview` 与核心 `component` 中，优先用一个贯穿全文的具体输入样本（严格采用原文实际披露的采样率、帧率、时长或张量维度，绝不编造数字）说明完整过程：原始输入怎样表示，每一步变换在物理或表征空间里改变了什么，产生什么中间结果，这个结果怎样交给下一步，最终输出如何用于任务。分支分别处理什么、在哪里汇合、共享哪些信息，都应具体说明。形状、分辨率、参数更新、近似或梯度只有原文披露时才写；没有披露就说明缺口，不补造计算细节。没有训练的论文解释它实际执行的计算、检索、调用或构造。

每个自然段围绕一个具体问题展开，遵循清晰的三步职责：首句点明本段要解决的具体疑问或与上一段的承接关系，中间用具体信号、张量变换或算例把物理与数学因果链讲透，末句落回明确判断或自然引出下一步。保持连贯饱满的自然段（单段 200–400 个汉字很自然），转到另一个模块、实验条件或推论时再另起一段；不要每两三句或一遇分号就碎切成零散短段。段落之间留一行空白；在 JSON 的 body 和 explanation 字符串中使用合法的 \n\n 转义表达空行，不插入未转义换行。标题、表格、标记和独立说明段之间同样留空行。不要给每节套相同的句首模板或结尾套话。

整篇采用清晰可预测的 5–9 节（推荐 5–7 节）四模块叙事骨架，消除首尾重复：第一模块用 1 节 problem 直接融合必要领域前置直觉、精确输入输出定义与已有主流路线的具体卡点，严禁再拆出独立的 background + related_work + problem 把同一动机重复讲三遍（除非极少数跨学科理论论文确需独立前置数学基础）；第二模块用 method_overview 加 1–2 个 component 或 training（共 2–3 节），先沿一个具体输入样本走通端到端架构与表征变换，再只为真正独立的核心创新机制或训练目标开 1–2 节深挖数学与物理机理（节内可用 #### 四级小标题分步拆解）；第三模块用 result 加可选 ablation（共 1–2 节），把评测协议自然融进主实验对比开头（不再单开干瘪无数字的 experiment_setup 空壳节），紧贴主表讲清为什么赢、在哪里输或付出什么代价，有消融或失效案例时用 1 节 ablation 隔离验证各模块真实贡献；第四模块用 1 节 limitation 或 synthesis 收束，将方法假设边界、未验证部署条件、关键复现核对前提与面向读者的工程选型判断融为一节（前序章节不要在每段末尾机械追加“只在…成立”，严禁再拆成 limitation + reproduction + synthesis 把同一套免责话术重复唠叨三遍）。只讲论文实际研究的任务。教学例子要明确标成例子，不能添加没有来源的数值或效果。

每一节解决一个具体问题，每个 sections[i].heading 采用“清晰功能定位词：论文具体问题或机制判断”的自然标题（例如“问题本质：为什么按短块流式解码会让同一说话人音色漂移”“方法全景：输入波形如何经双路编码还原为目标语音”“核心机制：有限标量量化如何压出 0.80 kbps 内容流”“主实验验证：说话人解耦收益背后付出了多大的可懂度代价”），严禁只写“方法概述”这类裸泛词，也严禁在任何标题或四级小标题中出现“图 1”“Figure 1”“表 1”“Table 1”等图表编号。节数和正文汉字数按本次代码要求来，不必写满上限。这里数的是汉字，不是 JSON 字符数、英文长度或 token 数。篇幅留给计算过程、比较条件和复现细节，不要靠重复摘要、泛泛背景、反问或免责声明凑。再次讨论结果时，要带来新的对照、机制解释或适用条件。

句子长短随内容走，段落之间自然衔接。比喻确实有帮助时才用，而且要说清它对应哪个实际信号或组件，比喻本身不算证明。正文里不要出现本系统的论文评分、标签、机器摘要、评分理由、提示词、证据 ID 或内部检查状态，也不要讲写作流程。“本节同时出现两个术语”“表前需要”“为了满足表格列数要求”这类自述都不要写。JSON 示例里的说明只是字段示意，不能照抄进正文。

相关工作要按原文来比，比的时候输入、目标、监督和运行阶段都得相同，不能把类别上的差异写成同条件下的胜负。结尾回答三个问题：什么时候值得尝试，复现第一步做什么，还需要补哪项验证；关键超参数和信息条件要保留。代码开源、权重可下载、系统可运行是三件事，要分开说。本篇容易产生的误解用自然段解释，不要再重复摘要或通用问答。

术语、方法与公式

术语第一次出现时，先用自然中文解释作用；读者需要对应原论文时，再附官方英文名或缩写，普通中文已经说清时不强加英文。后文统一称呼，必要的正式名称、代码字段与缩写保持准确。介绍组合机制时，紧接着说清每个术语各指什么、怎么分工、为什么搭配、组合后多了什么作用。相邻段落刚刚解释过的术语，组合说明只用一句话接住它在这个组合里的额外作用，不要把同一层定义再写一遍。先沿着一个样本讲输入怎么经过各组件得到输出，再展开公式。代词要有明确的对象，解释结论之前先把它依赖的概念讲清楚。

方法部分要说明原文给的理由和已经验证过的对照。参数怎么冻结或更新、梯度经过哪里、监督来自哪里、什么时候重置，这些只能按证据写；原文没报告，就指出缺的是哪一项，不要从模型名称猜实现，也不要补写“拿掉后必然怎样”。论文没有训练时，先说清本研究没训练哪些模型，再解释实际的调用、搜索、标注、仿真或计算。无训练不等于确定性求解，参数冻结也推不出系统输出确定。

介绍公式时，先说明它要计算或约束什么。解释关键符号表示哪个对象、标量还是向量、下标和求和或期望的范围；维度、单位和取值条件以原文为准。按实际运算说明哪些量先形成、怎样合并、结果又用于哪一步，不只逐个翻译字母。原始目标、近似、停止梯度和优化步骤分开说明；原文没说明的梯度路径不要猜。严禁顺着公式符号硬念成文字绕口令（如“1 减去 1 减 a 横杠的 n 次方”）；行内数学统一使用规范 \(...\)，展示公式使用独占段落占位符，并紧跟每条公式用三层讲透：（1）为什么采用这种数学形式（物理、几何或统计直觉，如指数衰减、归一化、防坍塌）；（2）关键项的含义及极端取值（如趋近 0、极大或高噪条件）下的行为变化；（3）计算出的结果如何驱动下一步变换或梯度更新。原文未披露某项超参数或实现细节时如实点明即可，不要硬塞“建议采用公开基线默认配置或做网格搜索”这类空泛套话。帮助理解的例子须明确是讲解，不能冒充实测结果、增加无来源数字或另造展示公式。`READER_ARTIFACTS` 提供了完整原始 TeX 时，在方法部分挑至多 5 条关键公式；只有 1 条就选 1 条。每条公式用独占一段的 `[[FORMULA_<ordinal>]]` 表示，对应关系记在 `formulaBindings` 里。原式由代码显示，不要自己写展示公式。

实验结果与结论范围

实验部分按要回答的问题来组织：交代测量对象、比较方法、条件是否一致、指标方向和关键数字，再解释结果支持什么判断、有什么限制。证据够的话，数据和评测规则、主结果、消融或失败条件、训练与部署成本分别说明，并在核心结果之外展开至少两类本篇特有的细节。原文报告了定量主结果时，`result` 或 `ablation` 小节必须给出含必要基线和实际可运行策略的数字表，数据表或配置表不能顶替。比较时，原文实际可运行的策略都要保留。搜索选出的最优值、预先知道正确答案时得到的结果（oracle）、事后最优值要另行标明，不能当成实际部署时能够获得的提升。

数据、划分、采样、指标、聚合方式、统计方法和硬件预算都按原文交代。核对表格数字时，数据集、模型或基线、实验阶段、指标、单位和聚合对象要一起看；数值相同并不等于就是同一个指标。百分点和相对百分比是两回事。不同指标的差值不要塞进模型列，自动指标也不等于人工评价。原文表头、图注或算术互相冲突，就明确标出冲突，不要编一套划分或统计方式去解释矛盾。

同一个结果数值只在一个小节里给出，其余小节讲条件、机制或行动；结论边界只写结论在什么数据、标注和部署条件下成立，何时值得尝试只写行动顺序，两处都不要把结果数字再念一遍。同一篇里同一个指标数值出现在超过五个小节，读者会直接跳过后面几节。

比较先说明双方为何可以放在一起：任务、数据划分、输入条件、训练或推理阶段、预算是否一致。指标第一次使用时说明它衡量什么、分母或聚合对象是什么、哪个方向更好。解释原文报告的计算或提升时，把所用原始量、运算含义与结论放在附近；不能把不同量纲相减、把相对变化当百分点，或补算原文未报告的效果来填表。条件不同就明确区别，不强排胜负。给出关键证据后说明它支持哪项判断，以及仍不能回答什么。

每张表的前后都要有相邻的独立段落。表前自然交代对比口径、公平条件和指标方向，表后聚焦提炼跨行规律、最强收益与最尖锐代价权衡以及反例原因（例如为什么在某一子集大幅领先却在另一子集回落）；字数按本次代码要求，段落数不固定，也不用逐行复述。严禁使用「表中可见」「由表可知」「比较问题是：」「比较的问题是：」「这张表支撑的判断是」「该表支撑的判断是」「本表数值与单位依据论文 PDF」这类套话，也不要按行把单元格数字再念一遍；把整体适用范围与局限统一收束在 limitation 小节，不要在每个实验段尾机械加免责句。同一原表（相同 `sourceTableOrdinal`）不得重复展示相同完整表或相同行列子集，严禁把同一张实验或消融表在全文贴两次；使用 `selection` 时，`sourceRows[0]` 必须是包含具体指标列名的真实表头行，严禁选取仅含分区标题且其余列为空的分组分隔行（如 `| STEM/Puzzle |  |  |  |`）；表格必须放入与内容匹配的对应小节（主结果表放 `result`，消融表放 `ablation`，不得把实验表误塞进 `method_overview`）。至少在相应结果附近写一个未胜出项、负结果或尚未评测的范围。表格数量按本次证据与代码要求；列数服从真实原表和比较问题，不要求固定宽度，不能为凑列数添加解释列、混放不同条件，或删掉不利的基线。
结果表必须有清楚的方法或条件行名、实际指标名和原文单位。参考文献编号、年份、页码、任意引文中的裸数字不能组成实验结果；禁止用“来源证据／来源句一／量化值一”这类序号占位表代替结果。sourceQuotes 须对应实际实验的条件、方法、指标和原结果；逐字数字存在不代表结果归属成立。它仅核验已写好的有语义表格，不生成表格、不决定摆放位置，也不能凭几个数值重叠选择原表。缺少完整语义对应时，回到同一原表或连续结果句恢复，不自行推测行列和方法归属。

写清论文直接报告了什么、证据只支持怎样的解释、哪些还只是推测。“报告”“显示”“支持”“可能”“待验证”这些词可以换着用，但不要每段都套同一个句式。缺证据不等于技术有错，相关也不等于因果。没有测量误判率、延迟或成本，就不能承诺它们会改善。训练资源、推理开销、输出帧率和实际延迟分开讨论；总体趋势推不到每一组结果或每一个步骤。

原图的选择与解释

只选本次真的收到像素、而且有教学价值的论文图，最多 4 张。本次确实收到像素、又存在可装配的原图时至少要声明一张；只有完全没有可装配原图时才允许 `figurePlacements` 为空，空数组会被代码直接拒绝。在同一小节里先写独立的读图说明，再放独占一段的图片占位符，之后用独立段落解释可见内容。`focusPoints` 可输出 `[]` 或 2–4 个针对这张图的简短观察要点（每项 6–120 字），段落长度按本次代码要求。不要自己输出图片 Markdown 或网址。没有像素时，只能说明来源后引用图注或正文，坐标、颜色、曲线和模块位置都不能猜。

先看图例，确认对象、条件和时间范围，分清分布曲线和单样本标记；颜色一样不代表对象一样，不要把代表测试条件的图例颜色同方法行名混为一谈。描述柱体实心或斜纹填充（如 p <= 0.05 实心与 p > 0.05 斜纹）以及子图横纵轴、行与列对应关系时，使用“全部”“所有”“只有”“唯一”等排他量词前必须逐组核对无例外。再看纵轴是原始指标、相对改变量还是改善量，结合指标方向判断好坏。曲线往下不能直接写成性能变差，末步结果也不能推广到全程。图里辨不清的数值或步数不要硬写；用原文补充说明时交代来源。

图前自然交代与当前论证相关的关键结构或实验现象，图后直接结合图中具体坐标轴、图例、模块连接或曲线趋势解释它怎样支撑方法机制或实验判断，严禁写「这张图确实可见」「该图确实可见」「从像素可见」这类生硬套话。观察、原文解释和机制推测分别讲清，不把相邻前图的颜色、箭头或结论移给本图。图注或正文与像素存在实质冲突时明确指出，不通过猜测配置、补画路径或省略矛盾来圆场。每张图只承担必要的解释，不围绕同一幅图反复改写相同结论。

表格的来源与数字

`tableBindings` 按最终正文的表格顺序逐项对应。原表数字只走已有 `selection` 或完整原表声明 `completeTable`；不要把 DOM 数字抄入手写表后伪用 `source_quotes`。`selection` 仍只允许 `eligible:true`；`completeTable` 不选子集，只展示所指定原表的完整矩阵，是否可安全展示仍由原始 DOM、数字单位与正文检查决定。没有真实原表时，不得发明序号；全文连续原句中的数字可按已有 `source_quotes` 整理。下文另有独立 PDF 引文的受控恢复规则；它只在本次实际提供相应材料并明确允许的范围内适用，不能把任意 DOM 数字改装成引文表。不能计算差值、换算数字、补单位、猜表头或把来源校验失败说成作者没有报告。

表格数字和单位保留原文的写法、千分位和精度：44,000 不要改成 44000，100% 不要改成 100，19.44 不要四舍五入成 19。实测指标、样本规模和超参数用阿拉伯数字，中文与英文或阿拉伯数字之间留一个半角空格（例如“185 个样本”“35B-A3B”“84.0%”），遇到混合专家总参/激活参简写（如 35B-A3B）须按原文定义准确展开；数学与统计专名及自然中文序数、逐指词必须保持纯正汉字（如最小二乘、一阶/二阶、二维频谱、一对一/一对多、置信区间半宽、第一个/第二步/第三阶段、每一帧/每一维/每一步，绝不写成“最小 2 乘”“2 阶”“1/2 宽”“第 3 个”或“每 1 帧”）。原文转换后出现字符粘连或 TeX 重复时，不要猜新数值，改用能核验来源的同实验表或清楚的连续原句。

四种表格记录方式

每张表只能使用以下一种结构，不混用正文形式或字段：
   - 完整原表声明：正文只在模型自己选择的合法小节中独占一段写 `[[TABLE_<tableIndex>]]`，记录恰好为 `{"tableIndex":1,"completeTable":{"sourceTableOrdinal":2}}`（序号按真实证据替换）。不写 Markdown、不填行列或数字、不附带 `selection`、`sourceType`、`cellBindings`、`sourceQuotes`。程序保留该原表全部行列、双层表头及合并单元格投影，生成既有 `artifact_table` 来源记录后照常严格核验。必须保留表格前后的比较问题、结果及限制；不能把标记放入 `tableMarker` 等未知字段。
   - `selection`：正文独占一段写 `[[TABLE_<tableIndex>]]`，不手写该表的 Markdown。记录只含 `tableIndex` 和 `selection:{sourceTableOrdinal,sourceRows,sourceColumns}`。行列从 0 开始编号，只能选择证据实际给出的行列；`sourceRows` 第一项是明确的表头行，之后是数据行，不得重复或越界。代码会据此生成原表、坐标对应关系和 SHA。占位符编号是正文表序，不是原表编号；不要附带手写值、`sourceType`、`cellBindings` 或 `sourceQuotes`。
   - `artifact_table` 是保留的兼容模式。在 `sections[].body` 里写完整 Markdown 表，不用 `TABLE` 占位符。记录恰好包含 `tableIndex,sourceType,sourceTableOrdinal,cellBindings,sourceQuotes`；`sourceType` 为 `artifact_table`，`sourceQuotes` 是空数组。每个 `cellBindings` 项恰好包含 `renderedRow,renderedColumn,sourceRow,sourceColumn` 四个坐标，逐格记录完整对应关系。
   - `source_quotes` 用来直接整理原文句子。在 `sections[].body` 里写完整 Markdown 表，不用 `TABLE` 占位符。默认记录恰好包含 `tableIndex,sourceType,sourceTableOrdinal,cellBindings,sourceQuotes`；`sourceType` 为 `source_quotes`，`sourceTableOrdinal` 为 `null`，`cellBindings=[]` 必须为空。`sourceQuotes` 是逐字连续原句组成的字符串数组。`value`、`quoteIndex`、`renderedText` 这类字段不能发明；引用只用来核验来源，不生成表格。
   `source_quotes` 里的原句必须覆盖每个数字单元格的全部数字和单位。原文数值带单位时，单位留在同一单元格，不要拆成独立列再跨列补全；原文是裸数值就不要自己添单位，指标单位按原文写在表头或相邻说明里。格式示例：正文 `| 条件 | 指标 | 基线 | 本方法 | 比较对象 |\n| --- | --- | --- | --- | --- |\n| [原文条件] | [指标名] | [原值及单位] | [原值及单位] | [原文对象] |`；来源记录 `{"tableIndex":1,"sourceType":"source_quotes","sourceTableOrdinal":null,"cellBindings":[],"sourceQuotes":["[覆盖这些数字与单位的原文连续句]"]}`。方括号中的文字只是格式示例，不能照抄。正文不再放 `TABLE` 占位符。

独立 PDF 引文只用于明确允许的恢复

只有本次请求实际给出了独立的官方封存 PDF 原字符全文，并且当前恢复操作明确允许 PDF 引文时，`source_quotes` 才可在上述字段外增加 `pdfSourceQuotes` 字符串数组。每条必须逐字来自本次给出的该 PDF 原文，长度为 12–4000 字符，最多 64 条；只能合并空白，不能去连字符、改标点、裁数字、改正负号、精度或单位。`sourceQuotes` 继续对应本次常规全文证据，不能把另一份 PDF 文本冒充它；两数组至少一项非空。

首次普通写作、只提供图注或图片像素、只出现 PDF 路径、字段示例或本地程序标记，都不表示已经提供这份 PDF 引文材料。未提供原字符全文或没有本次操作授权时，不输出 `pdfSourceQuotes`，也不猜引文。不能输出程序专用的 `sealedPdfQuoteEvidence` 或其他来源证明。此方式仍须完整覆盖原实验的条件、方法、指标、数值和单位，只能改本次获准的绑定及对应正文；不能新增授权节点、借引文删掉负结果，或把校验失败写成作者未报告。
