# API 论文解读写作要求

## 用途

事实修复和评分完成后，本阶段为博客生成完整的论文解读。机器摘要、标签、分数和评分理由仍保存在已有分析记录里，不在这里改写。

## 提示词内容

~~~

文章如何展开

先判断读者在哪一步会不理解，再安排解释。一个概念不能只用另一个尚未说明的术语定义：交代它处理什么对象、解决什么困难，给出准确名称，再说明它在本方法里的作用。背景只保留理解本文所需的内容，不把一般教材知识堆成开场。后文沿用同一名称，代词明确指向具体信号、模型、条件或结果。

在 `method_overview`、`component` 与 `training` 中，围绕“五环架构与完整流水线清单”讲透方法（所有数值与实现边界严格以原文披露为准，未披露即如实说明缺口，绝不编造）：
1. **输入输出信号与张量规格**：写清原始输入与最终输出的采样率、帧长/步长、码率、通道或特征维度以及任务目标。
2. **端到端分步数据流**：用一个贯穿全文的具体输入样本，按处理顺序（1 → 2 → 3 …）追踪它经过每个模块与分支时在物理或表征空间里的变化、张量形状/帧率传递以及多分支在哪里拆分与汇合。
3. **关键公式与机制直觉**：用 `[[FORMULA_<ordinal>]]` 锚定核心公式，紧跟公式自然讲清采用该数学形式的物理或统计动机、关键项含义及极端取值下的行为变化，以及输出如何驱动下一步变换或梯度更新（严禁在正文里复述“该式的三层含义”“可分三层理解”“三层读法”这类提示词口癖）。
4. **训练目标与参数冻结边界**：明确区分哪些模块冻结、哪些模块更新、多阶段训练顺序、各项损失函数及权重与梯度流向；没有训练的论文则明确说明未训练哪些模型，以及实际执行的检索、规则、闭式求解或调用步骤。
5. **推理与部署执行路径**：说明自回归或并行/分块流式方式、前瞻窗口/缓存状态、采样步数以及原文披露的延迟、实时率 RTF 或显存瓶颈。

每个自然段围绕一个具体问题展开，遵循清晰的三步职责：首句点明本段要解决的具体疑问或与上一段的承接关系，中间用具体信号、张量变换或算例把物理与数学因果链讲透，末句落回明确判断或自然引出下一步。保持节奏舒适的自然段（目标单段 120–320 个汉字，硬上限 420 个汉字），转到另一个模块、实验条件或推论时再另起一段；既不要把 400+ 字堆成密不透风的文字墙，也不要每两三句就碎切成零散短段。任一小节的散文正文若超过 950 个汉字，必须在节内用 2–3 个简洁的 `####` 四级小标题或结构化条目列表（至少 2 项）拆分层次，方便读者快速扫读定位。段落之间留一行空白；在 JSON 的 body 和 explanation 字符串中使用合法的 \n\n 转义表达空行，不插入未转义换行。标题、表格、标记和独立说明段之间同样留空行。不要给每节套相同的句首模板或结尾套话。

整篇采用清晰可预测的 5–9 节（推荐 5–7 节）四模块叙事骨架，消除首尾重复：第一模块用 1 节 problem 直接融合必要领域前置直觉、精确输入输出定义与已有主流路线的具体卡点，严禁再拆出独立的 background + related_work + problem 把同一动机重复讲三遍（除非极少数跨学科理论论文确需独立前置数学基础）；第二模块用 method_overview 加 1–2 个 component 或 training（共 2–3 节），按上方五环清单先沿一个具体输入样本走通端到端架构与表征变换，再只为真正独立的核心创新机制或训练目标开 1–2 节深挖数学与物理机理（散文超 950 字的小节须用 `####` 子标题或有序/无序列表分步拆解）；第三模块用 result 加可选 ablation（共 1–2 节），把评测协议与公平性核查自然融进主实验对比开头（不再单开干瘪无数字的 experiment_setup 空壳节），紧贴主表完成深度结果剖析，有消融或失效案例时用 1 节 ablation 隔离验证各模块真实贡献；第四模块用 1 节 limitation 或 synthesis 收束，将方法假设边界、未验证部署条件、关键复现核对前提与面向读者的工程选型判断融为一节（前序章节不要在每段末尾机械追加“只在…成立”，严禁再拆成 limitation + reproduction + synthesis 把同一套免责话术重复唠叨三遍）。只讲论文实际研究的任务。教学例子要明确标成例子，不能添加没有来源的数值或效果。

每一节解决一个具体问题，每个 `sections[i].heading` 必须直接承载这篇论文的具体机制、模块名、核心矛盾或实验结论（例如“单码本流式解码为何在低比特下丢掉音色一致性”“双路编码与有限标量量化：从 16 kHz 波形到 0.80 kbps 离散流”“跨语种评测下的可懂度收益与延迟代价”）。严禁只写“方法概述”这类裸泛词，严禁在全文中连续 3 节及以上套用“问题本质：”“方法全景：”“核心机制：”“主实验验证：”“适用边界：”“总结与选型：”等模板化前缀，也严禁在任何标题或四级小标题中出现“图 1”“Figure 1”“表 1”“Table 1”等图表编号。节数和正文汉字数按本次代码要求来，不必写满上限。这里数的是汉字，不是 JSON 字符数、英文长度或 token 数。篇幅留给计算过程、比较条件和复现细节，不要靠重复摘要、泛泛背景、反问或免责声明凑。再次讨论结果时，要带来新的对照、机制解释或适用条件。

句子长短随内容走，段落之间自然衔接。比喻确实有帮助时才用，而且要说清它对应哪个实际信号或组件，比喻本身不算证明。正文里不要出现本系统的论文评分、标签、机器摘要、评分理由、提示词、证据 ID 或内部检查状态，也不要讲写作流程。“本节同时出现两个术语”“表前需要”“为了满足表格列数要求”这类自述都不要写。JSON 示例里的说明只是字段示意，不能照抄进正文。

相关工作要按原文来比，比的时候输入、目标、监督和运行阶段都得相同，不能把类别上的差异写成同条件下的胜负。结尾回答三个问题：什么时候值得尝试，复现第一步做什么，还需要补哪项验证；关键超参数和信息条件要保留。代码开源、权重可下载、系统可运行是三件事，要分开说。本篇容易产生的误解用自然段解释，不要再重复摘要或通用问答。

术语、方法与公式

术语第一次出现时，先用自然中文解释作用；读者需要对应原论文时，再附官方英文名或缩写，普通中文已经说清时不强加英文。后文统一称呼，必要的正式名称、代码字段与缩写保持准确。介绍组合机制时，紧接着说清每个术语各指什么、怎么分工、为什么搭配、组合后多了什么作用。相邻段落刚刚解释过的术语，组合说明只用一句话接住它在这个组合里的额外作用，不要把同一层定义再写一遍。先沿着一个样本讲输入怎么经过各组件得到输出，再展开公式。代词要有明确的对象，解释结论之前先把它依赖的概念讲清楚。

方法部分要说明原文给的理由和已经验证过的对照。参数怎么冻结或更新、梯度经过哪里、监督来自哪里、什么时候重置，这些只能按证据写；原文没报告，就指出缺的是哪一项，不要从模型名称猜实现，也不要补写“拿掉后必然怎样”。论文没有训练时，先说清本研究没训练哪些模型，再解释实际的调用、搜索、标注、仿真或计算。无训练不等于确定性求解，参数冻结也推不出系统输出确定。

介绍公式时，先说明它要计算或约束什么。解释关键符号表示哪个对象、标量还是向量、下标和求和或期望的范围；维度、单位和取值条件以原文为准。按实际运算说明哪些量先形成、怎样合并、结果又用于哪一步，不只逐个翻译字母。原始目标、近似、停止梯度和优化步骤分开说明；原文没说明的梯度路径不要猜。严禁顺着公式符号硬念成文字绕口令（如“1 减去 1 减 a 横杠的 n 次方”）；行内数学统一使用规范 \(...\)，展示公式使用独占段落占位符，并在紧随其后的自然段中有机讲透三个实质问题：为什么采用这种数学形式（物理、几何或统计直觉，如指数衰减、归一化、防坍塌）、关键项含义及极端取值（如趋近 0、极大或高噪条件）下的行为变化、以及计算结果如何驱动下一步变换或梯度更新——**严禁直接套用“该式的三层含义是”“可分三层理解”“三层读法”等机械标签起句**。原文未披露某项超参数或实现细节时如实点明即可，不要硬塞“建议采用公开基线默认配置或做网格搜索”这类空泛套话。帮助理解的例子须明确是讲解，不能冒充实测结果、增加无来源数字或另造展示公式。`READER_ARTIFACTS` 提供了完整原始 TeX 时，在方法部分挑至多 5 条关键公式；只有 1 条就选 1 条。每条公式用独占一段的 `[[FORMULA_<ordinal>]]` 表示，对应关系记在 `formulaBindings` 里。原式由代码显示，不要自己写展示公式。

实验结果与结论范围

实验部分按“四步深度实验剖析”来组织，拒绝机械逐行念表：
1. **协议公平性与混杂因素核查**：交代测量对象、数据集与划分、指标方向，同时核查各对比方法是否在训练数据规模、参数量、输入码率/分辨率、因果流式 vs 离线条件上真正可比；存在不对等前提时必须明确点出，不能强排胜负。
2. **跨行主结果与权衡规律**：紧贴数字表提炼跨行趋势、最强收益与最尖锐的代价权衡（如某子集大幅领先但另一子集或延迟/显存明显回落），保留所有原文实际可运行的策略；搜索选出的最优值、oracle 或事后最优值另行标明，不当成真实部署收益。
3. **消融因果归因与关键缺口**：定量交代拆掉或替换每个组件引起的指标变化与交互效应；若论文对某项核心宣称缺少隔离消融，直接指明该缺口而非脑补效果。
4. **统计可靠性与失效案例诊断**：原文给出标准差、置信区间、显著性检验或人工评测样本/人数规模时一并核查，结合负结果、未胜出项或边界失效样本说明方法在什么条件下会退化。

原文报告了定量主结果时，`result` 小节必须给出含主要基线和实际可运行策略的主结果数字表，数据表、配置表或消融表均不能顶替主结果表。当 `READER_ARTIFACTS` 中存在合格（`eligible: true`）的主结果原表或消融原表时，**优先使用 `completeTable` 或 `selection` 完整呈现包含主要基线的原表**，不要舍弃可用原表去手写只摘录寥寥几行的 `source_quotes` 简表；**若主结果原表因原始 DOM 合并表头缺失等原因不可编译（`eligible: false`），必须用封存全文中的连续逐字原句（`source_quotes`）把主实验基线对比表完整整理进 `result` 小节，严禁拿消融原表冒充主结果表，也严禁把同一 `sourceTableOrdinal` 拆成高度重叠的两个子集重复展示**。当表内出现 `a | b` 多指标组合单元格或不同行混合 WER / CER 等量纲差异时，须在表前或表后明确交代斜线/竖线前后各对应哪项指标与量纲。证据够的话，在核心结果之外展开至少两类本篇特有的细节（如训练/推理成本对比、不同信噪比/码率工作点或附录关键补充实验）。

数据、划分、采样、指标、聚合方式、统计方法和硬件预算都按原文交代。核对表格数字时，数据集、模型或基线、实验阶段、指标、单位和聚合对象要一起看；数值相同并不等于就是同一个指标。百分点和相对百分比是两回事。不同指标的差值不要塞进模型列，自动指标也不等于人工评价。原文表头、图注或算术互相冲突，就明确标出冲突，不要编一套划分或统计方式去解释矛盾。

同一个结果数值只在一个小节里给出，其余小节讲条件、机制或行动；结论边界只写结论在什么数据、标注和部署条件下成立，何时值得尝试只写行动顺序，两处都不要把结果数字再念一遍。同一篇里同一个指标数值出现在超过五个小节，读者会直接跳过后面几节。

比较先说明双方为何可以放在一起：任务、数据划分、输入条件、训练或推理阶段、预算是否一致。指标第一次使用时说明它衡量什么、分母或聚合对象是什么、哪个方向更好。解释原文报告的计算或提升时，把所用原始量、运算含义与结论放在附近；不能把不同量纲相减、把相对变化当百分点，或补算原文未报告的效果来填表。条件不同就明确区别，不强排胜负。给出关键证据后说明它支持哪项判断，以及仍不能回答什么。

每张表的前后都要有相邻的独立段落。表前自然交代对比口径、公平条件、多值单元格含义和指标方向，表后聚焦提炼跨行规律、最强收益与最尖锐代价权衡以及反例原因（例如为什么在某一子集大幅领先却在另一子集回落，绝不能只挑胜出项而略过同表明显的落后项）；字数按本次代码要求，段落数不固定，也不用逐行复述。严禁使用「表中可见」「由表可知」「比较问题是：」「比较的问题是：」「这张表支撑的判断是」「该表支撑的判断是」「本表数值与单位依据论文 PDF」这类套话，也不要按行把单元格数字再念一遍；把整体适用范围与局限统一收束在 limitation 小节，不要在每个实验段尾机械加免责句。同一原表（相同 `sourceTableOrdinal`）不得重复展示相同完整表或数据格重合 >= 50% 的重叠子集，严禁把同一张实验或消融表在全文贴两次；使用 `selection` 时，`sourceRows[0]` 必须是包含具体指标列名的真实表头行，严禁选取仅含分区标题且其余列为空的分组分隔行（如 `| STEM/Puzzle |  |  |  |`）；表格必须放入与内容匹配的对应小节（主结果表放 `result`，消融表放 `ablation`，不得把消融表冒充主结果表放进 `result` 或把实验表误塞进 `method_overview`）。至少在相应结果附近写一个未胜出项、负结果或尚未评测的范围。表格数量按本次证据与代码要求；列数服从真实原表和比较问题，不要求固定宽度，不能为凑列数添加解释列、混放不同条件，或删掉不利的基线。

写清论文直接报告了什么、证据只支持怎样的解释、哪些还只是推测。“报告”“显示”“支持”“可能”“待验证”这些词可以换着用，但不要每段都套同一个句式。缺证据不等于技术有错，相关也不等于因果。没有测量误判率、延迟或成本，就不能承诺它们会改善。训练资源、推理开销、输出帧率和实际延迟分开讨论；总体趋势推不到每一组结果或每一个步骤。

先看图例，确认对象、条件和时间范围，分清分布曲线和单样本标记；颜色一样不代表对象一样，不要把代表测试条件的图例颜色同方法行名混为一谈。描述柱体实心或斜纹填充（如 p <= 0.05 实心与 p > 0.05 斜纹）以及子图横纵轴、行与列对应关系时，使用“全部”“所有”“只有”“唯一”等排他量词前必须逐组核对无例外。再看纵轴是原始指标、相对改变量还是改善量，结合指标方向判断好坏。曲线往下不能直接写成性能变差，末步结果也不能推广到全程。图里辨不清的数值或步数不要硬写；用原文补充说明时交代来源。

表格的来源与数字

`tableBindings` 按最终正文的表格顺序逐项对应。原表数字只走已有 `selection` 或完整原表声明 `completeTable`；不要把 DOM 数字抄入手写表后伪用 `source_quotes`。`selection` 仍只允许 `eligible:true`；`completeTable` 不选子集，只展示所指定原表的完整矩阵，是否可安全展示仍由原始 DOM、数字单位与正文检查决定。没有真实原表时，不得发明序号；全文连续原句中的数字可按已有 `source_quotes` 整理。下文另有独立 PDF 引文的受控恢复规则；它只在本次实际提供相应材料并明确允许的范围内适用，不能把任意 DOM 数字改装成引文表。不能计算差值、换算数字、补单位、猜表头或把来源校验失败说成作者没有报告。

   - `artifact_table` 是保留的兼容模式。在 `sections[].body` 里写完整 Markdown 表，不用 `TABLE` 占位符。记录恰好包含 `tableIndex,sourceType,sourceTableOrdinal,cellBindings,sourceQuotes`；`sourceType` 为 `artifact_table`，`sourceQuotes` 是空数组。每个 `cellBindings` 项恰好包含 `renderedRow,renderedColumn,sourceRow,sourceColumn` 四个坐标，逐格记录完整对应关系。

`figurePlacements` 最多 4 项；收到像素且存在可装配原图时不能为空。只能选请求末尾“模型本次真正收到像素”的论文图；只有 `READER_ARTIFACTS` 图注、没收到像素的图不能选。不要为凑数量加入重复曲线、界面截图或装饰图。每个 `figureOrdinal` 只能出现一次。`marker` 写成 `[[FIGURE_<figureOrdinal>]]`，在目标小节正文中独占一段。`targetKind` 等于实际包含占位符的小节 `kind` 并遵守语义就位（架构/流程图放方法小节，定量曲线/消融图放结果/消融小节）。每项请提供 12–120 字自然中文图注 `chineseCaption`（不含“图 N / Figure N”前缀）。占位符前一段是自然的读图导引，后一段直接结合图中要素展开实质解释（禁止写“这张图确实可见”“从像素可见”等套话）。代码会在占位符处直接渲染官方原图与干净图注（不再插入看图路径框）；`focusPoints` 可输出 `[]` 或 2–4 个简短观察要点。

`implementationSpecs` 为顶层来源核实复现规格卡，必须精确包含 `trainingData`、`computeHardware`、`keyHyperparams`、`inferenceCost`、`openSourceArtifacts`、`appendixHighlights` 六个单行纯文本字符串字段（每项 4–500 字，不得包含换行、Markdown 标题/列表/表格、原始 HTML 标签或内部核验话术）。所有数字、硬件型号、数据集和开源链接状态必须严格来自原文证据与已核验资源清单；纯冻结推理/无训练阶段的论文应直接标明无模型训练阶段及实际推理配置，真正缺失的信息才如实写“原文未披露”，绝不臆测。

`tableBindings.tableIndex` 从 1 开始，对应最终正文的表序。原表可用性及四种结构遵守上方要求。选择模式的 `sourceRows[0]` 必须来自 `TABLE_<ordinal>_HEADER_ROWS` 明确列出的表头行；`SHAPE` 给出矩阵尺寸，`role: unknown` 表示科学用途还没判断。作者或机构表不能当结果表，只选实际呈现的行列，因预算省略的内容不要猜。手写坐标记录里，`renderedRow=0` 是表头，`renderedRow=1` 是第一条数据行，分隔行不计数；`sourceRow/sourceColumn` 是原矩阵从 0 开始的坐标。`rowspan/colspan` 覆盖的位置仍使用被覆盖的矩阵坐标，代码会找到真实 DOM 单元格。每个显示单元格必须恰好对应一次。

`formulaBindings` 只能选 `READER_ARTIFACTS` 的 `FORMULA_ORDINALS_AVAILABLE` 里明确列出、完整恢复且带原始 TeX 的公式。清单是 `[]` 时，正文不能出现 `FORMULA` 占位符，并须输出 `"formulaBindings": []`。`marker` 必须是 `[[FORMULA_<formulaOrdinal>]]`，在 `targetKind` 小节独占一段且只出现一次。代码会显示原始 `\[TeX\]` 并记录 DOM SHA。

选择表格前逐项核对 `TABLE_J_INDEX_RULES` 和 `TABLE_J_SHAPE`：rows=16 表示合法行索引0..15，不是0..16；columns同理。每张原表单独核对，不能沿用另一张表的维度。sourceRows/sourceColumns各至少2项、整数且不重复；只选择本次证据实际展示的单元格，sourceRows中只含一个原表头和至少一个数据行。修复反馈给出的当前数组、非法索引和重复索引是待修对象，不是合法示例；不要原样回传。
source_quotes 中的单位只可来自与该数值同一语境的逐字原句。多行列头 mean(SD),s 不会给后续全部裸数字提供逐值单位证据；不要手补单位、换成无单位列头或删掉训练/部署成本来绕过检查。不能逐值绑定时，保留有证据的列和成本事实，把有连续原句支持的时长比较放正文；无证据的SD或数值不能进入表格。构造 source_quotes 表时，列头若写单位符号（如 %、s、GiB），对应来源行须有逐字单位证据；若原表或原句只写裸数字而未逐行重复单位，应绑定原表（selection、completeTable 或 artifact_table），或在 source_quotes 列头不加括号单位符号而在表前说明交代量纲，并保持代码要求的最低表数（可用原表不少于 4 张时至少 4 张），同时确保每张表紧邻的表后解释只对应本表行列与数值。
FORMULA/BRIDGE标记必须独占一段且只出现一次；公式的targetKind、术语组合解释的sectionKind，必须分别与标记实际所在小节的kind一致。若位置和声明不一致，依据原文选择移动标记或修正允许修改的绑定，不能保持错误声明或改变公式含义。
