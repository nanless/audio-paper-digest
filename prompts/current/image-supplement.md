# 选择论文插图并补充读图说明

## 用途

只用于双模型模式：主模型先完成最终纯文本分析，副模型（多模态）只查看候选论文图片并生成结构化插图计划。它不重写完整分析，也不修改评分、摘要、标签或评分理由。

## 调用方式

代码读取这个文件后，把占位符替换成实际值：
- `{title}` → 论文标题
- `{arxivId}` → arXiv ID
- `{imageList}` → 论文图片列表（编号、URL、图注）
- `{anchorCatalog}` → 代码生成的稳定段落 ID、章节和段落预览
- `{primaryAnalysis}` → 主模型输出的完整分析（Markdown 格式）

## 选图与插入位置

只解释这次实际收到的图片。只有图注、没有像素时，坐标轴、颜色、曲线和模块位置都不要猜。

逐张看候选图片。优先选与论文内容密切相关的流程图、模型或系统架构图、模块图、语谱图、波形图、实验结果、消融、对比和可视化分析图。标志、页眉页脚、作者照片、装饰图、重复图、截断或不可读的图、没有本篇信息的通用示意图，以及与正文主题没有明显关系的图，都排除掉。

最多选 4 张，`insertions` 按信息价值从高到低排。只保留有用且互不重复的图片，少选或者不选都行。插入章节仅限 `核心摘要`、`方法概述和架构`、`核心创新点`、`实验结果`、`细节详述`。

## 图前与图后说明

`lead` 是图前的一句话。要承接 `paragraph_id` 对应段落的具体内容，复用其中至少一个论文特有术语，并给出明确的读图任务，比如核对某条分支、比较两条曲线、追踪输入到输出。`conclusion_paragraph_id` 指向同节中不早于插入点的段落，作为图后解释所联系的后续论证或结论。

`explanation` 用图后的一到两句话说明实际可见的结构、曲线、色块、样例或对照，再联系 `conclusion_paragraph_id` 的具体结论和适用条件，并复用该段至少一个论文特有术语。说范围时写清本图的对象和设置，例如“这条曲线只覆盖 LibriSpeech test-clean 的 WER，不说明流式延迟”。“逐项对照”“不代表额外阶段”“不替代未报告配置”“只支持对应设置、不能外推”这类通用免责声明不要套用。

这一步不能改写、替换或删除已有文本，评分、机器摘要、标签、作者与机构、论文评价、评分理由、局限与问题、开源详情也都不能改。旧正文里的“毒舌点评”属于同一评价栏目，同样要保留。不要输出 `replacement`、`rewrite` 或其他替换字段，代码会忽略这些字段。图片与文字分析冲突时，原有结论仍不能改；只能在 `explanation` 里谨慎说明图中可见的补充信息，不要据此推翻已有分析的结论。

精确数量、比例、名次、技术计数和参数一律用阿拉伯数字，中文与由英文字母组成的技术词之间留空格。句子要自然完整，别出现重复词、重复连接，也别用分号拼残句。检查重复字时，“具有有限”“具有有界”“功能能否”“性能能够”这些正常结构不要误改成病句。

## 输出格式

只输出一个 JSON 对象，不要 Markdown、代码块或解释。下面只示意字段格式。图中的分支、融合位置和训练信息要以本次实际图片和相邻段落为准，不能照抄示例：

{
  "insertions": [
    {
      "image": 1,
      "section": "方法概述和架构",
      "paragraph_id": "s2p3",
      "conclusion_paragraph_id": "s2p4",
      "lead": "声学编码与语义编码在前面的步骤中分别处理输入，沿下图的两条箭头可以查看它们在哪里开始共享上下文。",
      "explanation": "图中的两路箭头在跨模态融合块汇合，随后进入任务头。这一连接对应正文说明的融合顺序，图中未提供训练损失的细节。"
    }
  ]
}

字段规则：
- `image` 必须是候选编号数字，只用来引用本次输入里的候选图片。候选编号不是论文的原始 Figure 编号，不能据此推断正文里的“图N/Figure N”。
- `section` 必须是允许章节之一。
- `paragraph_id` 要从“可选插入位置”里原样选，而且所属章节必须和 `section` 一致。不要输出自由文本 `anchor`；代码按段落 ID 精确定位，非法 ID 会被拒绝，也不会回退到章节末尾。
- `conclusion_paragraph_id` 同样来自同一章节，在目录顺序里不得早于 `paragraph_id`。代码会检查 `lead` 与插入点段落、`explanation` 与结论段是否共享论文特有术语；联系不上前后论证的插图会被拒绝。
- `lead` 位于图片之前，用“下图”引导读者；`explanation` 位于图片之后，用“图中”指代刚展示的内容，不再写“下图”。不要把候选编号“图1/图2/Figure 1”写进这两个字段；展示编号由代码按最终正文的出现顺序生成。
- `lead` 和 `explanation` 必须是中文，内容只与图像有关。
- 如果没有任何图片值得插入，输出 `{"insertions":[]}`。
