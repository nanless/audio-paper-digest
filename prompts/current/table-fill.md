# 实验表格补充提示词

当 `## 实验结果` 引用了表格却没有提供表格，或用省略标记代替数据时，依据原文重写这一节。

```text
请根据文末 `<paper_input>` 中可见的论文原文与表格检查反馈，补充或修正实验表格及解释。只输出 `## 实验结果` 及其完整正文。

只保留直接支撑当前结论的关键表格，最多 2 张。每张最多 12 个数据行和 8 个指标列，方法、模型和数据集等识别列不计入指标列数。实证论文的表格合计至少有 3 个数据行和 2 个可核对数字。选表时优先保留本文方法、最强基线，以及有代表性的传统或开源基线；平均或汇总行、关键消融和负结果也要保留。原文同时提供主结果与消融或效率证据时，优先各保留一张。

每张表第一列表头必须明确包含标准识别词（如“方法/模型/系统/数据集/设置/配置/条件/任务”）。指标有明确优化方向时，在表头标出 `↑/↓`（例如 WER/CER/EER/LSD/MCD/FAD/RTF 为 `↓`，PESQ/STOI/UTMOS/DNSMOS/ViSQOL/SI-SDR/CLAP/MOS 为 `↑`）。不要用“结果”“数值”“观察”“说明”“解释”“含义”“方向”或“结论”等叙述型列代替指标。原文包含消融（`ablation`/`w/o`/`without`/`remove`）或负结果/退化/不显著/失败证据，或下方表格检查反馈明确指出缺失时，必须在表内保留至少一行明确命名组件的消融对照行或负结果/退化行，并在相邻文字说明其因果意义与边界。

表前说明具体在比较什么问题、比较条件是什么，以及为什么保留这些方法和消融项。表后提炼最关键的跨行差异、权衡代价与适用范围，不逐行复述或套用固定句首；凡在表前或表后声称某方法/数值为“最优/最低/最高/第一/SOTA”，必须逐格核对同表同列全部可比方法行与 `↑/↓` 方向，绝不把同列存在更优值的条目写成最优。

表格及相邻解释中的精确数量、比例、名次、技术计数和参数都用阿拉伯数字。负号用 ASCII `-`，百分号用半角 `%`，小数保留前导零，例如 `p<0.001`，不能写 `p<.001`。中文与英文字母或数字之间留空格；尖括号文本标记（如 `<S>`、`<E>`）用反引号包裹以防被 Hugo 误解析为 HTML。

这次只补充表格和文字，不插入 Markdown 图片、HTML 图片或图片网址。不可见或原文未给出的数据写“论文未给出具体数值”，不估算或编造。

<paper_input>
论文标题：{title}
arXiv ID：{arxivId}

## 论文原文

{textForAnalysis}

## 已有实验结果

{resultsSection}

## 表格检查反馈

{tableIssue}
</paper_input>
```

## 调用方式

`deep-analyzer.js` 通过 `loadPrompt()` 替换 `{title}`、`{arxivId}`、`{textForAnalysis}`、`{resultsSection}` 和 `{tableIssue}`。这五项依次是论文标题、论文 ID、本次可用的论文证据、已有实验结果和本次触发补表的具体检查反馈。
