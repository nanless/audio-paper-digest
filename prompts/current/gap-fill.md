# 分析审校提示词

## 用途

对照原文检查主分析及资源扫描后的文本，纠正事实和评分问题，补充遗漏，输出完整版本，替换已有分析。这份结构化分析用于后续评分、修复和发布资料；默认博客正文由 API Reader 根据原文独立生成。

## 调用方式

代码通过 `loadPrompt()` 替换 `{title}`、`{arxivId}`、`{existingAnalysis}`、`{textForAnalysis}` 和 `{tagPromptText}`，分别提供标题、论文 ID、已有分析、本次论文证据和当前可用的标签定义。

## 提示词内容

~~~
请对照文末 `<paper_input>` 中的原文审校已有分析，纠正事实、数字、作者机构、实验结论与评分偏差，补充重要遗漏，删除无证据推断。输出完整替换文本，直接从 `## 评分` 开始，不加前言、问候或代码块围栏。

### 写作与自洽规则（仅用于执行，不写入正文，不扩大修改范围）
- 面向音频研究读者，用平实自然的中文写清对象、流程与证据；首次出现的术语说明作用，必要时附官方英文名或缩写，后文称呼保持统一。

### 输出结构

按顺序各输出一次 13 个一级章节（`## 章节名`，不增删重复）：评分、机器摘要、标签、作者与机构、论文评价、核心摘要、方法概述和架构、核心创新点、实验结果、细节详述、评分理由、局限与问题、开源详情。

评分用 `X.X/10`。机器摘要 18 个键各出现一次，纯文本 `key: value`（不加列表符号或 Markdown 标记）：

```
rubric_version: type-aware
document_type: 方法研究 / 系统技术报告 / 模型报告 / 数据集与基准 / 综述 / 理论研究 / 应用研究
rank_bucket: 前10% / 前25% / 前50% / 后50%
innovation: X.X
technical_rigor: X.X
experimental_sufficiency: X.X
clarity: X.X
impact: X.X
open_source: X.X
reproducibility: X.X
engineering_score: X.X
confidence: 高 / 中 / 低
primary_task_tag: #标签
primary_method_tag: #标签
sota_claim: 是 / 否 / 未说明
has_code: 是 / 否 / 未说明
has_model: 是 / 否 / 未说明
has_dataset: 是 / 否 / 未说明
```

`rubric_version` 固定写 `type-aware`。文档类型择一，分档（`≥ 8.5` 前10%、`≥ 7.5` 前25%、`≥ 6.0` 前50%、`< 6.0` 后50%）与置信度仅取示例值。八项分值全用 **0.0–10.0 统一量表**（非负、最多一位小数），开源分只允许 `0.0 / 1.5 / 3.0 / 6.0 / 8.0 / 10.0`；`sota_claim`、`has_code`、`has_model`、`has_dataset` 仅写“是/否/未说明”。

标签严格写四行（全部标签、`主任务标签：#...`、`主方法标签：#...`、`补充标签：#...`），以 `#` 开头、空格分隔、共 3–5 个，逐字使用上方 `active` 首选名（不输出 ID、别名、弃用名、自造词或 arXiv 类别，不同时选别名或上下位概念）。主任务取最具体的 `facet=task`，且任务标签（`facet=task`）总数最多 3 个；主方法取 `facet=method` 描述核心方法。易混淆规则：ASR 仅作测量工具时不标 `#语音识别`；有目标提示选 `#目标说话人提取`，仅视觉盲分离选 `#音视频语音分离`；表示/量化/数据/协议贡献不以骨干架构作主方法；无训练流程选信号处理或系统方法；场景标签须有研究或评测依据，`#实时处理` 须有实测延迟或吞吐；基准/语料/数据集论文必含 `#基准测试` 或 `#数据集`；仅用 WER 等指标不构成补充任务。

### 事实、正文与表格

核对并补充原文中遗漏的关键组件、训练细节、消融、与最强基线差距及作者局限；未披露项写“未提及”或“未说明”，不补造。核心摘要保持全景导读规格（10–26 句，汉字与中文标点 700–1400 个，目标 850–1150 个，3–4 个段首粗体引导词自然段，段间空行分隔，禁止 `#` 标题或独立编号行），覆盖问题与瓶颈、核心思路与方法架构、主基准对比与核心代价（免训练或理论工作如实说明计算方式）及适用边界与深读导览，不压缩回短单段；所有引用数值严格逐字对齐原文精度、正负号与百分号（不自算差值、不增删末尾零、不给原文裸数值硬加 `%`），若原文自身报告存在字面算术矛盾（如分项合计不等于总计），须明确注明“原文如此报告，存在字面算术出入，原文未解释”而非静默照抄。

方法不少于 600 个中文字符，写清各核心组件名称、功能、内部实现、输入输出及数据流，多阶段分述，设计动机标明原文依据或推断；本阶段无图片像素，仅据正文或图注说明关系，不编造图链。各节分工明确、不跨节重复同一组数字，精确量用阿拉伯数字，中英文间留空格，不用字段拼接、双重编号或连续否定句。

保留已有合格精简表（最多 2 张，每张最多 12 行、8 指标列，实证合计至少 3 数据行与 2 个可核对数字），不恢复原全表；表头含识别列、方向标 `↑/↓`，不用叙述列代指标，优先保留本文方法、强基线、汇总行、关键消融与负结果，表前交代比较问题与选行理由，表后解释差异、代价与范围，不逐行复述或写“详见原文”。负号用 `-`，百分号用 `%`，小数留前导零。公式用 `$...$`/`$$...$$`（如 `$RMS = \sqrt{\frac{1}{N} \sum y[n]^2}$`），`<S>`、`</S>`、`<E>`、`<task>`、`<perception>` 等尖括号标记用反引号包裹。

### 评分核对

八个维度按序各写一行 `* 中文维度名 (得分/10)：具体理由`，采用 **0.0–10.0 统一量表**（最多一位小数），不写总分计算过程（代码按文档类型自动加权并封顶 `10.0`）。

五档标尺锚点与反通胀红线（与主分析统一 10 分制对齐）：
- **9.0–10.0**：里程碑/突破级（同方向前 5%，跨多基准大幅领先且理论/消融/复现俱全）；
- **7.5–8.9**：明显优秀（清晰创新或跨规模跃升、强基线领先、消融闭环且无硬伤）；
- **6.0–7.4**：扎实良好（方法成立、实验可核对，属稳健渐进或有范围局限）；
- **4.0–5.9**：明显短板（常规模块拼装、弱基线、表文算术矛盾、窄受众或关键消融/复现缺口显著）；
- **0.0–3.9**：严重缺陷或不适用（实质硬伤、缺乏支撑或偏离音频核心贡献）。
反通胀红线：仅堆叠模块或调参不得将创新性拉上 8.0；缺关键消融、仅比弱/过时基线或用无真人听测的代理分冒充主观听感质量时，实验充分性不得虚高。

按论文类型核验适用证据（方法重基线/消融/泛化；系统与模型重质量/延迟/吞吐/成本/公平对比/失败案例；数据集与基准重覆盖/标注/防泄漏/协议；综述重检索与综合；理论重证明/边界/反例；应用重真实场景与部署约束），不因类型保底或豁免；仅声称组件收益却缺对照时才扣实验充分性。开源分严守 `0.0 / 1.5 / 3.0 / 6.0 / 8.0 / 10.0`（完整+文档全 10.0、文档不全 8.0、部分开放 6.0、承诺未发 3.0、仅演示 1.5、闭源无承诺 0.0；数据集类核验数据集，理论研究无代码/数据仓库最高 3.0），与开源详情及机器摘要资源状态同步一致；公开核心材料不低于 6.0，可复现性仅看论文配置与步骤披露度。同一缺陷只扣一个主要维度（缺核心材料→开源、缺配置步骤→可复现性、缺验证→实验充分性、表达/口径问题→清晰度、推导/逻辑错误→技术严谨性）；信息不足降 `confidence`，不把“无法验证”写成错误。非语音/音乐/音频核心贡献时影响力通常不超 4.0。局限部分同时核对作者自述限制与有证据支持的潜在问题。
