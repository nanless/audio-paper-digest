# 深度解读的讲解与比较方法

Reader 的目标是让读者能够复述方法的执行过程，并判断实验支持了什么。
结构与来源门禁是必要条件，字数、表格数或生动比喻不能单独证明文章质量。

## 写作约定

- 开场交代输入、输出、改变对象和保留条件，用一个明确的教学场景说明难点。
- 按真实操作解释组件：它接收什么、执行什么、把什么交给下一步；区分训练、推理、冻结、更新与重置。
- 对关键设计说明具体障碍和取舍。拿掉组件会怎样，只有真实消融才能写成实验证据；机制推测要明确边界。
- 解释公式中的信号、分布、可学习参数、近似和梯度路径，不让公式或比喻替代计算过程。
- 按比较问题呈现实验，区分绝对值、增量、百分比、数据集、停止点和指标方向。一个指标变好不能代替其他指标的结论。
- 表后选最有价值的收益和代价，不重复逐行读表。结尾回答适用条件、复现步骤与尚待验证的问题。
- 代码、权重、演示、可部署系统分别陈述；训练资源不等于推理资源，冻结参数不等于实时。

这些原则吸收了用户提供的 InfinityEdit 微信解读在任务辨析、模块分工、执行顺序、
基线比较和复现入口方面的优点，但不沿用其无证据的绝对化承诺或把示例表现外推为一般保证。
参考文章仅作为表达方式参考，不是其他论文的事实来源。

## 少返工的生成与修复

默认 `reader-source-only-v1` 只把论文原文证据与实际原图像素送入 Reader，不重复输入 canonical 的机器分析、评论或旧 Reader。
canonical 的 13 标题、评分和 provenance 继续保留，API 函数签名保持兼容，但它不再是默认 Reader 的写作素材。
显式反馈修订另用 `reader-source-signed-revision-v1`；内容模式进入阶段与失败候选指纹，不能跨模式借用旧稿。

机械要求由 `scripts/lib/reader-contract.js` 同时供 Prompt 与解析器使用。正常生成先输出完整计划；
有效 JSON 若未通过门禁，保存失败候选，只允许对报错关联的白名单节点打补丁，随后重新运行完整来源与质量门禁。
补丁绑定整稿和旧节点 SHA，不能自由覆盖未授权章节。两次无进展会停止；网络失败保留候选且不消耗正文尝试次数。
同一输入续跑可恢复候选，来源、像素、模型、Prompt、契约或预算变化时不能借用旧候选。
局部修复仍携带保守的来源证据，因此不能承诺每次输入 Token 都很低；它首先减少重复输出和错误扩散。

原始表格结构可靠时，模型只选择原表行列并放置 `[[TABLE_N]]`，由代码生成 Markdown 与逐格来源绑定。
源表若全部标成表头、表头为空、含双写 MathML 或无法逐字安全显示的 TeX，生成前即提示 `eligible=false`。
此时只能走原有逐字 quote 绑定路线；不猜表头，也不悄悄放宽数值/单位重放规则。
跨节近重复按 Reader 的实际章节检查并报告为提示，不能自动删改事实内容。

请求级用量默认保存在忽略目录 `data/runtime/llm-usage/`，不保存 Prompt、正文或密钥。
使用 `npm run usage:report -- --paper 2609.03622` 查看阶段汇总；`--date` 按北京时间筛选，`--dir` 可查看隔离实验。
真实 provider usage、字符估算、缓存/推理子项、失败和正文采用状态分别记录；未报告值为 `null`，不推算账单金额。

需要对照实验时，先运行 `scripts/evaluate-reader-efficiency.js` 的默认离线模式，显式提供同源全文、完整工件、签名快照和全新输出目录。
只有显式 `--live` 才调用模型；隔离模式上限为 3 次逻辑请求、每次 1 次传输尝试、完整输出 24000 / 补丁 8000 tokens。
输出不能进入 `data/current`，不会刷新 canonical 或发布博客。生成通过只代表生产解析门禁通过，仍需独立事实与视觉复核。
完整实施边界与验证结果见 [改进计划](reader-efficiency-plan.md)。

## 来源解析约定

MathML 和 TeX 的同值重复可能产生 `3.093.09` 等表面。数值重放只允许完整且精确相等的重复，
不能把不同数字、正负号或单位合并。双写恢复必须保留完整单位，`seconds` 可规范为 `s`，
但不能把下一行 `SE` 的首字母当成秒，也不能用带单位来源证明裸值。Node 与 Python 发布验证必须保持一致。

找不到来源的表格数值应返回 Reader 的内容修复循环，禁止静默把整格改成内部校验占位，
更不能宣称作者没有报告。作者信息存在于前言表格时，只能用明确上标及唯一机构映射绑定。
表格前后缺少具体论证时也应进入内容修复，不由代码自动拼接“缺少方差、跨域表现、部署成本”等
无来源判断。代码只可修复 Markdown 空行等表面，不能用通用套话代替论文解释。
反馈修订产生的完全相同术语桥前缀可确定性去重；记录修复前后 SHA，重绑定正文与计划，
不伪装为新 LLM 生成。质量统计仅对精确重放的官方图/公式注入块恢复原 marker，保持生成时口径。

## 单篇前后比较

1. 保存原博客字节、canonical、Reader、Prompt、模型、原文 SHA 和其他论文的内容 SHA。
2. 记录变化范围：通用 Prompt、解析修复、是否另附定向事实核对反馈。
3. 使用同一论文来源与模型重新生成；如果只比较 Reader，保持论文评分与主分析不变。
4. 同时检查来源与结构门禁，并以原文核对关键事实、比较条件和因果边界。
5. 分别评价准确性、机制可解释性、图表完整性、行文重复和可操作性，不因文风改善提高论文评分。
6. 新版如有实质错误，先修复再发布；按 generate → review → push 顺序完成单篇发布。

显式 `api:reader:refresh -- ID --feedback '反馈'` 的纠错应以当前已签名 Reader 作为修订参考，
保留正确事实与图表，不从旧 canonical 重新自由发挥。参考稿及模式版本进入指纹；
它不是事实来源，也不能绕过任何来源、图像、文风或最终发布门禁。无反馈的正常生成不采用此模式。

单篇结果只能证明这次受控修订的表现。若同时改了 Prompt、解析器并加入人工核查反馈，
不能把全部改善归因于 Prompt，也不能宣称已证明对所有论文有效。
