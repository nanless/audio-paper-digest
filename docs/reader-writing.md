# 深度解读的讲解与比较方法

解读应让刚接触这个方向的研究者能够复述方法的执行过程，并判断实验实际支持了什么。结构和来源检查是必要条件；字数、表格数量或生动的比喻都不能单独证明讲解充分。

先读[共同写作约定](writing-guide.md)，再用本文核对 Reader 的内容与来源边界。前两节说明怎样讲清论文；“生成与修复”之后是实现、显示及恢复参考，不是文章必须照抄的栏目。恢复入口和预算见[Reader 恢复](reader-explicit-retry.md)。

写文章时先看[写作约定](#写作约定)和[中文讲解与准确术语](#中文讲解与准确术语)；遇到表格或公式来源问题看[表格和公式](#表格和公式)，执行失败后先看[失败候选与局部修复](#失败候选与局部修复)。后半的数值、资源及图片规则解释程序边界，不要求把检查词写进论文解读。

## 写作约定

开场说明任务的输入、输出、改变对象和保留条件，再用具体场景解释难点。背景只解释理解本文所需的知识，避免在任务尚不清楚时堆叠研究名词。介绍组件时沿实际执行顺序说明各自接收、处理和传递的信息，分清训练与推理，以及哪些参数冻结、更新或重置。

### 概念与计算要能连起来

一个概念至少要让读者知道它处理什么对象、解决什么困难、在本方法里做什么。不能只把术语翻成中文，或用另一个陌生术语代替定义。先说明作用，再给准确名称；后文保持同一称呼。

沿一个样本解释输入如何表示、一次变换怎样发生、产生什么中间结果、结果交给谁，以及最后怎样得到任务输出。有并行分支时分别说明各自的信息和汇合位置。张量形状、采样分辨率、梯度和实现细节只按原文披露的范围说明，缺失时指出具体缺口，不按常见做法补造。

关键设计需要解释障碍和取舍。只有真实消融才支持“拿掉组件后会怎样”的实验结论；机制推测应标明依据和边界。没有训练的论文，解释其实际的调用、检索、标注、仿真、证明或计算，不套用训练模型的介绍顺序。

### 比较先交代条件

实验围绕比较问题展开。先交代测量对象、数据划分、输入条件、训练或测试阶段、预算和指标定义，再给关键数字与方向。说明指标的分母或聚合对象，区分绝对值、增量、百分点和相对百分比。不同指标不能相减，不同条件不能拼成同一场胜负；oracle、事后最优与实际可运行策略分别标明。

表前说明为什么比较这些对象，表后解释关键差异、代价、未胜出项和适用范围，不逐行重复表格。原始量、计算含义与结论放在结果附近；不能为了教计算而补算未报告的实验提升、换算表格数字或增加无来源单位。教学示例须明确身份，不能冒充本文实测或写入原表。

### 公式和图片帮助解释

公式先说明计算目标，再解释关键变量、下标、范围和单位，沿运算顺序说明结果怎样用于下一步。原目标、近似与优化步骤分开讲，不只列原式或逐个翻译字母。Reader 的展示公式由原始 TeX 和来源标记装配；原文没有披露的推导、维度或梯度路径不能补写。

图前给读者一个具体观察任务，图后先说明本图真正可见的对象、趋势或连接，再联系原文机制与结论。先核对图例、轴、条件和指标方向，不能把前图说明套给下一张图，也不能由颜色相同推断对象相同。观察、作者解释和机制推测要能区分；没有本次像素时不猜数值、位置、箭头或曲线。

一项指标变好不能替代其他指标的结论，整机改善也不能证明每个组件都有因果贡献。结尾给出适合尝试的条件、复现第一步及尚待验证的问题，避免重新抄摘要或泛泛升华。

代码、权重、演示和可部署系统分别说明。训练资源不等于推理资源，参数冻结也不等于实时。原文缺少某项证据时，只能说明尚无法判断，不能把缺失证据写成技术错误。

## 中文讲解与准确术语

正文用平和、朴实的中文解释具体问题、模块分工、输入的处理过程以及设计的作用。根据论文内容安排段落，不能把这些角度写成每节重复的固定栏目。每段围绕一个问题，转到新步骤、不同证据或推测时另起一段，段间留一行空白；句长随内容变化，不把每句话都拆成一段。JSON 的正文或解释字符串用合法的 `\n\n` 转义表达空行，不能插入未转义换行。标题、表格、图表与公式标记各保留原协议要求的独立段落。

解释条件和限制时指出具体对象，少用泛化的“槽位、落点、链路、口径”；这些词有明确专业含义时不作为禁词。真实步骤可以使用必要的先后连接词，不为“去模板”删掉转折、否定、归因或不确定程度。统计比较应直接说明指标定义、纳入样本、分母和聚合方法。

写作规则与术语对照只用于指导生成，不能逐句拼入文章。术语按论文实际任务正向解释；正文不复述翻译要求、来源校验或编辑流程。

术语应先说明作用，再给准确名称，后文统一称呼。critic 的含义由论文任务决定：强化学习的评价网络通常估计价值，DMD 的辅助模型拟合学生分布的分数，承担分类判别任务的 discriminator 可称判别器；不能把估计价值或学生分数的 critic 一律改称判别器。DMD 的分数是对数密度对输入的梯度，不是质量评分。FID 可解释为生成图像与参考图像在特征空间中的分布差异，参考样本集由原文决定，再保留准确全名 Fréchet Inception Distance；不能将 Inception 译成“起始”。patch FID 在图像块上计算，不是“补丁距离”。准确数学术语、模型专名和必要缩写不应被一律替换成口语。

来源字段和读者正文承担不同职责。逐字引文、原表、公式及其对应记录供程序核验；读者正文解释比较条件、结果、机制和边界。“列数满足要求”“表格数字来自连续原句”等检查过程不进入正文。文风修订不能改数字、单位、公式、指标方向、方法归属或逐字引用；局部修复仍受原授权字段限制，布局或来源修复不能顺带重写正确正文。

普通新请求使用当前登记的主分析 v6、Reader 写作 v9、局部修复 v13 和核心摘要 v7；分析审校 v4、方法补充 v3 和结构修复路径 v3 保持原职责。实际生效以程序登记的阶段路径与协议版本为准。旧正文从 Git 按原 SHA 核验，保留原声明与费用；运行时补充指令也进入对应阶段和失败候选身份，不能为换提示词重置已付费次数。写作标准提高不表示旧候选自动迁到新输入，也不授权重新生成。

会议旧活跃 Reader 的受控只读重验另有严格入口：原请求、响应、用量与认证来源全部闭合后，私有作用域可保留原 Prompt 声明及 Git 字节，按当前完整解析规则重验。该入口硬禁新模型请求，不是旧模板继续写作的许可，也不替日更或历史普通刷新放行。

## 生成与修复

### 写作输入和页面内容

论文原题中的真实价格符号保留在元数据中；汇总排行榜、英文题目链接和单篇标题在 Markdown 显示边界把字面 `$` 写为 `\$`，不改原始分析、Reader 或来源字节。数学标题仍沿用既有纯文本清理。Hugo 渲染后的字面美元只在源页面显式转义、完整标题及链接地址精确对应、出现次数相符的可见纯文本标题节点中认可；隐藏内容、代码、嵌套标签、错链、多余符号及普通正文不继承这项显示资格，裸美元公式检查保持严格。

真实表格单元格中的成本、价格、费用或预算标签，若以独立的 `($)` 标明货币单位，共享发布清洗只将 Markdown 字面美元写为 `\$`，网页仍显示原 `$`。Hugo 检查仅在真实表格的直接纯文本 `th`/`td` 中复用同一货币单位判定。原来源、Reader、数字及单位绑定不变；配对数学、代码、普通正文和嵌套 HTML 不继承这项规则。日更、会议和历史页面共用该处理。

默认 `reader-source-only-v1` 只把论文原文证据与实际图片像素交给解读模型，不重复输入正式分析正文、评论或旧解读。正式分析的 13 个标题、评分和来源记录仍保留，API 函数签名兼容，但这些文本不再作为默认解读素材。

有明确反馈的修订使用 `reader-source-signed-revision-v1`，参考当前已通过结构与来源核验的解读。输入模式进入阶段和失败候选指纹，不能跨模式复用旧稿；参考稿帮助保留正确内容，不能替代论文原文。

`beginner-researcher-v3` 的 `plan.oneSentenceThesis` 用于页面元数据、检索描述和一句话主线。当分析声明 `core-summary-detailed-v3` 时，单篇及汇总页的核心摘要必须逐字对应详细摘要阶段和评分阶段绑定的正文，不能退化为一句话。发布依据同时核对摘要规则、正文 SHA、阶段绑定 SHA，以及评分阶段的摘要输入、输出 SHA。

尚未升级的旧记录可以使用原兼容显示，但不能取得新的 `llm_api_production` 资格。旧 `imageSupplement=complete` 若没有插图前正文，不能仅凭三个自声明 SHA 证明当前发布有效，须升级为现行 Reader 流程。受控插图来自核验过来源和像素的图片安排。

当前 Reader 页面不再展示正式分析中的旧点评、资源复现配置或自然语言评分理由，以免提供两套解释。资源区只输出已核验的资源类型、原链接、重定向终点和可达状态。“模型相关资源”不一定是本文权重，链接可访问也不证明许可证、下载内容或可复现性。缺少记录只说明本次尚未核实开放状态，不能说论文没有开源。

“代码开源、权重下载、系统可运行／可部署”可以是待区分的三个概念。“三件不同的事／独立事项”或“把三件事分开验证”等表述，只在没有实物归属的完整列表范围内识别为概念说明。程序仍核对列举数量、不同资源类型及前后语境；引述、撤销区分或前后另有“本文代码已公开”等实际声明，不能借概念说明获得可用资格。紧邻分号后的闭合实际声明（如“三者均已公开可用”）也须核验；可用与否、待核、假设和否定不因此变成实际声明。

“三回事”等同义表述同样须恰好列出三类；只写“权重可下载、代码可运行”却称“三件事”仍不合格。“权重可下载与系统可运行需要另行确认”属于两个无实物归属概念的后置待核说明，不表示本文已提供这两种能力，也不能豁免相邻的真实发布声明。

对已装配的旧 Reader 重放资源检查时，逐节核对原计划及正文。仅允许原来已经使用的确定性标题排版投影（如“一帧”与“1 帧”），不接受改数、改义、换序、漏节或产生重复标题。原计划、文章、签名和费用保持原字节；Node 后处理与 Python 展示共用同一资源检查器。

八维分数和总分只在页首显示；页尾评分来源由代码按模型和协议元数据生成，说明分数是系统判断而非论文实验事实。旧分析的审查文字保留在保存的分析结果中。前言、资源、评分和汇总对应内容按实际数据重新核对；发布代码变化进入生成和审查指纹。历史 API v1/v2 及 Manual 页面继续采用对应兼容布局。

评分理由中的第三方资源状态须按归属判断。明确与具名闭源教师的做法比较，不表示本论文未开源；公共校验只屏蔽该对照短语中的状态词，同句其他本论文代码、权重或复现材料不足仍按原维度规则检查，不以整句正面评价豁免，也不修改分数、证据、原响应或费用。

渲染时只为计划中精确匹配的独立术语解释段补齐加粗结束符后的空格，不改原 `article`、`plan` SHA、代码块或表格、公式来源字节。最终页面采用同一渲染结果核验。

术语本身可含无空白的乘号，如“时间×模态遮挡”；组合连接采用程序生成的有空白 ` × `，回绑时保留原子术语，重复、缺项或分组歧义仍拒绝。正常格式修复可将完整测量值中的阿拉伯系数加“千”按十进制字符串精确展开，例如 `6千小时` 与 `0.6千小时` 对应 `6,000 小时` 与 `600 小时`；不推断共享量级范围、科学记号、标识符或数千、成千、上千，代码、公式和逐字引文保持原样。修复只改正常解析的展示输出，保留原响应、来源、次数及费用，并继续全篇校验。

### 失败候选与局部修复

`scripts/lib/reader-contract.js` 同时供提示词和解析器使用。正常生成先输出完整计划；有效 JSON 未通过结构、来源或质量检查时保存失败候选，随后只能修改报错允许的字段或数组项。补丁须匹配整稿及待修改项的旧 SHA，合并后重新运行完整检查，不能覆盖未授权章节。

表格数量不足使用 `reader_table_count_insufficient`、`requiredCount`、`actualCount` 指定问题。`diagnosticOnly: true` 的记录仅供参考，不触发修复动作。新诊断不从自然语言报错提取动作；旧保存文字只在限定兼容读取中使用。已有表格缺来源记录时，修复对应记录；确实缺表时才补表。自动定位要求唯一的顺序对应和明确的修复范围，歧义仍会停止。

正文已有普通表或公式、只是漏写来源记录时，程序可明确允许补齐整组记录。表格最多补四个缺口；公式可以补齐正文已有且唯一独占的标记，补齐后的总记录数最多十六项。其他正文、已有表格选择记录及未被指出有问题的旧记录保持原样。旧普通表绑定有错时，仍只按报错允许的范围修；补公式时全部旧公式绑定保持原样。已有唯一的表格选择标记若因前面插入普通表而编号错位，只能按实际表序改标记编号并移动对应记录；原表行列选择、数字和解释不能改。新记录合并后仍须通过完整的表格或原始 TeX 核验。重复标记、无法唯一对应、越权删改旧记录或借改编号修改正文，都会被拒绝。

局部修复的基础输出上限默认 8000 tokens，实际以原候选绑定的配置为准。一次补丁恰好在基础上限截断、且候选仍符合正常截断恢复条件时，程序保存失败草稿并停止；后续明确续跑可按原策略使用较高输出上限，默认最高 16000 tokens，且不超过正文预算。提高单次输出上限不增加内容响应或全文次数；原额度、无进展及传输记录仍须通过检查。实现升级不再签发新的额外恢复许可，旧许可只按原历史规则读取，不能当作第 7 次响应的依据。只要模型返回内容，就计入尝试次数；纯传输故障无内容时原内容次数不变，但传输历史保留。截断 JSON 仍不合格。

同一组问题连续两次无进展会停止。相同输入先完整重验原候选；内容规则的实现变化只有通过已有严格迁移链，才能保留原稿和原次数继续。当前完整检查发现真正不同的问题时，是否可用原余额由[两种失败签名和剩余额度](reader-explicit-retry.md#正常候选中的原余额)共同决定。来源、像素、模型、Prompt、反馈或预算的实际变化不能伪装成同输入恢复；没有合法路线时保留阻断。局部修复仍携带必要来源证据，不能保证每次输入 token 都很少；它减少的是重复输出及误改范围。

旧付费轮若没有收到可保存的新正文，但原档仍有完整失败稿，程序可在同一轮内恢复原稿继续局部修复。恢复前须核对当前长文实际输入、四份封存来源、原档和调用记录，并持有论文锁；原次数与已经预留的请求额度保持不变。主分析中的评分或资源可达状态更新，只有未改变长文实际输入时才不影响这项恢复。新开付费轮仍须核对当前完整主文，不能借恢复旧稿重新获得额度。

### 表格和公式

原表结构可靠时，通过 `selection` 选择真实 DOM 行列并放置 `[[TABLE_N]]`，由代码生成 Markdown 和逐格来源记录，不能用 `source_quotes` 绕过结构化选择。最低表数按实际送入生成器、经裁剪的 `TABLE` 证据数量计算；普通 v3 要求由当前 `readerRequirements()` 决定，不能用未经裁剪的原始证据条目总数代替。

代码会推导真实表头、修复唯一缺失表头，并把带数字的 `Ours`、`Proposed`、`Baseline` 等全 `th` 强调行识别为数据行。全部行都像表头、表头为空、MathML 双写或 TeX 无法安全逐字显示的源表，会在生成前标为 `eligible=false`。

原表不适合结构化选择时才走逐字引文路线。缺少部分数字列或行的引文，代码可按明确的来源对应关系裁去没有证据支持的部分，但仍须至少两列及一行数据。`[[TABLE_N]]` 和来源记录只有存在唯一、保持顺序的对应时，才自动重编号或去掉没有对应来源记录的手写表格；歧义不能猜。

每个数字和单位都要能对应原表单元格或完整原文引文；展示公式使用结构化原始 TeX。跨节近重复检查提供提示，不自动删改事实。表前应提出具体比较问题，表后解释结果和边界，不能靠通用过渡句完成检查。

会议与历史 PDF 的正常 `source_quotes` 表格可由程序保存 `authenticatedPdfTableEvidence`。来源能力只由真实来源程序签发，证明绑定原 PDF、来源快照、实际结构化投影、当前表格 SHA、唯一原表引文及行列映射；模型不能靠 JSON 或路径自行声明已核验。原表表头或明确表注须与目标指标和单位唯一对应，原行标签及数值顺序也须一致。重复指标列、无法定位的重排、中文别名或转置不据猜测映射，缺少原表单位也不能借其他段落或图轴补齐。解析、恢复、保存后检查及 Python 发布冷核须重新验证同一证明；旧完整会议的出版补证不授予正常未完成分析资格。

## 来源解析约定

MathML 和 TeX 的同值重复可能显示成 `3.093.09`。`.119` 与 `0.119`，以及带比例、分数、百分比、量级或括号单位的等价写法，按 Node 与 Python 共用规则核对。其他重复数字只有完整、精确相等时才可恢复；不同数字、正负号或单位不能合并。

完整表格单元格可投影带明确 TeX 注解的重复分数和脚注：分子、分母及 `{,}` 千位注解须逐字相同，百分比尾注原样保留；脚注只在数值精度、字母及次序全部一致时合并，`\ell` 对应 `ℓ`，可见脚注不能删除。`∼\sim` 仅作为完整同符号格值合并。裸重复、不同值或脚注、未知命令、单位和数学续式仍保留并接受正常检查；这项显示投影不补写脚注含义，也不替代原 DOM、连续引文或 PDF 来源资格。Node Reader、保存后绑定与 Python 最终页面使用相同规则，原来源和已付费正文不改。

恢复双写值必须保留完整单位。`seconds` 可规范成 `s`，但不能把下一行 `SE` 的首字母当作秒，也不能用带单位的来源证明一个裸值。Node 分析及 Python 发布须使用一致规则。

无来源的表格数值应进入内容修复，不能静默改成内部校验占位，也不能宣称作者没有报告。前言表中的作者机构只依据明确上标及唯一映射绑定。表格缺少具体论证时同样返回内容修复，代码不能拼接“缺少方差、跨域表现、部署成本”等无来源结论。代码可修复 Markdown 空行，不能用套话代替论文解释。

反馈修订出现完全相同的术语解释前缀时，可由代码去掉重复部分，记录修改前后 SHA 并重新绑定正文和计划，不能冒充新的模型输出。结构化证据文件采用稳定键序 SHA；兼容早期保存的证据文件时，须核验全文和来源清单，并满足记录的解析器版本重验条件，或属于实现认可、表格、公式和图片数组均为空的无布局来源。不能用任意旧布局声明放行，也不修改已保存的文件。统计文章质量时，只有官方图或公式插入块能重新精确核验，才恢复其原占位标记。

来源没有可选原图时，合法的图片列表和 Reader 选图可以为空，不能为凑数量补图。有候选图时，准备程序只按已区分的永久不可用原因处理跳过；瞬时网络失败、来源漂移或无法核验像素仍按原路线报错，不能一律降为“无图”。提供方明确拒绝损坏或不兼容 PNG 时，正常兼容路径可转换为白底 RGB JPEG 再重试，仍绑定实际输入像素 SHA，实际请求计入原预算。新日更页面通常引用同篇 arXiv 官方 HTTPS 图片；受控 SVG 或 PDF 原页派生资产另须保存并冷核来源证明，不能据此建立普通图片缓存。

汇总卡片的首图只使用中性替代文本“原论文配图（完整图注与解读见独立文章）”，不转抄截短的原图注或据来源数组序号猜作者图号。卡片中英文题目仍链接独立文章；完整图注、看图路径与解释保留在该文。图片来源、像素及派生资产认证保持不变，不改 Reader、原图或科学内容。

原 DOM 单元格有时同时包含可见数式与同值 TeX 注解。`source-cell-math-display-v1` 只识别整个格值中数值、符号和精度逐字一致的均值±误差样式副本，或完整方括号幂式与其唯一显式 TeX 副本。正常来源表编译和发布显示可使用这项有界投影；发布视图的最终比对须从原已绑定单元格重算同一投影。原 DOM、封存文件、已签 Reader 和原表 SHA 不改，普通正文、代码、裸重复数字、不同单位或数值不继承此规则。

## 单篇前后比较

先保存原博客字节、正式分析、解读、提示词、模型和原文 SHA，并记录其他论文的内容 SHA。对照时写清修改了通用提示词、解析程序，还是另加了定向事实核查反馈。

使用同一论文来源和模型重写；只比较解读时，保持主分析和评分不变。检查结构及来源后，再按原文核对关键事实、比较条件和因果边界。分别评价准确性、机制解释、图表完整性、重复程度和可操作性，不因文风改善提高论文分数。新版存在实质错误时先修复，再按 `generate → review → push` 完成单篇发布。

显式 `api:reader:refresh -- ID --feedback '反馈'` 以当前已通过结构与来源核验的解读作为修订参考，保留正确事实和图表，不从旧正式分析自由发挥。参考稿及模式版本进入指纹，但参考稿不是事实来源，也不能绕过来源、图片、文风或发布检查。正常无反馈生成不使用此模式。

发送修订参考前，程序把已核验且唯一的完整图块和展示公式还原成对应标记，保留旧计划中的图解和原始 TeX。图前导读、图后解释，以及保存记录中的原正文及其 SHA 保持不变；发给模型的标记参考稿另算 SHA。这样可减少模型把程序生成的看图路径、图像和图注再复制一遍。无法精确还原的图块或公式会被拒绝；已有重复说明仍须按正常修订流程纠正，不能手工删除后给旧记录补签。

单篇比较只说明这次受控修订的表现。同时修改提示词、解析程序并加入人工反馈时，不能把所有改善归因于提示词，也不能宣称对所有论文都有效。

## 从原始材料重新核验作者与机构

作者解析结果自身的 SHA-256 只能检查该记录内部是否一致，不能证明姓名与机构确实来自原文。新获取的官方 HTML 在原始 UTF-8 不超过 8 MiB、没有内联 `data:image`（包含实体编码）、SVG 或 canvas 图片时，保存完整原字节于 `source-runtime.json.readerAuthors.sourceHtml`。这份 HTML 只用于本地重新解析，不进入模型提示词，也不作为图片缓存；运行元数据总量仍不得超过 64 MiB。预算或图片检查不通过时不保存这份证据，机构只能明确标为不可得。

生产复用会先核验封存文本、结构化解析结果及当前 Reader 阶段的 SHA。有完整原 HTML 时，从它重新解析姓名与机构；会议 PDF 则从已保存的全文重新解析作者上标。日更四文件来源已经完整封存并绑定当前运行时，也可重新读取、核验这四份文件，使用其中的作者记录；单独复制的数组或记录自身的 SHA 不具备这种资格。Python 发布进程同样重新核对实际封存目录，不依赖分析进程中已经结束的临时核验状态。缺少上述依据时，作者刷新使用受控论文元数据姓名，并将机构记为明确不可得；不修改旧封存文件，也不给旧记录重新计算凭证。作者刷新与正常 Reader 刷新保持可用，纯图片刷新及评分中保留旧 Reader 的路径必须先满足当前复用来源记录所要求的检查。

机构文本末尾偶尔带有作者的 ORCID 编号。显示时只移除格式完整且校验位正确的末尾编号，不把它当作机构名；原始来源字节保持不变。编号不能用于推断作者属于哪所机构，中间位置、校验不通过的编号和机构中的普通数字也不自动删除。

历史会议的同步暂存复核没有全文时，只允许安全的“机构不可得”旧记录：必须重新核验计划中的 PDF 和原元数据文件 SHA、从原元数据取得完整姓名集合，并逐人核对姓名顺序、元数据绑定、明确不可得机构绑定及当前阶段 SHA。任何肯定机构、借来的姓名、缺少原元数据姓名全集或仅有文字标记、没有所需来源证明的记录都不具备此兼容资格。不会为这个分支新增来源运行协议或调用模型。

该限制作用于当前分析复用和发布资格，旧结构成功、只读状态及已发布历史统计继续保留。旧页面不会自动重写。Node 和 Python 发布入口共用不加载模型路由的纯作者解析器；Python 只通过私有文件描述符传递有大小限制的本地资料供本地重新解析，同时限制子进程时间和输出。

### 保留主分析证明的独立评分纠错

缺少支持结论的统计检验属于实验充分性；只有真实推导、逻辑或算法漏洞才属于技术严谨性。同一缺陷不能在两个维度扣分。外部反馈自身也须遵守这个归属，旧反馈要求不正确时须保留旧包并重新审查，不沿用错误要求。

受保护的主分析需要单独纠正评分时，可用 `withScoringFactReviews(scoringBound, primaryBound, currentPaper, callback)`。两个对象都必须先经公共 `validateFeedback` 接受，并绑定同一论文、日期、来源运行和四份封存文件。新包只能包含评分反馈；原包的主分析证明须精确等于当前保存值。评分请求只接收原主分析约束、新评分约束和完整逐字引文，合计不得超过 4000 字符。原主分析指纹和证明保留，新评分证明由正常评分刷新保存；原有 `withFactReview` 行为不变。

原输入已不在当前正文时，必须另有实际原输入只读副本，记录副本完整文件 SHA 与正文 SHA，在该原输入上核验原包。锁内重读的当前论文仍须独立核验新包、当前封存来源、保存的原主分析证明和已纠正的原错误句。原副本不能冒充当前论文，不补签原主分析或拼造原输入快照；缺失或被改时拒绝。正常评分刷新仍会按既有规则保存当前评分输入快照，这与伪造原主分析快照不同。若 Reader 或资源身份不能原样复用，本独立评分范围在评分请求前拒绝；它不授权主文、核心、标签或 Reader 模型重写。

## 避免重复修补

批次先让选定论文统一经过正常阶段，整轮结束后再只续仍可重试的失败集合。本文的局部修复是每篇正常流水线中的程序阶段，不要求执行者逐篇人工精改；外层总轮数不会清零 Reader 原候选、无进展或付费次数。多轮后的少量顽固项才按限定反馈做受控人工修正，随后完整重验，见 [批次规则](three-workflows.md#全批轮次与失败集合)。

小节超过 18 节且术语解释不足时，先允许在原稿上重排小节，再按新位置补术语解释。术语不足不能把小节重排入口也堵住。每次请求的修改范围仍独立核验，重排不能改动其他来源数组，最终篇幅、术语、图表和事实检查全部保留。

严格只含 `kind`、`heading`、`body` 的超节稿，在同类型连续合并足以满足节数时，使用运行时 `reader-section-index-groups-v1` 小计划：模型仅选择连续原索引分组与合并标题，程序从原稿派生类型并保留全部原标题、正文和图表公式标记。所有原索引必须按顺序完整覆盖，无遗漏、重复或跨类型合并；来源绑定数组不改。仅有唯一 `body2` 或 `body_after` 字符串且声明顺序明确的超节稿可走 `reader-section-body-index-groups-v2`：模型逐小节声明原字段拼接顺序，每个字段（包括空串）恰好引用一次；程序保留全部原字节、标题、类型和标记，不跨小节搬段、不推断事实或图像。其余未知字段或无法同类型连续合并的稿件继续原完整重排。新协议不新增尝试轮或预算，实际请求记录保存协议及真实提示 SHA，已有 `repairImplementationSha256` 覆盖协议与编译实现。结构恢复仍须经过同一完整正文、来源和发布校验。

如果只缺一个教学类型，程序可允许模型改写学习顺序上相邻、可以替代的小节，连同该节的类型一起修正。唯一必需小节、带有图表或术语标记的小节不能因此被改作别类。只有正文修改权限时无法补上缺失类型，不能对同一稿件反复发送这种无效请求。

正文中的圈号或上标数字，按原符号补排版空格，例如“公式②”改为“公式 ②”。不把②改写为另一个数值；公式、代码、引文和来源地址继续逐字保护。这类确定的排版不需要请求模型。

排版与数量检查共用任务、条件和随机种子的指代边界。“下一个任务”“另一个条件”“另一个随机种子”等承接文字不是实测数量，不应在排版恢复中文后再次报错；同分句有“只、仅、至少、总共”等数量限定，或另有参数、样本量、百分比时，仍逐项严格检查。Node 生成和 Python 最终文字核验采用一致规则。比较检查只屏蔽带明确设置名称的提前量、观察窗等完整时间量，以及有完整边界的长度单位；“同 1.5 秒提前量下准确率下降”与“误差小于 30 厘米的样本占比”不含裸露准确率结果。同句实际结果数值没有单位仍须拒绝，不能用设置量豁免整句话。

恢复旧稿时，同一次同步检查只建立一份追加请求记录索引，避免每篇候选反复扫描所有记录。来源、正文、原请求次数和每次追加的依据仍逐项核验；读取到损坏记录仍会报错。查询时检查目录是否变化，写入和扫描结束前复查所有依赖文件，不能把缓存中的旧结果当作当前许可。一次检查结束后释放索引。

### 已核验文章的精简修订输入

普通定向修订可显式启用 `signedRevisionMinimalDisplay: true`。程序先核对原文章、计划与封存来源摘要，再把原标记视图恢复为标准草稿，只从模型输入中去掉重复的派生来源数据。表格引文对象转换为原引文字符串前，仍须验证原引文摘要；不删除、截断或改写任何引文，也不改变正式保存的原计划。原文章与来源摘要全部保留，精简输入的协议与真实 SHA 进入请求指纹和完成阶段记录，240000 字符上限不提高。

原相同修订输入已有请求、传输失败、恢复原稿或明确追加轮时，拒绝切换输入显示，继续沿原身份恢复，不能借此重置已付费次数。默认修订与资源局部模式不变；精简输入仍生成正常完整 JSON，经过整篇内容、事实、图表与来源检查后才能保存。

### 数值、指标与方法说明

同句解释横纵两轴时，轮次分箱与准确率数值按各自的明确轴标签区分。完整连续的整数轮次区间及末端开放组属于计数坐标，不把末项如 `31+` 借给另一轴的准确率补百分号；另一轴及独立结果的单位仍逐项检查。缺失、重复或含混的轴声明、不连续或截断的分箱不获得这项格式兼容，来源、像素和全文其他检查照常执行。

实验表的“表示”“检测器”“生成器”“组合”及 NFE（函数求值次数）可明确标识每行比较的对象或设置；“表示准确率”“检测器误差”“生成器准确率”“函数求值耗时”等仍是指标列。原表已明确指标方向时，正文保留的数值退步和质量权衡应被识别为负面证据；删除训练阶段或将修正权重置零，只有在原文确有相应隔离对照时才计为消融。此规则不补齐缺失的来源、数值、指标方向或消融证据。

方法链检查关注前一步产生什么、后一步如何实际使用同一产物，不强迫正文套固定序号、动词或网络模块。相邻句中的同名产物、数量一致的承接和直接输入关系可以构成方法链；有明确中间产物的信号处理、候选推理、表示融合和实验统计流程也适用。候选对象名称中的“假设”和表示尺寸“与录音数无关”，须结合实际生产及消费关系判断，不能全局豁免假设或无关输入。同句或相邻句若撤回实际执行、说明只是设计示意或明确属于未采用的对照流程，仍拒绝；产物、主体或数量错配也不通过。Node 分析与 Python 发布采用对应判据，语义检查通过不能替代封存来源的事实核对。

明确的中文指标名（包括皮尔逊、斯皮尔曼及肯德尔相关系数的完整名称）及“前者／后者更高／更低”须结合同句具名对象、同一指标的实测数值、单位和数值关系核对，不能借参数量、跨指标或假设比较通过检查。结论的自然范围限定也须明确评测条件或未验证范围。同一指标在两个明确条件间的百分点差值，也按明确对象识别；假设、否定和跨指标比较仍拒绝。部分硬件披露不能写成完全没有成本信息。

明确说明结论仅在测试集或实录数据的原划分上成立，是评测范围边界，不必再套用固定免责声明。估计波形交给解析信号变换、再从解析信号导出相位导数，也属于真实的产物交接；同名波形没有实际交给后续步骤、否定执行或假设流程时仍拒绝。

同一指标的近似区间比较须保留两组上下界、相同单位和明确对象，只有端点支持方向时才识别，不能将区间当精确点值或计算精确提升。具名指标的百分点估计及紧邻置信区间可共享已明确的单位，其他裸数仍独立检查。表格单位可由同引文中相邻的同指标、同数值和显式单位证明；日更封存来源还可从唯一单层原表列头继承百分号，但须核对表注、原行名、同列原格及相关单元格身份。生成与保存后重验共享同一封存证据，只有实际用到原表单位能力时才保存完整结构化来源；保存的引文对象还须核对原文逐字包含与SHA。重复原表、模糊行名、复杂跨行跨列和单位换算继续拒绝；仅数值前导零与均值±标准差的等值表示可规范化。 独立封存 PDF 列单位能力还可核验完整原表中的标量及均值±非负标准差：必须保留全部行列、精确数值与精度，并由连续 PDF 引文、唯一表注和完整单元格 PDF 字形坐标共同证明。仅同一符号的显式 TeX 重复、相邻完整数字与±之间的空白、表号后的冒号/句点、单行上标的阅读顺序可作受限显示投影；不能借相邻列单位、截去不确定度、改变正负号或换算比例。当表头之间有多个空隙时，程序完整枚举候选列界，整张表最多尝试64种组合；所有文字框必须恰好归属一次、逐格文本必须与完整展示矩阵相同，最终只能留下唯一几何证明。超出上限、两种完整解释或缺格都拒绝，不选最宽间隙或首个命中。Node 分析与 Python 发布共用这份 Python 几何核验，不接受自行填写的单位证明。

会议及历史认证 PDF 的逐字原表可以混合带单位指标与无单位指标。补证只核验目标列原有的明确指标名和单位，保留其余列的位置，不替无单位列或未知单位列猜补单位。目标列之间夹有其他指标时，来源引文须连续覆盖原行名、完整数值及原列顺序，完整原行窗口在 PDF 中须唯一出现；不能要求删掉中间指标后两个数仍在原文中相邻，也不能借同数值的相似行名引文。原表、行名、列与连续引文仍须唯一对应；分组同名行、重复指标、跨表借单位、截短行名和错数继续拒绝。这项表格能力不代表整篇稿件已经通过，也不增加恢复次数或费用额度。

“两对零点”中的数学术语不能按得分比较拆开，明确的横轴预算完整整数枚举也不是性能值，真实的数值比较仍须单位对称。规则误报用原失败稿和原来源复现，在任务停止后统一修复、测试并恢复失败集合，不为迎合词表逐篇替换正确事实。

完整英文三元参数列表中的真实重复数值，须与当前表格绑定的原文逐字完整列表核对，顺序和次数不能变化，也不能截取更长列表或科学计数法中的数字。词内字面下划线保留可见分隔边界；真正的强调标记不能隐藏汉字与英文之间缺少空格的问题。三条流程共用这些检查，不按论文身份特殊放行。

实验结果检查也识别已报告的组件组合比较、分离门控贡献，以及 F1 等越高越好指标确实更低的自然说法。计划、讨论、假设或否定这些实验不算已完成证据；错误率降低也不能据此当作负面结果。此检查只判断文章是否说明对应实验，不替代原文事实和逐项数值核对。

### 资源声明与论文归属

资源否定句和区分不同主张的说明只在实际否定、未确认列表或说明范围内处理，不能吞掉前后真正的可用性声明；作者代码归属仍须绑定真实发布表述及其原链接。“不能把复现建立在代码已公开的假设上”只否定假设中的发布状态，不豁免“建立在”之前已经断言的代码公开事实；“没有作者资源可作权重已公开的证据”也不能夹带否认、反驳或双重否定。完整的“复现时分开表述”或“分清三件独立的事”可以列举代码运行、权重下载与数据获取这些概念，但论文实物归属、后续“均已公开”等声明仍须分别核验。转述“原文正文写了代码已公开”须有同类型封存原文支持，并明确区分本次尚未核实的可达状态；被引述、所谓、反驳或撤销的免责声明不能使发布声明通过，空格、逗号或 Markdown 强调也不改变这一边界。

“不能仅据此断定作者资源已正式开源或权重可下载”只在该有界否定范围内处理；“不能否认已开源”、被引述或已经撤回的否定，以及后续独立肯定仍须拒绝。封存原文明示本工作框架及模型检查点发布时，可以明确归于论文转述并同段说明当前链接未确认；不能用其他工作的发布、未来计划或代码发布替代模型证据，也不能把 `temporarily_unreachable` 等状态改成 `available`。

“没有可验证的公开证据”“未确认”“不作开放断言”和“即使权重可下载”只限定各自的否定、待核实或假设短语。裸概念列表须完整且不重复，明确说明不同、独立或待确认；“本文代码公开”“作者团队代码可用”等实际归属不因省略“已”而成为概念列表，后续“全部公开”也不能借列表免责。模态可用、容量或知识可用、损失权重、模态仓库中的线索和临床可用性属于功能或算法语境，不等于作者提供可下载模型、代码或数据；复现所需材料只列获取要求，不代表论文已经供应。

实物归属与肯定谓词须在同一逗号小句内关联；前半明确否认作者开放资源时，不能跨逗号把其中的“本研究代码和权重”接到后半独立的裸概念列表。前后另外出现的真实公开声明仍须单独核验。

原文检查点初始化、数据加载软件开源与作者数据集开放分别核对。来源支持的转述仍须明说当前可达性未确认，PDF 软换行不能切断转引、否定或未来计划的限定，也不能把“预计、可能开源”当作实际发布。链接返回 HTTP 200 只证明链接可访问，不能据此断言存档中已有可下载代码、模型权重或完整运行系统。

封存原文明确说明使用第三方基线已发布检查点时，只豁免对应使用短语，不据此认定本文作者当前提供权重；命名基线还须逐项核对名称和使用关系。对既有公开模型的评测也须绑定原文明确的评测数量、比较目标或既有检查点差异，只豁免对应短语，不豁免同句及相邻句中的当前发布或可下载声明。第三方编码器按已发布权重运行的说明须逐项绑定原文的引用依赖、帧率、维度和不微调事实；相关工作中旧语料的地域访问限制须绑定同一旧语料和地域，均不能支撑本文作者当前开放资源的声明。

### 图片准备与安全显示

官方内联 SVG 必须能独立提供完整像素。封存原图若包含依赖未封存网页 CSS／字体的空图标节点，经完整安全与尺寸校验后，可由受控渲染器明确登记为缺少依赖并省略；不能补画图标、默默渲染缺失内容，或让模型猜图。来源 SHA 不符、危险属性、渲染环境缺失、超时和普通子进程错误仍须阻断，不能统一当作不可用图片跳过。

官方内嵌 SVG 的数学排版只在真实 MathML 节点中接受 `mstyle`、`displaystyle`、`symmetric` 和 `movablelimits` 等静态设置。图内填充只接受精确的 `url(#元素ID)`，且必须指向同图唯一的 pattern 或渐变节点；LaTeX 的 `--ltx-fill-color` 同样逐项核验。外部地址、未知节点、重复 ID、事件和动态样式仍拒绝。渲染只生成本次阅读所需的临时 PNG，封存 SVG 原字节和来源 SHA 不变。
图形声明内容可超出原画布时，截图范围还须包含浏览器实际排出的文字与图形；负坐标通过整体平移留出空间，不改图内布局。实际绘制范围仍受同样尺寸上限约束，不能因原画布较小而绕过限制。

封存 SVG 的绘图依赖缺失或成环时，发布器可以从同一组日更封存 PDF 派生完整原页；仅在原图号和完整图注唯一匹配、页面未旋转或裁切且完整 mediaBox 可渲染时接受。页面如实标示“原论文 PDF 第 N 页（含图 M）”，不将整页称为精确裁剪图。原 Reader、旧模型像素 SHA 和四份封存来源不变；独立 `reader-sealed-pdf-page-asset-v1` 证明绑定旧像素、原 SVG/DOM、四源 SHA、PDF 页及尺寸、渲染器和新 PNG。生成清单保存这份证明与指纹，审查和推送重新核验来源、输出字节和页面；新页面须通过正常图片审查。正文导航链接不属于绘图依赖，无匹配或歧义时拒绝，不猜补 defs、不删图，也不冒用会议 PDF 身份。
旧 schema-v3 清单没有派生字段时，按原输入投影和原 Reader 像素逐项只读核验，不追溯补签。新生成清单必须保存派生列表与指纹；删除字段不能让替代的新 PNG 冒充旧像素。旧清单明确拥有而新一轮不再生成的资产，由正常安装日志绑定原 SHA 和安装前字节后列为删除项，不能手清无关图片。

### 核心摘要的结果与方法衔接

来源中的概率、统计估计、形态测量、听测准确率和表示相似度，也可能是实际结果。识别时须保留原文的观测动作、测量对象或评测条件，以及指标和数值的局部对应，不能只因出现数字或指标词就认定有实验结果。阶段编号、设备与样本数量、预设阈值、假设例子及转述他人的结果，不能冒充本文实测。来源有结果也不证明摘要中的比较对象、数值归属和协议已经正确，整篇检查与独立审查仍须继续。

会议 Reader 恢复的上游预检、Node 页面暂存和 Python 展示都使用同一篇已认证全文核对核心摘要；全文 SHA 必须对应正式记录。不能让缺少全文的检查先授予 Reader-only 路线，再到页面阶段才发现原核心摘要不合格。来源识别误报先以真实保存稿和封存来源复现，停止生产后修正规则；不为迎合误报把真实结果改写成“原文未提供”，也不重置旧次数或费用。

摘要中明确说明推理所需的前向计算次数，或带单位的运行时间，也属于运行负担。检查程序应识别这些实际说明，不强迫文章添加“成本”或“未披露成本”；否定、假设和无单位的时间数字不能据此通过。Node 与 Python 采用同一规则。

有明确单位的实际监督微调或强化学习阶段时长同样属于运行负担；训练语音本身的时长只是数据量，假设训练需要的时间也不是已报告运行成本。

核心摘要中的实验设置可以是以数字开头的明确基准名，运动质量 MotionQ 仍须与比较对象、数值和方向同句对应。布局进入块筛选、选中键块交给注意力内核、再恢复原顺序，属于实际产物交接；仅列组件、讨论假设或明确否定执行不算方法说明。结论明确限定一种注意力处理、另一些注意力保持原样时，也应识别这一范围限制，不能强迫作者添加无关领域词。

已实测的“在具体数据集五折交叉验证下／中／上”属于明确实验设置，Node 分析与 Python 发布必须作相同判断；同句仍须包含指标、比较方向、数值及比较对象。假设、计划、未来或否定进行的交叉验证不能替代实测结果，零折或仅提到交叉验证也不能通过。

明确人数的听辨、主观或重复聆听实验，明确位深和采样率的语音或音乐范围，以及具名的匹配、失配、跨域或未见说话人测试，可以构成具体设置。新增设置识别仍要求指标紧邻结果谓词和数值；完整“以某指标计／衡量”后的结果须明确归属于方法、系统或测量对象。新增对数似然比代价、声对比度和声压级只按紧邻数值的结果谓词识别，不能只是模型名的一部分或泛称某因素更重要。人数、年龄、设备数、训练时长和最优参数不能借附近指标名冒充结果。编码器输出的具名向量经编辑形成同名带撇变量后，只有下一解码器明确将这个新变量作为输入，才构成这类三步交接；记录变量名、把它用作文件名、改用另一变量、否定使用或丢弃均不构成方法链。年份与汉字相邻时，Python 按 Node 相同的 ASCII 标识符边界移除年份，保留真正的模型标识和结果小数。核心语义通过仍不等于整篇分析、评分、Reader、来源事实或发布资格通过，也不授予新的付费次数。

核心摘要允许用具体录音听辨条件说明 Sethares 不协和度的实测变化，也允许按硬件、房间数量及镜像源阶数说明平均仿真耗时。比较必须给出对应数值、单位和一致方向，计划、否定测量与假设不能代替已报告的结果；原文事实仍须独立核对。

### 事实原句修订与文字保护

正文中的“表后解释：”等写作标签，以及描述来源绑定、HTTPS 检查后要求“不得声称”的工作指令，都须改为自然的结果或资源状态说明；作者原文引述、公式、代码与真实表格仍受保护。已签文章进入局部修订时，来源引文对象须先核对原引文 SHA，再恢复为同一逐字字符串，不修改原计划和来源文件，避免把程序派生的引文格式误判为来源错误而阻断正文局部修复。

已有签名文章的事实局部修订使用独立提示词和协议版本。请求只包含获准正文中的完整错误原句、具体纠正意见和已核验原文证据；仍返回原正文局部补丁，句外字符及表格、公式和图片绑定不扩大授权。请求与成功记录保存实际提示词指纹，旧提示词原字节通过 Git 核验，旧费用记录保留。此方式不修改配置的尝试上限，不删改原付费记录，也不代表模型返回的修改已完成最终事实验收。

可用 `node --test tests/reader-fact-local-prompt.test.js` 检查提示词范围和拒绝边界。设置 `PD_READER_FACT_LOCAL_REQUEST_DIR` 与 `PD_READER_FACT_LOCAL_FEEDBACK_DIR` 时，还会重放四份真实失败请求的构造；未提供真实样本时明确跳过该项，不调用模型。

已核验事实的局部修订使用 `prompts/api-reader-fact-local-v3.md`，仅修改明确获准的正文或术语组合解释中的完整错误原句。术语列表、表格、图像及其他字段不在授权范围内。模型请求前检查全部仍存在的错误原句：出现重复、位于引文或其他未获准字段时停止，不发送只覆盖部分错误的请求。旧 v1/v2 提示词按原 SHA 从 Git 读取，已付费记录保留；新版本有独立输入身份，最终仍检查全文与来源。

普通局部修复保留完整论文和资源证据，仅按允许修改的内容提供实际需要的操作说明。文章仍经过全部既有程序检查，并须独立核对论文事实。术语组合可有 2–4 个不同概念，每项 2–48 字符，解释各项分工与组合意义。新请求使用文章 v9、局部修复 v13；v8/v12 及更早版本的原字节从 Git 按 SHA 读取，供原记录复核。复杂操作继续使用经原 SHA 核验的完整来源操作说明，实际使用字节参与实现指纹；旧付费响应不会被标成新提示词结果。

### 批量刷新与来源检查

批量刷新读者文章时，进入和结束各完整核验一次封存来源；每篇在等待锁之前和取得锁之后都重新读取正式数据，并核验当前论文的四份来源文件及完整论文集合。认证只在当前调用内有效，不缓存论文正文或来源内容。单篇入口仍各做一次开始与结束全批检查，因此此优化主要减少批量入口的重复读取，不能据此声称模型生成也按同样倍数加速。
