# 深度解读的讲解与比较方法

解读应让读者能够复述方法的执行过程，并判断实验实际支持了什么。结构和来源检查是必要条件；只把字数写够、多放几张表或者加个生动的比喻，都说明不了文章写得好。

## 写作约定

开场说明任务的输入、输出、改变对象和保留条件，再用具体场景解释难点。介绍组件时沿实际执行顺序说明各自接收、处理和传递的信息，分清训练与推理，以及哪些参数冻结、更新或重置。

关键设计需要解释障碍和取舍。只有真实消融才支持“拿掉组件后会怎样”的实验结论；机制推测应标明依据和边界。公式要讲清信号、分布、可学习参数、近似及梯度路径，不能用公式或比喻跳过计算过程。

实验围绕比较问题展开，交代数据集、停止点和指标方向，分清绝对值、增量与百分比。一项指标变好不能替代其他指标的结论。表后解释最有价值的收益、代价和适用边界，不逐行重复表格。结尾给出复现步骤及尚待验证的问题。

代码、权重、演示和可部署系统分别说明。训练资源不等于推理资源，参数冻结也不等于实时。原文缺少某项证据时，只能说明尚无法判断，不能把缺失证据写成技术错误。

本文记录的 InfinityEdit 微信解读示例用于参考任务辨析、模块分工、执行顺序、基线比较和复现入口的写法。示例不是其他论文的事实来源，其绝对化承诺或单次表现不能作为一般保证。

## 生成与修复

### 写作输入和页面内容

默认 `reader-source-only-v1` 只把论文原文证据与实际图片像素交给解读模型，不重复输入正式分析正文、评论或旧解读。正式分析的 13 个标题、评分和来源记录仍保留，API 函数签名兼容，但这些文本不再作为默认解读素材。

有明确反馈的修订使用 `reader-source-signed-revision-v1`，参考当前已通过结构与来源核验的解读。输入模式进入阶段和失败候选指纹，不能跨模式复用旧稿；参考稿帮助保留正确内容，不能替代论文原文。

`beginner-researcher-v3` 的 `plan.oneSentenceThesis` 用于页面元数据、检索描述和一句话主线。当分析声明 `core-summary-detailed-v3` 时，单篇及汇总页的核心摘要必须逐字对应详细摘要阶段和评分阶段绑定的正文，不能退化为一句话。发布依据同时核对摘要规则、正文 SHA、阶段绑定 SHA，以及评分阶段的摘要输入、输出 SHA。

尚未升级的旧记录可以使用原兼容显示，但不能取得新的 `llm_api_production` 资格。旧 `imageSupplement=complete` 若没有插图前正文，不能仅凭三个自声明 SHA 证明当前发布有效，须升级为现行 Reader 流程。受控插图来自核验过来源和像素的图片安排。

当前 Reader 页面不再展示正式分析中的旧点评、资源复现配置或自然语言评分理由，以免提供两套解释。资源区只输出已核验的资源类型、原链接、重定向终点和可达状态。“模型相关资源”不一定是本文权重，链接可访问也不证明许可证、下载内容或可复现性。缺少记录只说明本次尚未核实开放状态，不能说论文没有开源。

八维分数和总分只在页首显示；页尾评分来源由代码按模型和协议元数据生成，说明分数是系统判断而非论文实验事实。旧分析的审查文字保留在保存的分析结果中。前言、资源、评分和汇总对应内容按实际数据重新核对；发布代码变化进入生成和审查指纹。历史 API v1/v2 及 Manual 页面继续采用对应兼容布局。

渲染时只为计划中精确匹配的独立术语解释段补齐加粗结束符后的空格，不改原 `article`、`plan` SHA、代码块或表格、公式来源字节。最终页面采用同一渲染结果核验。

### 失败候选与局部修复

`scripts/lib/reader-contract.js` 同时供提示词和解析器使用。正常生成先输出完整计划；有效 JSON 未通过结构、来源或质量检查时保存失败候选，随后只能修改报错允许的节点。补丁须匹配整稿及旧节点 SHA，合并后重新运行完整检查，不能覆盖未授权章节。

表格数量不足使用 `reader_table_count_insufficient`、`requiredCount`、`actualCount` 指定问题。`diagnosticOnly: true` 的记录仅供参考，不触发修复动作。新诊断不从自然语言报错提取动作；旧保存文字只在限定兼容读取中使用。已有表格缺来源记录时，修复对应记录；确实缺表时才补表。自动定位要求唯一的顺序对应和明确的修复范围，歧义仍会停止。

局部修复通常最多输出 8000 tokens。一次补丁恰好在基础上限截断、且候选仍符合额外恢复条件时，程序保存失败草稿并停止；下次显式续跑才可使用一次较高预算，默认最多 16000 tokens。这次机会与实现升级的额外恢复共用，不能叠加。自定义上限由正文和基础修复预算计算，最高 16000 且不超过正文预算。只要模型返回内容，就计入尝试次数，纯传输故障无内容不消耗；截断 JSON 仍不合格。

两次无进展会停止。相同输入续跑可恢复候选，但来源、像素、模型、提示词、内容规则或预算变化后不能借用旧候选。局部修复仍携带必要来源证据，不能保证每次输入 token 都很少；它减少的是重复输出及误改范围。

### 表格和公式

原表结构可靠时，通过 `selection` 选择真实 DOM 行列并放置 `[[TABLE_N]]`，由代码生成 Markdown 和逐格来源记录，不能用 `source_quotes` 绕过结构化选择。最低表数按实际送入生成器、经裁剪的 `TABLE` 证据数量计算；普通 v3 要求由当前 `readerRequirements()` 决定，不能用未经裁剪的原始证据条目总数代替。

代码会推导真实表头、修复唯一缺失表头，并把带数字的 `Ours`、`Proposed`、`Baseline` 等全 `th` 强调行识别为数据行。全部行都像表头、表头为空、MathML 双写或 TeX 无法安全逐字显示的源表，会在生成前标为 `eligible=false`。

原表不适合结构化选择时才走逐字引文路线。缺少部分数字列或行的引文，代码可按明确的来源对应关系裁去没有证据支持的部分，但仍须至少两列及一行数据。`[[TABLE_N]]` 和来源记录只有存在唯一、保持顺序的对应时，才自动重编号或去掉没有对应来源记录的手写表格；歧义不能猜。

每个数字和单位都要能对应原表单元格或完整原文引文；展示公式使用结构化原始 TeX。跨节近重复检查提供提示，不自动删改事实。表前应提出具体比较问题，表后解释结果和边界，不能靠通用过渡句完成检查。

## 来源解析约定

MathML 和 TeX 的同值重复可能显示成 `3.093.09`。`.119` 与 `0.119`，以及带比例、分数、百分比、量级或括号单位的等价写法，按 Node 与 Python 共用规则核对。其他重复数字只有完整、精确相等时才可恢复；不同数字、正负号或单位不能合并。

恢复双写值必须保留完整单位。`seconds` 可规范成 `s`，但不能把下一行 `SE` 的首字母当作秒，也不能用带单位的来源证明一个裸值。Node 分析及 Python 发布须使用一致规则。

无来源的表格数值应进入内容修复，不能静默改成内部校验占位，也不能宣称作者没有报告。前言表中的作者机构只依据明确上标及唯一映射绑定。表格缺少具体论证时同样返回内容修复，代码不能拼接“缺少方差、跨域表现、部署成本”等无来源结论。代码可修复 Markdown 空行，不能用套话代替论文解释。

反馈修订出现完全相同的术语解释前缀时，可由代码去掉重复部分，记录修改前后 SHA 并重新绑定正文和计划，不能冒充新的模型输出。结构化证据文件采用稳定键序 SHA；兼容早期保存的证据文件时，须核验全文和来源清单，并满足记录的解析器版本重验条件，或属于实现认可、表格、公式和图片数组均为空的无布局来源。不能用任意旧布局声明放行，也不修改已保存的文件。统计文章质量时，只有官方图或公式插入块能重新精确核验，才恢复其原占位标记。

同篇图片允许个别瞬时失败，但至少须成功准备一张；单张响应超过上限时跳过。提供方明确拒绝损坏或不兼容 PNG 时，先转白底 RGB JPEG 再重试，仍绑定实际输入像素 SHA。新日更页面使用对应的 arXiv 官方 HTTPS 图片 URL，不把图片复制到博客仓库或运行缓存。

## 用量记录与隔离实验

请求用量默认保存在忽略目录 `data/runtime/llm-usage/`，不保存提示词、正文或密钥：

```bash
npm run usage:report -- --paper 2609.03622
```

`--date` 按北京时间筛选，`--dir` 可查看隔离实验。实际提供方用量、字符估算、缓存与推理子项、失败及正文是否采用分别记录；未报告的值为 `null`，不据此推算账单金额。

`scripts/evaluate-reader-efficiency.js` 默认离线重验，要求显式提供 `--paper`、`--source-text`、`--artifacts`、`--paper-snapshot`、`--output-dir`，使用同源全文、完整结构化证据文件、已核验快照和全新空输出目录。证据文件的哈希须满足该入口实际的 `JSON.stringify(artifactBody)` 计算规则，不能认为任意采用稳定键序哈希的证据文件都自动符合。

无图快照可通过图片输入检查。如果有图，每幅须有仍存在的 `cachePath` 和可重验的像素 SHA。当前有图日更不持久保存这些文件，不能直接套用该实验入口，也不能为运行实验制造旧缓存。是否适用由输入逐项校验决定，不能简单按新旧版本推断。

只有显式 `--live` 才请求模型。隔离模式最多 3 次逻辑请求，每次 1 次传输尝试，完整输出 24000、补丁 8000 tokens。输出不得进入 `data/current`，不更新正式分析或发布博客。离线运行会写实验报告；生成通过只证明解析检查通过，仍须独立事实与视觉审查。详细实施记录见[改进计划](reader-efficiency-plan.md)。

## 单篇前后比较

先保存原博客字节、正式分析、解读、提示词、模型和原文 SHA，并记录其他论文的内容 SHA。对照时写清修改了通用提示词、解析程序，还是另加了定向事实核查反馈。

使用同一论文来源和模型重写；只比较解读时，保持主分析和评分不变。检查结构及来源后，再按原文核对关键事实、比较条件和因果边界。分别评价准确性、机制解释、图表完整性、重复程度和可操作性，不因文风改善提高论文分数。新版存在实质错误时先修复，再按 `generate → review → push` 完成单篇发布。

显式 `api:reader:refresh -- ID --feedback '反馈'` 以当前已通过结构与来源核验的解读作为修订参考，保留正确事实和图表，不从旧正式分析自由发挥。参考稿及模式版本进入指纹，但参考稿不是事实来源，也不能绕过来源、图片、文风或发布检查。正常无反馈生成不使用此模式。

单篇比较只说明这次受控修订的表现。同时修改提示词、解析程序并加入人工反馈时，不能把所有改善归因于提示词，也不能宣称对所有论文都有效。

## 作者与机构的当前来源重放

作者解析结果自身的 SHA-256 只能检查该记录内部是否一致，不能证明姓名与机构确实来自原文。新获取的官方 HTML 在原始 UTF-8 不超过 8 MiB、没有内联 `data:image`（包含实体编码）、SVG 或 canvas 图片时，保存完整原字节于 `source-runtime.json.readerAuthors.sourceHtml`。这份 HTML 只用于本地重新解析，不进入模型提示词，也不作为图片缓存；运行元数据总量仍不得超过 64 MiB。预算或图片检查不通过时不保存这份证据，机构只能明确标为不可得。

生产复用会先核验封存文本、结构化解析结果、完整原 HTML 及当前 Reader 阶段的 SHA，再从完整 HTML 重新解析姓名与机构；会议 PDF 则从已保存的全文重新解析作者上标。旧来源没有完整 HTML 时，不能根据旧作者数组或该记录自身的 SHA 继续声称机构。原文不能可靠解析时，作者刷新使用受控论文元数据姓名，并将机构记为明确不可得；不修改旧封存文件，也不给旧记录重新计算凭证。作者刷新与正常 Reader 刷新保持可用，纯图片刷新及评分中保留旧 Reader 的路径必须先满足当前复用来源记录所要求的检查。

历史会议的同步暂存复核没有全文时，只允许安全的“机构不可得”旧记录：必须重新核验计划中的 PDF 和原元数据文件 SHA、从原元数据取得完整姓名集合，并逐人核对姓名顺序、元数据绑定、明确不可得机构绑定及当前阶段 SHA。任何肯定机构、借来的姓名、缺少原元数据姓名全集或仅有文字标记、没有所需来源证明的记录都不具备此兼容资格。不会为这个分支新增来源运行协议或调用模型。

该限制作用于当前分析复用和发布资格，旧结构成功、只读状态及已发布历史统计继续保留。旧页面不会自动重写。Node 和 Python 发布入口共用不加载模型路由的纯作者解析器；Python 只通过私有文件描述符传递有大小限制的本地资料供本地重新解析，同时限制子进程时间和输出。
