# 工作台审查、同步与发行手册

适用于同时修改 Mac 与 Android 的工作台、同步协议或安装包时安排审查与验收。各版本通过的项目与实际环境见 [1.3.0](workbench-1.3.0-review.md)、[1.3.7](workbench-1.3.7-review.md)、[1.4.0](workbench-1.4.0-review.md)、[1.4.1](workbench-1.4.1-review.md)、[1.4.3](workbench-1.4.3-review.md)和 [1.4.4](workbench-1.4.4-review.md)记录。下面的场景是后续验收清单，具体实现以对应协议和发行版本为准。

## 从使用路径检查两个端

| 路径 | 每轮检查的行为 |
|---|---|
| 找论文 | 对照网站核对日更、会议、论文库、分类入口及其顺序。用完整多级分类浏览分类下的全部可用论文。收藏按网站已有分类和真实收藏时间查看。旧记录缺时间时保留未知状态 |
| 打开后再回来 | 从日更、会议、搜索和收藏各打开一篇，返回同一天、同一分类或筛选、原滚动位置及当前页。Mac 用键盘复验焦点，Android 用系统返回和应用内操作复验 |
| 首屏和切页 | 观察空环境首启、已有缓存冷启、后台回前台、快速切换与离线重开。先显示可用缓存，后台刷新和有界预取热门入口。核对请求去重、旧响应不会覆盖较新结果，以及自动刷新后最新日更确实更新 |
| Android 阅读 | 用手机实际翻导读、博客、图片和表格，核对常规字号、系统大字、横竖屏和返回。旧缓存或恢复的 HTML 要跑同样的显示规则。字太大或闪退时记录版本、网络状态、打开路径、实际系统崩溃日志及复现次数 |
| 网络切换 | 在 Wi-Fi、移动网络、系统 VPN 或代理开启时验证同一正常入口。模拟断线、恢复和切换网络，确认后台刷新、缓存阅读及一键同步各自可用。用日志定位 WebView、进程退出和请求错误，网络状态只是复现条件 |
| 配置与同步 | 空环境首启能找到 WebDAV 与 Zotero，优先显示最少必要字段、连接验证和保存结果。自动同步和一键 WebDAV 同步入口并存。能看见上次成功、正在执行、失败原因和可重试操作。Android 保持原生手机操作，Mac 保持可用的双栏、键盘与辅助功能 |
| 移除功能 | 先查公开入口和历史资料是否依赖该功能，再移除重复的界面入口或设置。移除自建分类等旧入口时，保留能读取既有资料的兼容路径 |

现行入口见[收藏说明](favorite-collections.md)、[两端功能映射](android-feature-parity.md)和 [Android 字号修订记录](android-1.3.3-review.md)。

## 验证两端合并与重试

1. 先列出要核对的对象以及各自的逻辑身份。个人资料包括收藏、待读、笔记、批注和阅读进度。研究资料包括 PDF、离线导读、研究输入和响应、用量原记录、导出文件及归档历史。比较条目身份、正文、原文件摘要和关联引用。账号密码、模型密钥、本机授权和设备相关状态按各自设置处理。[全资料同步范围](workbench-full-webdav-sync.md) · [两端数据协议](android-cloud-contract.md)
2. 先用隔离工作区和可控传输测正常往返、两端同时编辑、修改与删除相遇、任一端先上传、上传写入后丢失回执、分页缺项、限流、断线重启、并行恢复及写盘失败。确认原件、待传材料与进度分别保存。重试按原编号和原字节继续，完成后回读。完整研究资料的只增合并与个人资料的编辑和删除语义分别核对。
3. 遇到坚果云不给强 ETag 时，不能依赖已存在文件的条件更新。1.4.1 的个人资料修订使用新的内容地址并完整回读。另测旧版客户端改写已迁移文件、同一设备同一修订号出现不同字节，以及相同修订的幂等重试。网站目录论文按站内身份辨认，同时保留缺原 PDF 的真实本地导入冲突用例。[1.4.1 修复和测试范围](workbench-1.4.1-review.md)
4. 用坚果云独立目录复测两端生产同步入口。再用正式包核验 Android 新增临时收藏能在 Mac 打开、Mac 新增临时笔记能在 Android 读到。验证断线并发时，两端从相同旧稿分别保存可区分的临时正文，再交替恢复连接。两端界面和云端只读回验都应能找回双方原稿。记录实际做过的上传顺序、客户端及服务端范围。
5. 撤回测试收藏或清空测试笔记后，两端再同步并核对原有资料。普通同步撤回会留下历史。需要从坚果云历史清理时，先逐个回读待删修订并检查所有成员、共享引用及相关依赖。整份修订里混有用户的收藏或笔记时保留整份修订。只有可以精确定位、证明完全属于测试且授权清理的对象才进入删除步骤。

## 审查、签名与覆盖升级

- 按任务约定分轮核对 Mac、Android、共用协议和发行脚本。每轮记录发现、复现、修复、针对性测试及复审。需要多个子代理时分配明确范围，再由主审核对两个端的相同行为和同一批样例。用户要求三轮或更多时，每轮都要有实际检查结果。模拟器、隔离引擎、实体机、真实窗口和真实账号分别登记。
- 从远端 main 的目标提交准备两端，校验版本号和构建号一致。中文提交只纳入本轮变更，推送到 main 后核对远端提交。若其他工作区有用户改动，避开该工作区。用同一来源固定签名、安装包、验收记录和发行附件。最后一次构建改变了产物，就复验受影响入口。可以逐字节证明相同的资产才复用原验收。
- Android 覆盖安装用原应用身份和发行证书。保留安装前资料的核对记录。升级后核对首次安装时间、原资料、实际启动和一键同步。Mac 检查安装目录、应用标识、签名、公证状态和首次启动。应用程序列表、Dock 固定项与实际运行分别检查。系统阻止启动时先区分安装位置、应用注册和安全提示。按系统提示处理当前应用或钥匙串授权，凭据留在系统输入框及本机密钥存储。
- 联合发行时从草稿按附件身份下载回读，核对两端资产字节、校验表、签名和标签提交。公开后再检查发行页和实际下载。记录设备版本、包字节身份、同步方向与未验场景。旧发行的删除作为单独的、明确限定版本范围的操作。[Mac 发行说明](mac-app-release.md) · [Android 验证说明](android-validation.md)
