# 选择博客展示的词表

## 三条流程共用的目录与呈现

日更、官方会议与历史博客更新使用同一份 `config/tag-catalog.json`。当前可选范围与[新版研究方向目录](https://nanless.github.io/audio-paper-digest-blog/tags/)的 **386 个概念、九个分类维度及父子关系**一致；原有262个概念与已修正的定义原样保留，仅追加目录中已有的124项，不创建词表外标签。

总目录保持完整，包括“0 条”方向。每篇仍只选择有本篇证据支持的3–5个直接概念，包含明确主任务和主方法；正文、汇总卡片与单篇分类卡片只呈现这些选项及它们的祖先路径。没有命中的分类维度、兄弟方向及全套目录均不出现在文章分类块中。祖先是导航，不写入 Hugo `tags`、`conceptIds`，也不另计为直接命中。可见路径链接到同一论文库的概念筛选。

原分类文件按原始SHA归档。只有原文件SHA真实、完整分类维度和原概念逐字段均为新词表前缀的纯追加升级，才可只读重放旧提示文本、阶段绑定、检查点和原选择；不补签、不填写升级注记、不改旧论文记录，也不因此重新请求模型。存在改名、改父级、改原定义或坏升级注记时，继续按原严格升级规则处理。

日更生成器将版本目录和新快照纳入同一精确发布清单。会议在生成及审查/推送共用的生成清单核验中，历史在规划、生成、审查、激活和推送前，核对站点 `data/` 与 `static/data/` 的版本目录和原快照；缺少本次分类SHA或双份内容不一致时阻断，不能让 Hugo 静默隐藏标签。首次词表同步只发布受控生成的词表资产，须审查精确差异、通过 Hugo 并验证远端及部署；不借此重写旧论文或改动无关页面。

分类词表与已批准的展示词表允许保留各自的定义说明，概念身份、顺序、名称、别名、分类维度、状态及父级路径必须一致。下面的原策略、归档和SHA约束继续适用；同一386项范围不能代替这些来源核验。

发布器默认用当前项目词表生成博客目录。已有明确批准的展示策略时，也可以展示归档中较丰富的词表。这个选择只影响目录，不改变论文的标签、主任务、主方法或原分类所对应的词表 SHA，也不重新判断旧论文的分类。

当前策略文件是博客仓库的 `data/tag-presentation-policy.json` 和 `static/data/tag-presentation-policy.json`，格式为 `paper-tag-presentation-policy-v2`。项目的 `config/tag-display-policy.json` 保存已批准策略，生成时核对它与博客已有策略的原始字节；博客尚无策略时，可以安装这份已批准策略。两处博客副本须逐字节相同，缺一份、格式错误或内容不同都会停止，不能悄悄改用默认版本。没有博客策略且没有项目批准配置时，才使用默认词表。

旧发布记录中的 `taxonomy-presentation-policy.json` 和 `paper-taxonomy-presentation-selection-v1` 按原格式核验和恢复。它们不是创建新发布文件时应使用的名称，不能把新格式写到旧文件路径，也不能改写旧凭证使新字节通过。

正文与汇总中的概念路径链接保留 `PAPER_DIGEST_BLOG_BASE_PATH` 部署前缀，默认指向 `/audio-paper-digest-blog/papers/`。共享渲染器同时支持站点根目录部署，并拒绝站外地址、路径穿越或查询片段作为部署前缀。

生成的Markdown保留共享渲染器输出的多级分类块，供独立审查及离线阅读。单篇网页由页头的 `paper_tags` 呈现同一分类；只有该页头确实已呈现经词表核验的分类，且正文恰有一对完整、有序的无空白边界注释时，`reader_article_content` 才在网页渲染时去掉这一块，避免分类重复。汇总页保留每篇的分类块；没有边界的旧页面或边界不完整、重复、顺序异常的内容均不猜测删除范围。这个处理不改源Markdown，不删除Reader正文，也不批量修改旧文章。

## 已发布页面切换到当前呈现

共享代码和站点词表资产各自上线后，既有Markdown仍保留原字节。用户要求某一批页面采用当前多级呈现时，须对该明确范围重新生成单篇及汇总，随后正常审查、精确推送、核验对应部署和全部目标页面。页面生成只读复用当前资格仍有效的分析、Reader、原分类与来源，不为显示路径而重跑付费写作；内容SHA未变的通过页继续复用原审查结果，变化页仍须独立审查。

站点首次需要修正上述页头/正文去重模板时，先单独审查模板精确差异并进行受控中文提交、推送与远端OID核验；模板不混入日更页面发布器的允许路径。随后以同步后的博客 `main` 为基线正常生成、审查、推送整批目标页面。新的批次凭证须绑定该基线和实际Hugo运行时，最终部署与逐页核验须覆盖模板及页面的共同效果，不能复用模板变更前的旧凭证。

| 流程 | 多级呈现实际调用 | 已有页面的受控更新位置 |
|---|---|---|
| 日更 | `publish-to-blog.py` 的单篇与汇总调用 `render_paper_tag_hierarchy()`，再调用共享 `tag_presentation.py` | 已发布完整日批显式使用 `blog:generate -- --date DATE --republish UUID` → `blog:review -- --date DATE` → `blog:push -- --date DATE`；保留本批来源和正式结果 |
| 官方会议 | `conference-page-render.py` 生成单篇；`lib/conference-postprocess.js` 对汇总成员批量调用同一共享渲染器 | 先让原 `conference:process` 的单篇暂存与汇总通过当前实现检查，再走 `conference:publish:generate/review/push/verify`；不能复用过期页面证明 |
| 历史更新 | arXiv单篇通过公共日更发布器、真实会议身份通过 `historical-page-render.py`；`lib/historical-direct-aggregate.js` 对每日、会议及会议任务汇总成员批量调用共享标签渲染器 | 同计划 `history:run` 重暂存旧实现页面，`history:aggregate` 重建对应汇总，再走 `history:publication` 的生成、审查与发布；冻结URL和原来源不变 |

审计时同时核对页首的直接概念和最终渲染路径：祖先仅作导航，不能通过向 `tags` 追加父级来制造多级效果。站点总目录始终保留零计数方向，不能将文章的“仅选中项”规则用于裁剪总目录。

日更已发布保护不因模板变化自动解除，`--republish UUID` 是明确范围的受控重发布入口；原发布证据不可变备份，待激活事务须同日期同UUID恢复，正式分析、Reader与费用不改。它不冒充新分析或fresh提升，也不允许选定子集/自定义数据重签原发布，完整边界见[同来源重发布协议](data-format.md#同来源同分析的日批重发布)。

会议汇总的多级统计区只列本期命中的分面和子树，分别保留直接计数与子树去重计数；各级链接使用同一部署前缀及概念ID进入论文库，目标筛选范围是全站，计数范围仍是本期。历史汇总页首的概念集合仅代表成员的去重主任务，正文逐篇分类仍使用各自完整所选集合。

## 策略中的六个字段

当前策略只允许以下六个字段，五个 SHA 均为 64 位小写十六进制字符串。

| 字段 | 含义 |
|---|---|
| `contract` | 当前格式名称 `paper-tag-presentation-policy-v2` |
| `baseRegistrySha256` | 策略签发时的基础分类词表原文件 SHA |
| `baseSnapshotSha256` | 策略签发时按固定格式生成的基础原快照字节 SHA |
| `preferredRegistrySha256` | 已批准展示的归档词表原文件 SHA |
| `preferredSnapshotSha256` | 归档中所选原快照的完整字节 SHA |
| `preferredProjectionSha256` | 按固定历史格式重新生成的标签提示文本 SHA |

基础词表与展示词表的原文件 SHA 必须不同。原词表文件、归档快照、当前展示副本和标签提示文本是不同内容，不能互换哈希。展示副本使用新格式名称，也不代表归档原快照或原词表变了；`preferredSnapshotSha256` 仍核对原归档，不核对换了格式头的展示副本。

历史标签提示文本保留 `historical-taxonomy-prompt-projection-v2` 哈希前缀。文本包含固定格式、词表版本及 SHA、分类维度、概念 ID、首选标签、定义和范围说明，不能缩成 ID 列表再计算哈希。这里的旧前缀用于核验既有批准记录，与当前模型提示的格式分开。六字段策略用于核对所选内容，本身不证明用户已经批准该版本。

## 从已有归档选择版本

当前展示副本分别保存为 `data/tag-catalog-snapshot.json` 和 `static/data/tag-catalog-snapshot.json`；版本目录分别为两处的 `tag-catalog-versions.json`。版本目录保存原快照对象，展示副本只按当前格式呈现所选快照。两类文件分别使用 `paper-tag-catalog-snapshot-v2` 和 `paper-tag-catalog-versions-v2`，路径与格式须对应。

新生成的词表归档使用 `data/tag-catalog-history/<SHA>.json` 和 `static/data/tag-catalog-history/<SHA>.json`，两份文件的字节须相同。快照对象、概念顺序及来源 SHA 保持原格式，不因为目录改名而替换快照的格式名称。

已有 `taxonomy-snapshots` 目录、`taxonomy-catalog.json` 和 `taxonomy-registry.json` 保留原路径与字节。生成器读取并核验这些原记录，将其内容纳入当前版本目录；不能移动旧来源文件，或把新展示副本当作原快照。相同词表 SHA 对应不同快照对象时，直接拒绝。新归档目录已经存在时，缺少副本或文件损坏会阻断生成，不能退回旧目录掩盖错误；展示策略所选的原快照仍须符合批准的完整文件 SHA。

所选版本须已经归档，两个归档副本与版本目录中的原对象须完全一致。概念数组必须以基础快照的全部概念开头，原顺序及每个对象的全部字段都须保留，包括名称、别名、定义、范围、状态和上下级关系。仅 ID 或数量相同不能证明内容未变。发布器还会重建上下级关系和标签提示文本，核对批准的 SHA；策略不能制造缺失版本，也不能仅凭概念更多、日期更新或名称相近选用它。

策略的签发基础与后来用于分类的当前词表分别核验。当前词表只修正概念的 `definition` 或 `scopeNote` 说明时，可以继续使用原已批准的历史展示版本，但必须从归档重放原签发基础：基础与所选版本的两个原字节副本、版本目录对象、策略 SHA 及完整前缀关系均须通过。当前与签发基础的格式、词表版本、概念数量、顺序及所有其他字段必须完全一致；名称、别名、分类维度、层级、状态或未知字段的变化都会拒绝这种兼容。

这种兼容不修改策略或历史快照的任何字节，也不把当前说明混入历史展示快照。当前完整快照按自己的真实 SHA 另存；新论文的标签、主任务、主方法及分类证明仍使用当前词表。历史展示保留其当时的定义和范围说明，并继续标示新旧分类混合，不能据此声称旧论文已按当前规则重新分类。

策略含有重复 JSON 键或多余字段，策略或所选归档缺少副本、内容不同、使用符号链接或多个硬链接，以及词表未知、归档缺失、SHA 或上下级关系不符时，都会阻断生成。这些检查确认输入与批准内容一致，不能代替对展示版本的批准。

## 生成、审查和恢复

生成器保留策略 JSON 的原始字节，包括排版和尾换行。策略及展示文件进入暂存目录、安装记录、生成清单和当前批次审查，推送时只提交凭证允许的精确差异。单篇发布仍不得借此升级全站词表。

生成或审查后，即使只改一个空格，也须重新生成并审查对应变更，不能补改旧发布凭证。逐页审查仍按相对路径和页面内容 SHA 复用：正文未变时，无需因为策略元数据变化再审同一页面，但当前批次检查和新的发布凭证不能省略。

安装中断后，先读取安装记录所绑定的完整原字节，再按记录的格式核验和恢复。程序接受三种完整文件集合：旧展示文件配旧归档目录、当前展示文件配旧归档目录，以及当前展示文件配新归档目录。恢复保留记录中的原路径与字节，不补建新目录；新旧归档混在同一集合中会被拒绝。旧归档中未被展示策略选用的快照仍按原规则比较完整对象，不额外要求 JSON 排版一致。目标文件已被外部修改时，程序拒绝覆盖；不能改安装记录来让另一份字节通过。

展示目录升级不代表旧文章已完成来源分类，也不生成新的历史分类证明。推送后仍须核验对应部署和正式页面，具体要求见 [发布说明](../AGENTS.md#博客三阶段与远端证明)。
