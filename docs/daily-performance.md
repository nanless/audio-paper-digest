## 造成长尾的具体机制

1. **系统误报被当成正文错误。** 下载包、运行系统、开源代码的概念区分，以及软件功能结果与模型性能摘要的区别，曾在公共校验中混淆。系统错误必须停产后用真实原稿和反例统一修复；再付费写一遍不可靠。
2. **Node/Python 对同一原表显示理解不同。** 双写数学符号、DOM 单元格与原始 TeX 等问题在发布边界才暴露。原表错误不属于正文局部补丁可以改变的范围。
3. **第一个阻断掩盖后续独立问题。** 修一处再暴露下一处，反复制作清单、重跑资格、重新审稿。诊断应收齐可独立执行的检查，依赖失败的后续项标明 blocked_by；最终完整 parser 仍须通过。
4. **预览没有完全重放真实调度。** completed-core 私有上下文、pending 义务、诊断迁移、旧付费候选与新空候选的选择，均影响下一请求。预算保护正确阻断，却被误当成“应当可局部恢复”。准备结果必须来自同一真实生产函数。
5. **临时资源观测影响生成身份。** GitHub 探测 deadline 曾改变 Reader 输入。不能冻结错误状态；应在正常身份与评分重放边界中明确处理资源变化。
6. **保存门槛晚于方案预检。** 预览参数通过并不代表真实 pending/父稿组合可保存；这次 Teacher 的 tag-only 父组合在正式保存时才暴露。需要在付费和人工方案提交前检查真实保存门槛。
7. **重复验证放大工程往返。** 69 篇一次成功资格原耗时约 27–29 秒，内部 105 次 Python 启动；状态回写、批次 reconcile、保存及汇总反复调用。零请求也可以耗费数分钟。

### CI 在独立 runner 隔离分片

提交 `8fc4421e`。每个 Node 版本分别运行 4 个原 JS 测试文件分片、完整 Python、完整语法与数据检查；共 12 个独立验证 job。测试文件来自 `package.json.scripts.test` 的真实集合，使用 Node 原生分片，各自仍串行执行，避免共享目录测试同时写入。
