# 日更耗时测量与优化

本页说明怎样定位抓取、分析、恢复、发布和站点构建的耗时，并汇总已有测量。操作顺序见[手册](../SKILL.md#日更耗时控制与尾部收尾)，公共模块见[共享实现](shared-workflow-review.md)。性能实验沿用原来源、响应、失败、次数和费用，正式数据保持原样。

## 先区分时间口径

| 指标 | 含义 |
|---|---|
| 墙钟时间 | 该阶段从开始到结束的实际经过时间。 |
| 累计请求时间 | 各请求耗时之和，并发部分会重复累计。 |
| 请求区间并集 | 至少有一个请求在途的全部时间段，重叠部分只算一次。 |
| 本地处理时间 | 来源读取、解析、保存、渲染及构建等实际观测。 |
| 未分类时间 | 日志粒度不足的间隔，保留为未知。 |

分析模型、博客审查、站点构建和工程 CI 分别测量。记录机器、并发、输入、实现版本、负载及计时范围；解释收益时使用同口径背靠背对照。减少进程或文件读取次数是结构变化，实际墙钟另测。

## 执行时的检查顺序

1. 运行前确认工作区、代理、模型、依赖、并发任务和锁；生产期间冻结共享实现。
2. 完整获取来源窗口，保留已发布去重、候选与筛选覆盖，不以截断输入换速度。
3. 完成本批首轮并保存结果，再收集完整失败集合；区分内容、来源、身份、系统误报和服务故障。
4. 恢复前同时核对原稿 CAS、父包及待完成义务、真实候选、问题和预算。必要时采用来源绑定的人工修正或已授权后续窗口。
5. 分开记录模型等待、本地核验、保存、页面审查、Git 推送和站点构建。最终部署、全页及视觉验收照常执行。

`run-daily-digest.sh` 输出实际执行阶段的目标日期、UTC 开始/结束及累计秒数，失败保留原退出码；跳过阶段不生成假计时。运行中用阶段日志、请求记录和检查点观察，完整状态报告用于要求的状态核验，不作秒级轮询。

## 已有观测

以下为 2026-10-16 日更及随后隔离对照，样本为 69 篇论文、70 个单篇及汇总页面。原发布为 `32c0e717`；[对应部署](https://github.com/nanless/audio-paper-digest-blog/actions/runs/38978013476)保留当时结果。它们是该输入和测量环境的观测，当前任务按其实际运行另记。

## 已采用的实现方式

### 同次调用内复用纯结果

状态回写对当前稿核验一次后分类，下一份报告重新核验。成功、失败、豁免保持互斥，最新失败和待完成义务优先按原规则处理；外部 `alreadyValid` 标志不授予资格。

发布器在同一完整性调用内传递已经计算的绑定；写入前和后续 review/push 边界重新读实际来源。不得增加跨调用缓存、公共跳核参数或自报通过字段。真实来源逐文件变化必须仍被拒绝。

### PDF 提取与作者批处理

PDF 仅在短作用域复用完整输入相同的纯 worker 输出，绑定程序、依赖、解释器、环境和来源。未知启动钩子、非标准 `.pth`、非隔离环境、链接的包或模块走原提取；解释器已核验目标的正常链接保留支持。异常和坏 JSON 不缓存，容量上限 32 MiB/128 项，返回独立副本；来源、表格、单位和资格照常重验。

作者来源批处理最多 8 项/32 MiB，逐项执行原四源、作者机构和父证明检查；全部对应结果通过且最后一组完成发送后才返回。旧单项及超批量单项的 128 MiB 路径保留，任一坏项或来源漂移均失败。

### 会议调度与同步读取

调度先按成功和不可重试项筛选，再为本阶段候选读取真实进度。冻结快照仅用于选工作；派发前重读，保存后读取新进度，下一阶段重新建立。原三次等技术上限、运行级停止及整篇资格不变。

保存候选恢复的锁前、锁内及后续读取分别使用自己的同步作用域，首次和出口均完整核验字节；不跨 `await`、成员、请求或保存缓存。窗口及排除路径走原完整读取。

来源不变断言按真实私有句柄合并重复文件，先核 SHA 和安全策略，再读每个唯一文件的完整字节，无跨调用缓存。父包首次加载后仍每次重读 intent、run、source、analysis 四文件及固定 SHA、成员和父身份；当前子稿及科学资格单独核验。来源实现变化须按同一 PDF、几何和像素正常重算当前证明，旧证明保留。

### 下一请求与连接诊断

`reader-next-request-plan` 展示真实候选、full/patch 类型、问题及余量；问题投影最多 128 项，阻断优先，保留总数、SHA 和省略数。它标有 `notFinalPreflight`、`notRequestAuthorization`，最终守卫仍在正式请求路径执行。完整无写入选择与迁移预演属于后续能力。

显式 `withReaderLocalRequestsOnly` 仅减少可用请求类型。实际需要 full 时，在提示词、请求诊断、usage-start、传输和本次空候选保存前拒绝；原候选、默认停止优先级和费用保持。

CONNECT/TLS 共用模型的有效时间计量，预算 60 秒；系统长停顿与真实无响应分别诊断，已发尝试不返还。详见[连接排障](troubleshooting.md#2-主模型请求失败超时或空响应)。

## 站点构建与工程 CI

站点构建属于博客仓库，独立于论文分析。原部署样本总计 32 分 55 秒，Hugo 自报约 22 分 50 秒；全页检查保留 13,773 个 HTML、903,513 条引用。优化模板与资源配置时继续执行真实 Hugo 正反例及全量链接检查。

已有资源对照同时将 `GOMEMLIMIT=3GiB→6GiB`、`GOMAXPROCS=2→4`，worker 保持 1。原始墙钟为 696.485 秒，扣除明确记录的 93.401 秒 CPU 让行暂停后，原净耗时为 603.084 秒；对照配置总耗时为 553.518 秒。20,009 个输出路径和字节完全相同。这是本机 10 CPU/32 GiB 的单次组合配置观测，峰值 RSS 6.335 GiB；资源、机器和 GitInfo 差异均影响解释。Go 内存限制是[软限制](https://go.dev/doc/gc-guide#Memory_limit)，生产远端收益以其实际运行记录为准。

某些减少调用的方案实际变慢，或收益不足以覆盖复杂度，不应安装。接受性能修改同时要求输出、来源与拒绝规则保持、实际绝对耗时改善；只减少进程数不足以接受。

工程 CI 的现行分片、完整覆盖和触发方式见[维护指南](maintenance.md#什么时候运行远端-ci)。各 Node 版本 JavaScript、Python、静态和 Hugo 要求完整保留；站点部署要求测试与构建均成功。理论并行收益与远端实测分别记录。

## 接受后续优化的条件

- 使用同一真实输入，比较完整输出与所有受保护材料；文件、来源或父稿发生变化继续拒绝。
- 新准备逻辑与真实请求共享候选、父稿、待完成义务、余额和请求类型；变化后重新准备。
- 问题收集覆盖当前完整失败集合，依赖失败项标明原因，最终完整解析器保留。
- 证据裁剪只用于可证明覆盖的单句或完整原表；缺覆盖沿原全量路径，响应后仍查整稿。
- 性能实验不改正式数据、不减少独立科学审计、不抹原尝试和费用。上线和内容质量按正常任务分别验收。
