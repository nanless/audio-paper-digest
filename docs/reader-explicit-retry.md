# 有预算的 Reader 重试

先判断要继续什么，再选择入口。本文面向执行者，说明恢复条件与权限；怎样把论文讲清楚见[Reader 写作](reader-writing.md)和[共同写作约定](writing-guide.md)。所有路径都保留真实来源、原请求、失败和费用。

用户已明确持续授权当前任务的全部必要付费轮时，该授权覆盖同一任务和既定来源范围内的后续恢复，不因技术窗口耗尽而逐轮重新询问。执行者结合真实进展、预计效果和累计成本，自主选择原稿零请求复验、局部修复、必要重生成或后续受控付费窗口。本文的许可、清单、回执和 UUID 是落实已有授权的执行凭证；登记新凭证不等于要求用户再次批准。

每个窗口的请求、输出和恢复上限仍按当前实现核验；旧次数、无进展、失败和费用不清零。没有正文进展的重复请求须先停派查因，运行级故障及来源或身份不明仍阻断；持续付费授权不降低质量检查，也不允许无限盲重试。任务、来源或人工修改范围实际扩大时，再核对是否仍在原授权内。

| 当前情况 | 应走的路径 | 模型与修改边界 |
|---|---|---|
| 普通失败稿，原额度仍有余额 | 正常批次恢复，先完整重验原候选 | 由真实诊断决定下一次原预算请求，不清旧计数 |
| 已完成主文，需要新 Reader 事实纠错 | 严格 Reader-only 来源反馈；已签稿少量原句可用受限局部模式 | 保护主文、核心摘要、评分和标签；核对跨输入原余额 |
| 已签名 Reader 的少量确定性修正 | 显式签名稿 v1/v2 入口，绑定完整真实父稿、原付费档与获准范围 | 不发模型请求；每篇仅1–8个已有节点，仍完整核验 |
| 原额度耗尽，确需新增付费 | 依据已有任务授权核验并登记后续窗口清单，无需逐轮确认 | 新旧费用与次数分别保留；不能把新轮称为原余额 |
| 会议原失败集合的独立追加 | [会议迁移追加恢复](conference-workflow.md#原额度耗尽后的独立付费恢复)，同一窗口继续使用同一 `--recovery-manifest` | 原会议来源与父子稿 CAS；当前单窗口最多3轮，Reader累计6次、完整长文2次；这些是技术限额，冷核仍禁止模型 |

会议真实尾集混有普通失败与原窗口延续时，同一登记合同显式使用v3，逐成员绑定初次普通失败的完整材料树或原严格延续链；仍覆盖完整停稳失败集合、保留旧窗口与费用，不拆集合重新授额。旧v1/v2按原含义读取。

“准备”只构造可核对的材料；“预览”只检查私有副本；二者不代表已执行修改或安装了新的技术窗口，也不撤销已有任务授权。本文中的 SHA 是内容身份，CAS 是写入前比较完整原稿身份；它们保护具体字节，不能证明论文事实一定正确。

先按 [三流程正常批次轮次](three-workflows.md#全批轮次与失败集合) 处理选定全批，再只续可重试失败集合。正常轮次使用已有候选和原额度，不自动安装新的窗口账本。原预算用尽后，仍须通过受控清单核验才能开启后续窗口；执行者在已有持续付费授权内完成登记，不逐轮向用户询问。`manualHandoff` 只是诊断，不安装清单或赋予模型调用能力。

## 正常候选中的原余额

日更、会议和历史更新共用的正常 Reader 默认上限为 6 次内容响应、其中最多 2 次完整长文；实际候选以原身份中已绑定的上限为准。修复共性误报后，须先用当前完整解析器重验原稿，通过则直接正常收尾。仍有新问题时，只有旧问题与保存的原始及规范化两种签名完全一致、新阻断不再包含任何旧规则组、原响应余额存在，才可继续原余额。完整长文尚有余额时沿用正常路径；已经用完 2 次完整长文时，只允许处理全部阻断问题均有明确路径、被 1–8 个既有节点完整覆盖的安全局部补丁。程序在最终请求前重核整稿及每节点旧 SHA，拒绝空目标、重叠路径、整数组、整节对象、原子或分组操作；需要来源整稿重试、问题无法定位或覆盖不完整时仍停止。这一路径不能退回全文生成，也不能借实现恢复许可增加响应或全文额度。

该判断不清零 `attempts`、`fullAttempts`、`noProgress`、`validationFailureStreak` 或旧签名，不建立新轮或实现恢复许可。后续真实请求仍沿原保存与费用规则更新；传输中断时原内容次数保持。原内容响应额度耗尽、已有传输或截断阻断、显式付费轮、旧签名缺失或不一致都不因此放行。仅改变阈值、同组新增缺项或换单元格仍视为原问题；只执行了归一化而未进入完整解析也不能释放旧停止条件。

下文的新付费轮与此处原余额不同，仍须独立的明确清单及完整来源核验。

同一来源优先输入因请求在发送前被阻断而留下零内容、零全文、无正文的空失败包时，显式 `refreshReaderDiagnostics: true` 可在真实日更四源和论文锁内保留该失败原字节及全部未发送用量记录，再交回既有兼容候选选择和实现迁移。仅 `blocked_before_transport`、`transportStarted=false`、无状态码、无输出且无用量的后续事件可支持这一步；未知起始请求、网络/HTTP失败或未保存的新付费响应仍阻断。旧付费次数、全文次数、无进展及失败签名不清零，空包的独立传输失败历史绑定正常迁移原档并可冷重放；这不是新的模型额度或发布通过凭证。

已完成会议的博客完整审查拒稿使用独立 `--reader-review-feedback` 正常 Reader 维护；必要新窗加 `--reader-review-window`，不套下文日更许可或把 complete 原稿改成失败。先完整正常审查，再对全部 text 及未解决格式问题全批处理，仅失败集合续轮；默认原意见标作待核验，额外事实断言才要求相关逐字来源。图像失败可以诚实 deferred 先做同 PDF 新展示与正常审查，残余语义再正常维护。原主文、核心、评分、标签、次数及费用保留，必要新窗持续授权，无人工15篇上限；pending 必须沿同一 manifest 继续，见[会议博客正常维护](conference-workflow.md#博客拒稿后的正常-reader-维护)。

## 显式的新付费轮

本节下方的四源清单与 `batch` 参数用于日更。会议使用[独立会议登记及子运行](conference-workflow.md#原额度耗尽后的独立付费恢复)，不能补造日更来源或把两种清单互换；历史流程也不能借会议许可增加额度。

更新写作指南或提示词不会自动开启这一入口。新版本有新的首模板及输入身份，旧记录仍按其原路径、版本和 Git 字节核验；存量候选没有对应的正常严格恢复路线时保留阻断，不能添加任意旧 SHA、换 epoch、清失败计数或让新输入隐含获得额外全文机会。

同输入的活动候选已有内容、全文或传输历史时，仅改变 Prompt 不能按首次生成重新计数。没有合法原迁移链会报 `READER_PROMPT_CHANGE_REQUIRES_CONTROLLED_RECOVERY`；应保留候选与费用并核查恢复路线，不能删候选重跑。会议已核原付费稿的私有只读重验可保留原 Prompt 身份，但硬禁新模型请求；这与授权新的付费轮是两件事。

这个入口为已核对的失败稿登记明确的新一轮付费尝试。登记依据已有任务授权，不是每轮重新索取用户批准；仍不改旧费用、不抹去旧次数，也不因为改了代码或提示词就隐式新增窗口。

Reader 保存资格与发布校验对术语采用同一窄显示规则：完整行内代码结束后、中文前由正常排版加入的 ASCII 空格不改变术语身份；代码内部、词内空白和其他字节仍逐字核对，显示等价的重复术语仍拒绝。完整解释必须真实可见，不能借代码、HTML 注释或缺词通过；这类校验修复不改原稿、原 SHA 或费用。

先在没有其他写入进程的冷态，完整核对当前批次来源与正文，再使用实际 Reader 输入构造生成、审查重试清单。`prepareApiReaderRetryIdentity(paper, analysis, sourceEvidence, options)` 使用正常 Reader 的身份构造，必须传入与正式调用相同的来源证据、事实反馈和预算；它不请求模型、不下载论文图，也不改变保存稿。不能手工改旧 SHA 让清单通过。

```bash
npm run batch -- --retry-failed-readers --reader-retry-manifest /absolute/path/reader-rounds.json --refresh-reader-diagnostics
```

程序调用支持 `main({ readerRetryManifestPath: '/absolute/path/reader-rounds.json', refreshReaderDiagnostics: true })`，不用改进程参数。清单外论文正常接续原草稿与次数；清单内论文在规范论文锁中重读当前正文与完整四来源，再核对真正 Reader 身份、原稿字节与恢复历史。已成功、仍有合法尝试、输入发生实质变化或缺少证明的稿件不能借旧稿开新轮。实现元数据变化只接现有公开恢复程序的可核对历史，不更改 epoch。

### 已安装轮使用普通批次续跑

首次清单用于把已有任务授权落实为一笔有明确输入身份和限额的技术窗口。原候选已经保存 `explicitReaderRetryRound`、相应回执为 `active` 后，继续该轮应直接走普通恢复：

```bash
npm run batch -- --refresh-reader-diagnostics
```

程序调用使用 `main({ refreshReaderDiagnostics: true })`，不再附 `readerRetryManifestPath`。正常入口在论文锁和同一封存来源中恢复原候选，完整重验已保存稿；实现升级需要迁移时，逐步核对原文件 SHA、唯一公共迁移记录、同一轮证明及未改变的实际输入。当前候选的 `roundId`、原回执、已用响应与全文次数、无进展、实际请求和预留输出预算继续沿用，校验通过即可完成；仍失败且余额耗尽或连续无改善时照常停止，不增加额度。

实现指纹变化后，不应再把旧首次安装清单作为已安装轮的续跑参数。带清单会重新进入首次登记作用域，在检查原 `identitySha256` 时因当前实现身份不同而报“长文当前输入与重试许可不一致”；同一 UUID 也不能替代输入核验。不能改写原 grant 的身份、提高预算、换 epoch 或补签回执解决。普通恢复使用 `validatePersistedRound()` 及其公共实现迁移链核验，继续原轮剩余额度。

已审但尚无安装回执的窗口与已安装轮不同。普通无清单恢复不会自动首次安装该窗口；保留原 UUID、候选、来源和原清单，只有原安装条件仍逐项匹配时才能登记。这里的机器状态不表示任务授权失效，也不要求用户重新批准；`prepared` 中断事务仍须按原事务证明恢复，不能当作新轮另发 UUID。

已经完成并保存完整来源与事实证明的核心摘要，后续由普通保存反馈恢复入口继续。原付费摘要 UUID 用于明确重验该原响应，不应在摘要完成后逐轮强制重放；缺失原反馈或摘要再次不合格时仍须停止核查，不能删掉约束。

清单顶层写实际 `batchDate`、`runId` 和 `rounds`。每项包含 `contract: reader-explicit-paid-retry-round-v1`、规范 `paperId`、唯一 UUID `roundId`、同一批次和运行、四个 `sourceFiles` SHA、当前 `wholeSha256`、实际最终 `identitySha256`，以及旧记录的 `originalIdentitySha256`、`envelopeSha256`、`payloadSha256`。这几项表示不同对象，不能互换。预算固定为 `maxResponses: 3`、`maxFullResponses: 1`、`maxPhysicalRequests: 6`、`maxReservedOutputTokens: 80000`。

原稿及当前实现下的失败记录各按原字节保存，原响应次数、完整生成次数和网络失败次数写入新轮记录。新轮自己的逻辑尝试计数在响应保存时递增，旧费用账仍在原处；累计花费应合计旧账与新账。每个实际请求在发出前先记入新轮预算，网络重试、账号切换和图片兼容性尝试也占实际请求额度。单次请求的 token 上限仍由正常配置决定，累计预留输出预算先达到80000时也会提前停止。输入和图片费用另按真实用量记录，不能承诺固定金额。

新轮最多保存3次内容尝试，其中已保存的完整重写最多1次；格式错误或被拒但已保存的内容也计数。这不是最多3个实际响应的保证：模型返回后、保存前进程中断，实际响应可能没有进入逻辑尝试计数。请求已在发送前持久登记，因此中断恢复也仍受累计最多6次实际请求和80000输出 token 预留限制；不退还已登记请求额度。已用完的新轮不会因普通恢复再次从零开始。同一窗口重复运行只能接续剩余额度；当前记录或原稿丢失、费用明细与总数矛盾时直接停止。准备记录写入后若中断，恢复只完成同一笔有来源、原稿SHA和唯一编号的事务，不自行生成另一个编号。

首次显式轮遇到已证明连续无改善的完整失败稿时，清单可明确附上 `fullRegenerationReason`，由 `reader-parent-recovery.fullReason()` 根据真实保存稿及失败签名生成，代码在安装和每次恢复时重新核对原档。只有 `complete_failed_draft_no_progress` 原因可用；局部轮不得携带该字段。此时保留并归档完整旧稿，首次模型请求改走完整再生，再使用正常局部修复；原有 3 次内容、1 次全文、6 次实际请求与 80000 输出 token 上限不变。未附字段的历史许可继续按原规则运行。

更换解析或修复实现后，原新轮编号、已发请求和已用预算保持不变。程序逐步核验正常恢复流程留下的原文件和迁移记录，才允许沿用同一轮剩余额度；来源、模型、正文输入或反馈实际变化不能借此复用。局部修复提示词只接受代码列明的精确版本升级。已有新轮不会再获得额外的实现修复次数，达到请求或输出预算上限后立即停止，不再等候网络重试。

完整无改善再生也可使用正常解析器的 `validationFailureStreak >= 2`：当前保存的 `validationFailureSignature` 必须逐字等于代码根据现存阻断问题重新计算的规范签名。两种无改善指标均须配合至少两次已登记的局部修复请求；不手工抬高计数，不借诊断迁移恢复额外预算。

旧版本可能在开始新轮时把当前草稿留成空值，而同一轮的封存原稿仍完整。正常恢复现在会核验原稿、来源、实际输入、版本迁移记录和费用账，只在尚未保存新内容、当前正文确实为空、且该轮只发出过全文请求时恢复这份原稿。恢复前另存空白记录的原字节，记录双方 SHA；原请求、轮编号和已预留额度不变，不增加全文机会。随后优先走正常局部修复，例如已预留48000且原上限80000时，仍只有32000可用。已有新稿、已保存内容或已请求局部修改的轮不适用，文件或证明不一致则停止。

原付费轮确实耗尽后，若仍保有完整失败稿，可以核验并登记一次仅修改局部内容的后续轮。其清单使用 `reader-explicit-parent-local-repair-v1`，额外绑定原轮的 `parentRoundId` 和 `parentReceiptSha256`；其余来源、正文和原稿证明仍须完整核验。这个旧协议仍只允许同一原轮有一个直接后续轮，不能再用同一旧协议从后续轮派生新轮；需要继续修复时必须使用下面的有界追加协议并重新核验清单，普通续跑不会自动创建新窗口。已有持续付费授权无需逐轮重新确认。

后续轮固定最多保存 1 次修改、发出 2 次实际请求，累计预留 32000 输出 token，完整重写次数为 0。它保留原稿，只允许正常的 `apiReaderRepair` 请求；请求发送前登记费用，保存前中断也不退还额度。原轮的请求记录、次数和原始文件保持不变；新增费用单独记录，不能说总花费没有增加。原轮尚有正常余额、只有半篇稿、原凭证变化或来源不一致时不允许开启。

已付费轮或上述旧局部轮用完额度后，`lib/reader-parent-recovery.js` 提供 `reader-explicit-parent-recovery-v1`。`mode: local` 必须保有完整可修正文，最多保存 3 次局部修改、发出 6 次实际请求、预留 96000 输出 token，不允许完整重写。`mode: full` 只接受两种有证据的失败：直接父轮的完整生成已用完、实际发出过全文请求，并且响应无法解析或缺少正文小节；或者父轮完整失败稿保有阻断问题与失败指纹、至少两次内容尝试且连续无改善达到 2，真实父账还须包含至少两次局部修复请求。完整失败稿始终按原字节归档，并在新轮保留；程序将首次请求改为完整再生，随后回到正常局部修复。新轮原因 SHA 必须与已核验父账一致，不能删除草稿伪装缺稿，也不能因普通表格不合格自行再生。完整轮最多保存 3 次尝试，其中已保存的完整生成最多 1 次，实际请求最多 6 次，预留输出最多 128000 token。

这项协议仍有整篇累计技术上限：从最初付费轮算起，最多 3 个追加轮，其中完整生成追加轮最多 1 个，追加实际请求上限合计不超过 18 次，追加预留输出上限合计不超过 320000 token。已有旧局部轮也占一个追加轮，其原预算一并计算。同一父轮不能有两个后续轮；旧请求、原稿、原 UUID 和已花费用全部保留。每轮额外绑定直接父轮编号、父回执字节 SHA、最初轮编号、真实继承层数和失败稿 SHA，任一文件或费用记录不一致便停止。

上述数值是当前恢复协议的技术边界，不是用户对整项任务的总付费授权上限。达到边界时，执行者在已有授权内核对失败原因和进展，选择下一条受控恢复方案；现入口不支持时保留断点并补齐必要实现与验证，不篡改旧凭证，也不把技术缺口转成逐轮询问用户。没有有效新方案或仍是同组无进展问题时先停止无效请求。

规划使用 `planParentRecovery({ directory, identity, paper, plan, mode })` 或 `planParentRecoveryManifest(requests)`；它们只读取并核验数据，返回待审清单及新旧预算合计，不发请求、不安装新轮。代码升级后若当前身份文件尚不存在，先由 `prepareParentRecoveryCandidate({ directory, originalIdentity, targetIdentity, paper, plan })` 在正常论文锁和封存来源中调用既有诊断迁移程序，保留旧稿归档和完整费用记录，再规划。该准备步骤会写诊断迁移记录，但不调用模型、不新增付费额度；只允许列明的实现字段变化，恢复版本、请求格式、提示词和真实输入不能借此改签。清单通过独立的来源、原稿和预算核验后，交给原批次入口执行并在实际 Reader 输入处再次核验；已有持续授权不要求用户重复批准这一步。

完整草稿只是小节过多时，19–64节可以进入专门的小节整理：模型只调整小节数组，其他信息和来源记录保持原样，最终仍须满足12–18节和全部内容检查。缺少必要字段的半篇稿不适用，也不能靠删除表格或正确内容凑够小节数。这项修复同样使用原轮剩余额度。

这个入口没有自动允许发布。新正文仍必须通过来源、结构、评分、Reader和完整批次资格检查，并经独立事实核对后进入正常博客流程。

### 少量顽固稿的来源绑定人工修正

本节后续命令是日更入口。会议使用[同一迁移命令的零请求Reader修正](conference-workflow.md#最后失败集合的零请求-reader-修正)，保留独立身份和完整原许可链。当前窗口技术停止时，可显式按真实当前与直接前驱的内容请求、失败及材料树核验历史正常执行资格；完整原JSON版本修正和两张已绑定TABLE占位恢复须另作明确声明，不能伪造原候选或宣称原稿已有表格。会议修正仍禁止新请求并完整重放来源及正文，不能套用日更封存身份。

实现、解析器或恢复版本变化不修改原 Reader 窗口额度，也不清除原连续失败状态。旧实现额外许可只保留作可核验历史，不能用于追加内容响应、全文生成或绕过同组停止条件；截断后的输出预算调整同样只能使用原剩余次数。需要后续付费时，在已有任务授权内走上文的显式来源绑定登记入口，不因更换窗口而再次询问用户。

整批完成多轮正常生成与失败集合恢复后，用户已明确授权的少量人工收尾使用：

```bash
npm run batch -- --reader-operator-corrections /absolute/path/operator-manifest.json --refresh-reader-diagnostics
```

清单必须覆盖当前完整失败集合，不能拆分清单、隐藏失败项或包含已成功论文。默认上限为 10 篇；大批次可按原封存入选集的 10% 向下取整增加，绝不超过 15 篇，即 `min(15, max(10, floor(N / 10)))`。超过 10 篇时，程序重读原封存运行清单，并要求传入论文集合与其完整、唯一地对应；`N` 不能取失败子集、命令行选择集或扩充列表。例如原批次 146 篇最多允许 14 篇收尾，109 篇仍最多 10 篇。

每篇保留原活跃候选的整文件 SHA、正文 SHA 和四份封存来源身份；只允许替换 1–8 个已存在的正文、表格、公式或插图节点及受控字段。人工记录明确为 `notLlmResponse: true`，不伪装模型响应，不修改身份、来源、旧计数、无进展或费用，也不授予新的 Reader 请求。修正仍通过完整正常解析、来源核验、发布资格与博客独立审查；条数上限不改变内容检查。

### 已完成稿的独立核心摘要恢复

`reanalyzeSelected(ids, { coreFeedbackFiles })` 只接受严格核心专用反馈包。论文锁内先由公共保存器归档原包并持久化未完成义务，再进入单节范围；原主文反馈如存在仍须按真实原包保留，不能把核心包当作自己的父包。模型请求前的中断、普通合并与状态更新不能用旧成功记录清掉这项义务。

完成稿通常已清理临时检查点。核心恢复先在禁止模型请求的原事实上下文核验完整上游、当次四源、实际分析输入及原版本 Prompt，才把最终正文用作本次运行检查点，并保留原已完成上游阶段与原指纹。最终正文不冒充各阶段的历史中间稿；此范围不改变普通强制全量重分析的失效规则。核心阶段逐字保护其他十二节，随后正常复核八维评分与必要 Reader，不能预设新评分不变。

核心与评分已经实际通过、仅 Reader 中断时，续跑可使用该次已接受的评分输出检查点。程序须核对检查点 SHA 等于真实 `scoringAudit.outputAnalysisSha256`、核心阶段仍绑定当前事实包、四源和完整上游资格均通过，才保留已完成阶段并仅续 Reader；不能重复付费修摘要或评分。不完整的旧快照保留记录并跳过，不能补造其中缺失的阶段。

旧核心入口已经误清空阶段并因尝试主文模型而在请求前失败时，公共选定入口的 `coreInputRecovery` 只接受当前失败整对象 SHA、真实完整父稿文件及文件 SHA。它须重新核对同一核心反馈、四源、原正文和原完成资格，严格限定已知损伤范围，并在 `coreInputRecoveryHistory` 保留原失败清单；不清除待办、次数或费用，也不补签旧阶段。之后仍交回正常核心修复及完整资格，失败不能手填为通过。

### 核心摘要的原付费响应重验

会议只有显式原迁移 `--retry-failed` 的既有正常分析子运行可按[会议恢复规则](conference-workflow.md#已有完整会议只更新页面)选择唯一最新同身份原请求，仍调用下述公共严格重验。最新请求缺链、时间不唯一或输入身份变化时停止，不能挑更旧响应；原外层轮次已满仍先阻断。该适配不使日更或历史默认自动扫描诊断，也不授予摘要、评分或 Reader 新额度。窗口阻断属于当前入口的技术边界；后续恢复在已有任务授权内安排，不把它解释成必须重新向用户申请付费。

核心摘要校验实现修正后，可通过程序入口 `reanalyzeSelected(ids, { coreSummaryDiagnosticIds: { paperId: requestUuid } })` 明确选择原付费请求重验。程序核对原请求、响应、处理记录、封存来源、原主文、证据及阶段身份，只将该原响应交回当前完整摘要与事实检查，其余十二节逐字保留。不能改写响应、手填摘要 SHA 或把三份已付费拒稿当成未用次数；重验失败会停止该篇，不自动另发摘要请求。摘要通过后，其余尚未完成阶段仍按正常流程和各自预算继续。

日更原付费摘要若另有一处已核实的中文短语错误，可在同一显式重验中附加 `paidCoreLiteralCorrectionFiles`，同时提供原 `coreFeedbackFiles`。`daily-paid-core-literal-correction-v1` 只允许唯一一次 2–8 个非数值汉字短语替换，绑定当前锁内完整父稿 CAS、真实用户任务指令、精确范围授权、四源、逐字来源证据及原请求/响应/处理记录的完整身份与字节 SHA。原付费响应不变，人工修正另存 operator 证明；冷资格检查重放原响应加唯一替换，不能把人工结果签作原模型输出。删除证明或标记、改变原源或其余十二节、重复匹配、加入数值或重验失败均停止，不回退到模型请求，也不增加摘要、评分或 Reader 额度。

### 同输入多份失败稿的正常自动续接

统一批量恢复在论文锁和完整封存来源中核验候选，模型、提示、恢复版本、事实反馈及实际输入均须相同。真实迁移凭证能证明唯一后代时沿用该稿；独立分支则须由本篇本运行最后一次真实付费请求、响应、用量记录，以及生产补丁和确定性规范化的逐字回放共同证明唯一保存稿。文件修改时间不参与选择，无法证明时仍报告歧义。

付费补丁后的旧失败稿若需要历史规范化，只能使用真实请求绑定的 Git 原程序、原表格编译器及完整依赖 blob。旧 `analysis-contract` 仅从该原 blob 提取逐声明固定 SHA 的 Markdown 纯闭包，记录字节边界，在无 `require` 的隔离上下文装载；不导入旧 Manual 模块，也不把当前实现当作旧程序。PDF 依赖仍须与原文件整字节一致，历史 PDF 重放及未知依赖继续拒绝。Git 读取禁止 lazy fetch 和替换对象，返回字节须符合原 blob OID。新 provenance 使用 v2 并强制带闭包证明；此前合法 v1 由外层候选/迁移记录的原 SHA 认证，再从原完整 Git blob 在内存重核相同闭包，不向旧文件补字段。缺失 v2 闭包、原 blob 或声明变化均拒绝。这只证明失败稿的付费来源，之后仍须通过当前完整来源、正文和发布检查。

自动续接保留全部旧稿、费用、响应与全文次数、网络失败、无进展和连续校验失败计数，不发放实现恢复许可。修复实现已经能接受的稿件照常完整重验；仍失败且额度用完时，整批统一准备并审查明确重试清单，再走原批次入口。不得清计数或手工修改身份。

失败合并保留旧公开 Reader 的完整资源束。普通源模式恢复需要本次实际使用的资源时，只在内存从同源失败束中取回当前上游资源扫描证明所指向的唯一资源，重放完整封存引文、归属、分类及已观察状态。完整来源、上游或原失败束变化就拒绝；签名定向修订不混用该资源。新 Reader 完整通过后才按正常流程替换整个资源束。

表格自动补证先按正常数字、单位及真实 PDF 行列规则检查已声明的逐字引文；完整合法时原样保留，不追加数字相同的邻表片段。缺证据时仍正常派生并完整核验，缺失数字、错误单位、无法定位的原列及伪造引文继续拒绝。剪列、预检及最终签表共用同一选择结果；旧候选可以正常重验，但原次数、失败历史和费用不重置。

自动规范化不从引文抽出裸数字制造结果表，不按数字重叠挑选结构化原表，也不搬动这些合成表来满足结果覆盖。正常 Reader 拒绝以“来源证据／量化值序号／来源句序号”替代真实条件与指标的占位结果表；合法的引用说明及有语义的真实指标表仍正常核验。来源表3或4列即可按原列呈现，固定宽表数量不作为补造列的理由。旧稿与原付费链保留，失败交正常修复，不能手改成功或用构造表填最低数量。

新响应与保存稿使用同一语义检测器。`hasValidApiReaderV3Records()` 必须检查实际保存的 `apiReaderArticle`，不能仅因旧正文、计划和阶段哈希闭合就授予当前资格；日更成功复用、会议页面暂存和历史改写共同执行此门。Python 的日更生成及独立历史发布还经现有 `reader-resource-claims-replay-cli.js` 对实际正文执行同一检测，不因直接从生成阶段恢复而绕过。诊断保留 `reader_placeholder_result_table` 及实际正文路径，会议后处理将诊断写入失败原因。历史来源与旧签名仍按原记录只读溯源，来源身份准备不承担当前正文资格检查。

资源肯定声明按每个匹配位置核验。明确“没有在证据中给出代码或权重可下载的陈述”，以及资源并列数量吻合的“代码、模型与数据已公开三件事都不能默认成立”，只是否定对应的声明范围；后续转折中的真实公开声明仍须有可达资源证据。引述、反驳否定与双重否定不能借此获得豁免。发布侧通过同一来源绑定的 Node 重放入口执行该规则，不另用宽松的否定词过滤。

“应把代码可下载、权重可下载和系统可运行分开看”属于无所属者的概念区分，仅识别闭合列表本身，不豁免前后作者发布声明。正文报告作者已提供某类资源、同时明确本次缺少可验证下载地址时，须有同类型、非第三方且非否定、假设或未来的原文声明；这只是带限定的原文报告，不将资源状态改成 `available`。省略“本文”的双重否定也不能成为当前开放声明的豁免。

“代码可达、权重可下载和系统可运行当作三件独立的事分别验证”属于待验证条件；“没有可验证的作者资源可写为已公开”属于缺少证据声明。只有对应字节范围被识别，后续重新肯定作者已发布仍须单独核验。“代码链接经核验为第三方可用”还要求当前资源身份确有可用第三方项；引述、否认、撤回归属以及另称作者已发布均不能借用这个结论。三条流程及发布冷核共用此规则，真实付费稿复验不重置请求或费用。

PDF 表中同名方法可按原 `Dim` 输入维度列定位，但须完整保留原数值列，原行名加条件唯一，再逐格核对结果和单位。缺条件、条件互换或同条件重名仍拒绝。平表的显式维度、容量、微调行带另由同一 PDF 完整表框、分隔线、表头字形及全部数据行重建；行带必须在完整数据带之前且每行有真实条件路径，不能从指标数值或正文推定。原层级表提取成功时不进入该补证分支，以保留已有证明。

“三点一致：”这类完整一致性枚举名词不按小数处理；只有名词后紧接标点或句末时才屏蔽其诊断，原稿不改。“三点一秒”“三点一个百分点”和“一致性得分三点一”仍要求阿拉伯数字。Node 与 Python 发布检查保持同一边界。

合并表头的百分比单位须有封存原表的完整 DOM 证据：程序展开全部原始行列跨度，检查每格覆盖唯一、无遗漏且与来源矩阵一致，再由原 `Method` 表头的跨度确定二至四层列路径。只有原表注显式声明 `(指标名, %)`、完整表注已逐字绑定、类别与末级指标唯一匹配、原行名与原单元格数值精确相同时，局部展示表才可继承该单位。完整表注中仅允许同值同精度的 `ρ×N` 与紧邻的 `\rho\times N` 显示副本合并比较；原表注、引文与来源 SHA 仍保留原字节。不能从任意表注百分号、别的类别、相同数字或正文猜测单位；生成、冷态恢复与 Python 发布重放执行同样检查。

真实资源可达状态、HTTP 状态或重定向终点改变时，普通源模式可以申请一次新的实际输入。程序必须沿原封存来源与完整父阶段证明，逐字重建最后真实请求的来源证据、合法旧反馈和输入指纹，再重放已付补丁及正常规范化，证明原失败稿归属。一次性入场记录绑定原请求、响应、用量和候选字节，固定当时正常 6 次内容响应、2 次全文响应和真实单请求重试、输出配置；旧身份、稿件、无进展和费用不变。相同来源、模型、提示和恢复版本范围只允许一次入场，后续只接同一新候选。错误文字、时间、重试策略或反馈机械渲染不构成新机会；已记录资源快照与当前资源仅元数据不同但 SHA 不同时，也在模型前保守拒绝，不放宽上游或发布检查。

封存原表中的完整布尔格若同时出现 `✓\checkmark` 或 `×\times`，Node 解析与 Python 发布复验只合并逐字同值的显示副本；全部原格、DOM 坐标、数值精度及列头单位仍须对应真实来源。不同符号、乘积、续式、未知命令和裸重复不具备此证据，不得据此清理。此实现修复不增加原候选的次数或预算。

### 已完成主文的独立 Reader 事实反馈

作者机构解析失败只能说明“机构信息未能在本次解析中与作者逐人可靠绑定”，不能据此写成论文没有披露。已绑定的机构仍须有原来源中的逐人对应证据；不得从姓名顺序、同一学校或资助单位推断。共享解析器保留旧不可得提示及其原签名的只读兼容，不批量改写旧文章。需要修正现有作者头时，显式运行 `npm run api:reader:refresh -- --authors-only ID1 ID2 --concurrency 1 --rounds 1`，只刷新选定论文的作者派生身份；它读取原封存四文件，不请求模型，不改来源、Reader 正文、摘要或评分。未保存可重放 HTML 且原作者集合不匹配时，应保留元数据姓名与本次无法可靠绑定的状态，不能补猜机构。随后重新生成并审查实际变化的页面；新的作者身份会改变后续受控修正的父稿 CAS，修正材料必须以刷新后的真实父稿重新准备。

完成核验按原签发上下文只读重放父反馈与 Reader 子反馈，逐项核对原包、四份来源、阶段签名和禁留原句；不能只用子包重算合并引文的指纹。此作用域不写反馈、不创建目录，也不允许任何模型请求。原来使用恢复型约束的记录仍按其原协议核验，不能改签为另一种上下文。

已签 Reader 的事实局部调用若在发送前因短片段覆盖检查失败、随后因该失败标记拒绝原 seed，可显式使用 `reader-fact-pre-request-recovery.withVerifiedReaderFactPreRequestRecovery(recordFile, callback)`。记录须绑定真实完整成功父文件、父论文 SHA、失败前执行记录及失败日志；入口重放父稿资格，锁内再次核验同一未完成反馈、四源、当前 Reader 与全部上游原字节，以及最后真实付费响应计数和此后无未知请求、无新付费响应的用量证据。普通错误、不同反馈或变更的正文不适用；不恢复旧正式文件、不换反馈、不增加额度或清除失败。仅此不透明作用域内，原反馈中 8–11 字片段可映射到原签名稿同一既有正文节点的唯一完整句；引用、代码、表格、公式、重复或移位内容均拒绝。原片段、输入和失败历史保留，普通调用的 12 字门槛不变，仍只走原局部余额和完整最终校验。

旧父反馈的上游恢复在进入分析前必须已有真实完整主分析检查点。恢复期间，原主文、摘要、评分、标签及非 Reader 阶段都受保护；保存回调同时检查原对象和传入检查点，发现变化须在写盘前拒绝并还原内存和回调。缺检查点或来源不符应保留失败，不能先删除原阶段再报错。错误前的真实快照仅可通过对应的来源绑定、完整父稿 CAS 恢复入口取回，不能手填完成状态。

程序入口 `reanalyzeSelected(ids, options)` 可通过 `readerFeedbackFiles` 指定新的 Reader 专用事实包。它与 `feedbackFiles` 中原主文反馈并存，不能与独立核心反馈混用，也不能启动新的全阶段主文重写。每篇反馈均在论文锁内重新核验当前正文、四份封存来源和原阶段证明。原主文、核心摘要、评分及全阶段身份沿用真实原包；只有 Reader 使用新反馈、输入指纹和完成证明。

这条路径适用于主文已完成而 Reader 尚未完成的论文，不要求伪造一份已签名 Reader。Reader 按正常生成及失败候选预算运行，真实输入变化时保存新的独立候选，旧输入候选、计数和费用记录保留。它不是清除旧次数的实现迁移，也不是命令行已提供的新参数。新反馈不能遗漏原有 Reader 事实约束，不能授权主文、摘要、评分或标签模型请求。

已正常完成并完整签名的 Reader 只需修正少量正文原句时，程序入口 `batch.main({ factFeedbackFiles: [readerOnlyFeedbackFile], readerFactLocalRevision: true })` 可显式选择已有的单句局部协议。此模式仅接受严格 Reader-only 来源反馈，不混用人工清单、新付费轮或自定义分析器，也不处理未给反馈的其它失败项；仍由公共批次、论文锁、来源恢复器和正常保存负责。真实核心父包保持 `coreSummaryRepair` 身份，新 Reader 子包通过公共 Reader 范围核验，局部目标及证据读取子包，原核心、评分和费用证明不变。

局部种子必须来自实际已核验的完整签名 Reader，不能把失败 source-only 候选冒充成签名稿。该模式不走失败资源束或 source-only 全文兜底；只允许唯一获准正文/术语解释原句，表格、公式、引用、来源元数据和结构标记仍受保护，不能借此修改表行或扩大为全文。新真实反馈具有自己的输入和候选，原候选和次数完整保留；模式本身不授予额外付费额度，执行者仍须核对原跨输入剩余额度，并在实际请求边界限制该窗口的局部次数。没有安全原句目标或原额度不足时停止这条局部路径，再按已有任务授权选择合法后续方案，不在原账中隐式加额。


### 调用程序丢失长文生成所用正文时的恢复

程序入口可显式传入 `readerInputSnapshotRecovery`，逐篇指定当前损坏记录的 `paperSha256` 与已保存原输入的 `snapshotSha256`。这不是命令行参数，也不是主分析失败的通用恢复开关。只有长文生成完成后调用程序丢弃正常返回、随后触发独立长文纠错范围拒绝的记录适用。

公共入口在本篇锁内验证原全阶段运行与原主文反馈、当前四份封存来源、新长文及计划哈希、新反馈和唯一原输入检查记录。原主文指纹、摘要、标签、评分与长文来源检查仍须通过。当前非长文阶段与检查记录不同时拒绝覆盖；只恢复现有主分析失效规则删除的阶段和协议。两个图片派生阶段只有更新时间可不同，并保留当前记录。资源扫描的当前空检查点只有在扫描阶段本身完全相同时才保留为空，不恢复旧扫描正文；其他非空差异仍拒绝。

恢复保留原失败、全部旧候选、费用和尝试计数，只把经来源核对的原始正文交回正常分析。图像派生、当前正文检查和事实修订仍由正常流程完成；恢复检查记录本身不能证明整篇成功。

正常深度分析完成会把原 `analysisCheckpoint` 返回为 `analysis` 并删除暂存检查点。调用程序应核对最终正文与原检查点的字节及完整非长文阶段，不能把这种正常转换当成正文改写。已知写作要求残留仍须按当前提示词、正常预算和真实局部请求纠正，不能通过恢复旧阶段状态绕过。


同一次正常恢复因调用程序的“原主分析记录不得改写”保护再次中止时，可额外指定 `recoveryHistorySha256`。该入口只接受已确认的长文范围拒绝和对应的正常原输入恢复记录：原来源、原主文反馈、新长文反馈及文章哈希都须一致，前次失败也须是同一范围拒绝。其他主文、评分、来源、传输失败或缺失/变动的恢复记录仍拒绝；前次失败与恢复记录完整保留。此选项仍不授予新的尝试次数，也不能跳过长文正文检查。


## 已签名日更稿的术语尾修

正常 Reader 已完成、最终审查又发现确定性的中文术语错字时，原付费候选可能已经正常退休。不得把退休文件复制回活动目录，也不能伪造失败标记。用户已授权少量尾部人工修正时，可显式运行：

```bash
npm run batch -- --reader-signed-corrections /绝对路径/manifest.json --fact-feedback-file /绝对路径/feedback.json
```

清单与逐篇记录使用 `daily-reader-signed-correction-v1`，仅适用于当前日更封存来源。入口要求完整父稿、Reader 正文和计划的 SHA、同篇四份封存来源、原退休付费稿及其原字节 SHA、明确授权和严格 Reader-only 反馈一致。反馈必须指出当前正文仍实际包含的错误原句，不能借此修改主分析、摘要、评分或标签。

原付费结构稿须经正常解析和原图注入，逐字重放为当前签名正文、计划及全部原图；不调用旧历史来源的反向恢复器。一次只允许一项 2–8 字的中文术语替换，显式声明实际 1–20 处匹配，仅修改 1–8 个已有正文或图片说明节点。补丁结果须严格等于原结构稿的这一项字词替换，不能添加数字、表格、公式、图片或其他表述。清单及反馈须覆盖本次全部未完成集合，并受原封存批次的小尾部数量上限约束。

原正常生成器确曾启用确定性来源裁剪时，v1 可和 v2 一样提供 `normalProducerProof`：只读核对真实 Git 祖先、生成器 blob/SHA、原输入解析器身份和付费结构稿 SHA 后，复用原正常解析选项。原始补丁前后及编译后与签名父稿的表格字节、表绑定和公式绑定必须全部不变；不能借裁剪兼容修改表格或扩大中文词替换范围。

来源引文的自动选择规则更新后，已认证原生成器可只读比较新旧派生 `sourceQuotes`：两侧引文及 SHA 都须逐项对应同一封存全文，原付费结构稿显式引文须完整按序保留，表格显示、单元格和其余计划字段全部不变。完整父稿 CAS 与原计划仍按原字节验证，不把新计划冒充旧父稿。v2 中当前裁剪器删去原表行列时，仅真实 `tableCorrections` 已授权的表槽可比较原 raw 的正常显示与已签父表，再核对当前表是同序唯一子投影、目标是同一完整 DOM 的全格绑定；其他正文、表格、公式或图片差异仍拒绝。旧批次根须先重放原付费稿与真实批次补丁，不能借派生比较跳过原历史或授予新请求。

实际执行仍持有正常论文锁和日更来源作用域，先保存真实反馈义务，再使用正常 Reader 解析与最终封装、来源校验、整篇资格和锁内保存。明确记录 `executionKind: operator` 与零新增模型请求，保留原 API 阶段、原候选、响应、尝试和费用。失败保留原成功正文及真实未完成义务；只有正常资格和当前反馈均完成后才清除，最后仍须重新生成并通过独立博客审查。

### 已签稿的有界事实修正 v2

同一显式入口也接受 `daily-reader-signed-correction-v2` 清单和记录；v1 的中文词长、次数及替换限制保持原样。v2 仅供已获准的小尾部事实修正，不是局部写作或收费重试入口。它仍要求完整当前父稿 CAS、四源、严格 Reader-only 反馈和完整实际尾集合，不允许修改主文、摘要、标签、评分、作者、资源或原图身份。

每条 v2 记录保存 `parentPaper` 完整当前对象，以及 1–8 个既有节点的 `patch`。`rangeCorrections` 为每个 `/sections/i/body` 或 `/conceptBridges/i/explanation` 指定 `path`、`oldSha256` 和有序 `edits`。每个 edit 明确 `claimIndex`、`claimStart`、`start`、`end`、`from`、`to`；位置均为同一原节点的 JavaScript UTF-16 偏移，修改只能落在对应 `rejectedReaderClaims` 的原句内，句外字节不能改变。当前父正文必须真实包含该受拒原句。原模型文本与排版后的原句不同，可另给逐字 `rawClaim`，但必须由原公共正常排版函数严格投影为反馈原句；不能自行删空白、合并数字或改原稿来凑范围。正文、术语解释与图片导读中的派生内容由正常装配器计算。

正常排版包含真实原节点中的定量中文数词处理。`rawClaim` 映射须从同一原节点重新执行公共定量诊断，再按正常生产器顺序执行仅问题绑定的数词排版和普通正文排版，逐字得到当前受拒句；不能将任意中文数词、近似数字或另一个节点当作等价证据。原节点、完整父稿和逐字修改范围的 CAS 限制不变。
该原句在原节点须唯一；诊断原始偏移和命中文字必须逐字对应，只取实际原句范围内的问题。还须用保留位置标记分别重放完整原节点与标记节点，以不猜测的前后文边界证明实际位置显示等于局部显示；引用、代码或另一句的排版结果不能替本句作证。边界受排版影响而无法精确对应时停止。

表绑定修正只支持同一已有展示表位置的 `tableCorrections`：同时绑定旧表 Markdown SHA、受拒单元格所在正文范围、当前 tableIndex、获准目标原 DOM 表的 ordinal/DOM SHA/整表 SHA。使用正常 `artifact_table` 逐格绑定，或正常 `selection` / `completeTable` 编译；仍须逐格通过正常数字、单位及来源检查。显式 artifact 子表必须逐格来自同一完整 DOM，保持原行列顺序，每个展示行和列各对应同一原行和原列，不能混拼、猜值或补单位。原表错位时只能按具体获准的同篇目标原表恢复，不能借来源引文任意换绑，也不能增加表、公式或图片。原公式和 figurePlacements 记录保持不变。

原付费结构稿保留紧凑 Markdown 分隔行时，显式 artifact 目标仍先逐格严格核对原 DOM 文本及行列映射，再用原正常生产器重建表格语法并比较完整输出。不能为补空格改动受拒原句之外的原稿；分隔行兼容不允许更改单元格值、来源坐标、原表 SHA 或表数量。

如果可信 `normalProducerProof` 对原付费稿及完整人工历史的真实重放已经证明，原 inline 表有数据行被正常确定性处理删除，可将该唯一原表的完整 `rawClaim` 映射到当前完整父稿同序表的逐字受拒 Markdown。此能力由重放后生成的内存句柄授予，记录中的布尔值不能代替。原表头必须保持，当前各数据行须为原数据行的有序真子集，不能借用相邻表或重复表；修改范围恰为整张原 inline 表，同时核验原节点、原表和完整父稿 SHA。目标必须逐格恢复同一获准完整 DOM 的全部行列并通过正常编译，表外文字仍按原逐字范围规则检查。普通段落、未验证的 producer、任意局部表格编辑或来源子表不适用。

已有 `source_quotes` 表的正文和显示已完整等于唯一原 DOM 时，可在同一真实重放能力下仅升级绑定。该 `tableCorrections` 项显式使用 `bindingOnly: true` 替代 `claimIndex`，其余原表及来源 SHA 字段不变；不能把正确显示伪称受拒句。原表所在正文节点不得出现在任何范围或 patch 授权中，原 raw 表和当前同序已签显示须逐字等于完整 DOM 的正常投影；缺行、改值、换序或来源子集均拒绝。此项只增加一个既有绑定节点，仍计入每篇 1–8 节点上限，不增加正文修改权限。

已有独立 `TABLE_N` 占位符只修复原表缺行时，须用原绑定重编译并逐字匹配当前父正文中的完整受拒表、原 canonical 表 SHA、来源 DOM 和逐格坐标，再将该原表的既有绑定改为完整表声明。只能补全同一原表，不能拿另一张表替换占位符；不得把编译后的表伪造成原结构稿中原本存在的 Markdown。

已有人工修正历史时，先核验原退休付费档，再按当前 `operatorHistory` 的真实清单、记录、来源及事实包逐条重放。旧 v1 原父稿须在 `historyParents` 中给出真实 `parentFile`、`parentFileSha256`，其整对象 CAS 必须等于旧记录声明；旧 v2 的完整父稿来自原 v2 记录，对应项为 `null`。不得从当前正文猜回历史父稿、把 operator-local 阶段改成 API 阶段或复活退休候选。每步必须重建对应正文、计划及原图，原 API 证明与全部人工历史保留。只读 `prepare` / `preview` 不登记新义务；实际 `apply` 才登记真实 pending，再经正常 finalizer 和公共引擎保存，最后仍须完整资格与独立博客审查。

首次完成稿本来就来自旧日更批次人工修正、没有完成 API 父稿时，v2 可显式绑定 `legacyBatchRoot`，给出真实失败父快照及原用户授权文件的 SHA；原候选使用 `baselineCandidateFile` / `baselineCandidateEnvelopeSha256`，不能把仍活跃的付费档称作退休 API 稿。独立只读核验器须重放原失败父的完整评分检查点、原精确批次授权与清单、原付费档、原补丁及全部四源，逐字得到当前签名 Reader，保留原次数、费用和像素。后续阶段将真实批次根保存为 `originBatchOperatorStage`，不补造 `originApiStage` 或旧人工历史，不恢复或退休原候选。新修正依据已有人工修改授权登记新清单，绑定完整当前父稿、严格范围反馈及完整实际失败集合；同一范围已明确获准时不重复申请，持续付费授权本身不扩大人工修改范围。

v2 的 `normalProducerProof` 不授权额外裁剪。未列入合法 `tableCorrections` 的原始和编译后表格、表绑定及全部公式绑定须保持；明确获准的表只能逐字采用同篇唯一 DOM 来源的正常表编译结果。内联表和独立 `TABLE_N` 占位符按同一实际全局顺序定位，不能拿原结构稿中第 N 张内联表代替已签正文的第 N 张表；占位符补全还须重放原选择、当前父表及逐格绑定，且只能补同一原表。

个别原结构稿只有采用正常生产器既有的确定性表格处理选项，才能重放已经签名的完整父稿。此时可显式提供 `normalProducerProof`，合同为 `reader-observed-current-producer-replay-v1`、模式为 `observed-current-replay`：核验当前 producer 文件 SHA、原退休输入的真实 parser 身份和 draft SHA，并以可信祖先 Git blob 证明该 normal producer 选项原已存在。Git 见证不冒充原输入的完整实现闭包；若原闭包不可得，保留其原 SHA，不补签历史。该有限兼容仅在当前完整父资格已通过、采用原选项重放正文/计划/图片逐字相同后生效。没有合法 `tableCorrections` 时，raw 全部表与绑定、正常输出的每个表格字节及表格/公式绑定必须与当前父稿完全相同；明确获准的表例外仍须按上面的同篇 DOM 及正常编译证明逐项验证。原图身份、像素证明及所有公式绑定始终保留，不授予额外删表、裁剪或更换来源的许可。默认 v2 不启用此分支。

该显式兼容还保留正常旧阶段未写入的 `fullAttempts`、`transportFailures` 空值；原付费 envelope 保留并由 provenance SHA 绑定，不向旧阶段补数，也不清零原账。`attempts` 和任何已经存在的计数仍须精确相等。普通 v1/v2 路径不因此放宽。
