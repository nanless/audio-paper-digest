# 坚果云资料保存与新增发行验收

本文记录用户新增的网盘保存与仓库 Release 要求，补充[原69项验收](mac-app-acceptance.md)，不替换或减少原要求。新增功能完成、最终应用安装与实际服务验收后，才进入公开 Release；本地测试通过不等于已经连接用户的坚果云账户。

## 保存范围与设备边界

应用通过坚果云官方 WebDAV 服务 `https://dav.jianguoyun.com/dav/`，使用为“论文速递”单独生成的第三方应用密码。[坚果云官方说明](https://help.jianguoyun.com/?p=2064)要求使用应用密码，并列出默认500M单文件上限、免费账户每30分钟600次请求及单次目录最多750项的限制；这些是2026-10-25查阅的服务规则。

完整快照包含本应用私有研究目录中的全部实际普通文件，包括隐藏文件，不按论文标题挑选子集：

- 笔记、摘录和标注、收藏、待读、阅读进度、问题草稿、个人文献索引与任务历史。
- 已保存解析、原问题、实际输入、完整回答、来源页码和版本、封存文件、用量事件及恢复完整性材料。
- 已下载的目录、导读、原文、导出文件、导入本机PDF、各版本离线包与图片、引用和来源记录。
- 本应用的Zotero归档journal、材料、原目标身份及续传检查点。

应用私有目录以外的文件没有因本功能获得上传资格。Zotero自身数据库、由Zotero管理的外部附件以及用户另存到其他目录的导出文件，仍由各自原存储负责。这里备份的是本应用中的研究资料和归档记录。

模型、Zotero和持久保存的网盘密码保留在各自本机钥匙串条目；网盘密码也可仅在本次运行内存中使用。备份不搬运这些授权。云端保存的是可恢复的完整研究备份，经HTTPS传输，目前没有额外的端到端加密。连接账号、设备目标ID、上传冷却及续传控制文件保存在研究目录旁的独立设备目录；运行期请求节流与非上传操作冷却由同一服务实例保留。恢复研究快照不会替换当前云账号或把待上传的大快照递归打包。

当前完整备份沿用已验证的`paperdigest-backup-v2`合同：原文件总计最多512MiB、编码最多750MiB、最多100000项。超限整体拒绝，不裁文件或把不完整子集标成成功；每块8MiB避免把完整编码包作为单个超限远端文件。界面明确展示这些边界。

## 日常保存、续传与版本

在设置的“坚果云资料”中保存账号和独立目录，通过原生安全窗口选择仅本次使用或保存应用密码，再主动检查连接。仅本次使用不会读取或写入钥匙串，不将密码传给网页、日志、备份或诊断；退出或更换连接目标后清除。使用内存密码前先持久暂停自动备份，本次真实连接检查通过后可在当前进程继续；重启后仍暂停，不会自动回退读取旧钥匙串。清除本次密码也会暂停自动备份，原钥匙串条目保留。打开设置和刷新状态只读取本机控制记录，不自动读取钥匙串或查询网盘。默认目录`PaperDigest`，支持单级1–64位ASCII名称，以字母或数字开头；不允许目录穿越或把路径指向Zotero的存储目录。

新备份先检查实际连接并保存当前编辑；仍有任务时提示稍后重试，没有自动排队。没有其他任务时，短暂冻结资料并采集完整一致快照。上传阶段使用这份已经封存的字节，阅读与后续编辑可以继续；后续改动进入下一份快照。已有未完成快照的“继续保存同一快照”使用原编码、目标ID及检查点，不重新采集或把后来的改动冒充原续传。

每个版本使用独立UUID目录。分块只创建新对象，上传后逐块GET回读；全部分块完成后才写完成清单并回读，最后持久化本机完成回执。丢失应答时先核原远端对象，不能直接新建版本或覆盖原文件。不同设备保留各自不可变版本，不自动用较新的时间戳覆盖另一台设备的研究资料，也没有宣称已经实现逐字段双向合并。

版本按UTC月份归档，界面时间按本机显示。读取指定月份，核验完整目录及各完成清单；达到服务截断边界、无效XML、异常身份或中途限流均报错，不返回看似完整的前缀，也不把读取失败显示成“云端没有备份”。未完成目录没有完成清单，不列为可恢复成功版本。

认证失败停止当前传输并暂停自动备份，等待用户修正后主动检查。429/503遵循`Retry-After`停止新请求；上传冷却写入原检查点，重启仍保留。相同目标复用同一服务实例，串行请求与节流跨检查、列表、下载和上传保留。没有在后台自动更换账户、重置次数或读取其他程序的网盘密码。

如果原账号已失效、目录不可写或本地传输材料损坏，可明确选择“保留快照并停止本次续传…”。原生确认后，现存材料、检查点与连接记录整体原样移到本机保留目录，云端半成品和旧版本保留；自动保存暂停，随后可以重新配置目标。通过“在Finder查看保留的快照”找到文件，只有完整且通过正常校验的`snapshot.paperdigest`才可使用“文件→恢复个人资料…”恢复；损坏或缺失材料不保证可恢复。该动作结束这次上传，不把后续新目标称作继续原远端版本。

自动保存默认关闭，用户可设置应用运行时每6–168小时保存，默认24小时；退出应用后不运行。任务、原生详情、维护或退出期间不新建快照，失败在本机状态和任务中保留。手动保存与自动保存使用同一完整快照、传输和核验逻辑。

## 恢复保护

恢复先下载全部分块，核每块及总SHA，再走原完整`BackupCodec`路径、文件及合同校验。在原生确认前不替换当前研究空间；确认取消、下载失败、坏清单、错误SHA、源路径冲突或其他任务仍活跃均保留当前资料。

恢复后研究资料回到所选快照时点。本机模型端点、模型、协议、网络与预算配置保留，防止备份里的另一个端点取得本机现有密钥；原备份的`personal.json`字节另存恢复凭据，不伪造原文件SHA。原始来源、输入、响应和费用文件不为显示方便改写。

已派发请求身份与时间在当前及目标历史间按唯一ID合并，用于每日请求上限，不能通过恢复旧快照重获已经使用的请求数。同ID时间冲突或坏连续性记录拒绝恢复，不猜造token或金额。快照时点之后的笔记、解析及完整费用原始记录保存在恢复前副本中；这是受控的时间点恢复，不宣称把全部研究改动自动合并成同一现行正文。

新空间完成暂存验证后原子替换，初始化失败回滚，恢复前副本保留。Zotero原实例与目标绑定继续正常核验，恢复旧journal不授予新Zotero授权。下载完成不能提前把整次恢复任务写成成功；最终取消、失败和成功以实际确认及安装结果为准。
