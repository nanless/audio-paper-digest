# 论文速递三端宣传片与小红书素材复盘

本文记录 2026 年 11 月这次宣传素材的制作经验。通用的实机录制、音频和手机验收步骤见 [phone-first-demo-production skill](../skills/phone-first-demo-production/SKILL.md)。这里的剪辑顺序、读法和封面文字是本项目当轮确认的要求。素材可交付给用户自行发布。项目原有的小红书自动发布流程保持退役。

## 这次采用的镜头顺序

| 段落 | 录制和验收重点 |
|---|---|
| 网站首页 | 从页顶连续下滑，旁白介绍导航、最新一期、研究入口和往期日更。最新一期与研究入口稍作停留，往期日更快速划过几排 |
| 某天的日更 | 单独切镜，从页面顶部翻到完整展示一篇论文的介绍。速度可以快于首页，仍要看得出页面内容连续变化 |
| 独立论文博客 | 画面提示和旁白明确进入论文博客。连续从一处能辨认的原图滚到表格，图表都留出识读时间。阅读整篇不属于本镜头目标 |
| Mac 工作台 | 双栏展示中文导读和原始 PDF。放慢点星标、打开收藏栏和展开详情，保留操作结果。加大画面时检查两栏边界及标题 |
| Android 工作台 | 从收藏点开与 Mac 镜头相同的论文，能看到打开结果。随后切到日更首页，展示原生列表的连续滑动 |
| 网页会议论文集 | 滑动浏览，给会议入口更长的识读时间。画面和口播顺序为 AAAI、ICML、ICASSP、InterSpeech |
| 下载与项目入口 | 指明 GitHub Releases 中 Mac 选 DMG、Android 选 APK。片尾分别显示 GitHub 仓库与博客首页完整地址 |

网页论文博客和 Mac 的演示论文可以分别选择。当镜头说 Android 接着打开同一篇时，核对的是 Mac 收藏和 Android 收藏中的论文身份。用户最后取消双向同步演示，所以片中跨端打开同一篇只展示阅读衔接。笔记双向同步另由工作台验收覆盖。

早期版的竖屏画面因为文字过密、网页与 Mac 边缘裁掉而返工。先用实际录屏预览一个首页片段和一个双栏片段，再决定取景和界面缩放。实机滚动按段录制，避免用一连串静态截图模拟。首页与日更的滚动段保持平稳，停顿安排在要识读的入口。各端的标题提示和旁白对齐。所有切屏用短淡入淡出，动作和旁白都结束后及时切下一屏。

## 旁白与配乐

Drama 3 整稿试音出现提前结束，正式旁白改由托管接口逐句生成。实际模型标识为 OpenRouter 的 `fish-audio/drama-3`。Qwen3-TTS 用于本地同稿对照，Drama 3 的本地推理没有完成成片验收。比较本地和托管方案时，音色选择、参考音频和响度也会改变听感。不能只凭一条样本判断模型水平，更不能用英语榜单代替普通话读法验收。

| 屏幕文字 | 本片口播要求 |
|---|---|
| 日更 | 「更」读 gēng，一声 |
| AAAI | triple AI |
| ICML | 依次读英文字母 |
| ICASSP | āi kà si pu，ai 一声、ka 四声，si 和 pu 轻声 |
| InterSpeech | 英语读法 |

普通句子直接读定稿。自动转写用于查词、顺序和句尾，指定读法仍需听。ICASSP 最终用四个单独生成的音节拼接，调整声调、时长和衔接，再放回完整会议句试听。片尾旁白、字幕与卡面分别核对，项目 MIT 开源声明和语音模型许可按各自对象说明。

配乐用本地 ACE-Step 生成并试听候选。早期音乐听感突兀，保留的候选以节奏稳定、音色自然和旁白清晰为准。修改旁白或时长后重新混音，检查进入下一段时音乐有无突变，轻声和专名能否听清。记录正式使用的模型、运行方式和选定样本，避免把试音模型当成最终成片来源。

## 封面和发帖文案

- 封面只保留大标题「语音／音乐／音频论文速递」和小字「完全开源」。实机画面用一个有层次的构图组织，网页作为后层，Mac 双栏为主体，Android 放在侧前方。最终封面用 1080×1440 导出，并在 180×240 缩略图核对标题和三端画面。MIT、端别标签和额外说明都从本次封面删除。
- 发帖文案独立成稿。标题直接交代完全开源与语音、音乐、音频论文。开头讲工作台帮研究者追日更、按方向和会议找论文、对着原文记笔记。正文重点写 Mac 工作台覆盖网站的大部分阅读功能、双栏读原文与笔记，再写 Android 接着读。网站入口和下载方式简洁收尾。需要提同步时带上同一 WebDAV 目录与已同步的条件。采用直接说明，避免编造读者经历、复述视频和堆功能。
- 研究小红书写法时，可从真实作者展示的标题、内容和公开数据提取可用做法。例如「你的 Zotero 会替你找论文」直接讲工具能做的事。作者分享及自报数据只反映各自案例。发布前按当前平台和任务需要另行核对格式和规则。[作者原帖](https://linux.do/t/topic/1751458) · [作者公开的数据案例](https://yueying526.github.io/xhs-analytics/)

## 最后一次修订怎样交付

- 视频为 1080×1920，最终节奏版约 82.1 秒。完整解码、字幕与画面顺序核对另于手机播放记录保存。小米 15 Ultra 曾实际查看先前的竖屏版本，按比例播放时顶部与底部可见少量留边。后续版本的解码与抽帧结果单独记录，不能沿用旧手机复验的结论。
- 本次发现节奏版随附的「文案与分镜」仍带着早期发布文案，随视频复制的旧封面也早于单独交付的三端一体封面。以后用单独的成品清单明确当前视频、字幕、封面和发帖文案。发布稿与分镜分开命名，逐个打开核对。改过口播和剪辑节奏时，用最终时间线校验字幕和分镜标记。
- 片尾需要读清完整地址。视频和发帖文案可以同时给用户这两个入口。下载方式使用当次发行实际存在的 DMG、APK，并核对系统要求。版本变更后从发行页重新确认。[GitHub 仓库](https://github.com/nanless/audio-paper-digest) · [博客首页](https://nanless.github.io/audio-paper-digest-blog/) · [发行页](https://github.com/nanless/audio-paper-digest/releases/latest)
