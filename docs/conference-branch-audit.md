# 历史会议分支审计与迁移边界

这份审计记录写于 2026-09-06，检查了 `icassp-2026-analysis`、`iclr-2026-analysis` 和 `icml-2026-analysis` 三个分支，并讨论如何将其中可用的会议处理功能迁入当时的 `main`。下文的数量、文件状态和能力限制均指审计时的观察，没有在本次文档整理中重新核验。

现在处理新会议应按 [会议工作流](conference-workflow.md) 操作；重写已发布的历史会议页面应按 [历史重写流程](history-rewrite.md) 和 [历史直接发布流程](history-direct-publication.md) 操作。下面的迁移顺序是当时的方案，不是现在必须重走的入口。

<a id="总结"></a>
## 审计结论

三个分支都从较早的主线分叉，之后通过复制共享文件同步代码。到审计时，它们已不能满足 `main` 对论文身份、来源、Reader、评分、分类、账号池、锁、生成清单、审查和远端提交的要求。因此，不能整体合并分支、覆盖共享文件或批量挑选提交；可保留的会议算法和页面设计也必须重新接入当前接口，并通过测试。

三个分支都没有受版本控制的正式会议数据。旧筛选决定、全文、分析和图片主要保存在本机，Git 提交历史无法证明某次会议任务处理完整，也无法证明这些结果能从原始来源重放。

## ICASSP 2026

当时本机有 3,694 条 `{arnumber,title}` 元数据和 3,694 份 PDF。标题归一化能找到全部文件，但这只能用于发现候选，最终身份仍须由 IEEE `arnumber` 确定。

旧入选和分析结果约有 898 篇。筛选记录中，6 篇没有决定，5 篇同时被标为入选和排除；结果也缺少来源 SHA、Reader、分析清单和生成证明。因此，这些结果只能用于差异对照。远端分支的筛选提示词与解析器已不匹配，图片配置还会使实际模型输入没有图片，即发送 0 张图。

可参考批量定位 PDF、分页提取、任务分组和会议总览的设计。以下做法不能迁入新流程：用标题认定身份、直接发送 HTTPS 模型请求、把请求失败记为排除、仅凭标题或摘要降级发布、使用 `git add -A`、宽泛删除博客图片，以及没有核验记录的图床上传。

## ICLR 2026

当时本机有 5,352 条 OpenReview 元数据和 5,352 份以 `forum_id` 命名的 PDF。旧音频候选为 957 篇，历史入选和分析结果为 133 篇；这 133 篇的 forum ID、标题、作者和 PDF 能精确对应，但缺少来源 SHA、实际用量、Reader 和筛选输入输出证明，不能直接成为新正文的来源。

分支最后的代码将会议 PDF 接入只支持 arXiv 的分析器，筛选提示词也与解析器冲突，因而当时的分支 HEAD 无法正确重跑。可参考 OpenReview ID 文件布局、用 PyMuPDF 寻找图注和绘图区域，以及按任务查看会议论文的设计。不得用 `arnumber=forum_id` 伪装身份兼容，不得沿用自由标签、将会议状态混入 `data/current`，也不得沿用旧发布器。

## ICML 2026

当时官方元数据缓存有 6,567 篇，旧分支快照只有 6,341 篇，少了 226 篇。因此，旧会议总数和筛选集合不能作为完整记录继续使用。

历史入选的 137 篇实际上都有本机 OpenReview PDF 和文本。目录共有 139 份 PDF，其中额外 2 份需要核验身份；“只有 47 篇 PDF”的旧说法指额外下载的 arXiv 副本，并不表示正文总覆盖只有这些论文。这 137 篇仍缺少可核验的来源记录，其中 19 篇受到过时的 120k 字符前缀截断影响；标签还有 26 篇为空、9 篇缺主任务、4 篇缺主方法。

可参考 OpenReview forum ID 与会议数字编号的对应关系、先筛元数据再下载、逐页提取和会议排行榜生成方式。不得读取 Chrome Cookie/Keychain，不得用模糊标题映射 arXiv，不得覆盖式下载、任意注入 `fullText/imageUrls`、按摘要降级发布，或沿用混在一起执行 generate/review/push 的旧发布器。

## 统一迁移顺序

当时提出以下迁移步骤。它们说明旧分支接入生产流程时应保留哪些核验，不替代现在的新会议入口。

1. 用 `conference:discover` 保存官方目录、论文主身份和本地 PDF 候选报告。
2. 为全集论文保存逐篇筛选决定。请求失败须保留为 `pending/failed`，不能记成 `excluded`。
3. 先用固定提取器处理 `included` 论文，人工复核暂存结果，再由受控导入器生成完整来源快照；过程只接受不能自行构造的来源清单句柄，每一步都要重新核对上游记录。
4. 会议分析的来源上下文只接受完整上游文件链生成的计划句柄。低层清单和运行构造器只用于未获生产授权的测试数据；分析适配器只将结果写入独立执行目录，复用 Reader、评分和用量记录，不写日更的 `data/current`。
5. 分类证据文件绑定词表 SHA、原文证据及未知或冲突标签的审核结果。
6. 按会议范围生成稳定的单篇 URL、任务视图和会议汇总，依次生成、审查、按精确允许的差异推送，再核验远端 OID。
7. 用隔离小样本验证旧分支迁移代码。当前历史直接重写无须先完成这项迁移试验，使用本地元数据/PDF 目录、冻结的页面对应关系和独立并发队列。

旧分析和旧博客正文只用于差异检查，不得用来生成新的 Reader、标签、评分或汇总。
