# 日更补抓的起止时间

补抓只从博客已核验远端 origin/main 基线中的日更汇总及其独立页确定上一次批次，不读取未提交会议页面，也不把当前未发布的入选集当作已发布。每次固定 UTC 结束时间；续跑须以保存的结束时间重新核验同一批次和边界身份，不能因为当天重新启动就移动窗口。

旧批次没有完整抓取检查点或原始提交时间时，核验全部已发布 arXiv 编号、独立页和引用元数据的 SHA，以最早编号所属提交月份的月首作为保守下界。这个下界不是精确发布时间，也不证明旧批次抓取完整。2026-10-03 的16篇均为2610编号，因此从2026-10-01 UTC补抓；会重复抓取部分论文，但只排除真正已发布的论文；失败、仅入库或仅分析记录不能当作已发布。旧论文或其他来源缺少可验证编号时明确失败，不静默缩短窗口；首次运行须另行明确初始化起始时间，不自动默认七天。

每页100条是分页大小，不是整个分类的总量上限。较旧的批次可能需要更多页；不得用更新日期或遇到一个历史编号就提前结束。当前实现只支持可核验 arXiv 编号的旧日更边界，不声称已解决任意 HuggingFace 混合旧批次的初始化。新 v7 批次归档完整后，核验七类 arXiv 与 HuggingFace 来源计数、内容 SHA、覆盖窗口、候选与入选集合，并把深度分析文件及生成清单关联到远端已提交页面，再使用上一窗口的精确结束时间。上一批次归档中的 v7 证明，或 current 中已关联上次正式页面的 v7 证明损坏时明确拒绝，不退回月首掩盖错误。

正常运行前应先同步远端引用；helper只读取缓存的 origin/main，并确认本地HEAD包含它。缺远端引用明确失败，本地未推送提交不算发布。缓存引用本身不证明网页部署，仍须独立保留最后远端验证与上线检查。

同日发布后数据尚在 current 时，只在批次日期、完整窗口和已提交页面生成清单全部关联通过时使用该窗口。current 中其他日期或未完成的新尝试不能充当上一发布证明；无法绑定时仍用保守月首重叠，不缩短范围。

单次 arXiv API 查询仍受服务数量限制：超过 30000 条时自动拆分成不重叠的分钟范围，并核对拆分前后总数；最小一分钟仍超过限制时明确失败，不静默截断。请求经共享主机调度，间隔至少 3 秒，已有更长等待仍保留。

当前目录中的合法 JSON 若属于另一日期或尚未关联上次已发布页面，可以保守重叠抓取，并通过不写入边界身份的诊断信息说明原因；已关联正式页面的 v7 来源证明损坏则停止，不能退回月首掩盖问题。读取或 JSON 解析失败也必须报出。

日更的整个抓取流程先取得独立运行锁，避免两个批次同时改写当前数据。默认使用 `LOCAL_DEAD_PROCESS_OPERATION_LOCK_RECOVERY`：锁记录、权限和文件身份均符合要求，且明确确认持有者属于本机、进程已退出时，可以在原过期时间之前恢复这把运行锁。仍活跃的进程、其他机器的持有者或不安全的锁不能走这条提前恢复；不能仅凭时间较久或一次启动超时手工删除锁。原有过期判断及逐篇论文锁规则不变。取得运行锁后仍须核对北京时间批次日期，随后才可归档和抓取。
