# 论文速递工作台：机密审计与发布边界

Mac 与 Android 客户端统一使用“论文速递工作台”作为显示名称。网站、来源项目名称、应用标识、签名身份、既有资料目录和备份协议不因显示名改变而迁移。下载入口见[项目发行页](https://github.com/nanless/audio-paper-digest/releases)。

## 本次审计覆盖什么

2026-10-29，多位独立执行者按互不重叠的范围检查源码，另行检查 Git 历史和已公开的 v1.0.0 附件。源码基线是 `ac686d6e29a8b5a1979c36de118e0880c6703186`，不是尚未构建的新版本安装包。

## 发现怎样处置

本次未确认上述基线中存在真实生产凭据或私钥泄漏。与此同时，审计发现了不能用“没有硬编码 key”掩盖的条件风险：

- Android 自定义认证头构造异常可能带入凭据，随后进入界面或持久化错误记录。保护应放在实际请求构造边界，转换为固定安全失败，不携带原异常消息或 cause。
- Python 模型请求不能沿默认 HTTP 重定向把认证头或请求体转交另一地址。认证模型调用采用拒绝自动重定向的策略，同时保留原代理、失败分类与费用记录。
- 代理状态行、服务错误正文等不可信诊断不能原样作为公共错误消息。共享请求层、客户端 worker 和控制台边界分别处理；成功回答、真实用量及原始私有恢复证据不能为脱敏而悄悄改写。
- 机器 home 路径属于低风险隐私元数据，并非密钥。当前操作说明使用 `$HOME` 表达；历史提交、原始测试见证和合法第三方构建信息不因此被篡改。

这些修复须通过合成输入、正常调用链和负例回归，不能用真实凭据发请求来验证候选，也不能把源码测试当作新安装包已经通过的证明。

## 安装包与凭据的边界

- 安装包不得包含项目环境配置、账号口令、签名私钥、本机记忆库、私人研究资料或私有审计目录。Git 跟踪状态只是来源约束，不替代内容审计。
- 客户端仅使用用户自行配置的本机凭据。Mac 通过原生 Keychain 路径，Android 通过本机安全存储；显示名变更不能创建另一套应用身份或绕过旧资料保护。
- 两项本机研究完整性密钥不属于可迁移研究资料，备份、云上传与恢复分别执行排除及不覆盖本机密钥的规则。
- 原始研究、用户笔记、模型回答和完整备份本来可能含私人内容，不能将“受保护的本机恢复材料”解释为“可公开附件”。上游服务还可能在正文中反射敏感信息；固定界面错误不等于所有原始正文已匿名化。不要公开这些原件，亦不要为了审计重写旧回答、计数、回执或费用。
- 公开许可证署名、公共 CA 证书、软件和安装包校验和、测试明确构造的假凭据，不等同于生产秘密。分类须核对真实来源或用途，不能仅因文件位于测试目录就放行。

## 新版本如何验收

改名或安全修复后的版本必须重新绑定最终源码和实际字节，不能复用旧包的结论替它签发资格：

1. 定向回归及独立复核后冻结来源，再运行该提交的完整 CI。
2. 通过正常构建、既有签名和发行工具生成新包，不覆盖旧发布掩盖发现。
3. 从实际 Mac bundle 校验显示名、应用身份和文件名；从实际 APK 校验应用及 launcher 名称，并解码网络、备份和设备迁移安全 XML，拒绝编译资源覆盖放宽策略。
4. 对全部新资产增量扫描、容器解码及凭据排除检查；只输出位置、类型、数量和脱敏结论，不输出凭据原文、片段或其稳定指纹。
5. 下载远端实际附件核 SHA 与来源，再核公开页面和下载可用性。发布计划、私有草稿或本机包通过均不等于已经公开发布。

本次 Mac 发行仍为 ad-hoc 签名、未经过 Apple 公证；Android 的设备验收范围应明确标注为模拟器，不冒称实体机覆盖。

## 结论不能超出证据

有限规则与静态审计无法证明任意加密、混淆、隐写、未知格式和未来用户输入均没有秘密。历史中有未完全溯源的少量不透明测试候选及机器路径元数据，均保留其边界，不以“高熵”“vendor”或“fixture”标签直接判安全。针对当前已知配置的仅内存等值检查也只排除这些被比较的值，不排除退休或未知凭据。

因此，应表述为“在明确列出的来源、字节、规则及复核范围内，未确认生产秘密泄漏”，而不是“保证所有代码和安装包绝无任何机密”。如后续确认真实凭据泄漏，应停止分发受影响版本、通过安全渠道处理凭据与公开记录；不能只删除当前文件便宣称历史暴露已经消失。
