# 收藏分类与收藏时间

工作台的收藏沿用网站已经发布的多级分类。分类名称、所属分面及父子关系来自网站目录，论文所属类别来自每篇导读的原分类记录；客户端不另建分类，不提供创建、重命名或手动归类入口。按收藏时间分区与网站分类筛选可以同时使用。

新收藏记录实际操作时间；重复点击收藏、切换分类、同步网站和恢复备份都不重置该时间。旧版只保存编号，无法恢复真实收藏时间，因此显示“时间未知”，不得用论文发布日期、安装时间或恢复时间代填。

## 网站分类怎样使用

自 1.3.0 起，Mac 的“研究方向／全部论文”和 Android 的论文库都可使用这份完整目录；收藏与待读再按各自范围显示结果。目录包含零结果节点，支持中文、英文、别名和编号查找、完整路径及定义。展开层级和应用筛选分别操作；高级筛选保持同分面或、跨分面且、直接／子树及主要／全部角色规则，条件由同一篇导读满足。

同步网站后，在收藏中选择网站分类；研究任务、研究方法、研究条件、信号、应用、研究重点、研究产物、科学主题和模型家族沿用网站的九个分面。展开父类查看子类，选择父类也可查看所属子类的收藏；每篇论文的计数只计一次。论文卡片展示原本选中的分类及其路径，路径中的祖先用于导航，不会写成论文新增的直接标签。

同一论文可能有多篇已发布导读，每篇导读的分类分别保留，不能把不同导读的任务和方法拼成一次匹配。客户端读取完整的网站索引，并在同步时配对读取 `data/tag-catalog-snapshot.json` 和 `data/tag-catalog-versions.json`。先按论文原词表版本核对分类，再按网站当前目录展示层级；不使用项目中另一份写作用词表代替已发布网站目录。

旧缓存没有结构化分类时，提示同步网站；网站暂未提供或分类资料暂不可核对时分别说明原因，仍可阅读和取消收藏，不根据标题、任务文字或平面标签猜分类。分类文件读取失败不能使已同步论文消失。

## 两端共用的个人资料

以下是 1.2.0 引入的兼容格式。自 1.2.1 起继续保留原收藏时间和旧自建分类资料，旧文件夹不再作为界面分类来源，也不会被改写成网站分类。完整备份继续保留这些原字段，不为移除界面入口删除用户资料。

`personal.json` 保持 `schema: 1`，`favorites: [paperID]` 继续作为是否收藏的唯一依据。可选字段如下：

```json
{
  "favoriteCollections": {
    "version": 1,
    "revision": 0,
    "folders": [
      {
        "id": "11111111-1111-4111-8111-111111111111",
        "name": "语音识别",
        "createdAt": "2026-11-01T09:00:00.000Z"
      }
    ],
    "items": {
      "synthetic:example": {
        "addedAt": null,
        "folderIDs": ["11111111-1111-4111-8111-111111111111"]
      }
    }
  }
}
```

以上编号和时间是明确的合成示例。字段缺失时视为没有附加收藏资料、修订号零；没有条目或 `addedAt: null` 均表示未知收藏时间，不在启动时补造。

- 分类最多 200 个，条目最多 100,000 个。分类 ID 是小写 UUID；原生端生成 ID，界面不传入任意文件路径。
- 名称去除首尾空白并按 NFC 规范化，规范化后精确重名拒绝，区分大小写。名称须非空、UTF-8 不超过 128 字节，不含 C0/C1 控制字符（U+0000–001F、U+007F–009F）。
- 新条目与操作的论文 ID 须非空白、UTF-8 不超过 256 字节。已有 `favorites` 数组仍沿原 schema 读取，不因这个新增功能收紧旧数据结构。
- `folderIDs` 不重复且必须指向已存在的分类。新写入按 ID 排序；这些旧关系仅用于兼容读取与备份，不能决定网站分类筛选结果。
- `revision` 是 0–2,147,483,647 的整数。布尔、数字字符串、小数和越界值拒绝；达到上限时有效更改拒绝，原资料保留，不清零。
- 新时间由原生时钟生成，保存 UTC、三位毫秒和 `Z`。读取接受 UTC `Z`、零至九位小数及 ISO 延伸公历的真实日期（不采用 1582 年的历史历法跳日），年份 1–9999；非法日期、年零及闰秒拒绝。已有时间字符串及未知字段保留；完整备份与恢复原件另按原字节合同保存。
- 旧端可能只修改 `favorites`，留下已取消项的分类条目。允许读取这些有界残留，但界面只展示与 `favorites` 的交集，不能复活收藏。再次真正收藏该编号时写本次时间，已知旧分类不自动复用。
- 未知未来版本整块保留，基础收藏仍可阅读，收藏更改明确提示需要升级；笔记、待读、任务与完整备份不受影响。损坏的已知 v1 按原损坏资料政策保留原件并拒绝，不重置成空资料。

## 增量收藏与旧接口兼容

新界面不再把旧快照的整列编号传回覆盖。`personal.list.edit` 接收 `key: favorites|reading`、`action: add|remove|toggle` 和 `ids`，在原生锁内读当前名单并一次保存。实际界面的收藏按钮发送明确的 `add` 或 `remove`；两个旧视图都点击“收藏”不能因两次 toggle 抵消。

原有 `personal.favorite.edit` 保留下列兼容操作，1.2.1 界面不调用它们建立或修改分类。所有旧分类写入仍必须带当前 `expectedRevision`；接口兼容不授予网页内容修改权限，也不能将个人文件夹当成网站分类。

| action | 附加字段 | 结果 |
|---|---|---|
| `folder.create` | `name` | 原生创建 ID 和时间 |
| `folder.rename` | `folderID`, `name` | 保留 ID、创建时间及条目的收藏时间 |
| `folder.delete` | `folderID` | 解除该分类关系，保留收藏和其他分类 |
| `items.assign` | `ids`, `folderIDs`, `mode: add|remove|replace` | 添加、移除或明确替换分类 |

`items.assign` 默认要求所有编号已经收藏，任何未收藏成员都拒绝整组操作。只有明确的 `addMissing: true` 才同时收藏缺少的成员。这是旧版兼容行为；当前界面通过增量收藏接口保存真实收藏时间。

删除不存在但格式有效的分类是幂等操作，仍先检查修订号；重命名不存在的分类拒绝。只有有效的收藏变更推进本字段修订号；重复添加、相同归类或原名重命名是幂等操作。笔记和任务更新不推进收藏修订号。保留的 `personal.setList` 兼容入口也在当前锁内计算差量，已有成员的时间、分类和未知字段保留。保存失败时内存与磁盘都保持原状态。

## 时间分区与恢复

默认按收藏时间从新到旧，时间未知单独放置。按本机时区的自然日提供今天、近七天、更早和时间未知分区，也可按月份查看；“论文发布日期”不得冒充“收藏于”。分区依据本地日历而非固定 24 小时，覆盖跨时区和夏令时边界。

完整备份、WebDAV 保存和跨端恢复继续按原合同封存 `personal.json` 字节；收藏分类、时间及未知字段随所选快照保留，不自动合并两台设备。恢复仍保留原始个人资料回执，不重签模型材料、不更改来源、费用或本机凭据政策。旧端未被新端观察到的“取消后再收藏”无法可靠推断时间，不能承诺补回历史。
