# Mac 与 Android：功能、数据和使用范围

“论文速递工作台”提供 Mac 与 Android 两个原生客户端，用于阅读网站已发布的论文解读、核对原始 PDF、保存个人研究，以及连接 Zotero 和坚果云。主项目与网站仍叫“论文速递”，日更、会议和历史文章继续由网站工作流生产。客户端安装、同步、阅读或换设备均不自动重新分析论文。

当前 Mac 与 Android 源码均为 1.4.4（构建号 20），公开安装包以[发行页](https://github.com/nanless/audio-paper-digest/releases)为准；1.4.3 已于 2026-11-05 公开发布，下载见[1.4.3 发行页](https://github.com/nanless/audio-paper-digest/releases/tag/v1.4.3)。1.3.0 时的全站分类、两端界面及正式发行验收见 [1.3.0 审改记录](workbench-1.3.0-review.md)；1.4.4 的改动与验证范围见 [1.4.4 记录](workbench-1.4.4-review.md)，1.4.3 的改动、自动测试与未重做的人工验收见 [1.4.3 记录](workbench-1.4.3-review.md#发行状态)。Android 支持 API 28 及以上系统；Mac 支持 macOS 15 及以上的 ARM64 设备，使用本地签名、未经 Apple 公证。下载安装与版本状态见[Android 验证说明](<android-validation.md>)和 [Mac 发行说明](<mac-app-release.md>)；性能与发行核验见[客户端性能](client-performance.md)和[客户端发行核验](client-release-verification.md)。

## 两个原生界面，共用研究资料

| 场景 | Mac | Android |
|---|---|---|
| 文献库 | 桌面侧栏、可调整窗口与快捷操作 | 手机底部导航，大窗口侧栏 |
| 未打开 PDF | 单阅读栏 | 单阅读栏 |
| 已打开 PDF | 导读与原文并排，可调整或聚焦 | 手机切换阅读与 PDF，宽度足够时并排 |
| 设置与文件 | 原生窗口、系统文件面板 | Compose 页面、系统返回和文件选择器 |
| 个人研究 | 主动确认后调用自己配置的模型服务 | 主动确认后调用自己配置的模型服务，提供通知和取消 |
| PDF | PDFKit 阅读与文字提取 | Jetpack PDF 阅读；PDFBox 提取文字、提供查找与选区兼容路径，并显示加密原件 |
| 凭据 | 本机钥匙串 | Android Keystore 加密保护 |

Android 以手机为主要设备，按实际可用宽度适配平板、折叠屏和分屏。输入法、系统栏、大字号和屏幕折痕均参与布局计算。空间不足时切换内容，不将双栏压缩到无法阅读。科学图和 PDF 保持原色，宽表与长公式可局部滚动。

## 阅读和同步

当前源码优先读取 `client/index.json`，只有该地址返回 HTTP 404 或 410 才读取原 `index.json`；新格式损坏或网络错误不会触发兼容回退。已发行客户端的原入口继续保留。随后应用取得对应入口的目录分片；具体读取与四文件兼容边界见[网站数据适配](mac-app-data.md)。分片是将大目录拆开的多个文件；应用逐份核对大小、SHA 内容指纹、论文身份、来源和明确版本，全部校验后才切换资料库。失败时上一份完整结果仍可用。文章正文、引用、研究上下文、图片和 PDF 按需取得，不自动下载全库原件。

网站移除、论文撤稿与旧版本是不同状态。目录更新保留私人笔记、研究回答、旧稿和归档映射。离线包绑定原文章、来源修订、PDF 与图片；缺图、缺原件或未核版本会显示相应状态。

Android 使用 WorkManager 调度同步和备份，执行时间受网络、电量、存储和系统配额影响。强制停止应用后，任务需等系统允许或用户重新打开应用才能继续。

## 研究、来源和费用

用户配置端点、协议、模型、代理、输出预算、超时与本机请求上限，密钥通过专用安全输入保存。Muse 使用明确配置的 HTTP CONNECT 代理；其他模型采用各自路由。

个人研究在设备上管理，不代表推理一定在设备上完成。选择远程模型端点时，确认的材料会发送给该服务；只有连接本机模型服务时，推理才在本机执行。当前两端发送的是提取文字，不发送 PDF 原文件或图片。

研究开始前，先保存实际问题、选区或物理页范围、PDF SHA、文章修订和配置，再登记“请求已经派发”，最后发送网络请求。这个顺序使应用在中断后仍能判断一次请求可能已经消费，不能因为没有收到回答就把它当作未执行。

回答、原始响应、实际用量、失败、截断、取消和未知费用分别保存。恢复或重新打开页面不重发已派发请求；相同输入复用已有结果，明确重做另建记录并保留历史。

修改端点、密钥、论文、PDF、选区、问题或预算会使旧确认失效。个人回答与原文证据、网站导读分别展示；页级来源只定位到原页，不生成逐句高亮或未经提取的图像结论。扫描页可保留原件阅读，当前不承诺 OCR 或模型视觉理解。

## Zotero 归档

Android 使用官方 Web API v3，由用户单独配置专用授权；不要求 Mac 在线，也不读取其他应用的密码。Mac 本地许可与 Android Web API 授权分别管理。

确认目标文库、分类与所选材料后，归档分别处理书目、来源元数据、原 PDF、图文导读、研究和笔记。对象 key、版本和检查点长期保存，用于去重、保护远端用户修改，以及取消后继续。完成时逐项回读字段和实际文件。

系统分享是快捷交出 URL 或文件的入口；接收方负责后续保存。完整归档使用上述 API 流程。个人文库可使用 Zotero Storage 或已配置的 WebDAV，群组附件不使用 WebDAV。官方 Android 客户端已在 1.0.0-247 上验证指定归档的 PDF、导读和笔记离线读取；其他版本或格式按各自支持范围使用。详见[Zotero 说明](<android-zotero-research.md>)。

## 备份、恢复与多设备

当前源码使用稳定合同 `paperdigest-backup` 保存研究文件，用 `paperdigest-cloud-snapshot` 记录这些文件在云端如何分块保存。两种新文件都带结构指纹；旧包与旧清单仍按各自原格式和实际字节核验。每次备份在独立目录 `PaperDigest` 下建立一个版本，已保存版本不被后续编辑覆盖。8 MiB 分块上传后，逐块下载回来比较原字节，最后写入并核验完成清单。取消保留原快照与进度检查点；继续时仍使用同一份字节、UUID 唯一编号和目标。

恢复先完整下载、核验和暂存，再经用户确认替换；恢复前副本保留，失败回滚。当前设备的模型连接、凭据、派发计数和云端控制设置受保护。模型与网盘密码、设备授权、两份本机响应完整性密钥不进入新备份；旧包原始记录保留，不将其中的完整性密钥安装到另一设备。

资料包没有额外端到端加密。跨端恢复保留原文、未知字段、原始输入、回答和费用，路径由原文件 SHA 约束重定位；历史模型记录可阅读，但只有受支持的合同和原证明满足条件时才可复用。多设备以独立版本与显式恢复时点管理资料，不提供笔记的实时自动合并。字段与上限见[备份合同](<android-cloud-contract.md>)。

## 验证与发行

既有 Android 功能测试使用 API 28、API 35 模拟器，覆盖原生阅读、系统文件操作、不同窗口和字体、模型、Zotero、坚果云及跨端资料读取。历史 1.1.0 的 code4→5、33 个研究文件保持按原范围保留；本次 1.3.0 的 code7→8、61 份原文件与六对象保持、全站分类及界面增量分别按自己的正式记录核验，不把历史操作写成新包重测。具体版本范围见[验证说明](<android-validation.md>)和[86 项功能表](<android-feature-parity.md>)。

正式 APK 与 Mac 安装包在同一仓库的 [GitHub Releases](https://github.com/nanless/audio-paper-digest/releases) 提供。版本、来源、最低系统、架构、签名和 SHA 由实际发行文件记录。1.3.0 的联合验收记录见[1.3.0](https://github.com/nanless/audio-paper-digest/releases/tag/v1.3.0)；当前 1.4.3 的十二件附件、签名证书和匿名下载核验见[客户端发行核验](client-release-verification.md)。正式包不包含验收样稿、用户资料、签名私钥、运行配置或本地审查记录。
