# Mac 与 Android 应用的范围、数据和验收

两端围绕同一项工作：阅读已经发布的论文解读，打开原始 PDF 核对，保存自己的研究记录，再将完整资料存入 Zotero 或坚果云。网站继续承担日更、会议与历史文章的生产；客户端读取这些成果，不因安装、同步、换设备或打开文章重新调用写作模型。

本文汇总截至 2026-10-25 的产品要求与实施边界。Android 正在开发、测试及交叉审查，尚未完成发行验收。具体逐项标准在 [Android 功能对照与验收表](android-feature-parity.md)；原 Mac 的 [69 项](mac-app-acceptance.md)及[云端与发行 17 项](mac-app-cloud.md)继续保留，不能以 Android 新增工作替代原有未完成项目。

## 两个原生界面，共用成果与资料合同

| 场景 | Mac | Android |
|---|---|---|
| 资料库 | 桌面侧栏、可调整窗口与完整快捷操作 | 手机底部导航；大窗口侧栏，按可用宽度变化 |
| 未打开 PDF | 保持适合长文的单阅读栏 | 单阅读栏，不留空白 PDF 面板 |
| 已打开 PDF | 解读与原文双栏，可调整分隔和聚焦 | 手机在阅读/PDF 间切换；足够宽的平板、折叠屏或分屏才并排 |
| 设置与确认 | 独立原生窗口和系统文件面板 | 原生 Compose 页面、系统返回、文件选择器及确认对话框 |
| 私人研究 | 明确提问后才调用本机配置的模型 | 同样由用户主动发起；使用后台任务、通知和可取消操作 |
| PDF 证据 | PDFKit 的真实页、文字、目录和选区 | 原生 PDF 视图；缺能力的旧系统使用真实 PDFBox 提取、搜索和选区适配 |
| 系统权限 | 本机钥匙串、Zotero 桌面授权 | Android Keystore；不继承另一设备或另一应用的权限 |

用户已明确：Android 以手机为主要使用设备，同时必须适配平板和折叠屏。手机首屏、输入法开启、系统返回及大字阅读优先验收，宽屏并排不能代替手机可用性。Android 不是 Mac 网页缩小版，也不使用手机布局代替 Mac 窗口。布局按实际可用 dp 适配，测试还须覆盖横竖屏、分屏、输入法、字体放大、浅深色、返回、旋转和进程重建。[Android 官方自适应布局](https://developer.android.com/develop/ui/compose/layouts/adaptive/list-detail)

## 数据从哪里来

优先读取网站现有的 `index.json` 清单、带大小和 SHA 的目录分片、正式文章正文、引用和研究上下文附加文件。客户端核验论文身份、来源地址、明确的 arXiv 版本及文件内容后再保存；同步失败保留上一份完整资料库。公开网站数据与本机私人笔记、模型配置、用量和存档记录分开。

客户端的定时任务只同步服务器已经生成的成果。Android 使用 WorkManager 执行持久后台任务；它受网络、电量、系统配额与强制停止等条件影响，不能承诺固定时刻必定运行。用户手动发起的较长研究和传输需要可取消通知，并持久保存材料和检查点。[Android 官方长任务说明](https://developer.android.com/develop/background-work/background-tasks/persistent/how-to/long-running)

同步目录后不能仅凭同名标题判断论文相同；退役页面和旧修订也不能直接删除。正在阅读的离线包、模型原输入和标注各自绑定原版本。旧稿可以继续阅读，但必须明确它没有取得网站当前修订的资格。

## 本机研究如何保存

设置覆盖模型端点、协议、模型名称、代理、输出预算、超时及本机请求上限；API key 走专门安全输入，不进入普通设置或任务 JSON。Muse 使用明确的 HTTP CONNECT 代理，其他模型不悄悄继承该代理。

每次研究先封存用户问题、实际材料、物理页范围、PDF SHA、文章修订和有效配置，再记录派发事实。真实响应先保存原字节和完整性记录，再解释回答与用量。截断、认证失败、取消和消费未知分别保留，不能把缺失用量记为零，不能因重启或恢复自动重发已派发请求。

相同输入的复用必须重新核对原封存输入、原响应、回答、实际模型及用量事实。改变当前端点后，旧准备任务不能取当前密钥发向旧地址；改变阅读对象、PDF、选区或当前页后，等待中的操作也不能把旧问题与新材料拼接。

完整研究空间包含原始输入、回答、费用和历史。API、网盘与 Zotero 凭据以及本机派发许可不随研究备份迁移。响应完整性的恢复材料属于研究原始记录，须原字节保留；它不是模型或网盘密码，也不使明文备份成为端到端加密备份。

## Zotero 的 Android 决定

Android 提供可选的官方 Web API v3 完整存档。它不需要一台同时开着的 Mac，但需本机单独配置 Zotero 专用授权。桌面 `localhost:23119` 的许可、Server-ID 和对象版本不能复制给移动端使用。[Zotero 官方 API 与授权说明](https://www.zotero.org/support/dev/web_api/v3/basics)

完整存档至少分别处理书目、来源元数据、原 PDF、图文导读、私人研究及笔记。准备页读取真实材料和目标分类；确认后沿长期保存的对象 key 与检查点写入，最后分别回读父子关系、字段、笔记和实际文件 SHA。父项创建成功或附件上传返回成功，都不能单独算完整归档。

重复准备和续传不应重建已完成书目；新材料需要保留历史，并保护用户在 Zotero 中的编辑。个人文库、群组及分类分别核权限，群组文件写入还需核实际角色。HTTP 412、文件配额、Backoff、取消和丢失应答都必须保留可追溯状态。

“分享到 Zotero”只是补充入口。分享 URL 或交给另一个应用处理，不能冒充上述完整写入和回读。官方 Android 客户端对 HTML 快照的阅读支持也须按实际稳定版本验证；保留 HTML 不等于已经证明对方可阅读，必要的导读 PDF 派生件应与原 HTML 同存并单独验收。详细依据和实现取舍见 [Zotero 调研](android-zotero-research.md)。

## 坚果云与换设备

两端使用同一套 `paperdigest-backup-v2` 与不可变分块快照合同，独立目录默认 `PaperDigest`，不进入 Zotero 的附件同步目录。固定 WebDAV 服务、应用专用密码、逐块 SHA、完成清单最后写入和再次 GET 回读共同构成成功条件。账号、目录或原待传材料变化时不能继续套用旧检查点。

停止传输后保留原快照字节、UUID 和实际检查点；恢复时先下载并完整校验，再取得明确确认，暂存、替换和重新加载。失败回滚，恢复前副本保留。本机模型连接、实际派发计数、凭据与云端控制状态不能被旧备份覆盖。

跨端互通不只要求 JSON 能解析：旧绝对路径必须经原 SHA 约束重定位，目录与 PDF 回执必须共用合同，Markdown/MathML/未知字段不能丢失或补签，PDF 标注要按真实裁切框和旋转转换坐标。对平台特有的历史模型合同只保留原事实，不能凭普通 JSON 赋予新的科学或付费资格。[完整备份与迁移合同](android-cloud-contract.md)、[兼容性向量](android-cloud-portable-fixtures.md)

## 先验证失败边界，再发布

开发持续使用“修改 → 测试 → 非作者审查 → 再修改”。修复旧问题后保留原失败结果；测试夹具初始化失败、编译成功、模拟 HTTP 和真实 Android 系统行为分别记账，不能互相代替。最终还需不少于五轮有实际证据的完整改进和审查，而不是为了凑轮数重复未变代码的检查。

验收分为：合同与负例单测、真实 Android 原生组件、真实公开论文的界面、不同系统/窗口尺寸、跨端原包回读，以及真实模型/Zotero/坚果云。模拟器上的成功不冒充某个品牌手机已通过；假服务器的成功不冒充真实账号已经存档。

当前重点闭环包括：旧稿与未知字段保全、路径与离线包双向验证、付费前保存预检、阅读上下文并发、PDF 隔离进程、旧系统搜索、单一标注权威、存档去重与远端编辑保护。功能表上尚未通过的项目继续保留，不因应用能启动就改为完成。

## 同一个 GitHub Releases 页面

最终在当前仓库的 Releases 同时提供 Mac 安装资产和可独立安装的 Android APK。各端记录自己的运行源码、版本、最低系统、签名及 SHA，安装后再次验证。Android 的 debug APK 不作最终发行包；Mac 仍需如实声明签名和公证状态。测试用运行资料、私钥、配置、设备文件、构建缓存与本地审查材料不提交。

Mac 原候选与 Android 新源码的来源边界需独立核对，不能把 Android 代码变更叫作“仅文档修改”，也不能为通过发行检查删去未完成验收。只有最终候选、安装、回读与独立审查对应一致后，才发布正式资产。
