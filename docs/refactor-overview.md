## 一、重构目标与范围

目标是让名称直接说明对象和操作，让文字准确表达已经执行的检查及其结果。
范围包括主仓库的 JavaScript、Python、shell、提示词、文档和测试，以及独立博客仓库的组件、模板、脚本和对应测试。
这项工作包含接口迁移和保存格式迁移，不能概括成只换单词，也不能据此声称所有接口或所有 SHA 不变。

| 目标 | 期望结果 | 实施与验收依据 |
|---|---|---|
| 变量、参数与函数 | 名称说明输入、对象、职责或返回值，不让一个抽象词指代多种内容 | 阅读赋值、返回值及全部实际调用；同步导出、依赖注入、对象简写和关键字参数 |
| 模块、命令与路径 | 当前入口使用易懂且一致的名称，所有实际引用与新入口一致 | 同步模块加载、命令帮助、模板调用、实现指纹清单和测试路径；旧资料路径另按原格式读取 |
| 中文说明 | 句子完整，动作与结果明确，减少中英拼接和重复译注 | 按实际条件改写诊断、注释和用户文字；核对重试、失败分类、修复与测试消费者 |
| 英文说明 | 英文文档自然表达，准确对应当前操作与协议 | 与中文说明和真实写入方核对，保留历史事实及明确的接口标识 |
| 模型提示词 | 用准确的对象和操作描述任务，保持输出与解析对应 | 检查实际读取的首个围栏、占位符、输出字段、文本 SHA、阶段指纹和旧任务恢复范围 |
| 旧保存格式 | 当前新写入使用新名称，旧资料可按已知原格式只读核验和恢复 | 先核原对象或文件摘要，再识别格式；拒绝混用与错代，不改写旧内容后重新计算身份或补发凭证 |
| 测试与审查 | 验证真实写入、读取和恢复行为，保留首次失败与必要修补 | 复用完整受影响测试文件，固定文件内容和 SHA-256 后独立审查；区分局部回归、完整本地验证与远端 CI |
| 中文提交与推送 | 每批原因、范围、兼容边界和验收事实可追溯 | 具体中文提交，正常推送，核对远端的确切提交；再分别记录 CI 与网站部署结果 |

新名称应使用常见词，准确性仍优先于简短。
词表、规则、论文记录、页面字段和保存凭证的职责不同，不能因为都与标签有关，就全部改成一个宽泛名字。
同样，API、JSON、SHA、HTTP 和正式接口名称有明确用途，不能把所有英文片段都当作表达问题。

## 二、典型问题及处理方式

### 一个名称混指多个业务对象

`taxonomy` 是已有的信息组织术语，出现这个词不能证明代码由 AI 编写。
问题在于本仓库曾用它同时指标签词表、标签规则服务、检查结果、分析阶段、历史标签分配和页面元数据。
读者往往要进入实现，才能知道某个变量到底保存了什么。

词表保存名称、别名、分类维度、上下级关系和启用状态，适合叫 `tagCatalog`。
规则服务负责解析和核验标签，适合叫 `tagRules`；检查结果、选择阶段和历史分配则分别使用对应名称。
当前模块、网站全局对象和普通文件名也已按职责迁移，例如 `tag-core.js`、`tag-browser.js` 与 `ResearchTags`。
旧记录中的字段和原证明协议要另行判断，不能与当前普通模块名称混为一类。

### 同一个抽象词指向四种输出

`projection` 曾用于至少四种不同操作：生成模型可读的标签文本、提取汇总页展示内容、遮住可修改字段后的全文，以及提取供页面比较的内容。
这些返回值的用途、组成和读取它们的程序不同，统一换成另一个抽象词仍会让人困惑。

标签提示文本的生成已使用 `buildTagPromptText`。
其他位置应分别说明“提取展示内容”“遮住分类字段”“提取页面比较内容”，再根据真实返回值选择代码名称。
原协议中的 `projectionSha256` 或固定提示文本哈希由专门的程序读取，不能随着普通变量一并机械修改。

### 当前记录与规范地址不能混改

部分局部 `canonical` 实际只是当前保存的分析记录或运行汇总，适合按用途改成 `storedAnalysis`、`analysisResult` 或 `analysisRunSummary`。
某处 Python 局部对象保存的是词表破坏性变更的原因字段，用于计算原因摘要，已按实际内容改成 `reason_fields`。

真正的规范网页地址，以及为稳定 JSON 摘要明确使用的规范化序列化，有具体技术含义。
这些位置不能只因检索到同一词根就改名，更不能通过删字段来改变旧对象的摘要核验。
局部名称、稳定 JSON、网页地址和已保存身份必须分别处理。

### 比喻掩盖了原始来源

表格修复中的 `donorSectionPath` 和 `donorGlobalTableIndex` 实际表达原表所在小节与原表编号。
普通说明用“原表所在小节”“原表编号”更准确，代码候选名称也可以是 `sourceSectionPath` 和 `sourceGlobalTableIndex`。

但这些名称仍涉及模型输出和修复计划接口，不能仅改局部变量就宣称整个模型格式已迁移。
完整迁移需要同步修改提示词、解析器和计划读取程序，并核验旧版本、拒绝格式冲突。
本次总览将它们保留为后续工作，不把建议名称当作已经完成的接口事实。

### 中英拼接、重复括注与抽象动作

“分类兼容说明（taxonomy compat）”“用量记录（usage ledger）”“分类词表（taxonomy registry）”没有增加中文读者所需的信息。
会议研究报告已删除这些普通重复译注，并将论文集、来源适配器、数量核对依据等叙述写成自然中文。
正式字段、代码字面量、统计数字、链接及相应研究日期全部保持。

“已封口 stage 的回放”“精确闭环”“决策投影”则省略了实际动作。
更合适的文字是“重新核验已保存的阶段记录”“图片前后的说明与插图计划一致”“汇总页展示的摘要、资源情况和评分理由”。
错误提示还应说明哪一项不一致，不能将所有分支统一写成“检查失败”。

### 名称或文字夸大了证据

来源文件已经保存、某项字段通过格式检查、页面绑定了 SHA、链接能够访问，分别证明不同事情。
不能因为名称里有 `signedReader`，就暗示文章内容已经独立审查或已经获得发布资格。
此类视觉与恢复相关名称仍需检查实际读取和使用这些值的程序，不应只把形容词换成另一个更强的词。

修订说明必须与代码实际执行的条件对应。
未传入像素不能说图片细节已核验，候选表格不能等同可信 DOM 单元格，已获取来源也不等于论文或网站已发布。
这类准确性要求始终适用于命名重构，不能以改善措辞为由改变资格规则。

### 旧说明、重复日志与无效代码

历史文档应保留当时的范围与事实；当前操作文档则要使用现行写入要求并说明旧格式读法。
旧新页协议要求若与当前生产写入冲突，需要同步修正，不能继续让维护者依据过时说明操作。

原进度文件曾有 2758 行逐批记录，重复抄录计划和临时状态。
第 62 批将当前说明改成可阅读的结果与待办，完整旧记录仍保存在固定 Git 版本中，没有抹去失败。

第 63 批还删除了两个确实无效的生产残留。
必需阶段列表本来没有 `taxonomySeal`，对它做过滤不会改变结果；删除该比较前后，数组内容及顺序完全相同。
生产发布器中的旧词表生成函数只有定义，没有生产调用，其 49 行完整原函数已从生产删除并原样保存为测试辅助文件。
真正的旧安装恢复仍由当前读取器核验原路径、文件 SHA 和完整资产集合，并直接返回原字节。

下面列的是已经处理的具体职责，不是对所有同词位置的全局替换规则。
模型接口、固定原字段及尚未迁移的位置，仍按各自原格式识别。

## 三、采用的八种实施方法

### 1. 固定基线和具体范围

先确定 Git 基线、目标名称、生产文件、调用或读取这些文件的程序及必要测试，再开始编辑。
最初研究基线为 `b388b883e17f0a59d799d17c69a1033907bdbb88`，当时保存了 562 份受跟踪文件。
每一批另冻结自己的明确范围，不能把全仓检索结果直接当作同一批修改清单。

运行数据、词表原文件、固定证明资料和用户无关改动要单独列为保护对象。
作者只能修改自己的文件，其他作者、审查者和主整合者按分工处理，避免同一目录中互相覆盖。

### 2. 阅读赋值、返回值和调用，按职责命名

先确认变量保存什么、函数返回什么、哪个调用方使用结果，再决定新名称。
词表 API、标签规则 API 和历史标签分配 API 即使原来都叫 `taxonomyApi`，也不能一律改为同一个名字。

同样，诊断文字必须根据完整条件改写。
若条件同时检查格式与 SHA，不能只说“SHA 不一致”；若只检查对象形状，也不能声称完整论文身份已经核验。
名称和说明都要落到真实对象与检查范围上。

### 3. 区分局部、导出和保存格式

局部改名通常只涉及代码引用；导出改名还涉及导入、依赖注入和跨语言调用。
保存字段、模型字段和协议标识则需要设计明确版本、旧读取器和冲突规则。
这三种变更不能使用同一种替换办法。

JavaScript 对象简写尤其容易误改保存字段。
局部变量更名后，若旧格式仍要求原字段，应显式写出原字段与新变量的对应，而不能让简写偷偷生成新字段。
Python 还须检查关键字参数及嵌入测试中的真实调用，避免函数定义改了而调用名称未同步。

### 4. 同时核对写入、读取、恢复和使用错误文字的程序

完整迁移要让当前写入始终使用新格式，让旧读取按明确已知格式工作。
格式标识与版本必须是支持的准确组合，不能只检查前缀或值是否为真；一组迁移字段是否存在，要检查这些字段本身。
双字段即使值相等或都为 `null`，也不能被简单的逻辑或表达式掩盖。

先执行原对象摘要、文件 SHA 和来源绑定检查，再选择保存时的字段或格式。
当前文件损坏、缺少副本或新旧混用时，应拒绝，不能退回旧目录使错误消失。
同时保留原恢复允许的范围，不因迁移给合法旧资料增加原来没有的使用限制。

有些程序会读取或匹配错误文字：重试条件、失败分类、修复入口和测试正则都可能依赖它。
只搜索完整旧句不够，短正则片段和分类条件必须一起核对；后面的 CI 遗漏正是这个教训。

### 5. 用原实现与完整原字节建立旧样本

旧样本须由修改前的原实现生成，或直接保存原 Git 版本的完整字节。
不能先构造新对象，再换成旧格式头并重新计算摘要，冒充真实旧输出。
原源码、原产物、来源记录与凭证要说明各自的身份和用途。

离线样本中的词表、来源资格、模拟网络或 Git 操作的辅助程序也必须明确标注。
它们用于测试恢复条件，不是实际论文的来源证明或发布凭证。
第 63 批的旧生成器测试辅助文件先核完整 SHA，再确认只有一个指定函数，之后才与当前函数组合用于构造旧格式测试资料。

### 6. 作者停笔后冻结身份，核对等价边界

作者完成后停笔，记录实际修改范围、完整 SHA、长度和权限。
对纯名称迁移，可在明确批准的范围内逆还原名称，再对比语法树、字节或输出字段；对格式迁移则按实际新旧输出验证。
两类检查不能混用，更不能把“改名后还原所得的 SHA”冒充当前文件的原始 SHA。

冻结后若有窄修，应更新实际身份并保留首次发现的问题。
未变文件不用无因重复验证；已经变化的文件也不能沿用旧冻结结果，独立审查与测试必须对应同一份内容。

### 7. 作者分工、独立审查和主整合

作者分别承担 Node、Python、网站或文档等明确范围，必要时先协商最小接口。
独立审查者阅读实际差异和关键调用链。负责汇总修改的人再检查不同入口的写入与读取是否一致，确认受保护的资料未变，并核对最终修改范围。
审查不是只看作者说明，也不能把一个模拟调用当作完整生产链。

审查结论有范围限制。
完整读取检索结果、重点检查恢复条件和格式要求，不等于所有剩余代码的所有条件都已证明正确。
没有发现未解决的严重或主要问题，也不能代替完整套件和精确提交的远端验收。

### 8. 复用必要测试，保存失败，避免无因重复

优先运行完整受影响测试文件及实际在其他语言或入口中读取结果的程序，覆盖新写入、旧恢复、混字段、错代、原 SHA 漂移和必要拒绝边界。
不要为每一行实现另造一份镜像测试，也不要为了达到预定文件数而改无关测试样例数据。
低影响文档变更按读取其内容的程序和实际用途检查，不需要重复完整项目验证。

首次失败、定位、窄修及补验分别保留。
相关回归通过只能说明所运行范围通过，不能写成完整验收；整个 CI 的某个任务通过，也不能代表另一 Node 版本已通过。
必要完整验收只执行一次；新增失败或源码变化有真实理由时，再补跑受影响范围。

## 九、剩余工作与优先顺序

当前普通模块和提示词中的明显旧名已大幅减少，迁移仍未覆盖全部接口和表达。
剩余工作应按真实用途分组，不按词根计数一次性批量替换。

| 类别 | 仍需处理的边界 | 后续方式 |
|---|---|---|
| 旧字段与旧目录 | 仍有已知旧记录、缓存及读取旧记录以继续任务的程序 | 先确认实际使用范围；需要迁移时同步当前写入、严格旧读取与冲突拒绝，保原资料 |
| 固定正文及提示哈希输入 | `__TAXONOMY_SECTION__`、历史提示文本和固定证明字符串 | 单独设计版本、身份与旧恢复规则，不能当普通文案替换 |
| 模型修复字段 | `donorSectionPath`、`donorGlobalTableIndex`、部分 `projection` 字段 | 连同提示词、解析器、修复计划与旧格式一起迁移 |
| 其他日更来源诊断 | 仍有 `sealed source` 等生硬叙述，以及影响失败分类的旧英文 | 核对完整条件、短正则及依据错误文字分类的程序，再改自然中文 |
| 视觉与恢复命名 | 提示词中的 `signed Reader`、`Reader signature`、`canonical analysis`，以及 SHA、阶段和恢复指纹周边仍需按职责检查 | 名称不能夸大证据，修改须考虑已保存任务及格式边界 |
| 其他注释、测试与文档 | 普通语句仍可能含陌生缩写、重复译注或省略动作 | 按实际读者与对象整理，不改历史事实和固定原样测试辅助文件 |
| 网站可见措辞 | 标签页标题 `Tags` 等尚未自然化的文字 | 修改真实显示入口及使用这些文字的程序，再核页面和必要回归 |
| 后续提交的完整 CI | `aaac5300` 源码的两个版本已通过；新增本说明的提交为 `444cc7a`，其 CI 尚未验证 | 后续仍按每次精确提交核对结果，不将基线的通过结果冒充新提交的验收 |

受跟踪文件名中该旧词根为零，不等于全部阶段、字段、文案和旧格式工作完成。
Hugo 的 `Site.Taxonomies` 等框架接口有固定含义，不能直接改名；原归档和固定协议也不能因名字显旧而批量覆写。
对于剩余检索结果，应明确哪些是当前普通表达、哪些是仍在使用的旧读取、哪些是固定证明或外部接口。
