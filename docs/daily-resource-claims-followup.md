# 日更资源声明硬验待办

2026-10-12 恢复检查发现，普通日更 Reader 的资源身份及引文绑定检查不等于可用状态声明的完整语义检查。

- `parseApiReaderArticleResult()` 当前仅在会议 `readerCapabilityPolicy` 分支调用严格的 `conferenceReaderResourceClaimIssues()`。
- `publish-to-blog.py` 最终页面检查核对资源展示和 `availableTypes`，并用有限正则拦截“代码……已开源/可以访问/仓库可用”等声明。它不等价覆盖严格声明检查器中的全部句式和归因。
- 本次显式资源局部恢复也启用严格检查；它不放宽原有检查。普通日更的等价硬验仍需独立修复。

后续修复应让普通日更在生成、复用和发布资格核验时，都要求“已开源/当前可用”声明有 `available` 资源支持，并分别保留作者原文的发布承诺、第三方依赖与当前可达状态。必须覆盖原文提供入口但暂不可达、不同资源类型的限定、第三方开源与本文资源、条件或否定句，以及正文使用现有发布正则没有覆盖的同义声明等正反例。不能因为当前核验不可达，就改写作者的原文承诺为未提供资源。
