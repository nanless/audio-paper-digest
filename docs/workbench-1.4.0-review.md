# 工作台 1.4.0 全资料同步审改与验收

Mac 和 Android 的发行版本均为 1.4.0，构建号均为 16。两端正式安装资产来自 `2397918fe15da68996f5df3835bf42596bba7a81`。发布页提供安装包和各平台的 SHA-256 校验表。[1.4.0 发行页](https://github.com/nanless/audio-paper-digest/releases/tag/v1.4.0)

## 第一轮　保留待传原件并恢复断点

研究快照使用独立目录和不可变编号。开始上传前，客户端在本机固定原件和检查点。下载用临时文件，逐块和整体核验后才交给本机合并。程序退出或丢失成功回执后，重试沿用同一编号。服务器目录漏掉已核验版本时报告缺失，原件仍可取回。

Mac 隔离用例模拟写入完成清单后丢失回执。Android 隔离设备用例模拟写入分块后连接中断。两端还验证先保存待传原件、再恢复旧工作区、最后续传时，原先的研究资料能重新合入当前工作区。

## 第二轮　两端按原件身份合并

测试使用两份有效的离线导读包、一份同 SHA 的 PDF，以及两个设备在同一研究或归档编号下保存的不同原稿。离线包按完整目录验收后发布。同一 PDF 在本机去重。冲突原稿保存在可取回的完整快照中，接收的归档历史从独立的只读目录展示。

Mac 阅读器另验安卓原研究回答的正文显示。安卓把同步来的研究历史排除在本机模型复用、重新派发和派发计数之外。两端均保留原输入、原响应和归档日志。设备专用校验密钥、连接配置和执行许可不进入研究快照。

隔离回归包括 Mac 云传输 46 项、云设置 66 项、主窗口 24 项、归档浏览器界面 11 项，以及 Android 云端与研究逻辑 151 项和专用 API 35 设备用例。共用夹具另做原件摘要和排除规则验证。

## 第三轮　坚果云实服与正式安装资产

先用坚果云网页创建独立个人测试目录，再使用同一目录的合成资料运行 Mac 和安卓的生产同步引擎。两端各完成两轮真实上传与拉取。Mac 使用原生验证入口核对原件，安卓从该模拟器的隔离资料目录直接读回并校验字节。验证包括同一份 PDF、两份离线导读的成员，以及同一研究和归档身份下双方的原件摘要。测试未读取或替换日常工作区。实服用例用于核对跨端传输与合并，断线与丢回执在隔离用例中控制时序。

本次实服工具中，一个额外的 Mac 导出文件标记未在播种时生成，安卓自动核对停在该标记。实际要求的四类资料随后从设备中独立逐件核对。播种脚本已补齐对称标记，便于下一次自动复验。

安卓正式 APK 沿用原证书。在专用 API 35 模拟器中，旧正式版覆盖升级后保留原 UID、首次安装时间及 12 份原件。另用隔离的全新 Android 用户启动，验证日更和一键同步入口。最终 APK 与实测文件逐字节一致。Mac 最终 ZIP 解包后通过严格签名检查，在空工作区和历史资料克隆中分别启动，保留历史克隆的六类个人资料和 56 份文件。本轮 Mac 正式包启动检查采用隔离进程，界面操作覆盖来自单独的浏览器和原生回归。Mac 安装包采用本机签名，未获 Apple 公证。

联合发行草稿按附件 ID 下载 12 件资产，逐件核对实际字节，再由两端的正式核验入口重新检查。公开状态及下载校验与同一发行标签对应。更细的同步行为和后续设计见[全资料同步说明](workbench-full-webdav-sync.md)。
