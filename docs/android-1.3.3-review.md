# 安卓 1.3.3：缩小阅读字号与留白

1.3.2 的手机阅读仍显得过大：默认正文为 16，行高为 26.4，一级标题为 22.4；段间距、作者列表缩进和双排工具栏进一步挤占首屏。用户反馈后，这次直接调整默认排版，安卓版本更新为 1.3.3、构建号 11。Mac 仍为 1.3.0。

论文导读、日更、会议、网站页面和研究回答共用的阅读外壳，现在采用 14 的默认正文、21 的行高、约 18 的一级标题及约 16 的二级标题。上下和左右留白、段距、引文间距、表格单元格间距与列表缩进同步收紧。手机可用宽度小于 600 时使用已有的单排阅读模式菜单；平板仍可显示独立标签。论文信息、来源提示与完整内容继续可访问。

论文阅读和网站页面菜单新增“缩小文字”“放大文字”“恢复默认文字大小”，与设置中的阅读比例共用原有保存字段。调整只更新同一阅读控件的文字比例，不重新下载或替换正文。系统字体缩放继续生效；默认排版变小不代表清除用户明确保存的阅读比例。

检查还发现旧版恢复的 HTML 可能残留网页自身的 `style` 元素。正常网站提取已清除这些样式，但旧 HTML 显示分支没有全部移除，可能重新覆盖手机字号。这次只清理阅读显示副本里的原网页样式，随后加入随包的可信公式样式；原 HTML、来源身份、表格数值与导出契约分别保留。

API 35 隔离设备已执行 6 项阅读控件测试和 10 项科学渲染测试，均通过。实际阅读控件测得正文及段落为 14、一级标题约 18、行高 21；在两倍系统字体输入下，正文为 28，仍保留用户的放大能力。宽表保持独立横向滚动；阅读菜单连续缩小、放大、恢复默认时，原文档对象没有被替换。另有旧 HTML、流式正文、原资料保留和公式样式的专门回归。

最终变更已完整运行 888 项 JVM 测试、静态检查和 7 项应用标识与版本脚本检查，全部通过。原签名、网站数据、同步和崩溃修复沿用前序版本；这些未变化功能的旧设备证据不改写成新增实体机检查。

正式安装包仍须沿用原签名，以同一篇公开论文的实际界面检查首屏密度、模式菜单和返回行为，再核验六件发行附件。公开状态以 [GitHub 发行页](https://github.com/nanless/audio-paper-digest/releases)为准；小米 15 Ultra 的实体机显示仍需在该设备上复验。
