# 日更耗时检查与修复记录

本轮按用户要求停止生产日更，只做离线审查、代码修复和验证。不得依据这份报告自动启动抓取、分析、恢复或发布。停止时保留了 245 篇正式记录；中断中的请求可能尚未返回或保存，不能把已有草稿当作完成结果。博客中原有的 1355 个未提交页面保持不动。

## 比较方法

模型与修补链的逐类错误、请求体积及仍未解决的问题见[专项审查](model-repair-performance-audit-2026-10-12.md)；续跑与检查点保存见[恢复审查](recovery-efficiency-review-2026-10-12.md)。

速度以通过完整分析和来源核验的论文数计算。模型返回 HTTP 200、写入草稿、阶段完成或测试通过，都不能计入整篇完成数。比较至少区分抓取等待、准备、模型等待、修补轮数、保存耗时和最终成功数；并行请求的时长总和不能当作墙钟时间。

十倍是优化目标，不是已经取得的端到端结果。生产已停止，本轮的本地计时、旧响应重放和请求数验证不能替代下一次真实运行的吞吐验证。

## 停机前的实际耗时

2026-10-12 最后一轮（R16）的日志覆盖窗口约 620 秒，并非整个日更生命周期。日志记录 195 次请求启动、183 条请求终态；中断时有缺口，不能把未记账的请求当作免费或已经保存。166 次 HTTP 200 中，149 次 Reader 结果被拒绝，未记录到新增整篇完成；日志记录 50 次因连续两轮没有改善而停止的消息；这不是 50 篇独立论文。请求时长的并行累计为 10939 秒，其完成请求覆盖的墙钟区间约 560 秒，两者不能相混。

中央结果文件保存了 326 次，累计序列化约 27.2 GB。读取解析约 87.2 秒、序列化约 27.5 秒、写入约 21.5 秒，合计约 136.3 秒，占本轮墙钟约 22%。锁等待累计约 7.6 秒，会与其他任务重叠。即使完全消除这部分保存成本，按此比例推算也只有约 1.28 倍，不能据此承诺十倍。

本轮启动前的恢复计划另耗时 368 秒，192 项诊断迁移反复扫描近 522 份候选记录；这是待修复的重复工作。上一轮同类准备耗时 273 秒。后续应分别比较准备时间、每次有用模型请求数和整篇成功数。

发布侧也已只读测量：现有博客的审查协议指纹首次约 0.40 秒、后两次约 0.11 秒。它不是此次十分钟零新增完成的主因，本轮不为缩短这部分时间削弱文件变更检查。

## 候选扫描的实测边界

停止后的真实目录有 522 份候选、约 37.23 MB。其中 315 份为普通候选，184 份有付费轮证明，23 份有修复许可证明。普通克隆数据的缓存原型约快 9.82 倍，但真实混合目录连续五次扫描仅由 11.204 秒降至 10.150 秒，约 1.104 倍。有证明记录须逐次完整验证，不能缓存未重新核验的外部证明。收益不足以抵偿新增缓存复杂度，该索引没有采用，也不能据此称 368 秒的规划已经解决。

采用更小的共享读取改动：恢复扫描从一次安全读取中取得候选外层记录、候选内容与原文件字节 SHA，减少重复解析和内容哈希；付费轮及修复许可证明仍完整验证。真实混合目录五次扫描由 10.891 秒降至 9.981 秒，约 1.091 倍。这是扫描分量的本地计时，未测完整规划的提速倍数。独立副本中的七篇公开恢复回放保留了十四份旧费用账及原稿文件的 SHA，未发送模型请求或安装新预算；不能将该回放记为正式论文恢复。

共享读取的相关离线回归 213 项通过，反例覆盖损坏正文、身份与文件名错配、读取期间替换、权限变化及跨目录读取；相对目录的原有兼容行为保留。读取后再次核对文件描述符状态与命名路径，不能用旧读出的对象认证已经替换的文件。

来源检查的源码显示，恢复入口完整核验 245 篇的四份来源文件，公开论文恢复在锁内还会重读该篇来源。这项锁内核验仍需保留。主助手对正式文件做了三遍只读完整来源核验，耗时分别为 1.551、1.276、1.288 秒；每遍记录 1229 次同步文件读取，共 877702272 字节，包含内部重复读取和元数据，不能将读取次数当成不同文件数。已确认原实现每篇有事实反馈的论文在锁内重跑全批核验；现改为入口与结束全批核验，锁内读取最新批次信息并重新核验当前论文。细节见[锁内来源检查](locked-source-validation.md)，不能把候选扫描和来源核验混成一个耗时结论。图片重复下载及服务端排队细分尚未完成独立基准。

## 锁内来源检查的真实只读比较

代码合入当前仓库后，对同一批 245 篇来源的前三篇分别比较旧全批检查与新锁内检查。旧检查每篇读取 1229 次、877702272 字节，耗时 1283.8、1284.5、1428.2 毫秒；新检查各读取 9 次、804740／1517326／551278 字节，耗时 2.66、4.20、4.56 毫秒。读次数包括运行清单与元数据，不能当成不同文件数。最后全批检查仍读取 1229 次、877702272 字节，耗时 1295.1 毫秒。没有模型请求或正式数据写入。

这是锁内来源检查函数的比较，不是整篇准备或整条日更的速度。公开准备流程还会为复用判断、来源准备重复读取本篇；合成双论文测试中共 16 次来源读取、4 个唯一文件，全部属于当前论文。入口额外检查、模型耗时和结果保存仍存在，不能用上述毫秒数推算全批完成时间。只读记录位于 `/tmp/root-locked-source-readonly-benchmark.json`。

## 已确认的问题

| 问题 | 原因与影响 | 修复与验证范围 |
| --- | --- | --- |
| 完成同一事实纠错后仍重复入队 | 批次只看“有反馈”，成功论文也重新分析；早失败又会把它标成失败 | 初筛和论文锁内重读使用同一严格完成判断，核验完整资格、当前来源、反馈证明及残留错误句。新反馈和不完整记录仍处理 |
| 预检报错删除已有检查点 | 恢复状态准备先改动原记录，随后事实范围预检报错，外层又将缺失检查点的状态保存 | 先在私有副本准备，预检接受后才应用；公共入口、论文锁与失败保存的反例确认保留旧正文和检查点，并继续保留失败标记 |
| 小节过多与术语解释不足互相阻断 | 重排入口先要求术语数量达标；完整旧稿无法进入局部重排 | 先按有界完整结构允许仅重排小节，再单独处理其余问题。其他根数组不改，最终检查保留 |
| 缺教学类型却只能改正文 | 修改正文不能改变小节类型，连续重试不可能消除该错误 | 结构化诊断只允许改写一个相邻可替代小节的完整对象；唯一必需小节和已有图表、公式、术语标记不受此授权影响 |
| 圈号数字的排版反复失败 | 检查器把“式②”归一化成“式2”，修复程序只找 ASCII 数字 | 保留②、⑥、上标等原符号，仅补汉字边界空格；引用、代码、公式和 URL 不动。真实旧稿重放消除了此项错误，其他宽表问题仍被拒绝 |
| 公式缺失记录超过四项时修不到正确位置 | 两篇稿件各有十二个公式位置、缺七条来源记录，固定最多补四条导致转去修改无关内容 | 允许追加正文已有且唯一的公式来源记录，总数仍限十六；旧记录、正文和其他数组保持原样，完整解析器仍核验原始公式，未知编号及越界拒绝 |
| 停止后内部仍继续请求 | 外层只停止领取新论文，同篇的后续修补和重试仍可能发送；最后一篇成功还可能让入口继续发布 | 统一传递停止状态，在实际发送和登记预算之前再次检查；保存已返回结果后以运行级停止结束。真实信号、排队、最终保存期间停止及费用保留均有回归，适用边界见停止说明 |
| 标签内容修补用完后被外层重发 | 同一轮两次内容拒绝没有终止整篇自动重试，公共反例实际发送六次 | 第二次内容拒绝停止该篇本轮自动重试，反例降为两次；网络暂时失败仍保留原策略，第二次合法响应继续成功。R16 没有标签请求，不把这项修复计为该轮实际节省 |
| 隐藏表格被计入有效正文 | 注释、代码或原样 HTML 区域里的表格仍被 Markdown 扫描器计数；直接删注释又会误伤可见代码示例 | 编译前拒绝隐藏表格标记，提取时按区域遮罩并保留字符位置与行号；正常单元格代码和 HTML 块外可见表保留。共享的 30 个实际 Hugo 页面 DOM 对照样例通过，Python 通用提取与 Reader 发布核验同步使用相同规则，不把出现 table 字样当成真实显示 |
| 隐藏解释、公式或图片仍取得正文资格 | 旧检查只找原字符串，未区分实际展示与注释、代码示例；图片地址中的括号也会被旧扫描截断 | 补齐保存记录及发布端可见性检查，保留正常引用、局部代码和多行原始 TeX；图片按完整地址及真实展示位置核对，未知图和重复图仍拒绝。实际模型请求补充可见标记要求，旧提示词及原始来源不改签；最后组合与独立核验记录见下文 |
| 分类切换重复等待 | 请求调度器已有间隔和失败退避，外层仍首次等 30 秒、每类再等 70–90 秒，还把分页用时长误作限流 | 删除重复等待及无用配置。七分类真实流程的虚拟时钟回放：旧 450 秒，新 18 秒；3 秒最小间隔、503 与 429 冷却仍核验。这是等待部分减少 96%，不代表整条日更提速 25 倍 |
