# 桌面论文研究工作台规划

本文把需求落实为可实施的产品、数据与验收方案。调研日期为 2026-10-24，仓库基线为 `5ffac44b`。下文明确区分已核对的现状、拟新增的能力和仍需通过原型验证的选择。本文与随附界面示意均为规划，桌面应用尚未实现，示意中的 PDF、模型回答和存档操作不代表真实执行。

## 1. 产品目标与默认行为

桌面应用直接消费已经发布的网站成果，提供双栏精读、个人研究和 Zotero 完整存档。已有论文不重新筛选、不重新评分、不重新生成导读。用户只有主动选择进一步解析时，才调用自己在应用中配置的 LLM API。

每天的使用过程应当是：打开应用，看见网站新增论文；按当前网站任务、方法、标签和评分筛选；打开一篇，左边看图文导读，右边读同一版本 PDF；选中看不懂的句子、公式或图，追加解析；把需要长期保留的论文连同原文、导读、引用信息和自己的研究笔记存进 Zotero。

这里“本地解析”指任务、密钥配置、记录与管理在本机。使用远程 LLM API 时，所选材料仍会发送给该服务。只有连接本机模型服务且不调用其他远程能力时，才是离线推理。界面必须说明实际发送范围。

| 用户动作 | 默认行为 | 是否调用 LLM |
|---|---|---|
| 同步今日论文 | 获取网站索引、增量元数据与已发布内容 | 否 |
| 打开历史论文 | 读取已有导读，按需下载对应 PDF | 否 |
| 搜索、筛选、收藏、做笔记 | 使用本地数据库和全文索引 | 否 |
| 离线保存、导出、Zotero 存档 | 整理现有资料与附件 | 否 |
| 解读选中文本或图表 | 按所选范围调用配置的模型 | 是 |
| 重新理解整篇 PDF | 显式建立新的个人解析任务，展示范围和预计消耗 | 是 |

产品初期默认支持 macOS、当前公开博客和个人 Zotero 文库。保留 Windows 的架构兼容，待首个平台完整验收后再提供安装包。日更、会议与历史维护继续由现有生产系统执行；桌面端第一版的后台管理负责同步、下载、提取、个人解析和存档，不自动启动生产重写。

## 2. 已核对的项目基础及实际缺口

### 2.1 可直接利用的成果

- 公开站点为 [audio-paper-digest-blog](https://nanless.github.io/audio-paper-digest-blog/)。实时探测的 `/index.json` 返回 `paper-search-index-manifest-v1`，含 22 个分片、8,718 条页面记录。记录中包含不同页面类型，不能把它解释成 8,718 篇去重论文。本次验证了首个分片的实际字节、SHA 与记录数，没有审计全站每篇内容。
- 博客已有中文标题、任务与方法、多级标签、网站评分、原论文链接、图文正文和引用导出。客户端应显示这些已有结果，并保留其来源和版本。
- 现有 `researcher-sidecars-v1` 包含 `citation.json`、`citation.bib`、`citation.ris`、`rethink-context.json`。具体字段由发布器生成；不能把上下文资料误认为完整 Reader。
- 博客搜索分片加载器已经检查同源路径、长度、SHA 与数量。桌面同步可以沿用这套约束的设计，增加本地事务与版本管理。
- 日更、会议、历史已经共用分析、评分、Reader 与发布核心，但来源资格与恢复边界各自独立。应用消费公开结果，不需要复制三条生产入口。

### 2.2 公开数据不是现成的完整桌面协议

目前索引的 `summary` 是短摘要，`date` 是博客日期，不一定是论文发表日期。正文、完整评分解释、图片及 PDF 锚点不在搜索索引中。部分字段缺失是实际状态，不能根据页面位置或模型猜测补齐。

以已发布的 [RubatoCodec 页面](https://nanless.github.io/audio-paper-digest-blog/posts/2026-10-23-rubatocodec-budgeted-adaptive-speech-tokenization-2610-29434/)为抽样：页面有完整导读和 4 个图片元素，图片来自 arXiv 外部地址；引用指向 `2610.29434v1`，公开引用记录的完整性标志仍为 `complete:false`。这意味着“缓存 HTML”不等于“图文已经离线”，“已有身份核验”也不等于“所有书目字段齐全”。

现有博客明确退役了收藏、私人笔记、本地助手和直接 Zotero 桥接等功能，详见[博客阅读资料](blog-reading-tools.md)。这些个人功能适合放在新客户端。公开静态站本身并非无法使用 Zotero Connector；新增应用的价值是把阅读、追加研究和完整附件存档做成连续流程，而不是因为 GitHub Pages 原理上不能保存引用。

### 2.3 Zotero 的当前兼容条件

本机此前只读检查发现安装的是 Zotero 9.0.6，当时本地端口未连接成功。未启动、升级或改写文库。当前官方文档说明 Zotero 10+ 本地 API 支持经授权写入与附件上传，因此实现前必须探测实际版本与能力，不能把新版接口套到当前安装上。

规划首选 Zotero 10+ 官方本地写入路径。若用户继续使用 9，则需要单独验证一个范围很小的 Zotero 插件桥接方案；BibTeX/RIS 导入只能作为基本引用回退，不能冒称完成了 PDF、图文和笔记的完整存档。不得直接修改 Zotero SQLite 数据库。依据：[本地 API](https://www.zotero.org/support/dev/web_api/v3/local_api)、[客户端 JavaScript API](https://www.zotero.org/support/dev/client_coding/javascript_api)。

## 3. 研究结果怎样变成功能决策

下表是对官方功能和文档的研究，不是对第三方产品准确率、速度或完整性的实测。

| 参考对象 | 可借鉴的交互或能力 | 本应用采用方式 |
|---|---|---|
| [Readwise Ghostreader](https://docs.readwise.io/reader/guides/ghostreader/overview) | 文档级和选区级处理、可定制提示 | 先支持选区解读与常用研究模板，保留自定义问题；不默认每次发送整篇 |
| [LiquidText](https://www.liquidtext.net/features) | 摘录、工作区与文档来源之间的往返 | 每条证据和笔记能回到实际 PDF 位置；先做好双栏，后续再评估自由画布 |
| [Elicit 图表提取](https://support.elicit.com/en/articles/14758168-extracting-data-from-a-table-or-figure-within-a-paper-in-column-answers) | 图表需要不同于正文的提取路径，复杂解析有额外消耗 | 文本先行，图表按需发送原页或裁图；显示证据与提取局限，不把破损表格当可靠数据 |
| [Zotero 阅读器](https://www.zotero.org/support/pdf_reader)与[笔记](https://www.zotero.org/support/notes) | 原文标注与可编辑研究笔记 | 存档时兼顾附件、结构化笔记和真实位置；不把所有内容塞进一条不可维护的摘要 |
| [PDF.js](https://mozilla.github.io/pdf.js/getting_started/) | 可嵌入 PDF 显示层与阅读器 | 使用成熟阅读能力，重点开发解析联动、证据与存档，不自行实现 PDF 格式解析 |
| [Gemini PDF 文档](https://ai.google.dev/gemini-api/docs/document-processing)、[Claude PDF](https://platform.claude.com/docs/en/build-with-claude/pdf-support) | 部分提供商支持原生 PDF/视觉输入 | 模型适配器声明能力；不假设任意兼容端点都能接收 PDF 或看图 |
| [Claude citations](https://platform.claude.com/docs/en/build-with-claude/citations) | 支持提供来源位置的结构化引用 | 优先利用真实引用字段，同时核验本地 PDF；页码引用不能自动变成精确高亮矩形 |

这些研究共同支持一个设计顺序：先让用户能从解释回到证据，再扩展整库问答、自动综述和研究图谱。漂亮的回答如果找不到原文依据，就不能成为可靠的研究笔记。

## 4. 信息结构：三层内容、两个工作区域

### 4.1 三层内容各自保存

1. **网站导读**：保存发布时的正文、图、评分、标签与来源信息，按站点修订更新，保留旧快照。
2. **本地解析**：保存用户发起的问题、PDF 输入范围、模型回答、引用、时间和实际用量；每次重新生成创建新版本。
3. **我的笔记**：用户自己的摘录、批注、待验证想法和总结。网站更新、模型失败、缓存清理均不能覆盖这些内容。

页面顶部始终能看出当前阅读的是哪一层。网站评分显示为“网站评分”，个人兴趣或自定义评分单列。个人追加解析不获得生产发布资格，不修改网站原评分，不反写正式论文结果。

### 4.2 导航结构

| 位置 | 内容 | 设计目的 |
|---|---|---|
| 应用导航 | 今日更新、论文库、收藏与待读、研究专题、后台任务、设置 | 先找论文，再进入精读 |
| 论文列表 | 中文标题、原题、来源、任务/方法、网站分数、日期、阅读/离线/Zotero 状态 | 一眼判断相关性与当前进度 |
| 精读顶部 | 标题、版本、来源、网站评分、离线、Zotero 存档 | 论文身份与主要动作不随内容滚动丢失 |
| 左侧内容区 | 网站导读 / 本地解析 / 我的笔记 | 在同一位置切换理解材料 |
| 右侧原文区 | PDF、目录、页码、搜索、缩放、选区动作 | 随时核对原文 |
| 按需抽屉 | 证据详情、存档预览、任务详情、模型配置 | 避免长期堆出四五栏 |

默认左解析、右 PDF，各占约一半，可拖动分隔线、交换左右、临时放大任一栏。论文列表进入精读后可收起。宽度不足时切换“导读 / PDF”聚焦视图，保留页码、选区与滚动位置；实际桌面断点通过原型验收，不以压小文字强塞双栏。

### 4.3 导读与 PDF 的联动规则

不把两栏按滚动百分比机械绑定。网站导读经过重组，章节位置不等于 PDF 的位置。

- 点击经过验证的原文引用、图或表，PDF 跳到对应页并高亮实际范围。
- 仅知道页码时只跳页，并显示“页级定位”；没有可靠定位时显示“尚未定位”，不伪造精确高亮。
- 在 PDF 选中文本后，可“解释这段”“翻译”“解释符号”“分析这张图”“加入笔记”。选区上下文与 PDF 版本随问题保存。
- PDF 页序与印刷页码分别保存，支持罗马数字、附录、旋转页和多栏文字。
- 网站导读中的图先与来源图号和 PDF 证据匹配。未匹配图片仍可阅读，不授予其不存在的坐标证明。

## 5. 五条核心用户流程

### 5.1 每日阅读，无需再次分析

启动后展示上次可用内容，同时增量检查网站。新论文按网站发布日期分组；用户可切换论文原始日期。获取元数据后立即可筛选，正文与 PDF 按打开、收藏或明确离线策略下载，不在第一次启动时下载全站原文。

“已同步”“导读可离线”“原文可离线”“已完整存入 Zotero”是不同状态。每种状态必须有实际文件或回读结果支撑。每日自动同步时间可配置；电脑睡眠后醒来补查一次，不按错过的每个时段重复建任务。

### 5.2 基于 PDF 的追加理解

用户选中一段后，输入框上方显示：当前论文与版本、选区/当前页/章节/全文、是否含图、目标模型、发送材料说明。默认范围为选区及必要上下文。全文研究必须主动选择，并在发送前展示估计范围和预算；没有定价配置时显示用量估计，金额标为未知。

回答按“结论—解释—原文证据—限制/待核实”组织。可展开术语或推导，但模型推测必须标成推测。导读可作为辅助背景，不能替 PDF 为原文事实作证。外网检索另行开启，外部来源和论文内证据分开显示。

再次提出同一问题时，先提供与当前输入版本完全相符的已有回答。用户仍可主动“重新生成”，新回答保留父版本、模型、输入和费用，不能删除旧记录来伪装首次请求。

### 5.3 完整存入 Zotero

首次连接探测客户端、API、实例和目标文库。新版本写入授权采用 Zotero 官方对话框；应用说明目的，不重复索取已经授予的权限。连接故障时允许加入待存档队列，不能显示成功。

用户第一次存档可选择目标分类与附带材料，之后记住选择。进入归档预览，列出字段完整度、PDF 版本、导读快照、个人解析和笔记；默认包括当前可获得的原始资料，缺失项明确显示。

存档完成后可以“在 Zotero 中打开”。只有父条目、必需附件、应用管理的笔记经过回读核验，才能显示完整成功。只有元数据成功而 PDF 上传失败时，显示部分完成并继续已有条目，不新建重复论文。

### 5.4 离线阅读与研究项目

“离线保存这篇”下载正文、被引用图片、必要数学渲染资源和指定版本 PDF，检查完成后才授予离线状态。离线时仍可读、搜索和做笔记；远程模型任务等待网络恢复，本机模型按能力继续。

专题是用户自己的论文集合与问题清单，不重写网站标签。后续可选择两到五篇建立对照表；每格记录条件、数据集、指标定义和证据。不同实验设置的结果不能直接排序成“谁更好”。

### 5.5 后台任务管理

任务页分“进行中 / 等待 / 需要处理 / 已完成”，每项显示当前阶段、对象、进度依据、是否会产生模型费用、最近错误及下一动作。普通用户不需要阅读脚本日志才能恢复。

支持暂停、取消未派发任务、有限重试、打开结果与诊断导出。取消已发出的模型请求不保证服务端未消费；应用保留已返回内容和未知用量状态。认证失败、端点错误、存储失败与服务不可用分别处理，不能一律无限自动重试。

## 6. 网站接入与增量同步方案

### 6.1 先兼容现站，再提供稳定静态导出

第一阶段读取现有索引、引用 sidecar 与已发布文章 HTML，按明确页面类型识别正文。为旧文章保留原始快照与导入器版本。正文选择器失配时标为待适配，不抓整页导航当论文解析，更不调用 LLM 修补导入结果。

长期增加专用桌面静态数据出口，由博客构建阶段从已有发布成果生成，不使用 LLM，不要求重新分析历史论文，不改写旧凭证。新出口应覆盖实际现有文章；只有缺少必要历史产物时才逐项登记缺口，不能把“导出协议升级”扩大为全库重写。

以下路径为拟议协议名，当前尚未存在：`/desktop/v1/manifest.json`、内容分片及按内容 SHA 定位的文章/资源文件。旧四份 sidecar 合同与页面 URL 保持兼容。桌面协议单独有版本和迁移策略。

### 6.2 出口需要包含什么

| 数据 | 必要字段与约束 |
|---|---|
| 发布清单 | 协议版本、发布身份、生成时间、分片描述、字节数、SHA、完整记录数 |
| 论文身份 | 规范身份、来源类型、已核验标识、出现过的页面及版本关系；不靠标题强行合并 |
| 书目资料 | 原题、中文题、作者顺序、DOI/arXiv、官方页面/PDF、会议期刊等；未知字段为空并说明来源 |
| 导读 | 可安全渲染的正文或结构化内容、章节、公式、图表、脚注、评分解释及原站修订身份 |
| 标签与评分 | 现行标签标识、词表版本、网站分数及量表；旧分数不得猜测转换 |
| 资源 | 图片/数学资源/PDF 的 URL、媒体类型、已知长度与 SHA；没有生产者 SHA 时明确缺失 |
| 日期 | 论文日期、博客发布日期、页面更新时间分别表达；客户端另记同步时间 |
| 关系 | 论文与日更/会议汇总的出现关系、预印本与正式版的已证实关系、撤回/替换标志 |

不能把未公开的 API 响应、账户记录、费用账本、私有失败稿和生产检查点打包给客户端。客户端只接收专门定义的公开研究数据对象。

### 6.3 同步的一致性

同步先把候选清单与变更文件下载到暂存区，核验原始字节、SHA、大小、数量和路径，再用本地事务切换当前视图。下载失败或混入不同发布版本时保留上一版完整快照，不能把半批记录当今日完整更新。

同一论文出现在多天或多个会议汇总里，保存一份论文身份、多个出现记录及必要版本。无法证明相同的条目保留待确认关系。站点删除或更正页面时显示变动，但不连带删除个人笔记、解析和 Zotero 映射。

外部图和 PDF 的下载需要限制协议、重定向、地址范围、媒体类型和文件大小，复用现有来源下载安全原则。arXiv 使用项目要求的代理路径；客户端提供可理解的网络配置，不要求用户复制整个仓库 `.env`。

客户端下载 PDF 得到的 SHA 只证明“这次取得的字节”，不能冒充生产系统封存原文的 SHA。网站导读绑定 v1 时不静默打开 v2；若指定版本不可得，提示缺失或让用户明确另开版本，旧笔记仍绑定旧文件。

## 7. 本地 PDF 与 LLM 引擎

### 7.1 提取与模型输入

采用 PDF.js 显示 PDF、文字层与位置。提取过程保留物理页序、页面标签、文本片段、图块/裁图与坐标转换。复杂多栏、扫描页、表格、公式分别标记提取质量；按需增加 OCR 或视觉解析，不能全库自动开启。

模型适配器声明文本、图片、原生 PDF、结构化引用、流式输出、上下文和文件限制等能力。原生 PDF 能力经真实最小请求验证后才启用；仅文本模型使用提取文本，遇到需要图像的问题要明确能力不足。不能仅凭“兼容 OpenAI API”推断其支持所有文件接口。

PDF 全文解析是可选研究任务，按章节建立问题与证据，再综合成个人结果。已有网站导读直接复用；新增结果保存为个人解析，明确“基于哪个 PDF、使用什么模型、何时生成”。不让多阶段模板自动触发当前生产流水线全部付费阶段。

### 7.2 证据与引用数据

一条证据至少绑定 PDF SHA、页序、原文引句和提取版本。精确高亮另需经过验证的文本位置或矩形，并记录旋转与坐标系统。无法定位时降为页级引用。模型返回页码不等于它返回了可靠矩形。

回答中的事实区分“PDF 原文支持”“引用网站解释”“模型推断”“尚未核验”。这是证据类型，不显示没有校准依据的百分比可信度。关键数值、比较对象、否定和条件需要回到实际引句；图表读数如为视觉估计必须标注，不能当原表精确值。

提供可维护的研究模板：初学者讲解、符号与维度、公式逐步推导、实验设计、贡献边界、失败条件、复现准备、图表解读、与选定论文比较。模板版本随记录保存，用户可修改问题，但不会改变已保存回答的原输入。

### 7.3 配置、复用与费用

- 设置按提供商配置端点、模型、能力和网络；密钥保存在操作系统凭据存储，页面和普通导出读不到密钥。
- 不自动复制生产账号池。需要复用时走显式本机导入和能力核验；生产与个人研究的任务、费用、限流记录分开，不能互相清零。
- 公共请求协议、响应截断处理、代理与费用保存可提炼复用；不得导入会启动正式任务的生产入口。Muse 等路由仍遵守其代理条件，不静默直连。
- 回答复用键包括 PDF 字节、提取器、问题、实际证据范围、提示版本、提供商/模型、选项及加入的导读版本。相似标题或相同 arXiv 基础编号不足以复用。
- 请求开始即记录任务，结束保存真实内容与用量；无法确认计费时记未知。超时、截断、认证失败、用户取消和磁盘写入失败各有明确终态。
- 默认不向全库做向量化。先使用本地全文检索；可选语义检索单独显示服务、发送范围和费用。用户可设置单任务、每日或每月上限。

## 8. Zotero 完整存档合同

### 8.1 数据怎么放

| 论文资料 | Zotero 保存位置 | 保护规则 |
|---|---|---|
| 原题、作者、DOI/arXiv、期刊会议、日期、URL、语言 | 正确条目类型和标准书目字段，必要时 Extra | 只写已获得的事实；中文译题和博客日期不冒充原题与论文日期 |
| 论文原始摘要 | abstractNote 等适合字段 | AI 总结另存笔记，不覆盖原始摘要 |
| 指定版本 PDF | 父条目下的存储附件 | 校验实际字节；不使用易失临时文件链接 |
| 图文导读 | 自包含 HTML 附件，必要时可阅读 PDF 导出 | 包含可离线图片和公式；保留原站 URL、修订与获取时间 |
| 网站评分、标签、资源链接、局限与出处 | 应用管理的结构化研究笔记 | 标明来自网站，保留量表与版本 |
| 个人解析、问题与证据 | 独立笔记及必要附件 | 标明模型/时间/输入版本；用户选择纳入哪些会话 |
| 我的摘录与总结 | 可编辑笔记；合法位置可进一步映射原生标注 | 不覆盖用户在 Zotero 的手工编辑 |
| 标准字段容纳不了的事实 | 补充笔记与可读 JSON 附件 | 包括来源、版本、必要关系；不导出密钥、私人运行账本 |

“全部信息”指把当前实际获得且用户选择保存的资料完整归档，并展示缺口；不承诺为原文没有的信息造值。作者机构、ORCID、许可、代码与数据链接有证据才保存。PDF 附录和补充材料可选，不能把网页链接存在当成附件已下载。

### 8.2 去重、更新与完整性

本地维护 Zotero 实例身份、文库、父条目 key、各附件/笔记 key 与归档版本。新 API 的本地对象版本与云端版本分开处理；切换文库或实例必须重新核对目标，不能沿用旧写入状态。

初次存档用规范来源标识匹配已有条目；DOI、arXiv 版本与来源关系一起核对，不按中文标题直接合并。预印本和正式发表版本需要可证实关系后才由用户选择关联；同一 PDF 不重复上传，文件变化保存版本或让用户确认替换策略。

归档是多个可恢复步骤：准备 → 匹配/创建父条目 → 书目写入 → 附件传输 → 笔记写入 → 回读核验 → 完成。每步保存实际对象 key。服务端已写入但应答丢失时，先查找该次操作的既有对象，再决定重试，不能盲目再次创建。

应用管理的笔记更新采用版本检查；用户修改后产生冲突，保留双方版本并提供合并预览。应用不删除用户附件、不覆盖个人标签、不自动清理 Zotero 中的旧研究笔记。多设备同步是否完成由 Zotero 自己负责，本地归档成功不等于云端文件已同步。依据：[写请求](https://www.zotero.org/support/dev/web_api/v3/write_requests)、[附件上传](https://www.zotero.org/support/dev/web_api/v3/file_upload)、[同步说明](https://www.zotero.org/support/sync)。

### 8.3 兼容路线与早期验证

第一批技术验证就做真实“条目 + PDF + 离线导读 + 笔记”的完整闭环，避免界面完成后才发现当前版本无法写附件。验证使用隔离测试分类和人工可检查条目，真实写入另按实施任务授权执行；本次规划没有写文库。

10+ 走官方授权接口；9 的兼容插件必须限定导入、附件与笔记能力，配套安装/升级/卸载和协议版本。连接器只导入引用时界面必须显示降级模式，不把降级当作通过完整存档验收。

## 9. 后台架构与本地数据

建议先验证 Electron + React/TypeScript + PDF.js + SQLite。这样便于复用现有 Node 经验和 PDF 前端生态，并将长任务放入独立 worker。是否引入 Python 提取器取决于复杂 PDF 实测；不为第一版打包整个 Hugo、博客 Git 仓库和生产生成环境。该选择仍需安装包体积、内存、原生依赖与升级测试后确定。

```text
现有三条生产流程 → 博客发布成果 → 静态索引/正文/资源导出
                                      ↓ 只读同步
桌面界面 ↔ 本地资料库与任务服务 ↔ PDF/图片缓存
                ├→ 用户指定 LLM：只执行主动研究任务
                └→ Zotero 适配器：版本探测、可恢复归档、回读核验
```

| 本地实体 | 主要用途 |
|---|---|
| PaperIdentity / Appearance | 论文身份与出现在日更、会议、历史页面的关系 |
| SiteRevision / Asset | 网站快照、正文、图片、数学资源、字节与来源描述 |
| PdfRevision / Extraction | 精确原文版本、下载 SHA、页与文字/图块提取 |
| StudySession / Response / Evidence | 私人问题、模型结果、输入、费用与证据 |
| Note / Annotation / ReadingState | 用户笔记、位置、阅读进度与编辑版本 |
| Job / Attempt / Usage | 后台任务、每次请求、可恢复检查点和实际用量 |
| ArchiveOperation / ZoteroMapping | 归档步骤、实例/文库/对象 key、冲突与核验 |

持久数据保存在应用自己的用户数据目录。临时裁图和中间文件有明确生命周期，不写项目 `data/current`，不伪装任何生产封存来源。个人研究身份与日更/会议/历史 owner 分开。

任务按网络下载、PDF 提取/OCR、模型请求、Zotero 写入各自限流。失败只恢复必要步骤。磁盘写入失败停止新派发并保留可恢复内容；启动后核对在途任务，不把进程退出视作未花费、未写入。

全文搜索优先覆盖标题、作者、标签、导读和个人笔记，PDF 索引按需加入。[SQLite FTS5](https://www.sqlite.org/fts5.html)可提供基础能力，但中文分词和短词需要专门策略；不能假设默认英文分词能处理全部中文，三元切分也不能单独覆盖一两字查询。

远端缓存可按容量回收；已收藏离线原文、仍被证据引用的版本和用户原创内容不可随意回收。备份包含本地数据库、必要文件和归档映射，密钥另由系统凭据存储管理。数据库迁移先备份，并验证中断与回滚恢复。

## 10. 客户端边界与交付质量

网站 HTML 必须清理后渲染，移除脚本与危险 URL；远端文章不获得 Node、密钥、任意文件读写或模型调用权限。界面和主进程通过窄范围、具类型的命令交互。文档中的提示语是待分析内容，不能让它变成执行工具或上传其他资料的指令。

Electron 应采用隔离上下文、禁用阅读界面的 Node 权限并及时维护运行时；凭据存储按实际发行版本选择受支持 API，不复制已废弃接口。依据：[Electron 安全](https://www.electronjs.org/docs/latest/tutorial/security)、[上下文隔离](https://www.electronjs.org/docs/latest/tutorial/context-isolation)、[凭据存储](https://www.electronjs.org/docs/latest/api/safe-storage)。

首个发行包需要签名、公证、可理解的安装和升级流程。用户无需安装 Node/Python、克隆仓库或运行终端。提供数据目录、缓存容量、备份、诊断导出的图形入口。诊断默认去除密钥、认证头、私人问题和完整本地路径等敏感内容。

支持键盘操作、文字缩放、可读对比度、暗色模式和屏幕阅读器标签。公式、图表与代码既能阅读，也能保留来源；复制/导出不丢失引用。长 PDF、弱网、断网和应用重启是正常使用条件，要进入测试设计。

## 11. 功能优先级与后续扩展

| 优先级 | 功能 | 进入这一层的理由 |
|---|---|---|
| 第一版必需 | 网站增量同步、论文库、任务/方法/标签/评分筛选、双栏 PDF、离线资料、个人笔记 | 完整复用当前项目成果，是全部研究操作的基础 |
| 第一版必需 | 自配 API、选区问答、按需图表/公式解释、真实证据定位、记录与费用 | 满足进一步理解原文，不强迫重跑全文 |
| 第一版必需 | Zotero 版本适配、完整附件和笔记归档、去重、部分失败恢复、回读核验 | 是用户提出桌面应用的核心原因 |
| 第二阶段 | 术语表、符号表、解释深度切换 | 减少中文术语漂移，服务初学研究者 |
| 第二阶段 | 多篇对照、复现清单、代码/数据/权重/许可资料卡 | 让阅读转向实际研究，保留实验条件与出处 |
| 第二阶段 | PDF 版本差异、导读修订提示、证据失效提醒 | 防止旧笔记被套到新版本上 |
| 第二阶段 | Markdown/HTML/PDF 研究包导出，按专题导出引用 | 降低资料被单一应用锁定的风险 |
| 后续可选 | 语义检索、选定专题综述、阅读测验与复习 | 有明确收益再启用；单列模型消耗，默认不开全库后台生成 |
| 后续可选 | 音频论文的官方 Demo 收听、AB 对照与实验记录 | 契合音频方向；明确授权与来源，不执行下载代码 |
| 后续可选 | 参考文献关系图、自由研究画布、跨设备私人同步 | 依赖可靠身份、证据和冲突处理，不能挤占核心闭环 |

额外建议的第一项是“研究问题收件箱”：看论文时把暂时不懂的问题挂到原文位置，随后集中解析、解决或标为待实验。它比单纯聊天记录更容易积累自己的研究线索，且可以先以普通笔记实现，不增加默认模型请求。

## 12. 实施批次与完成条件

不根据猜测承诺固定工期。每批完成实施、相应测试和独立 review；发现问题后修复并复验，直到当前批次没有未解决的阻断或重大问题，再进入下一批。review 不能证明未来永无缺陷，验收应明确实际覆盖范围。

| 批次 | 具体工作 | 完成条件 |
|---|---|---|
| A：高风险验证 | 真实站点导入样本；精确版本 PDF；9/10 Zotero 能力与完整写入路径；基础安装包 | 日更/会议/历史文章均能识别；不重跑 LLM；Zotero 附件和笔记可回读，兼容选择明确 |
| B：只读工作台 | 静态导出与兼容导入、事务同步、本地库、筛选、双栏、按需离线 | 更新/断网/失败仍可读上一版；一篇图文和对应 PDF 完整离线；私人笔记不受更新影响 |
| C：原文研究 | 模型配置、能力检测、提取与选区、问答、证据、取消/恢复/费用 | 真实 PDF 问答可定位；不支持的能力清晰拒绝；已有结果复用；没有静默全文重跑 |
| D：完整归档 | 存档预览、父子条目、附件、笔记、去重、冲突与部分恢复 | 重复点击不重复建库；中断后继续；人工修改受保护；完整状态有真实回读依据 |
| E：研究增强与发行 | 多篇比较、术语、导出、可访问性、迁移、签名升级、长期运行 | 核心回归通过，安装/升级/恢复可由普通用户完成，扩展功能有自己的证据验收 |

A 批验证 Zotero 时就展示最小可用操作入口；D 批把它变成可靠的完整用户流程。这样能够早期验证核心目标，又不把所有功能一次堆到初版。

可并行拆分为四个清晰责任面：网站导出合同、客户端与 PDF、本地模型研究、Zotero 与任务恢复。修改共享合同先对齐，最终由不同实现者做交叉 review；并行不能让多个执行者同时改生产运行数据或发布博客。

## 13. 必须覆盖的验收场景

这些是未来实现的验收要求，本次没有把它们冒充已执行测试。

| 类别 | 场景及预期 |
|---|---|
| 零重复消费 | 首次导入全部元数据、打开旧导读、离线下载和存档，模型请求数均为 0 |
| 来源类型 | 日更、会议、历史单篇及汇总页正确区分；一篇多次出现不会生成多份个人笔记 |
| 索引兼容 | 旧数组索引与分片协议分别适配；未知协议拒绝升级而保留旧库 |
| 字节一致 | 分片 SHA/长度/数量错误、不同发布混入或缓存错误时不能切换成完整新版本 |
| 增量变化 | 新增、更正、撤回与删除分别展示；个人笔记和 Zotero 映射不被站点删除 |
| 元数据缺失 | DOI/日期/作者信息缺失时明确显示，绝不拿博客日期自动补论文日期 |
| PDF 版本 | 导读 v1 不静默搭配 v2；替换后旧引用保留旧文件且提醒当前不一致 |
| 离线 | HTML 已缓存但外部图缺失不能显示完整离线；断网仍能阅读已完成包 |
| 复杂原文 | 扫描、双栏、旋转、表格、公式、附录与密码 PDF 有正确能力说明或可恢复失败 |
| 定位 | 页序与页码标签不混淆；找不到引句时只能降级页级或待核验，不能伪高亮 |
| 模型能力 | 文本端点不能假装看图；原生 PDF 上传失败能解释并由用户选择合法回退 |
| 范围控制 | 选区问答只发送声明范围；全文模式显式启用；打开论文不自动上传 |
| 证据质量 | 数字、否定、比较对象与实验条件有来源；网站解释与模型推断分开标识 |
| 请求失败 | 401、限流、超时、截断、磁盘失败有不同终态，保留已付响应与未知用量 |
| 取消与崩溃 | 取消停止新派发；重启不重发已完成请求，不把已发请求记为零费用 |
| 复用 | 相同输入复用；PDF/提示/模型/上下文改变不误用旧结果；强制重做保留历史 |
| 文档隔离 | 原文中的恶意指令不能调用文件、上传其他论文或改动工具配置 |
| Zotero 版本 | 未运行、API 关闭、9 与 10+、授权拒绝分别提示，不将基础导入当完整归档 |
| Zotero 完整 | 父条目、PDF、离线导读、笔记逐项回读；部分上传失败保持部分状态 |
| Zotero 去重 | 双击、超时后重试、服务端成功但应答丢失均不盲建重复条目 |
| Zotero 冲突 | 用户修改笔记、删除附件、切换文库/实例，应用不覆盖或误写旧目标 |
| 本地与云端 | 本地附件保存成功不能冒称 Zotero 云端文件同步已完成 |
| 中文搜索 | 一字、二字术语、英文缩写、混合公式/标点可搜索；分词误差有实际样本测试 |
| 缓存回收 | 回收下载缓存不删除私人笔记、固定离线包或证据仍依赖的原文 |

性能通过真实文库测量首屏、检索、内存、PDF 打开与后台并行表现，再制定目标；本规划不宣称尚未测试的速度或节费比例。
