# Android 与 Mac 功能对齐及平台验收

本页把用户“除Zotero另行研究决定，其余与Mac一致、Android原生适配、美观、坚果云、两端最终GitHub Release”的要求逐项落实。依据[Mac需求](mac-app-requirements.md)、[原69项](mac-app-acceptance.md)与[新增17项](mac-app-cloud.md)，不减少原功能，也不将Mac通过记录授予Android。核查日期2026-10-25。第14c两台模拟器各执行87项、通过86项；第14d的257项JVM及必要设备复测已通过，API28完整阅读预热后的48MiB全库同步、API35原生PDF关闭已复验成功，必要消费者分别33/33与34/34通过，真实Android目录XML解析各3/3通过。这不是重跑全部87项。各行保留直接覆盖的部分范围，第16批引用原件、加密PDF、保留导出和跨端恢复已有较新局部结果，公开合并工程399项单测及17项资源检查通过；详细范围见[验收记录](android-validation.md#第16批核心与第17次公开源码合并检查)，未完成最终86项验收。

`A-`编号对应同名Mac原项。Zotero最终选择完整Web API v3可选联动，系统分享只作补充；官方能力及限制见[研究说明](android-zotero-research.md)。用户不配置Zotero不影响阅读、模型或坚果云，但实现和发行说明不能将未验完整归档说成已完成。

## 所有平台必须保持的合同

- 从同一公开发布成果读取目录、原评分、分类、完整导读和引用，不重跑已有论文，不读取生产.env/runtime。基础论文身份、原件版本、导读修订和私人会话分别保存，未知值保留。
- 共用数据/材料合同、错误语义、真实测试材料、原输入封存与用量记账规则。Swift/AppKit不是Android运行库；Kotlin适配器必须用共同正反例交叉核，不能只写同名函数就称流程共用。
- 已露出的按钮、菜单、配置和后台动作都必须接通真实服务；不以演示回答、虚构任务或假百分比过关。所有功能仍须经历修改、测试、非作者审查与实际设备验证。
- 坚果云保不可变设备版本，恢复是明确时间点切换并保前副本。没有实现实时逐字段合并时不承诺该能力；不把另一设备的模型端点、密钥或云账户覆盖本机。

## 原生布局和系统行为

手机以底导航进入论文库、任务、笔记和设置；大窗口改用导航rail。无PDF时完整单页导读，打开PDF且可用宽度足够才左导读/解析/笔记、右原文；窄窗提供保状态的聚焦切换，不把Mac双栏等比压缩。按实际窗口dp、折叠姿态、IME和系统栏决定布局，符合[Android自适应布局](https://developer.android.com/develop/ui/compose/layouts/adaptive/get-started-with-adaptive-apps)原则。

图标延续用户选定第三个C石墨边注的品牌关系，按Android自适应图标重新适配。科学图/PDF原色、中文排版、字号、留白、列表和所有错误/空/禁用/焦点状态都用真实论文验证。导入导出使用[系统文件选择器](https://developer.android.com/training/data-storage/shared/documents-files)，共享用[系统分享](https://developer.android.com/develop/ui/compose/sharing/send)，打印原文用[系统打印服务](https://developer.android.com/training/printing)。

[WorkManager](https://developer.android.com/develop/background-work/background-tasks/persistent?hl=en)支持适合持久调度的工作，但不是精确闹钟；[周期执行](https://developer.android.com/reference/androidx/work/PeriodicWorkRequest)受省电和约束影响。返回桌面、划掉最近任务、系统回收、强制停止、重启和显式停用各自验收，不声称被强制停止后还能持续执行。后台重试不得重发可能已经付费的模型请求。

## 实现分工、验证次序与未验边界

共享发布数据、个人研究记录、材料合同、费用/派发连续性、Zotero journal和云快照规则是业务核心；Android原生导航、PDF、文件选择、Keystore和后台调度是平台适配层。本轮Kotlin/Compose的具体库/版本由构建锁定并实际编译，不在研究文档虚构一个已经存在的稳定SDK组合。

先核真实网站全库与完整长文，再把导读/原PDF/个人研究、离线/导出/恢复、坚果云与Zotero分别贯通。每个阶段先用隔离故障验证保存/恢复，再在独立可识别的真实数据上取证。保每轮失败及修复版本，不通过降低断言或把假回答塞进演示来凑完成。

Mac的`release_tools.py`来源检查已明确允许Android独立代码树以及该工具和两份验证测试的受控变化，其余非运行差异单独登记。原Mac来源字节、实际包、签名与69+17门禁保持；这项合同升级不等于APK签名、Android验收或GitHub发行通过。两端仍须按各自最终可追溯来源构建并核实际资产。

第14c已在API28与API35模拟器完整执行各87项，真实Main旅程、在线MiCLA科学图文、系统保存及必要隔离检查有直接证据；两端仍各有1项失败，完整结果与历史见[验收记录](android-validation.md)。Android没有真实模型、坚果云或Zotero账户验收；物理手机、320dp/200%字号、IME短屏、平板/折叠、完整生命周期与正式Release仍未完成。Mac本地Zotero的99项回读只属于Mac路线，不授予Android Web API或官方客户端同步通过。
