# 故障排查

## 使用方法

从最早失败的阶段查起，确认当时使用的输入、配置和记录，再选择恢复入口。所有项目诊断命令须在沙箱外运行；沙箱内无法访问本机代理，并不能证明目标站点故障。不要为消除报错而手改进度或来源文件。

第一次排查时，先分清问题所在。配置、认证、额度和存储故障影响整次运行，应先停止新请求；单篇内容失败保留原稿，再按正常失败集合恢复。命令的完整前提见 [操作手册](../SKILL.md)，费用及原余额边界见 [Reader 恢复](reader-explicit-retry.md)。

核心摘要误报“原文无可核定量结果”时，先核封存原文与真实响应。规划器在已声明、具名硬件的留出模型与批量验证池中选中实测最快设计的计数属于选择准确率；GPU 数、批量和输入采集 GPU-min 本身不能替代结果。此类结果须保留原分子、分母和条件，假设、否定、引用及他人结果不能冒充本研究实测。规则修正后，可通过选定重分析 API 的 `coreSummaryDiagnosticIds` 显式指定原请求重验，仍核对原输入、来源、证据、阶段身份及事实反馈，保留三次旧请求和费用；日更不能使用仅限会议的自动最新响应索引。

核心专用父包之后再次纠正 Reader 时，完成核验使用与正常执行相同的反馈渲染器。原始 Reader 反馈 SHA 和首次不含核心指导的路径继续保留；只有父子包、来源和已完成上游均经核验，且完整核心指导渲染精确匹配原阶段 SHA 时，才重放该已有路径。未知哈希、包或引文变化仍拒绝，普通 4000 字符上限不变，不借此取得 8000 字符、模型请求或跳过检查的权限。

## 1. 启动即报缺少配置

检查项目根目录 `.env` 是否存在及权限是否正确，确认其中已填写 `PAPER_ANALYZER_API_KEY`、`PAPER_ANALYZER_MODEL` 和 `PAPER_ANALYZER_ENDPOINT`。公开端点须使用 HTTPS。加载器会清理继承的项目变量，`.zshrc` 中的值不能补齐缺少的配置。

```bash
ls -l .env
npm run workspace:role -- status
```

角色应与目录用途一致；缺少标记或真实路径不匹配时，按[安装说明](setup.md)确认用途后再绑定。需要单独验证模型连接时，可运行 `node scripts/test-api-key.js`，但它会发送真实 API 请求，不是离线检查。

## 2. 主模型请求失败、超时或空响应

确认模型名称与项目配置一致，命令在沙箱外运行。使用 Muse 时，`HTTPS_PROXY` 或 `HTTP_PROXY` 须指向 `http(s)://` HTTP CONNECT 代理，代理出口与地区还要符合账号要求；启用 `PD_OPENAI_RESPONSES_STREAM=1` 时，还需检查代理能否正常传输 SSE。

Muse 每次请求使用独立的 CONNECT 代理连接对象，用完关闭，不能改成直连。`incomplete/max_output_tokens` 表示输出被截断；调整证据、输出预算或提示词后重试，不能接受半截 JSON。

Node CONNECT 与 TLS 握手合计最多等待 60 秒有效时间。与模型整体预算共用的计时器会排除超过 30 秒的长停顿，仅计入原有的 2 秒恢复成本；连续较短停顿仍正常累计。预算耗尽后先让已就绪网络事件处理一次，再确认是否超时；成功、错误和连接对象销毁均清理计时器，销毁后的迟到事件不能重新建立连接。

日志的“系统睡眠/长时间挂起”同时覆盖系统挂起和本地同步代码长时间占用事件循环。若系统电源记录没有睡眠、进程持续处理来源核验，不能仅凭该日志要求更新凭据或把电脑睡眠当作根因。先保存并停止在途任务，修正规则、验证真实超时与阻塞后恢复两种情况，再沿原清单、候选、次数和费用续跑；不要原样循环重启。

配置账号池后，可查看 `data/runtime/llm-account-pool.json` 中的 `activeAccountId`（仅观测最近一次选择）、`rotationCursor`、`limitName` 和 `blockedUntil`。它不含原始密钥，但稳定凭据指纹仍属敏感记录，须保持 `0600` 权限，不上传或归档。

同一池内所有账号等权，按稳定排序轮转。只有当前账号返回明确 `GoUsageLimitError` 或 `Insufficient balance` 时，系统才在同一逻辑请求内切换到下一个可用账号，且每个账号至多尝试一次。普通认证 401 会停止本次运行，普通 429 按原有限流规则退避，不切账号。不要为切回某个账号删除或修改状态；冷却到期后账号会自动回到轮转。状态损坏、版本计数不合法或路径不安全时，程序会在网络请求前停止。

生产停稳后，认证排查可以在独立诊断中逐个测试全部已配置凭据，不能仅凭当前账号 401 就判定没有可用账号。每个账号每条实际路由只发一次最小请求，仍使用正常模型、代理及公共请求封装，保存真实用量并按账号序号报告认证、额度、传输或成功结果；不输出密钥、认证头或稳定凭据指纹。主副路由和凭据相同时去重测试。HTTP 200 的截断响应只能证明请求被接受；选定成功账号后确认完整响应，备份原配置并同步主副配置，保留原池及冷却记录，再恢复任务。持续授权已覆盖这项诊断，不需要重新索要费用确认；仅完整排查后确实缺少可用凭据时，才请用户更新配置。

### 费用记录保存失败

Node 与 Python 均在真实请求发送前保存 `request_started`，终态沿用同一 `eventId`。发送前保存失败不调用传输层；终态或 Reader 采用记录保存失败报告 `LLM_USAGE_NOT_PERSISTED`，停止新派发，不能将已返回内容当作无消费再请求。普通传输只在原单阶段尝试内重试，用尽后按运行级故障停止；事件循环长停顿可以从有效时间中扣除，但不能返还实际请求次数。

仅在账本保存失败时，程序尝试将真实返回正文及安全事件元数据另存为私有 `data/runtime/llm-response-recovery/` 文件，权限 `0600`，保留回读 SHA；不保存密钥、认证头或 Prompt。它是恢复证据，不是完成证明或自动重放入口。磁盘完全不可写时明确记录保全失败，只保留进程内实际响应，不能声称已经落盘。先排除磁盘、权限或目录故障，核对原请求和实际响应后受控恢复；不删除旧账或把未知请求改成零消费。

## 3. MiMo/Kimi 403

MiMo 和 Kimi 请求默认设置 `agent:false`，直接连接。若 curl 直连正常而脚本返回 403，检查调用方是否绕过 `requestLlmJson()`，或自行传入代理连接对象。不要把 Muse 的强制代理规则用于其他模型。

资源扫描收到 OpenAI Responses 明确的结构化拒答时，记录为单篇 `MODEL_REFUSAL`，不重复请求；仅开源链接扫描复用正常的封存原文 URL 提取后备，仍须核验资源归属、可达状态及整篇资格。其他分析阶段继续保留拒答失败。未知空输出、网络、认证、配额、截断或异常终态不能冒充拒答，也不能由此放行。

## 4. arXiv/HuggingFace 抓取失败

先检查项目代理和相应来源的进度记录。arXiv Node 请求须使用 HTTP CONNECT；HuggingFace curl 可额外使用 `ALL_PROXY=socks5h://...`。遇到 429 应按配置退避，不要删除进度文件后用更高并发反复请求。

来源候选数量或 SHA 不一致时，只重新获取该来源。缺代理的 HuggingFace 请求不能记成正常的空结果。HTML 只有标题、作者等元数据而没有可靠全文时，应在来源获取阶段尝试 PDF 提取。

## 5. filtered 不完整

先运行只读检查：

```bash
npm run validate:data
```

常见原因包括候选与筛选决定的输入 SHA 不匹配、决定未覆盖全部候选、API 错误项仍为 `pending`、入选结果包含非 `related` 项，或模型、提示词、关键词版本改变后只更新了部分文件。重新运行筛选入口补齐决定，不要手工删除未知决定。

## 6. 分析慢或反复失败

### 先确认失败阶段和本轮进度

先查看本次选定集合、轮次报告和失败阶段。首轮先统一跑完正常流程，下一轮只续可重试失败项；默认最多3轮，完成项按当前资格复用，不先逐篇人工精改。整篇分析默认并发为3，Reader重阶段及批量刷新的配置并发默认5，筛选批次由 `PD_FILTER_BATCH_SIZE` 控制。主分析、局部修复和解读正文分别使用自己的输出与上下文预算。

解读局部修复通常最多输出 8000 tokens。某次修复精确在基础上限截断、候选仍有额外恢复资格时，程序保存失败草稿并停止；下一次显式续跑可使用一次提高预算的修复，默认最多 16000 tokens。

这个机会与实现升级的额外尝试共用，不能叠加；自定义上限仍受正文与基础修复预算限制。模型返回任何内容就会消耗这次机会，纯网络故障不消耗，截断的正文仍不接受。

### 本地页面冷核超时

先看有界子进程的真实超时、截断和退出状态，再解释 JSON；空 stdout 不能单独证明内容、来源或认证错误。会议和历史共享 `publication_replay_policy.json`：复杂认证来源一次冷重放最多600秒，单页 Python 总预算720秒，Node 外层再留15秒清理；普通会议600秒、普通历史180秒。最多8篇的会议汇总按实际成员所需预算相加，再加120秒固定开销。这里是硬截止，不是每页必须等待的时间；普通日更资源核验仍保持原期限。

同一页渲染中，真实来源、资源、原表、来源纠正和核心摘要检查共用一次正常 Node 冷重放结果。该结果只在本次同步渲染、同一个论文对象及同 SHA 来源中有效，退出销毁；下一篇、异步恢复或字节变化均不能复用。期限到达先清理本次子进程组。只有固定程序通过私有文件描述符报告、并经实际程序 SHA 核验的本地超时，才进入全批首轮后的单次串行恢复；不能由 stderr、JSON 或正文自报获得重试。

### 选择已有资格允许的恢复入口


```bash
npm run deep -- --date YYYY-MM-DD
# 保留已付费草稿及原调用次数，只更新核验后的修复诊断
npm run batch -- --refresh-reader-diagnostics

# 仅在原候选额度已耗尽、重试清单已核验且有明确授权时，开启有界付费轮
npm run batch -- --retry-failed-readers --reader-retry-manifest /absolute/path/reader-rounds.json
npm run api:reader:refresh -- --all --date YYYY-MM-DD --concurrency 5 --scoring-and-reader
```

Reader 刷新可以用 `--rounds N`（1–10）覆写本次总轮数，未传时使用 `PD_ANALYSIS_BATCH_MAX_ROUNDS`（默认3）。它只续明确 `retryable=true` 的失败项；未知或不可重试错误不自动重跑，来源计划、运行级和存储故障停止补派。诊断保存在 `data/runtime/analysis-batch-reports/`，错误携带本次报告路径；诊断不能授予请求或发布资格。

普通批次轮数不是付费 Reader 追加轮，不能因前者结束而清计数、换epoch或自动加重试清单。`manualHandoff` 的 `eligibleIds` 只是多轮小失败集合建议；`blockedIds`/`budgetExhaustedIds` 应先查真实阻断。服务故障先修服务，来源或身份不符先保留现场，预算耗尽只走明确受控修正或有界追加。人工修正后的正文仍须通过正常完整校验及发布审查，不手填成功。详见 [共同处理顺序](three-workflows.md#全批轮次与失败集合)。

明确重试必须提供 `--reader-retry-manifest /绝对路径/reader-rounds.json`，不能按论文批量停用旧稿。程序在规范论文锁内核对当前批次、四份封存来源、正文和实际 Reader 输入，只为清单中确实耗尽的失败稿开一轮。

原稿、原调用次数和费用记录完整保留；新轮最多 3 次已保存内容尝试、1 次全文、6 次实际请求，输出预留合计不超过 80000 tokens。同一授权续跑只用剩余额度，普通恢复和实现版本变化不自动开新轮。它可以与 `--refresh-reader-diagnostics` 同用：无授权论文仍按原次数正常恢复。详见[有预算的 Reader 重试](reader-explicit-retry.md)。

### 结构检查疑似误报时

损失归一化、辅助损失等列可能表示训练开关。只有原文的完整已执行配置表、各行身份与开关值逐项对应时，才按设置列核验，不为“是／否”添加数值升降箭头。扰动类型、融合调度等设置轴也须绑定当前原表；这种列类型识别不证明数值正确，不代替表后解释、消融或负面结果检查。

自然录音与生成录音在严格匹配后仍可区分，可以是实际负面结果。核验须保留同一生成器、样本数、独立参照组、描述总数及可区分数，并与原文和对应表行相符；假设、引用、他人实验或已撤销结果不能作证。发现真实数字或实验口径错误时，仍通过来源绑定的事实反馈恢复。

结构修复失败后，正式文件中的 `analysisCheckpoint` 可能仍是修复前输入。先分别核对失败日志、费用与阶段指纹，不能把输入检查点冒称最后一次拒绝响应；旧返回全文未保存时，不补造原响应或重验凭证。

### 来源或旧签名不符时先保留现场

`READER_PROMPT_CHANGE_REQUIRES_CONTROLLED_RECOVERY` 表示同输入仍有不同提示词版本的原请求历史。程序阻止把它当新稿从零计数；不要删候选、改 epoch 或重跑首次生成来消除错误。先核对原候选、提示词、来源和剩余次数，再按 [Reader 恢复](reader-explicit-retry.md)选择已有合法路线。更新代码或写作规则不隐式重开原付费窗口，也不清零历史次数；必要的新增付费恢复按 [持续授权](../AGENTS.md#持续授权以效率和效果为准) 登记并执行，不再逐轮询问。

恢复命令报告日更来源缺失或变化时，不要改进度文件，也不要补入旧 `data/current` 文本。目标仍为北京时间当天时，重新运行同日 `npm run digest:prepare -- YYYY-MM-DD` 获取并保存来源；历史日期不能重新从抓取开始，应保留失败记录并按历史维护流程处理。

若日更 Reader 已有完整签名却仍报告未完成，先核对原父包、子包与实际合并引文上下文，不能单用子包改签 `reviewFeedbackSha256`。只读完成核验不清除最新失败；旧父恢复缺真实主检查点或试图改变非 Reader 上游时须停止并保留原稿。若旧版本已删除阶段，只能用经来源和完整父稿 CAS 核验的真实快照恢复，再交回正常流程，详见[反馈恢复](reader-explicit-retry.md#已完成主文的独立-reader-事实反馈)。

## 6.1 历史来源获取或暂存页面失败

先确认失败的是哪种来源。历史 arXiv 的当前这组已保存文件保存在 `data/runtime/fetched-arxiv-sources/<arxivId>/generation-XXXXXX/`，应包含文本、PDF、来源信息和清单；`generation` 是获取序号，不是论文的 `vN` 版本号。重新运行同一 `history:sources`，直到当前计划所选论文均已在对应获取序号下达到 `ready`，再运行 `history:run --apply`。

`history:run` 不补抓来源，来源状态缺失、为 `handoff` 或 `failed` 时，会在模型请求前停止。再次运行会核对来源，并复用 `analysis-recovery.json` 中仍与来源相符的阶段结果。若渲染实现已变化，它可使用匹配的分析结果重新生成暂存页，不再请求模型，也不覆盖旧暂存文件。

已完成分析的恢复遇磁盘、真实来源身份或类型化运行故障时，保留原分析、来源、恢复指针和次数，保存最新失败并暂停后续派发。普通正文校验失败仍报告真实拒稿；分析文件确已漂移时不会保留为合格结果。只有 PDF 资源脚注而没有表格的历史稿，也须在真实 PDF 来源作用域内冷核。

无版本号的当前 arXiv PDF 明确返回 HTTP 404 时，可以保持参数不变，重跑同一获取序号的来源任务。程序只会尝试同一论文的官方历史版本，不会猜测另一 arXiv ID。成功后，应有记录当前稿 404 的 `sourceVersion`、从所选 PDF 提取的 `source.txt`、分析输入顶部的版本警告，以及最终页面的“当前稿不可用”提示。来源身份和哈希必须一致。

未证明当前 PDF 为 404、地址指向另一论文或包含查询参数或片段标识时，不得手工导入或改进度文件。普通当前 PDF 来源不走这个条件分支。同一论文的官方版本全部不可用时，才按已保存、命名明确的 arXiv 失败备用记录记录进入对应补救流程。

怀疑会议外部文件路径变化时，用一次 `history:status ... --verify-sources true` 重算论文信息和 PDF 的 SHA，不要在持续观察模式中使用深度校验。普通状态查询只检查路径、类型和文件大小，以免长期观察反复读取大量文件。

会议条目应检查本地来源清单中的论文信息与 PDF 路径、SHA，以及冻结页面清单和会议页面映射。缺失或损坏的本地会议来源会使该条目停止，不能套用 arXiv 失败备用记录流程。不得用旧博客正文、旧分析、相似文件名或随意标题搜索补齐来源。

会议博客维护收到停止信号后，会在初始化保存稿复验及调度快照的完整成员之间处理信号并检查停止状态。已经开始的单篇仍先完成正常复验、暂存和保存，再停止下一篇；不在禁止模型的重放作用域内检查模型派发权限，不中断原子写入，也不增加模型请求或重置次数。

## 7. 解读句式重复，或表格、图片脱节

最终页面把 `T5* Time` 之类技术表头转义为字面星号时，来源校验只在原显示格与原来源格逐字相同、发布格又恰好等于既有转义函数输出时承认这项显示变化。原表、正文、绑定与 DOM 的 SHA 保持不变，合并分类行仍须通过完整逐格投影；不能全局删除反斜杠或用显示等价放过错数、缺格与错误来源。

英文原题作为字面文本展示，发布器显式转义其中的星号和美元号，原题元数据保持原样。含 `phon*` 的链接即使在 Goldmark 中已经正确显示，也采用显式字面转义以减少审查歧义；回归须确认转义前后真实 HTML 的题目、链接和强调范围一致。

先按 [Reader 写作说明](reader-writing.md)检查解释是否完整，再按 [中文写作约定](writing-guide.md)调整段落和表达。把概念、计算或比较拆开讲，不代表可以增加没有来源的结果，也不扩大局部修复的节点范围。

将 `apiReaderPlan` 与正文对照，检查读者能否理解组合术语各自的分工、搭配原因和效果；表前是否提出比较问题，表后是否解释收益、失败条件及边界；图前导读、观察顺序、原图、图注和解释是否相邻。模型未看到图片时，不能描述其颜色、坐标轴或模块。段落中的“它”“该方法”“这一结果”应有明确指代。

调整提示词或结构化审查意见后刷新解读，不在博客审查阶段直接改页面。表格数量不足的诊断使用 `reader_table_count_insufficient`、`requiredCount` 和 `actualCount`；这些字段用于程序恢复，操作者不应手改。正文已有表格但缺来源记录时，应补对应记录，不为消除数量报错盲目加表。

表格还需检查 `selection` 是否引用真实 DOM 行列，表格标记与来源记录是否有唯一顺序对应，原文引文模式裁剪后是否仍至少两列、一行数据。旧结构化来源须通过来源清单和全文 SHA 校验，并能按记录的解析器版本重新验证。例外仅限实现认可的无布局来源标记，且表格、公式和图片数组均为空；不能用任意布局声明取得兼容资格，也不得重写已保存的文件来制造新 SHA。

单张图片的 `RESPONSE_TOO_LARGE` 会使程序跳过该图。如果一张图都未能准备成功，再检查代理、图片地址、MIME 或源 PDF。

## 8. blog:generate 失败

检查正式分析结果是否满足当前发布要求，包括批次日期、八维评分、Reader v3、作者机构及安全的图片地址，再检查目标博客工作区。生成命令会拒绝覆盖目标日期已有的人工 Git 修改。指定单篇或排除项却未命中时也会停止，这是发布范围检查，不能忽略。

## 9. blog:review 失败

若 Hugo 报连续重复概念标签残留 `**`，共享展示器只合并逐字相同的完整加粗标签；标签内完整平衡的行内代码按原字节比较，代码内部不归并。链接、URL、引句、代码块、缩进代码和未闭合行内代码仍受保护。原 Reader、来源及身份不改，修复后正常重新生成并审查，仍须通过 Hugo 构建检查。

来源绑定表格若出现 `0.991​m​s0.991ms` 这类显示副本，仅完整单元格含恰好两个 U+200B、两份数字逐字同值同精度且单位均为 `ms` 时，出版视图可显示为 `0.991 ms`。该证明记为 `zero-width-unit-duplicate`，不推断未保存的 MathML 标签；原来源文本、表格 SHA、DOM 和坐标仍参与冷核。无来源绑定的表格、引文模式、裸重复、异值或续式不适用。

若同表含跨全宽的分类或脚注行，Node 出版重放也须识别这项精确显示投影，才能验证原合并格的空白位置。仅当原绑定文字逐字等于来源文字、显示格恰为同数字加空格与 `ms` 时桥接，随后仍检查整表全部 DOM、坐标与单元格；不能因空白脚注失败而填值、删行、改来源或跳过整表核验。

审查只读取页面。内容问题回到生成或分析阶段修复；瞬时 API 故障只重试失败页面。通过记录按“相对路径 + 页面内容 SHA”复用，内容变化才重审该文件。生成清单元数据、模型、发布器代码、协议或 Hugo 运行时变化时，重跑当前批次检查并保存新审查记录，不重审内容未变的页面。Git 基线或远端身份变化仍会阻止推送。

会议 complete 但博客内容被拒时，先等完整 batch-failure 结算。text 和共享格式变换仍不通过 gate 的 Markdown 走[正常 Reader 全批维护](conference-workflow.md#博客拒稿后的正常-reader-维护)，不手动改分析为失败、不逐篇先精修；图片可先同认证 PDF 完整页新展示并正常目标图审查，残余图文语义再正常维护。裸美元等科学正文格式问题不能猜币种或借图注规则豁免。pending 时沿原显式维护 manifest 恢复，不删除义务/目录或另跑普通迁移漂移基线；必要新窗口按持续授权登记，不重复索费。

若汇总裸控制词元或合法图片 ALT 的 `\[` 转义触发格式问题，先核共享显示与正常 Markdown/Hugo 诊断；确认生成或诊断语境问题时保留原失败，正常修复实现并重建汇总或全页复审，不盲付 Reader、不改原页面字节躲检查。新整批含旧协议 passed 是正常缓存复用：核正式路径/页 SHA cache、原 result 自哈希和精确记录，不改签或重审字节未变通过页。无 cache、被改字节或失败项协议不符仍拒绝；不能把内容拒稿改成 passed。新完整原页像素也只证明展示来源，不证明 Reader 模型曾见该页。

Hugo 内存异常时，先检查是否有遗留并行进程，核对目标仓库和主题，再运行受控构建检查。不能跳过 Hugo 后把审查记录为成功。

## 10. blog:push 失败

检查审查记录是否对应当前生成结果，博客 `HEAD` 是否仍为审查时的基线，已暂存、未暂存和未跟踪的文件是否符合允许的精确变更，远端名称及推送地址是否变化，以及远端 `main` 是否仍匹配可重试的提交。

推送阶段不生成或审查正文，不能借已有本地提交绕过审查记录。有效的本地发布提交尚未推送成功时，按原入口继续，让程序核对并复用，不手工扩大发布范围。

### Git 已推送，但页面未上线

检查对应提交的 GitHub Pages 构建与部署结果。失败时读取日志、修复并等待成功；部署的是后续提交时，须验证它仍保留本批已审页面内容。逐页检查目标汇总与论文页面的 HTTP 200、正式地址和标题，保存核验结果。远端提交匹配或 `digest:status` 显示完成，都不能代替这些人工核验。

## 11. 视觉 pending 或 record 失败

先确认发布提交已在远端验证，再运行：

```bash
npm run visual:prepare -- --date YYYY-MM-DD
npm run visual:status -- --date YYYY-MM-DD
npm run cover:status -- --date YYYY-MM-DD
```

任务清单本身缺失或失效时，先重跑 `npm run visual:post-publish -- --date YYYY-MM-DD` 重建任务，再走上面的生图前准备。

只使用本次准备命令输出的绝对参考路径。新日更核对官方图片身份后会返回空引用列表，这是预期行为，不能改用旧缓存。登记须提供当前任务 token、正式分析文件及 `--qa-attested true`，并且已逐图目检。任务清单、发布记录或图片 SHA 变化会使旧完成记录失效。

封存 HTML 中的内联 SVG 使用原页面加元素锚点的地址，例如 `https://arxiv.org/html/论文ID#元素ID`。这类地址须通过已签 Reader 的内联 SVG 来源与渲染证明校验，不能按普通图片地址一律拒绝锚点，也不能为通过检查而删掉锚点、改写正式图片记录或恢复旧缓存。临时图片模式的视觉规划只核对身份并返回空引用，不重新抓图。

博客已推送但视觉规划失败时，保留原发布凭证，修复后只重跑 `visual:post-publish`。用户已经明确取消视觉时，规划恢复后运行 `npm run digest:waive-visuals -- --date YYYY-MM-DD --reason "用户明确要求本批次不执行发布后视觉任务"`，使豁免绑定当前发布和任务清单，再核验部署、网页并重新读取 `digest:status`；不必重新生成、审查或推送字节未变的博客。

## 12. 状态报告与现实不一致

`digest:status` 只反映读取时状态，推送、登记图片或取消配图后须重新运行。当前日期的失败不会被归档数据掩盖；历史日期也只有在各文件日期、来源和论文集合匹配时才能使用归档。网页上线另按上述部署与页面核验要求确认。

## 仍无法定位

记录运行命令、目标日期、最早错误、所在阶段、相关清单路径和脱敏日志片段。不要附 API 密钥、认证头、Cookie 或完整 `.env`。
