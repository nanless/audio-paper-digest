# 安卓 1.3.2：修正阅读返回后的自动更新

最终安卓源码为 1.3.2、构建号 10，包含 [首轮候选的全部修复](android-1.3.1-review.md)。1.3.1 只建立过私有草稿，没有公开安装包；原 Git 标签和测试记录保留，避免改写已经固定的来源。Mac 仍为 1.3.0。

正式包逐项复验时，发现阅读返回后还有一个自动更新问题：工作台会保留上次打开的论文，以便恢复阅读和位置，但原自动检查把“仍保存了选中论文”当成“阅读界面仍在前台”。因此，即使用户已经回到论文列表，之后的自动检查仍可能被跳过。

这次将阅读状态改为由实际界面登记。每个界面分别拥有自己的显示标记，离开或销毁时只撤销自身的标记；最后一个阅读界面离开后，再按原有间隔、离线模式和失败冷却安排自动检查。上次论文、PDF、滚动位置和来源身份不因此清除。

| 实际状态 | 是否保留上次论文 | 自动检查行为 |
|---|---|---|
| 前台正在阅读 | 保留 | 等待当前阅读，前台操作仍优先 |
| 返回论文列表 | 保留 | 按间隔正常检查，不再误判为正在阅读 |
| 多个界面仍有一个在阅读 | 各自保留 | 一个界面离开不会清除其他阅读标记 |
| 应用进入后台 | 保留 | 由系统周期任务和正常资格检查控制 |

新增回归必须覆盖“选中论文仍在，但界面已经返回列表”、多个阅读界面分别退出和组件销毁。首次同步、普通返回和首屏显示的既有检查继续保留；原候选已经完成的检查只按实际未变化范围复用，不将旧包或旧 CI 结果改写成最终版本通过。

这项小修先通过 27 个相关主机测试、编译和静态检查；隔离 API 35 设备完成 7 个真实控制器用例和 2 个界面导航用例，包含保留选中论文后重新允许自动检查、多个阅读界面分别退出、原生返回和组件销毁。最终 1.3.2 源码又完整运行了 887 个 JVM 测试、静态检查以及 11 组共 161 项脚本检查，全部通过。首轮候选的 41 个按明确布局验证的设备方法和正式窗口结果继续保留原范围；最终签名包仍另行验收，不改写旧记录。

正式包仍须用最终同一签名 APK 完成旧版覆盖升级、空白首启、自动获取网站目录、实际论文阅读与返回，再核对固定草稿的六件附件和公开下载。源码与安装包是否公开以 [GitHub 发行页](https://github.com/nanless/audio-paper-digest/releases)为准。小米 15 Ultra 的实体机复验仍需在用户设备上进行。
