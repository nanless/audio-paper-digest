# 数据与发布兼容规则

下表分别列出当前写入格式、旧记录用途，以及继续分析或发布时的检查。日更、会议和历史更新核验各自的来源与范围；退役 Manual 记录按原协议只读核验。

## 怎样识别保存格式

新格式一般用 `contract` 说明记录的用途，用 `schemaFingerprint` 标明实际登记的字段和规则。程序从 [格式登记目录](../config/protocols/) 读取这两项，并用内容、来源和保存范围继续核对。格式名称相同，只能说明用途相同；结构指纹不同，读取时必须找到实际登记的结构。

旧文件可能只保存一个名称或整数。历史读取器按原字段解释，重新计算旧记录的哈希时也使用原字段和原字节。已经签发的文件不补写新声明；未变化的已付响应、原次数和费用也不重记。

网页内嵌的客户端声明另有一条规则：Hugo 会把 front matter 参数 map 的嵌套键递归小写，所以页面里的 `paper-tools__client-sidecars` 必须按白名单重建并保留 `schemaFingerprint` 的驼峰写法，不能直接序列化参数 map。已发行的 2026-11-03、11-04 页面曾输出小写 `schemafingerprint`；客户端只接受这一个已知别名，归一化后仍按登记指纹严格校验。

客户端 1.4.3 的目录紧凑投影、分类证据索引和论文详情都是本机桥接返回，不写回网站数据，也不改变本文的发布格式、来源或审查规则。

## 分析与来源

| 数据或记录 | 怎样核对 |
|---|---|
| 筛选决定 | 决定必须覆盖完整候选集合；候选、模型和实际提示词匹配时，才可按原规则复用。 |
| 分析阶段清单 | 新建 API 清单用 `analysis-stage-manifest`。已有清单可以按原格式续跑；摘要、方法、表格、评分、来源和 Reader 各自核验。退役的人工分析记录按原声明读取。 |
| 日更来源 | 核对目标日期、完整入选集合及每篇的 PDF、文本、来源信息和清单。旧文本或 PDF 缓存不能替代封存来源。 |
| 论文解读 | `beginner-researcher` 声明正文要求，`api-reader-source-bindings` 绑定表格和公式，作者与资源另有各自的来源证明。较早且不具备这些来源证明的记录只可用于历史读取。 |
| 评分审查 | `api-scoring-audit` 绑定实际依据和最终分析；重算八维总分，在满足触发条件时另查评分是否稳定。旧页面分数仍可显示。 |

## 页面、审查与维护

| 数据或记录 | 怎样核对 |
|---|---|
| 生成清单和审查凭证 | 正式清单用 `blog-generation` 绑定全部论文快照和文件；`blog-review-receipt` 绑定实际审查文件、生成清单、博客 Git 基线和 Hugo 构建。完整的旧快照按原格式核验；仅含文件列表的旧清单不能代替正式日更记录。 |
| 阅读与下载资料 | 页面按 `researcher-workbench` 声明，四份受控下载资料各自核对路径和内容 SHA。旧页面仍可阅读；没有有效声明的页面不能据此获得结构化下载资格。 |
| 发布后的图片 | 日更保留正文中有来源证明的论文原图，不再生成长图和汇总封面。历史图片只核对原文件、原审查和原发布记录。 |
| OpenCode Go 账号池 | 同池等权轮转。只有明确的 `GoUsageLimitError` 或 `Insufficient balance` 才能在同一次逻辑请求内切换账号；冷却状态继续保留。状态文件不保存密钥，未知格式不能被覆盖。 |
| 历史目录、暂存与发布 | 保留冲突来源和不可访问论文，不能只凭一个编号合并不同页面。核对实际来源、范围和页面字节，再经独立审查、提交及远端核验。 |
| 退役的人工分析结果 | 只核验和显示原有结果。独立人工博客审查仍可用，按逐页事实、图片和实际审查身份签发新的凭证。 |

## 兼容读取的具体限制

“能读取旧记录”与“能继续生产”是两件事。兼容读取先解释旧文件当时采用的格式、来源与签名；继续分析、生成页面或推送时，还要满足对应入口的当前要求。下面按对象说明这条区别。

### Reader 来源与页面审查

Reader 正文、表格和公式各有独立要求。通过其中一项，不能代替另外两项。早期结构化来源须通过来源清单和全文 SHA 核验；兼容按旧键顺序计算的哈希时，还须能按记录的 `parserVersion` 重验。例外仅限实现认可的、没有页面布局信息的来源标记，且 `tables`、`formulas`、`figures` 数组均为空。不能随意填写布局声明来让来源通过校验，也不能改写已保存的文件来生成新 SHA。

页面审查的通过记录只按最终文件路径和内容 SHA 复用。模型、代码、协议、生成清单或 Hugo 变化后，仍要执行当前批次检查并生成新的审查记录；已通过且字节未变的页面不用重新请求模型审查。

会议后续批次可以保留旧协议的 `passed` 记录，但必须逐字段核对正式通过缓存中的路径、页面 SHA 和完整 `result` 自身的哈希。失败项仍严格绑定当前批次协议。

未完成维护的 `pending` 状态不能因旧完成记录可读而清除；历史出版图的来源能力也只认证原审查意见所依据的材料，详见[会议博客维护](conference-workflow.md#博客拒稿后的正常-reader-维护)。Git 基线或远端身份不匹配时仍禁止推送。

### 退役 Manual 的原始证据

Manual 包内保存的旧提示词和编辑规范副本不代表当前任务可以继续。旧提示词已从工作区删除；只读核验保留原指定路径及声明 SHA，从受控 Git 物件索引取回原字节并重新计算 SHA，不把旧全文恢复到工作区，也不把当前模板代替旧证据。编辑规范、来源及成稿材料继续核对指定实际文件和 SHA；缺失证据或不符即停止。旧正式结果仍可核验和显示，但旧任务包不能据此获得新的写作或发布资格。

### 历史发布与封存预览

独立历史发布入口已经存在，但计划或暂存文件齐全不证明全历史任务已发布。详细操作及来源限制见[历史重写](history-rewrite.md)和[历史发布](history-direct-publication.md)。已有批次重写的人工补丁还受旧运行身份限制，见[从原文重写](history-rewrite.md)；不能手填缺失 SHA 扩大兼容范围。

旧 `sealed_tutorial_preview` 只保留材料读取，停止新页面生成、审查声明与推送。其旧加载器验证的局部哈希不能替代完整文章、来源和当前发布资格核验。

## 迁移原则

1. 新建记录按当前登记格式写入；续用已有记录时保留它依赖的原声明和证据。
2. 兼容读取不能授予旧结果新的分析或发布资格。
3. 迁移重新打开来源文件，核验真实路径、文件长度和 SHA。
4. 实际结构、提示词、预算或算法发生变化时，重新计算受影响阶段的指纹；未变化且仍能核验的阶段继续复用。
5. 来源或论文集合无法核实时，停止操作；页面看起来正常不能代替校验。
6. 内部登记更新后，仍要检查公开输出的真实消费者。网站词表经过发布边界继续按 Hugo 和浏览器使用的格式输出。变更公开格式时先核对部署模板、前端及现有客户端，并验证已有数据。迁移中遇到的实例见[日更与清理复盘](2026-11-daily-maintenance-retrospective.md#清理前先找到所有实际使用者)。
