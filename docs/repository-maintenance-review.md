# 代码、文档与提示词维护约定

维护工作以实际调用关系为依据：公共算法集中修改，来源、范围、预算和发布事务由各流程分别核验。日常步骤见[维护指南](maintenance.md)，三条生产流程的关系见[架构说明](three-workflows.md)。

## 判断代码是否仍有用途

删除前依次核对：

1. `package.json` 的 npm 入口及直接诊断命令。
2. 静态导入、动态加载、跨语言子进程和内部工作线程。
3. 测试、旧格式读取器、来源证明和签名重放。
4. 提示词的原路径、Git blob 和原声明 SHA。

没有普通 `import` 或 `require` 只说明缺少一种调用方式。例如，`scripts/test-api-key.js` 是显式真实请求诊断；Manual 签名模块仍供旧记录核验。少用、旧名称和仅在兼容测试中使用，都不是单独的删除理由。

确无调用的写入接口可以移除，旧来源、检查点、响应、失败、费用、签名及必要读取器继续保留。兼容测试在临时目录构造原格式，验证正常读取、字节变化、来源变化、缺文件和伪造外层 SHA；读取过程不补建材料或改写原记录。

## 公共实现与来源适配

| 共同职责 | 维护要求 |
|---|---|
| 主分析、Reader、评分和标签 | 修改实际公共调用，避免另建流程专用算法。 |
| Node 与 Python 的对应规则 | 使用同一组正反向量核对数值、类型、单位和来源语义。 |
| 单篇及汇总展示 | 复用详细摘要、资源和评分展示；显示字段不授予来源或发布资格。 |
| 三条流程的输入与保存 | 保留各自完整成员、日期或计划、真实来源、父稿、费用及事务。 |

日更读取当批四份官方封存文件，会议核验原计划和官方 PDF，历史按冻结页面与 URL 准备真实来源。历史任务的覆盖范围已经固定，维护公共模块时不增加筛选或扩充成员。来源提示、版本披露和页面身份由各适配器保留。

展示桥按原大小和期限处理有界批次，逐篇对应身份。详细摘要须重验原阶段；会议或历史读取自己真实来源，不创建假日更目录，也不以简短摘要回退掩盖错误。普通 `paidDiagnosticReplay` 记录按原调用方的来源、完成和核心阶段核验，不能仅因字段存在就拒绝；专属人工修正仍只适用于其原授权范围。

## 提示词升级与旧记录

- 工作树保留当前登记的 18 份模板。实际运行内容是 `loadPrompt()` 读取的首个围栏，说明页与运行正文分别核对。
- 修改必要内容时，同步 JavaScript、Python、阶段合同与版本登记。退休版本使用已有 Git 中的原字节及原 SHA 核验，不重签旧结果。
- 原付费候选继续按其声明和恢复链读取。提示词变化不清空内容、全文、传输、无进展和费用，也不让旧活动历史按首次生成重新计数。
- 两份冻结的 Manual 编辑合同保持原字节；当前写作说明放在[导航页](../manual/README.md)。

核心摘要的比较须来自同一表、同一指标下条件明确的对象，保留表头、单位、精度和唯一对应。跨指标拼接、自算差值与单位转换继续禁止。请求实际预算与输入指纹一致，旧版本沿用原预算；核心摘要原三次上限及耗尽状态保持。

Reader 的内容和来源要求见[写作说明](reader-writing.md)。真实无图来源可为零图；下载失败、来源漂移和缺失像素分别处理。局部修复限于获准既有节点，原表、原 TeX、图像和归属仍完整核验。

## 错误、保存与恢复

1. 先持久化请求开始记录，真实终态沿用同一请求 ID。未知消费保持未知；保存失败停止新派发并保全实际响应，完全不可写时如实报告。
2. 认证、费用、服务或来源等运行级错误保留其类型和范围。原传输尝试用尽后停止补派，已发次数不因长停顿退回。
3. 已完成保存稿进入正常后处理池；普通单篇失败先收集，运行级故障停止补派并等待在途保存。主线程核来源、父稿、页面、资产和 CAS。
4. 真实本地超时保留退出状态、期限和私有诊断。先完成首轮，再对规定的固定本地超时项各串行恢复一次；认证、网络、来源和模型故障另按原规则处理。
5. 同一同步页面内可合并重复的真实来源读取；不跨页、异步或保存缓存资格。最终全批采纳仍在锁内重新核对来源、正文、页面和 CAS。
6. 历史恢复保留完成指针、来源和原付费稿；保存故障保存失败并暂停。纯脚注稿也保留真实 PDF 来源上下文。

详细入口见[恢复说明](reader-explicit-retry.md)和[故障排查](troubleshooting.md)。

## 验证与交付

- 定向测试使用临时目录、模拟传输和显式来源，覆盖正例、越权、来源漂移、字节变化、父稿 CAS、失败保存和运行级停止；隔离所有数据根，不默认读取活跃生产资料。
- 真实稿回放须显式选择材料及物理 SHA。它与可移植单测分别记录；缺项或漂移按失败处理。
- 稳定修改先做必要定向与交叉审阅，再对最终提交完成完整工程验收。CI 由 PR 自动触发或主动运行，覆盖 Node 20/22 全部分片、Python、静态及固定 Hugo 构建，见[CI 操作](maintenance.md#什么时候运行远端-ci)。
- 推送核验精确差异、远端身份和提交；上线还须核对对应部署及全部目标页面，包括标题、H1、多级分类和正文。视觉按用户本次实际范围处理。

维护实现和文档本身不启动论文生成、重置费用或重新发布内容；生产任务按其授权及正常入口执行。
