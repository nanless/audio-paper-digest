# 仓库清理与文档、Prompt 改造记录

审计日期：2026-10-17，初始源码基线 `5e1eaeb17c745092b86bf8f17f39f5239f96b9fc`。本轮检查当前生产入口、共享部件、旧记录核验、十八份现行提示词，以及各级操作与设计文档。

本页记录发现、修改理由与验证范围。第一次使用项目请从 [首页](../README.md)开始；具体操作见 [操作手册](../SKILL.md)，三条流程的共用关系见 [架构说明](three-workflows.md)。上一轮性能测量与公共部件抽取分别保留在 [耗时审计](daily-performance.md)和 [共享审计](shared-workflow-review.md)。

## 怎样判断代码已经没有用途

本轮先按 `package.json` 建立入口集合，再检查模块导入、动态加载、子进程路径、直接诊断命令和测试。扫描时有 89 个 npm 命令、68 个显式脚本入口；脚本目录库存为 310 个跟踪中的 JavaScript、Python 和 Shell 文件，其中 307 个进入普通 npm 依赖展开，另 3 个逐项检查。此处是审计时的库存数字，不是实时计数，也不说明所有文件都直接由 npm 启动。

没有普通 `import` 或 `require` 不能作为删除理由。例如，诊断脚本可以由维护者直接运行，Python 与 Node 之间可以通过子进程通信，旧提示词则通过路径、原 SHA 和 Git blob 读取。这些路径需要分别追踪。

扫描发现三项不在普通 npm 调用展开中的文件，处理如下。

| 文件 | 实际用途 | 处理 |
|---|---|---|
| `scripts/test-api-key.js` | 配置和故障文档明确使用的真实 API 路由诊断 | 保留；说明它会产生真实请求 |
| `manual/scripts/manual-signature-contract.js` | 旧跨语言签名核验的参照实现与回归依据 | 保留；不恢复 Manual 生产入口 |
| `manual/scripts/manual-artifact-index.js` | 旧结构化产物的纯重建、读取与验证；另残留已退役写入链 | 只删除退役写入 API，保留读取与核验 |

## 实际删除了什么

删除范围限于下面十三个函数及其专用导入、别名和导出；没有删除运行数据、原始来源或旧签名材料。

| 位置 | 删除内容 | 删除依据与保留能力 |
|---|---|---|
| `scripts/fetch-papers.js` | `loadPapers`、`savePapers`、`loadAnalyzed`、`saveAnalyzed` | 跟踪代码、测试与文档没有调用；正式论文库由 `full-fetch` 调用 `digest-status` 的真实读写实现 |
| 同文件 | `deduplicatePapers`、`isSpeechAudioRelated` | 无调用的旧类别去重与布尔薄包装；实际候选合并、来源去重及完整筛选决定保留 |
| `scripts/deep-analyzer.js` | `cachePublicImageDetailed` | 只为已退役 Manual 作者链提供过包装；当前下载、安全网络、缓存核验和 Reader 图片准备保留 |
| `manual/scripts/manual-artifact-index.js` | 初始化、快照保存、单篇写入、检查点创建、失败写入、最终完成这六个 API | 没有生产调用，仅旧写入测试使用；旧快照、索引和清单的只读验证与原字段保持 |

不再测试退役生产写入。对应测试改为在系统临时目录显式构造旧格式文件，再由原读取器验证：正常文件可重放，字节变化、来源变化、缺文件及只重算外层 SHA 均不能蒙混通过；读取过程不补建文件，也不改失败、用量和来源清单。

仍在使用的受控恢复入口继续保留。少用、名字旧或只有兼容测试使用，都不等于可以删除；尤其不能删掉原费用、来源和身份的负例，以换取更短的测试时间。

## 文档怎样重新组织

首页现在先解释产出、第一次配置和任务选择。操作手册先连续讲日更、会议、历史三条正常链路，再讲失败恢复。执行约束仍保留强制规则，通过小标题区分轮次、预算、来源和锁，避免一段同时承担多种职责。

脚本索引按真实职责分表；每个文件仍能查到，长表中的空行不再打断 Markdown。Reader 写作说明把内容解释与机器协议分开，恢复文档先提供入口选择，再保留各自预算及身份细则。

本轮核出的具体事实问题包括：

- 配置文档仍说当前主模型使用 Chat Completions，已改为当前 Muse 的 Responses 路由。
- 历史目录说明把清单误写成保留旧正文；现按实际扫描范围区分字节身份、有限元数据和可用于写作的来源。
- 历史审查说明未写清同字节拒稿的重审门槛；现要求旧、新协议均合法且确实变化，不能靠重复调用获得通过。
- 标签设计仍保留卡片尚待实现的措辞，并有两个不存在的脚本锚点；现指向实际分层呈现与有效说明。
- 日更热门计数、逐篇直接标签和祖先导航容易混淆；现分别解释，附有明确标示的教学计数例子。

数据格式、补抓边界、来源锁内检查和故障排查补了阅读顺序、术语、范围表与小标题。已有性能报告保留原提交、数字和测量条件，只增加阅读导航，不把历史观测改成当前承诺。

### 内容解释的统一标准

[写作约定](writing-guide.md)集中解释段落、术语、概念机制、比较条件、计算、字母与单位、公式和图表。它附有项目评分示例：八维分数求和后封顶 10，八维上限之和为 11，不能误写成归一化到十分制。

复杂机制按输入、操作和输出展开。公式说明符号、范围、运算和用途；比较说明数据、协议、指标方向和限制；图前提出观察任务，图后区分实际观察与机制解释。读者应能沿文字跟随过程，而不是只看到术语列表。

段落按解释任务分开，段间留空行。说明可以详实，但不把同一事实换几个说法反复写，也不为每节强加相同栏目。命令、字段、原始 TeX 和逐字来源继续保持各自语法。

网上方法研究参考 Google、Microsoft、Diátaxis，以及四个公开 humanizer 项目的作者说明，完整链接与取舍在写作约定末尾。采用事实核对、读者定位和具体表达；没有安装外部 skill，也不使用检测器分数、虚构经历或英语句长配额作为写作目标。

## Prompt 怎样升级，旧稿怎样保留

十八份模板逐项审查后，只对需要改变实际运行文本的三份做版本升级：主分析 v5 → v6、完整 Reader v8 → v9、有界 Reader 修复 v12 → v13。筛选、标签、评分、单句纠错等其余十五份模板继续履行原职责，不为了统一文风扩大它们的输出权限。

新版强化概念先后关系、一次真实计算或数据流、比较成立条件、符号与图表解释，并明确 JSON 正文中自然段的合法换行表达。有界修复仍只改获准的既有节点；没有来源的信息不补猜，图像像素、原表、原 TeX 与公式标记的要求不放松。

版本更新同时维护 JavaScript 与 Python 的现行登记、阶段合同和旧路径映射。退休模板用已存在 Git 提交中的真实 blob 与原整文件 SHA 归档；现行工作树仍只保留十八份。模板首围栏是实际模型输入，外围说明不能代替运行文本。

旧完成稿依原声明只读重验。新版本身份不自动授予活跃付费候选迁移许可，不清空原次数、费用、失败或连续无进展记录。两份被历史来源绑定的 Manual 合同保持原字节，现行解释放在导航页，避免破坏旧 SHA。

### 深查发现的恢复计数缺口

进一步沿实际调用检查发现，仅仅不增加迁移白名单还不够：旧候选因 Prompt 不兼容而返回空值后，生成器可能把它当成没有历史的新输入，从零初始化 Reader 次数。这个缺口必须在启用新模板前修复，不能只在文档里承诺保留预算。

保护放在三流程共用的 Reader 恢复入口。正常选择旧候选之后，检查是否还存在同输入、不同 Prompt 的活动请求历史；来源、运行范围、模型、反馈、原预算和 epoch 都参与比较。旧内容尝试、全文尝试和传输失败记录均不能因 Prompt 变化被绕过；新当前候选也不能掩盖旧活动分支。

不兼容时保留原记录，返回明确的不可重试阻断，再选择已有受控恢复路线。已有合法迁移仍由原选择器和证明链处理，不增加 Prompt SHA 白名单或放行参数。检查发生在新的模型请求、额度登记和候选保存之前；当前调用可能已经完成图片准备，不能将它说成阻止了全部网络操作。

## 怎样复审和验证

第一轮由三个子代理分别审查调用关系、操作文档、Reader 与 Prompt；根代理整理共同写作约定并修改数据、来源和标签说明。第二轮交换审阅对象，核对实际代码、原约束与最终文字，再修正发现的问题。

交叉审查纠正了文档中的两个不存在模块名、过时 Prompt 链接、旧 Manual 格式可能被误读成仍可写入的表述，以及脚本库存与依赖展开数量的混用。Prompt 索引的重复键由严格解析拒绝后，移除新增的重复项，原条目保留；没有放宽解析器。

根复审还发现新增段落示例用了双反斜杠，会让 JSON 解码后留下字面的 `\n`。修正为每个 `n` 前一个反斜杠，并从实际 Prompt 取出示例，通过 JSON 解码检查它确实产生两个换行。这个例子说明，只断言“文案包含某个词”不足以检查表达是否真的有用。

版本接线的独立复核确认，原有 79 组阶段与版本映射、105 个退役路径以及 291 条原 Git blob 条目均保持；新增退休路径继续指向真实原字节。只读兼容、输入身份和付费恢复权限分别检查，不能把它们合并成一个“兼容通过”。

删除部分的必要定向测试共 125 项通过，保留的十二个只读函数与删除前逐字相同。它们证明清理没有改变对应读验路径，不代表已经验证整个仓库，也不证明新 Prompt 的实际生成质量。

最终验收以冻结后的代码为准，覆盖文档、Prompt、恢复兼容和完整工程检查，并核验远端提交。逐项结果见本轮提交及对应 CI；不以单个通过分片代替全套通过。此轮不重新生成论文、不请求论文模型、不修改正式分析数据，也不把文档和 Prompt 改造宣称为已实测的全日更提速。
