## 修复范围

- Reader 的排版修复不能新增图像事实、猜测百分比，或用方向箭头代替单位。
- PDF 公式保留字形、上下标、坐标和像素。按布局恢复的表达不能冒称作者原始 TeX；页面使用尺寸受限的原公式裁图，不用整页大图替代公式。
- 在 Node 论文分析调度中，运行级模型故障会停止领取新的分析任务，已经开始的任务保存结果后再报告具体错误。重试次数受限，冷却和再次运行仍受相应授权约束。这项修复不表示所有会议筛选或 Python 批处理都具有相同的停派行为。
- 迁移恢复会回到原始批次，避免普通入口绕过完成记录；升级旧来源时保留原始成果。
- 发布检查 Git index 和 commit 的实际字节，阻止提交无关文件，并支持从各中断点恢复。
- 生成阶段不再提前上传图床。HTML 构建使用固定 Git 树和子模块提交，避免博客工作区的人工改动混入审查。
- 会议队列按显式计划逐个会议推进，并区分旧发布记录与新的验收结果。
- 工作区诊断分别报告活动进程、遗留状态、完成证明和发布状态。存储报告覆盖大目录；PDF 重复报告区分记录中声明的哈希与实际字节校验，不提供自动删除来源的入口。
- 当时本机的重复配置在保留实际生效值后已去重；主、副模型使用相同的四账号池，选中第四顺位。密钥仅保存在被忽略的私有配置中，不在提交内。这是当时的配置记录，没有核验今天仍使用同一账号。

## 验收结果的范围

单元和集成测试、Hugo 构建、HTML 结构检查、Git 远端字节核验与线上 URL 检查验证的是不同事项。程序检查通过不等于文章已通过语义审查，也不等于浏览器执行数学脚本正常或图片已由人工确认。

`status` 读取已有证明的快照；显式 `verify` 才执行新的在线验证。那次修复没有做实际的在线发布验收，因此不能据此宣称所有线上旧文章已修复。现在宣告上线还须核验对应部署和正式网页的状态、地址及标题，具体要求见上述工作流。
