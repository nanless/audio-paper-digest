# 模型请求与修补链的离线审查

本报告补充日更耗时总报告，只覆盖模型生成、Reader 修补、解析、权限和重试链。生产已停止；本报告不授权启动生产或模型请求。旧付费文件、封存来源、次数和许可没有改写。

十倍是目标，尚无端到端十倍结果。下面的本地回放与测试只证明特定故障不再阻断合法修复，不能证明模型下一次必然给出正确全文，也不能把 HTTP 200 计为论文完成。

## 实际被拒绝的输出

停止的 R16 日志 `/tmp/root-r265-normal-daily-run.log` 共有 149 条“读者文章校验失败”。它们是输出事件，不是 149 篇不同论文；同篇可能重复出现。按真实错误文本逐项归类如下：

| 类别 | 输出事件数 | 结论 |
| --- | ---: | --- |
| 原表坐标、列头或完整表声明 | 25 | 不能据此放宽原表身份、逐格数字或坐标核验 |
| 表格顺序、标记与来源记录不闭合 | 20 | 要先核对正文实际表数、模式和记录；不能直接删多余记录 |
| 图片声明、位置或当前像素 | 14 | 未改旧记录与新增图解要分别证明；不能拿历史图片当本次像素 |
| 术语组合解释 | 13 | 数量、编号、位置与内容错误不同，不能只改正文解决数组缺口 |
| 比较单位 | 12 | 真实百分号或单位缺失与明确参数条件要区分，不作泛数字豁免 |
| 表格逐字引文或数字来源 | 12 | HTTP 成功不能证明引文逐字存在；继续严格核对来源 |
| 表格覆盖、宽表或解释 | 10 | 当前要求仍保留，不能靠空列或无依据解释凑数 |
| 文风与数字排版 | 10 | 可机械修正的等值排版不应反复调用模型；保护引文、代码、公式和网址 |
| 小节重排结构 | 10 | 最终仍须 12–18 节；不能接受原样返回的超量数组 |
| 篇幅 | 8 | 不降低字数门槛；诊断须指出差额和本轮可修改的位置 |
| 公式声明与位置 | 6 | 区分真实错误公式与完整原公式的记录缺口 |
| 补丁格式、SHA 或权限 | 5 | 仍拒绝越权、旧 SHA 和错误响应形状 |
| 缺少教学类型 | 4 | 只有正文权限无法改变 kind；需受限的小节对象权限 |
| 合计 | 149 | 不是网络故障统计，也不是整篇正确性统计 |

其中四类表格问题合计 67 次，占这 149 次拒绝约 45%。不能把它们全归为解析器误报：有真实越界坐标、无原表却声明序号、非逐字引文和错误的表格模式。

独立只读用量窗口 UTC 07:36–08:20 与同一封存运行对应，记录到 148 次 Reader 修补、1 次 Reader 完整生成、14 次评分、2 次结构修复、1 次核心摘要的 HTTP 200，合计 166 次。开始事件与终态事件没有混加；“传输前阻断”也没有算成 HTTP 请求成功。149 次 Reader 的 HTTP 成功仍全部进入了上述拒绝，说明当前主要问题是产出可用率，不是单纯增加并发。

## 已定位并修正的不可完成修补

| 问题 | 原因 | 修复及验证边界 |
| --- | --- | --- |
| 少于四组术语解释却只能改前八节正文 | 原目标生成器没有整组追加权限 | 只在完整、有界、可定位的稿件中补到四组。旧解释前缀逐字保留；正文只追加新标记，已有唯一缺记录标记则正文不动。六份 R14 冷备稿得到两项明确目标。新增解释仍由模型依据封存原文给出 |
| 超节数与少术语互相阻断 | 重排入口先调用要求术语数量已达标的解析器 | 仅按有界完整结构保留重排输入，只授权整个 sections 数组；其他根数组逐字不变。真实 03125 的 19 节、3 组解释从无重排许可转为唯一 /sections 许可。最终仍拒绝过多节数或少解释 |
| 无 DOM 原表的指导没有进入真实请求 | 深度生成入口没有把 structuredArtifacts 传给修补上下文 | 补上接线，真实生成与续跑请求验证精确绑定和对应正文指导；证据、目标及原 SHA 不变 |
| 缺 training 却只授予 body | 正文修改不能补上小节类型 | 单一缺失类型只允许相邻可替代、无绑定标记的一节完整对象。坏结构、乱序、伪缺失和绑定联动不放行；两候选只授权一项 |
| 公式缺七条记录被硬上限挡住 | 两份稿件各有十二个唯一独占公式标记、五条正确旧绑定，但原补齐只允许缺四条 | 已有补齐操作改为最终总记录最多十六。原记录、正文、其他数组不动；真实 05310、09701 的十二个原始 TeX/DOM 绑定回放通过。未知编号、重复标记、坏前缀仍拒，未宣称整篇通过 |
| 圈号数字排版反复失败 | 检查器把②、⑥归一化为2、6，排版器却只定位 ASCII | 保留原 Unicode 数字，只补汉字边界空格。真实04570不再报式2/6，但原宽表失败仍拒绝 |

上述变更都没有新增付费轮、改动已保存次数、扩大来源许可或替模型编写论文结论。组合代码完整验证记录以主报告为准。

## 表格与重排的真实复合失败

R15 表格请求语料包含 58 对完整请求和响应、42 篇论文；最新失败中有 40 篇属于表序或坐标类别。其中 16 篇是正文与绑定记录不闭合。可复核的原因至少包括：

- 10749、04826、04333 把普通 source_quotes 记录配上 TABLE 占位符；这种模式应有普通 Markdown 表，不能保留该占位符。
- 08850 正文三表却有四条绑定，两条记录引用同一原表但单元格映射不同；不能直接删其中一条冒充修复。
- 03125 同时有19节、3组解释和正文四表/五条绑定。修表权限无法减少节数，旧重排资格又因少解释拒绝，形成实际互锁。
- 04333 的重排回复确实从19节降到14节，但保留了非法表格模式，所以后续表格闭合失败仍然正确。

16次重排请求中，15次回复仍为19–27节，属于模型未遵守明确数量要求；只有1次降到允许范围。不能为了消除报错而放宽12–18，也不能据此认定所有15次都是程序错误。专用提示现明确本轮只解决节数和获准的小节结构，其余数组缺陷留到下一次重新定位与授权。

## 请求体积与串行依赖

同一58条表格相关请求中，提示文本最短33,404字符，中位85,601字符，90百分位163,202字符，最长189,500字符；32条请求只有一到两个修改目标。请求到响应记录间隔中位约50.7秒，最长约173秒，这包括服务响应和本地事件循环、日志延迟，不能称为纯模型计算耗时。

少量修改目标仍会携带大量封存证据。当前修补上下文保持完整证据，是安全策略，不是全部已证明可裁剪的冗余。下一步只能针对可证明完整的任务缩减上下文，并保留事实、来源与旧 SHA 核验；不能未经回放就删原文、删除背景或宣称降低90%输入不会影响正确性。原表声明只有序号，模型无需再次输出几十个坐标，现有 completeTable 路线应优先明确使用。

正常顺序仍有必须保留的依赖：主文与结构修复、标签、核心摘要、评分、Reader 最终装配与保存不能随意同时写同篇记录。模型输出成功后，还必须经过来源核验、图像装配和中央保存；保存失败不能提前把付费候选改成已解决。已经完成且同反馈全部证明、错句和来源检查均通过的论文可以跳过主动重跑，但最终整批反馈核验仍保留。

## 尚未证明已解决的部分

1. 表格模式错误、越界坐标、假引文、原文与解释不一致仍需逐篇真实修复；已增加可执行路径不等于模型已成功。
2. 超长证据是否可以按任务可靠缩减，尚无完整正文与所有引用的等价性证明，本轮未实施裁剪。
3. 局部结果后的缓存、失败保存与停止请求必须再交叉验证；不能仅看 complete 状态复用，也不能把停止中的响应计为免费。
4. 代码中标签修补最多两次，但第二次内容拒绝仍可能让整篇外层重试。当前 R16 用量窗口未发现标签模型请求，未把这个潜在路径计为本轮实测浪费；后续应以有效异常和来源边界测试后再收窄该终态。
5. 宽表、字数和正确事实检查继续保留。结构修复、格式修复及请求数减少不能替代逐篇全文内容审查。
