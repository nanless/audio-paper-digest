# Mac 论文研究应用验收矩阵

本文用于把已有需求落实为可安装 Mac 应用的检查项目，供实现者、测试者和独立审查者共同使用。本表保留正式验收条件，实际进度和证据见[最新验收记录](mac-app-validation.md)。已有真实安装、全库读取、模型、导出及备份恢复证据；尚未逐项关闭的条件继续待验，此前浏览器原型的通过记录不能替代安装包、真实模型或 Zotero 的验证。

需求依据为用户历次明确要求，以及[产品规划](desktop-research-workbench-plan.md)、[数据合同](desktop-data-contract.md)、[Mac 界面研究](macos-interface-design-research.md)和[原型验证记录](desktop-prototype-validation.md)。本轮要求至少完成 5 轮有实质修改、测试、独立审查及修复复验的循环；5 轮是最低要求，存在未解决问题时继续，不以轮数达到作为完成依据。

## 1. 交付范围和判定方式

### 1.1 必须得到什么

用户要能在自己的 Mac 安装并启动一个真正的 `.app`，直接读取已有网站成果、阅读完整图文导读、按需对照 PDF、用自己的 LLM 进一步研究，并把选择的论文及资料完整存入 Zotero。已有论文不重新筛选、评分或生成导读。日更、会议和历史生产仍由原系统负责，客户端不启动生产重写。

界面遵循 Mac 桌面操作。默认单栏；只有打开 PDF 后才进入左侧导读/解析/笔记、右侧 PDF 的双栏。所有窗口和状态都需认真设计。1440×900 是设计参考，不是唯一窗口尺寸；不因聊天预览变窄就改成手机布局。

“所有功能都能工作”指本应用范围内的完整用户流程、全部已暴露的命令和配置，以及它们需要的保存、恢复和错误处理。不能把按钮、菜单、状态切换、示例回答或待接入页面当成已完成的业务能力。

### 1.2 范围怎样保持清楚

| 范围 | 本轮要求 |
|---|---|
| 首版必需 | 本文 `M` 项全部实现并验收；它们覆盖用户已明确提出的桌面阅读、真实数据、个人研究和完整归档 |
| 已暴露的能力 | 无论实现者把它归为基本或增强功能，最终安装包中出现的可执行按钮、菜单、快捷键和设置都必须有效，有独立证据 |
| 合理降级 | 来源本就缺失、PDF 受保护、模型不支持视觉、Zotero 无权限等，允许准确说明并保留可读内容；不能把核心功能整体未接入叫作降级完成 |
| 可选增强 | 多篇研究图谱、自由画布、语义检索、自动测验、官方音频 Demo、跨设备私人同步等，未承诺实现时不进入本轮必需范围；不得在成品中伪装可用 |
| 外部分发 | 本机可安装启动为必需；如宣称可在其他 Mac 无开发环境安装、已签名、公证或自动更新，须有对应真实验证。缺分发证书不能写成已公证 |
| 非本应用职责 | 手机/Windows 版本、通用办公套件、邮件日历、重新生产全库论文等，不因“全部功能”无限扩展进本轮 |

此范围用于防止漏验和虚报完成，不能据此删掉用户已经要求的真实 LLM、完整 Zotero、全库同步或可安装应用。实质范围变化须由主任务明确记录，不能在实现后悄悄将失败项改成可选。

### 1.3 状态和证据

每项初始状态为 `待验`。之后只使用 `通过`、`失败`、`受阻`、`不适用（有具体条件）`；“测试未执行”“外部服务不可用”和“代码看起来正确”不能写成通过。发现缺口时保存原失败与复验结果，不能删除失败记录或把未知值补成零。

每个通过项记录构建/提交身份、测试日期、环境、输入、实际动作、输出与证据路径。源码审查、隔离自动化、真实服务端到端、人工截图检查、辅助功能检查分别说明；一种证据不能冒充另一种。费用账、密钥、授权头和私人正文不进入公开测试报告。

## 2. 安装、原生窗口和桌面操作

下表各项为 `M`，当前均待验。

| ID | 要求 | 通过证据与必测反例 |
|---|---|---|
| APP-01 | 提供真正的 `.app` 安装产物 | 实际复制到约定安装位置，从 Finder/Launchpad 启动；无开发服务器、终端或原仓库仍能运行 |
| APP-02 | 系统窗口与菜单 | 真正系统窗口、关闭/最小化/全屏、激活/失焦、Dock 再打开、标准应用菜单可用；不能用网页画的窗口灯和菜单替代 |
| APP-03 | 独立设置窗口 | 应用菜单与 `⌘,` 打开，切分组/关闭/重开保留合理状态，主阅读上下文不丢；拖动、缩窗、关闭期间缩窗后重开都完整可达 |
| APP-04 | 桌面尺寸和分栏 | 至少检查 1280×800、1440×900、1728×1117、1920×1080 和实际最小窗口；全屏、侧栏开关、分隔线极值不裁切主要动作 |
| APP-05 | 键盘及编辑习惯 | `⌘F` 当前文档、全库查找、`⌘,`、撤销/重做、复制/粘贴、Return、Escape、Tab/方向键有正确作用域；输入法组合期间不误发送付费请求 |
| APP-06 | 辅助功能 | 系统辅助功能树可读出窗口、按钮名、选中/禁用/进度，核心流程可只用键盘；实际检查 VoiceOver 或等价系统读出，不只检查 HTML 标签 |
| APP-07 | 系统外观和可读性 | 浅/深色、活动/非活动、高对比度、减少透明度/动态效果、放大字号；正文主要文本色，科学图和 PDF 保留原色 |
| APP-08 | 安装后生命周期 | 首次启动、退出、重启、再打开、崩溃后恢复不丢资料；显示真实版本/构建与数据位置；升级及卸载路径明确，卸载不默删私人库 |
| APP-09 | 发行声明真实 | 记录架构、最低系统、签名/公证实际状态；发行包无开发密钥、内部路径或生产配置；不能将本机 ad-hoc 启动说成公证发行 |

原生窗口与系统交互是结果要求。正文采用受限 WebKit 或成熟 PDF 组件不自动不合格，但网页内容不能拥有系统密钥、任意文件访问或任意原生调用权限。技术选型不能成为把网页原型改名为正式 Mac 应用的理由。

| DATA-03 | 论文身份和版本 | 原题/译题、作者顺序、论文/博客/更新时间、基础论文/来源版本/出现记录分开；未知 DOI、作者机构、身份保留缺口，不按标题猜合并 |
| DATA-04 | 全文与引用可用 | 从多种来源真正打开完整导读、引用导出、原站链接和对应版本 PDF；短摘要不能冒称完整 Reader，特殊 PDF 警告及非 camera-ready 提示保留 |

| DATA-06 | 新增、更正和移除 | 区分站点移除与真实撤稿，恢复记录不再被旧删除事件隐藏；网站更正、删除和缓存回收均不删除私人笔记、旧回答与 Zotero 映射 |
| DATA-07 | 默认低成本读取 | 首次同步轻目录与必要词表，正文/图/PDF 按需下载；后台检查不会自动触发论文 LLM、全库原文下载或重复所有旧任务 |
| DATA-08 | 按需完整离线包 | 一键保存正文、真实图、表、公式依赖和指定版本 PDF；检查资产后才显示完整离线，离线状态能在断网并重启后实际阅读 |
| DATA-09 | 离线缺失与损坏 | 缺图、PDF 404、指定版不可得、媒体类型或内容指纹不符时准确标记；不静默换新版 PDF 或用通用示意图顶替 |
| DATA-10 | 取消、恢复及睡眠 | 同步/下载可取消，重启只续未完成阶段；睡眠唤醒补查一次，不因错过时间段重复建任务 |
| DATA-11 | 缓存管理 | 真实显示容量、离线与临时状态；清缓存不删除私人研究、固定离线包、证据依赖版本，磁盘不足有可恢复状态 |
| DATA-12 | 出口和兼容说明 | 采用 `desktop/v1` 或明确过渡适配时记录实际合同；出口未部署不能当已用，HTML 适配失配不能靠 LLM 修补，公开数据不携带凭据/费用账 |
| DATA-13 | 每日更新读取 | 定时检查可配置，手动立即同步有效；新部署的论文实际进入本机目录，按网站日期与论文日期正确展示，不在本机重新生成日更 |

正式接入优先遵循[静态数据合同](desktop-data-contract.md)。允许经明确评审的过渡读取路线，但必须保持发布、身份、完整性和私人数据保护语义，不能把搜索索引改个合同名就声称完整协议已实现。

| LLM-08 | 用量与费用 | 实际请求开始/终态关联，真实供应商用量记录；未知金额/用量保持未知，不能把取消/失败写为零，支持所承诺预算限制 |

| ZOT-01 | 真实连接与权限 | 检查正在运行的实例/版本、本地 API/桥接、文库和读写能力；未运行、端口关闭、授权拒绝、只读目标分别提示；不能只探端口就显示完整连接 |
| ZOT-02 | 完整写入路线 | 以实际支持版本验证父条目、存储附件与笔记；若需兼容插件，安装/协议/升级/移除有明确边界；RIS/BibTeX 仅引用导入不能冒称完整归档 |
| ZOT-03 | 范围和分类预览 | 真实读取目标文库/分类，显示字段缺口、PDF 版本、导读、解析、笔记选项；记住合法选择，缺资产不能勾成已准备 |
| ZOT-04 | 标准书目字段 | 正确条目类型、原题、作者顺序、实际论文日期/DOI/arXiv/venue/语言/URL/原摘要；中文题、博客日期和 AI 总结不覆盖原始事实，未知项不造值 |
| ZOT-05 | 信息完整保存 | 当前已有且用户选择的机构/ORCID/许可/资源链接/评分/量表/标签/版本/来源等保存在适合字段、Extra 或结构化补充笔记，不因标准字段容不下而丢弃 |
| ZOT-06 | 原 PDF 为真实存储附件 | 父条目正确、指定版本真实字节、非临时文件链接；回读附件实际可打开且 SHA/内容对应，缺失/不符为部分完成 |
| ZOT-07 | 图文导读离线存档 | 自包含 HTML 或已承诺的等价可读格式，含科学图、表、公式、图注与原站修订/时间；断开 App 缓存或网络后从 Zotero 打开仍可读 |
| ZOT-08 | 解析与个人笔记 | 按用户选择保存独立可编辑笔记/附件，保留问题、模型/时间、原文版本、证据页和个人归属；原摘要不被 AI 回答替换 |
| ZOT-09 | 逐项回读完成 | 保存父/子 key 与操作身份，真实重新读取字段、附件和笔记并核对；只有全部必需项通过才完整成功，提供实际“在 Zotero 打开” |
| ZOT-10 | 去重和应答丢失 | 同篇重复点击、应用重启、重试、服务端成功但应答丢失不重复建条目/附件；DOI/arXiv及版本共同核对，不按中文标题强合并 |
| ZOT-11 | 更新与人工编辑保护 | 网站更新、个人解析新增、用户在 Zotero 改笔记/标签/字段/删附件后，先检查版本与差异，冲突保留双方；不覆盖或删除用户内容 |
| ZOT-12 | 分步失败恢复 | 父条目已成/PDF失败/笔记失败等保存真实部分状态，仅恢复失败步骤；中途取消和重启不回滚成未开始，也不重新创建成功对象 |
| ZOT-13 | 目标变化隔离 | 切文库/分类/实例、账号或旧目标无权限后重新核验；原映射不能指向错误文库，异常不误写到默认分类 |
| ZOT-14 | 本机成功与云同步区别 | 本地回读成功不能冒称 Zotero 云端文件同步完成；界面与报告明确实际范围，故障不靠 App 直接改数据库修复 |

首个真实归档测试须使用可人工检查的明确论文和独立测试分类，记录真实目标及回读结果，不展示凭据。后续清理只处理可确认属于本次测试且已授权清理的对象，不删其他文库资料。真实存档是用户本轮要求的核心工作；已有明确授权时不逐个附件再次索取批准。
