# 安卓 1.3.1：自动更新、阅读速度和稳定性修复

本次针对安卓用户反馈的四个问题修改：首次使用仍需手动同步、点进论文等待过久、阅读时退出应用，以及博客正文过大。Mac 版本保持 1.3.0；安卓源码版本为 1.3.1、构建号 9。本文记录实现边界和实际验证，正式包签名、升级、下载与公开状态以对应发行说明为准。

## 自动同步与预加载

旧实现只有周期后台任务，首次执行还要等待默认的 12 小时。新实现会在首次打开、目录尚未同步时自动获取网站目录；以后回到前台时，按最近成功同步时间和设置的同步间隔检查更新。后台任务继续由 Android 调度，执行时间可能受系统节电影响。离线模式关闭这些联网行为。

自动检查和手动同步共用去重入口。失败不会清空旧目录；自动失败采用有限冷却，避免反复请求。预加载只覆盖近期少量内容，不下载整个网站、全部 PDF 或调用付费模型。用户主动打开论文或执行资料操作时，后台同步和预加载要及时让路。

## 正文先显示，图片随后补齐

旧导读读取会等待所有图片和附加引用文件完成，页面导航才结束。新读取入口在完成真实网页的解析与来源绑定后，先保存并显示可读正文；图片和附加文件在应用拥有的任务中继续准备。切换论文时，旧结果不能覆盖新页面；取消图片准备也保留已保存文字。

提前保存的正文仍是未完成资料，不能仅因图片列表为空就把它当作完整缓存。零图片、附加文件读取中断后，再打开仍会继续正常读取。原有来源身份、引用下载页面和原文版本检查继续执行。

## 图片读取和异常恢复

公网地址检查原来在 DNS 回调中抛出普通异常。VPN 使用模拟地址或域名解析返回受保护地址时，这类异常会被网络库视为程序错误，并从异步网络线程继续抛出。现在共享联网和 Zotero WebDAV 路径都返回正常的地址解析异常，由应用显示连接失败；公网、HTTPS、重定向和凭据隔离要求保持原样。实际行为依据项目固定版本 [OkHttp 4.12.0 的 DNS 接口](https://github.com/square/okhttp/blob/parent-4.12.0/okhttp/src/main/kotlin/okhttp3/Dns.kt)和[异步请求实现](https://github.com/square/okhttp/blob/parent-4.12.0/okhttp/src/main/kotlin/okhttp3/internal/connection/RealCall.kt)核对。测试分别重现旧异常逃出独立线程，以及新实现向调用者返回失败且没有未捕获异常；测试不连接真实 VPN，也不代表已在用户的小米 15 Ultra 上完成验证。

新的在线导读不再把整组图片反复转为 Base64 大字符串放入阅读状态和持久化 HTML。阅读器为每份文档生成独立的本地地址，按需要读取保存的原图；实际字节在同一个文件句柄内核验并交给阅读器。图片地址不能用于读取其他文件，也不允许网页直接联网。

导出、打印和 Zotero 材料仍须包含可以独立打开的图片。阅读器内部临时地址不能进入这些文件；导出路径读取同一份已核验原图，按原有单图和总量上限嵌入文件，不重新下载另一修订。

阅读页、公式排版和许可阅读页分别处理渲染进程退出。阅读器清理已失效的窗口内容，保留原生操作界面和原资料，由用户明确重试，避免自动重复打开同一故障页面。Android 的回调处理要求参见[官方渲染进程退出说明](https://developer.android.com/develop/ui/views/layout/webapps/handle-termination)。这项保护不等于已经复现并排除所有手机上的系统内存不足问题。

工作台初始化改在后台读取本地目录。读取失败时显示可重试的启动界面，保留原文件；界面和后台任务等待同一份初始化结果，不能同时创建两份个人资料存储。阅读排版也按内容相等判断是否还是同一篇资料，避免仅因后台复制了相同状态就把正常更新当成未处理异常。

## 手机排版

阅读页面采用独立的手机样式：标准正文为 16 CSS 像素，缩小标题与边距，长网址可以换行，宽表格在自身区域横向滚动。用户阅读大小和系统字体大小继续生效；设置用百分比表示相对标准大小。独立导出和打印的样式保持原有文档合同。

## 验证记录

代码交叉审查后，887 个 JVM 测试与静态检查通过。后续针对取消、自动检查和启动路径的修改另经对应编译、静态检查与实际设备测试，不将第一次全量结果冒充后续实现的重跑。测试入口的 19 项设备选择检查、新增独立发行流程的 28 项检查及原发行工具的 43 项检查分别通过。

API 35 模拟器完成 41 个不同的定向用例：阅读、导出、打印、原图与许可相关的 27 项，真实控制器的正文先返回、快速取消、旧图撤销、原汇总返回、首次自动同步、并发去重、离线与失败保留相关的 6 项，启动界面与坏目录重试 2 项，既有导航 2 项，以及 PDF 原生组件 4 项。读取和联网夹具使用明确的合成响应，不使用模型或真实账号；原始失败和修正后结果分别保留。

PDF 的一个实际 13 页读取、翻页、搜索、选区和关闭用例在手机窄窗口通过；另外三个既有定位用例在窄窗失败，因为一屏可见多页，而断言要求目标页是第一可见页。这三个用例在其宽窗口条件下通过，PDF 的 13 个生产文件、5 个调试夹具和原测试文件与 1.3.0 逐字相同。本次没有放宽它们的断言或把宽窗结果记成手机窄窗通过。

手机排版另读取实际页面样式并等待原生绘制完成后检查截图：标准字体为 16px，系统缩放输入 200% 时为 32px；表格可横向滚动，长网址可换行。这是同一阅读组件的实际测试，不是小米手机的截图，也不是 Android 全局字号设置认证。

测试中发现构建工具默认会在设备用例结束后卸载测试应用，旧 API 35 验收设备上的测试资料因此被移除。入口现强制保留应用，不接受自动卸载选项；之后的用例使用明确的自有隔离设备，不操作实体手机。此记录不能被写成旧验收资料始终未变。

独立安卓发行使用 `android-private-draft-plan`、`android-public-plan` 和 `verify-android-downloaded`：固定注释标签及源码，只上传六件安卓附件，先建立私有草稿，再按固定附件 ID 下载并正常重验签名、内容和来源，最后仅为同一草稿生成公开命令。公开前仍要求原 86 项验收 ID 完整通过；未变化功能保留原有证据范围。Mac 和联合发行的既有流程不变，不能借此次修复虚构 Mac 新版本或重签旧凭证。

这些检查尚不代表已在用户出现问题的小米 15 Ultra 上复现并排除原始闪退，也不声明所有设备已经通过验证。覆盖升级和空白首启须使用与公开附件相同的正式签名 APK 独立核对，不能用调试包测试替代。
