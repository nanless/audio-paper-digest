# 三条流程的公共模块与适配规则

日更、官方会议与历史更新使用同一分析、修复和展示实现。来源、任务范围、已付费状态、保存事务与发布凭证由各自适配器核验。入门见[三流程说明](three-workflows.md)，命令定位见[脚本索引](../scripts/README.md)。

## 实际调用关系

| 流程 | 输入与范围 | 公共处理 | 保留的独立记录 |
|---|---|---|---|
| 日更 | 完整来源窗口、已发布去重、本批官方四文件 | `analysis-engine`、`deep-analyzer`、Reader、评分、标签与展示 | 日期、完整成员、来源、生成、审查和发布 |
| 会议 | 官方目录、真实会议 ID、官方 PDF 及认证摘要 | 同一引擎和提示词，PDF 来源适配进入公共提取 | process、父子执行、来源能力、单篇和完整汇总、发布 |
| 历史 | 冻结页面与 URL、同篇去重、本次真实来源 | 同一引擎和 Reader，arXiv/会议分别适配 | 原页面、完整覆盖、博客基线、生成、审查及发布事务 |

历史任务按冻结范围更新，不增加一次重新筛选。来源适配提供本流程真实输入，不互换日更、会议或历史凭证。

## 公共职责与对应实现

| 职责 | 主要实现 |
|---|---|
| 分析、论文锁、保存与恢复 | `analysis-engine.js`、`deep-analyzer.js` |
| 批次失败轮 | `lib/analysis-failure-rounds.js` |
| Reader 与局部修复 | `lib/reader-contract.js`、`reader-repair.js`、`reader-draft-order.js` |
| 筛选解析、模板选择与填充 | `lib/filter-decision.js`、`lib/filter-prompt.js`、`lib/prompt-text-versions.js` |
| PDF 纯提取 | `lib/reader-pdf-extraction-scope.js` 与认证来源适配 |
| 错误类型与运行范围 | `lib/workflow-error-policy.js` |
| 页面和引用展示 | `paper_reader_presentation.py`、`tag_presentation.py`、研究引用导出 |
| 内容与图片审查 | `publish_common.py`、各流程发布器 |

查找模块时以[脚本索引](../scripts/README.md)及实际调用为准。新模块同时纳入真实依赖指纹；相同职责修改公共实现，来源、冻结集合、事务和原预算留在适配器。

## 相同输入的纯计算复用

认证 PDF 的 `withVerifiedSource` 在真实来源范围内进入公共提取作用域，quote worker 使用同一执行器。复用项是完整输入相同的纯 worker 输出；来源前后 `assertUnchanged`、表范围、行列、单位和原 PDF 核验每次照常执行。

- 日更保留原最小环境，认证 PDF 保留原继承环境。
- 输入、程序、固定依赖、解释器及运行环境参与身份核对。未知 Python、链接器或启动钩子覆盖，以及 `PD_PYTHON_RUNTIME_DISABLE_VENV=1`，禁用复用后仍正常提取。
- 异常和坏 JSON 不缓存，作用域上限为 32 MiB/128 项，结束后清空，调用方取得独立副本。
- 来源资格、单元格资格、最终通过状态和模型额度不缓存。

单篇和汇总调用公共展示解析器，详细摘要继续重放其原来源及付费阶段。作者、资源、评分、多级标签与引用导出共用格式；原 plan、作者/资源对象、会议预印本过滤、版本披露和返回链接由适配器逐项核验。显示结果不修改原分析和来源记录。

八维字段、中文名与上限由 `paper_reader_presentation.SCORE_DIMENSIONS` 定义，数值、类型与资格按原流程核验。相邻重复标题清理保留代码、引文、链接、图片和来源图注；数值、TeX 及单元格的显示转换仍走专用来源规则。引用附件统一 LF、非空、大小、公开 URL 和 SHA，真实身份和上下文分别核验。

## 失败、审查与旧记录

错误投影保留 code、retryable、category、status 和 scope，真实运行级故障停止新派发。科学内容中的“协议”“超时”或“不可用资源”按实际问题判断；模型回答不能自报为程序保留的基础设施错误。

通过页按“路径 + 内容 SHA”永久复用。内容拒稿只有输入变化，或旧、新协议均为合法 SHA 且确实不同时，才进入原正常审查；损坏的失败证据停止执行。原失败、响应、尝试与费用保留，阻断时不新增请求或 attempt。

文本单块审查共用 `publish_common.interpret_readonly_text_unit`，核对返回结构、失败原因和建议稿。建议修改属于内容问题，交回生成阶段，不原地改最终文件或写通过缓存；日更整页字节守卫及各流程凭证继续核验。

历史外层和分块审查指纹均覆盖实际可达的 JS/Python 依赖，使用完整相对路径区分同名文件。旧 receipt 按原 schema、完整自校验和原链接只读验证；新激活与发布核当前实现，不给旧签名补字段或加入任意 SHA 白名单。归档模板按声明版本和原字节读取，只读版本不签发新请求。

## 文件桥与 Git 预算

会议和历史页面使用 `lib/python-json-packet-bridge.js` 传递输入：系统临时目录、独占 `0600` 文件、项目 Python、输入/输出上限、期限及清理。桥负责字节传输，来源、结构、页面资产和发布资格由调用方核验。

| 操作 | 预算与规则 |
|---|---|
| 普通读取或单文件 Git 输出 | 128 MiB |
| 完整站点归档 | 独立 1 GiB；`PD_GIT_ARCHIVE_TIMEOUT_SECONDS` 默认 180 秒、允许 10–900 秒 |
| Node 本地 Git 命令 | 默认 30 秒 |
| Node 提交与网络 Git 命令 | 默认 180 秒 |

Git 执行器保留工作目录、受限环境、返回类型、严格解码及二进制原字节；不缓存 Git 返回值。启动异常、信号、期限、截断或无有效状态均拒绝，原推送只调用一次。远端身份、精确差异、父提交和 OID 由原发布事务核验。

Node 同步期限针对直接子进程；Git/SSH 后代清理由对应执行方式处理。Python 通过临时文件收集后有界读取，磁盘写入容量另行管理。归档路径、链接和递归 gitlink 的限制保持。

## 修改后的验证

按影响范围检查真实三路调用、旧 parser/prompt 字节、认证 PDF 与假句柄、来源漂移、作用域结束、运行级停止、旧审查只读、依赖变化、拒稿零新请求和通过缓存复用。实现身份相关的回归在相关文件停写后执行。

稳定版本完成[工程验证](maintenance.md#验证矩阵)，生产数据走原只读验证。论文生成质量、实际费用和上线结果分别按正常生产任务验收，不由模块测试代替。
