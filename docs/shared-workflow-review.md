# 日更、会议、历史：公共部件审计与收敛

审计日期：2026-10-17。基线为 `4eb2c5c8`。目标是让同一项分析、修复、展示和效率改进通过真实公共调用传播到三条生产流程；来源、任务范围、已付费状态和发布凭证仍由原适配器负责。本轮只改实现和测试，不重新抓取、写作或发布论文，不增加模型次数或费用。

## 实际调用链

| 流程 | 输入与范围 | 公共内容链 | 输出与资格边界 |
|---|---|---|---|
| 日更 | 按来源窗口补抓、已发布去重、关键词及 LLM 筛选；本批官方 HTML/PDF 四文件封存 | `analysis-engine` → `deep-analyzer` → 当前主文、摘要、评分、标签、Reader 与修复；公共 PDF 提取及来源检查 | 日更完整论文集合、逐篇页面和汇总、generation/review/publication 凭证、视觉处置 |
| 会议 | 官方完整目录、真实会议 ID、官方 PDF、认证摘要证据；按本会规则筛选 | 同一引擎及 Prompt；真实会议来源能力适配 Reader；认证 PDF 表格接公共提取执行器 | process/父子 execution、官方记录/PDF 链接、原图与公式能力、会议单篇及完整汇总、独立发布凭证 |

历史重写的目标集合已被冻结，没有另一个“重新筛掉历史页面”的生产阶段。公共筛选可以供有筛选职责的日更和会议调用；向历史强加一次筛选会改变覆盖范围，不能以统一为由增加它。

## 本轮发现并实际收敛的缺口

### 1. 筛选公共库不再反向依赖日更抓取入口

原会议为复用决定解析器，加载整份 `fetch-papers.js`。解析语义虽相同，库却依赖带环境、日志及抓取职责的日更入口，后续容易分叉或产生额外初始化。

现在 `lib/filter-decision.js` 唯一定义决定解析、理由提取和 v3 版本；日更旧 export 保留同一函数别名，会议直接调用公共库。`lib/filter-prompt.js` 共用模板填充，各适配器显式传原捕获路径及已准备的来源字段。当前及旧版 Prompt 的请求字节、会议 policy/config SHA 和原决定版本保持；不扩大格式修复请求或把不确定回答签成正式相关。

### 2. 认证 PDF 真正使用同一提取执行及复用能力

原日更 Reader 对两个纯 PDF 提取器已有短作用域 stdout 复用，会议/历史的认证 PDF 表格却直接启动相同 Python worker，享受不到该改进。

现在认证 PDF 的 `withVerifiedSource` 在原真实来源能力内进入公共提取作用域，quote worker 通过 `reader-pdf-extraction-scope` 执行。原 opaque handle、来源前后 `assertUnchanged`、表范围/行列/单位核验均继续运行。日更仍传原最小环境；认证 PDF 仍保留原继承环境。未知 Python/链接器/启动钩子覆盖和 `PD_PYTHON_RUNTIME_DISABLE_VENV=1` 仅禁用复用，正常提取照旧；不会把外部解释器错当成已指纹的项目 venv。

复用的是相同完整输入的纯 worker 输出，不是来源、单元格资格、通过状态或模型额度；作用域结束后重新提取。

### 3. 单篇博客的读者决策展示只有一个实现

原日更 `_build_api_reader_display_fields` 与会议/历史的 `build_reader_presentation` 分别计算摘要、资源和评分说明；日更的显示修正不能传给其他路径。

现在三者调用 `paper_reader_presentation.resolve_reader_decision_display`。详细摘要继续真实重放来源及原付费阶段，资源及评分使用同一显示函数；仅显示层的重复术语修正也自然传播。实际日更独立页、会议 `render_packet`、历史 `render_packet` 有调用级回归证明，公共返回变化会传到三路。

各入口的 `_api_reader_payload`、原 plan/作者/资源对象比对、来源重放、会议预印本 URL 过滤继续保留。会议及历史显式传已加载的 publisher，避免重复 loader；来源提示、页头身份、图表能力、分类、外框和返回链接仍由各适配器组合。原已发布页面及凭证不因代码改变而改写。

### 4. 会议和历史使用公共错误策略

历史恢复原先反向调用会议恢复模块，重建失败时只传 code/retryable，丢失正式分析保存的 category/status/scope，运行级故障可能退成逐篇失败。

`lib/workflow-error-policy.js` 现在承载原失败分类、嵌套存储错误检测及完整正式错误字段投影。会议旧 export 兼容同一函数；历史直接调用公共库并保留运行级范围。原两个分类函数逐字迁移，原冷却、重试上限、保存、会议状态及历史队列不迁入公共层。日更已经完整保留这些字段，不修改它的正常模型路由。

### 5. 三路共用内容拒稿的重试门槛

原日更会阻止“同一路径、相同输入、相同或未知协议”的内容拒稿再次付费；会议仅读通过缓存，历史失败 attempt 仅用于下个编号，都能对未改内容再次请求。

现在三路共用 `publish_common.unchanged_content_rejection_blocks_retry` 和失败分类。通过结果仍按路径与内容 SHA 复用；内容拒稿只有输入改变，或原/当前协议均为合法 SHA 且确实不同，才能继续进入原正常检查。该公共函数只阻断，不授予请求或发布许可。

会议每批一次读取并自校验原不可变失败记录，先核当前页面及已通过分块，再决定是否派发；历史读取并核验原 attempt，阻断时不新增请求、不增加 attempt、不删除旧失败。基础设施故障仍按正常机制恢复；损坏失败证据停止。原失败记录、响应和费用保留。

独立 review 还发现原日更分类器将“实验协议”“推理超时”“不可用资源”等科学问题误判成临时故障。本轮在公共层收紧为明确基础设施类型或受控旧诊断外壳；模型输出归一化时不能冒充程序保留的基础设施/协议类型或缺省诊断外壳，原响应仍保存在请求审计中。保留真实图片下载截止和旧 `LLM 文本 review` 协议错误恢复，混合内容/服务错误仍按内容拒稿阻断。

### 6. 历史审查的外层与分块协议都覆盖公共依赖

原历史外层指纹维护短文件清单，遗漏公共发布模块等叶依赖；只修外层还不够，因为历史分块失败比较的是内部 semantic 协议。

两层现在均使用 `workflow-implementation-files.collectWorkflowImplementationFiles`：新指纹覆盖实际可达的公共 JS/Python worker，用完整仓库相对路径消除同名文件冲突。单独变更 `publish_common.py` 时，外层、semantic implementation 和 semantic protocol 均变化；Prompt SHA 保持原职责。

原已签 receipt 的 `loadReview` 不改写、不补签：仍按原 schema、完整自校验和原链接只读验证，新的激活/发布才按当前实现检查。非法旧签名仍拒绝，不能添加任意旧 SHA 白名单。

### 7. Git 执行共用有界内核，发布事务不混用

会议 `git` 与 `blob_sha` 原先各自无期限地收集输出，现在都调用日更既有的有界子进程执行器。适配器显式传入原工作目录和受限环境，保留 `CompletedProcess`、严格文本解码、换行归一与二进制原字节；只缓存执行器模块，不缓存 Git 返回值，不修改发布器全局仓库。

普通读取/单文件仍限制 128 MiB。完整站点归档单独限制 1 GiB，`PD_GIT_ARCHIVE_TIMEOUT_SECONDS` 默认 180 秒、允许 10–900 秒。实物树的文件总量约 724 MB，不能套单文件预算；只读规模审查发现这一回归后，使用真实本地 Git 验证 134,217,729 字节文件（压缩对象约 586 KB）能够完整导出为 134,225,920 字节 tar，原文件与唯一成员 SHA 相同。原归档路径、链接及递归 gitlink 守卫不改，也没有对生产站点构建归档。

历史发布与公共文件模块原来各自包装 `spawnSync`，现共用 `lib/publication-git-process.js`。本地命令默认 30 秒，提交和网络命令默认 180 秒，保留原环境差别和返回类型。启动异常、信号、期限、截断或无有效状态都必须拒绝，即使调用方允许普通非零退出；原推送仍只调用一次。远端身份、精确差异、父提交与 OID 核验继续由原事务负责。

边界：Node 同步调用的期限针对直接子进程，不能承诺 Git/SSH 全部后代的硬截止；Python 复用的执行器通过临时文件收集后有界读取，并非实时磁盘写入容量限制。本轮不以通用框架名义重写这两个不同运行时。

### 8. 声明过的筛选模板只有一个解析入口

会议的新请求生成与旧请求重放原来各维护当前、v1–v4 及归档模板选择。现在 `resolveDeclaredDailyFilterPrompt` 共用版本选择和真实模板 SHA 检查；生成与匹配继续保留各自的拒绝/不匹配结果。仅供归档核验的模板仍不能签发新请求，旧输入字段、单次替换和请求字节不改变。

### 9. 单篇页面的私有 Python 文件传输共用一层

会议 `conference-postprocess.render` 与历史 `paper-page-staging.defaultRender` 共用 `lib/python-json-packet-bridge.js`：系统临时目录、独占创建的 `0600` 输入文件、项目 Python 运行时、输入/输出上限、期限和清理。会议保留严格 JSON 解析，历史保留自己的 Markdown/资源结构检查；不同的参数名、packet 身份、清理策略及最终内容门槛留在适配器。桥只传输字节，不认证来源，也不能签发成功或发布许可。

### 10. 文本审查的只读结果解释统一

日更和历史原先丢弃单块返回的建议稿字段，会议则会拒绝建议稿与输入不同。日更另有整页修正建议和最终字节守卫，历史缺少对应的单块判断。

公共 `publish_common.interpret_readonly_text_unit` 统一核验三元返回结构、明确未通过却无阻断原因、以及建议稿改动。三入口在写入成功缓存前解释原结果；建议改动作为内容问题返回生成阶段，不写回页面。各流程的原检查点、拒稿门槛、并发和审查凭证保留；日更仍执行最终整页误报过滤、修正建议计算和字节不变检查。

### 11. 评分规格、连续重复标题和引用附件的机械规则收敛

- 八维字段、中文名称和满分只在 `paper_reader_presentation.SCORE_DIMENSIONS` 定义一次。日更/历史的原显示格式、会议的完整性/范围检查及一位小数格式保留；规格共享不代替评分资格。
- 三路 Reader 正文共用完全相同的连续重复加粗标题投影。代码、引用、链接、图片及来源图注保留原文；只收敛显示规则，不改保存的 Reader 或图表绑定。数值、TeX 与来源单元格的专用投影继续留在原严格核验路径，不能据此推定其他来源也获得了新的数值转换许可。
- 日更/arXiv 与会议研究引用导出的附件，统一 LF、非空、大小、公开 URL 和 SHA 记录组装。真实身份、公开摘要可得性、上下文协议和来源认证分别保留；历史 Node 的独立冷核仍逐字核对，不因共享生产函数而删除。
