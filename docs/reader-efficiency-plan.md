## 当时保留的运行约束

改进保留正式分析数据的 13 个解析标题，以及 Reader 的 12–18 节、5000–18000 中文字、4–10 组术语组合解释要求。全文来源、数字和单位、公式、图片像素、作者机构及资源身份仍须核验，不能为节省调用放宽事实条件。

论文锁、原子写入、结果修订序号 `generation`、只读审查、精确 Git 变更范围和远端 OID 核验也保持不变。工程实验不恢复本机助手，不运行整批日更，不自动重写或发布已有博客。项目脚本和测试仍须在沙箱外执行，不能绕过环境守卫。

## 工程分工与实施计划

| 工作包 | 当时负责者 | 交付内容 | 必须检查的行为 |
| --- | --- | --- | --- |
| A. Reader 局部修复与恢复 | Reader 代理 | 受限正文补丁、输入 SHA 校验、失败候选保存、无进展检测和相关证据上下文 | 一次定位多个错误；未改节点不变；拒绝越权或陈旧补丁；恢复失败不能记为成功 |
| B. 发布前置检查与缓存 | 发布代理 | 在 LLM 前完成确定性与 Hugo 检查，按逐文件内容 SHA 保存通过记录，保存结构化失败原因 | 已知格式错误不调用 LLM；模型、提示词、代码或 Hugo 变化仍复用未变页的通过记录；字节与事务检查通过 |
| C. 统一验证与 CI | 验证代理 | 完整验证入口、固定 Hugo、必须运行的集成检查、离线重放与验证范围说明 | JS、默认及 Manual Python、语法、数据和 Hugo 均检查；关键集成不能静默跳过 |
| D. 用量与成本归因 | 主代理 | 每次请求的实报 `usage` 或不可得状态、论文与阶段信息、用量汇总命令 | 支持 Responses、Chat、Anthropic 用量；记录失败；不记录正文或密钥；估算与实报分开 |
| E. Reader 要求与确定性表格 | 集成阶段 | 共享结构检查、选择原表后由代码渲染、按实际章节检查文风、精简写作要求 | 提示词与代码一致；表格位置及数字关联正确；检查跨节近重复；保留旧协议兼容 |
| F. 独立核查与交付 | 主代理和独立复核者 | 基线重放、故障注入、完整回归、一篇受控真实试写及结果报告 | 失败须定位修复并复验；没有实测不能宣布节省比例 |

分工按文件及函数区段划定，公共配置和包命令由主代理协调，并行编辑不能覆盖其他人的变更。

计划先保存工作树和已有成功文件的 SHA，避免向正式分析结果或线上页写入实验稿。A/B/C 并行、主代理完成 D，各自先建立故障用例并回归，再集成 A/D/E。原表只由模型选择来源行列，表格与绑定由代码生成；补丁合并后仍完整解析、核对来源和文风。

通用写作要求与论文特有反馈分别处理，章节近重复按实际 Reader 章节检查。确定性检查在付费审查前完成；逐页通过记录只绑定相对路径与内容 SHA，当前协议和批次元数据写入新的 `receipt`，不能据此让未变文件重新付费审查。

离线重放至少覆盖多个错误、数字或单位错误、图片标记错位、坏 JSON、陈旧补丁、候选损坏、恢复、无进展、协议变化、Hugo 失败及真实跨节重复。修复后先复验受影响套件，再完整验证。真实试写先限定为一篇已归档同源论文，明确请求与输出预算，使用公共请求路由；失败保留记录，不无限追加请求或覆盖已发布结果。最后独立核查实际用量、修复范围、内容质量及未解决的问题。

## 验收指标与未证明的目标

确定性格式错误应产生 0 次 LLM 调用，本地排版和表格组装不能改变来源事实。补丁只改白名单节点，其他节点 SHA 不变，合并后全部检查通过才算成功。同输入可恢复失败候选，来源、模型、提示词或协议变化时须拒绝错误复用。

逐页通过记录的复用条件是“相对路径 + 页面内容 SHA”。审查要求、模型、提示词、发布器代码、`generation manifest` 或 Hugo 变化不能单独让未变文件重审；当前批次检查与新凭证仍要完成。服务未返回用量时记录不可得，不把字符估算写成计费量，失败请求也纳入记录。

内容验收检查学习顺序、执行过程、实验条件、指标方向和适用范围；字数或节数达标不能证明质量。固定评测集的目标为累计 Token 降低 30%、首次程序检查通过率 85%、局部修复次数的第 95 百分位（p95）不超过两轮。下文的单篇试写、字符减少和缓存复用都不能证明这些总体目标。

当时没有计划废除 13 标题、降低篇幅或章节要求、替换模型、取消事实审查，也没有模糊或跨文件复用通过记录。正式分析数据的全量结构迁移、评分分歧裁决和大规模模型 A/B 当时另列工作。

### 首次暂停与诊断恢复修正

首次运行在 Reader 连续失败后主动停止，保留 30/30 原文、已完成分析与评分检查点，以及内容尝试预算。暂停时尚无完整成功论文，没有替换正式结果或发布。中断请求可能缺完整 `usage` 回执，记录不是完整账单。

暂停后修正了正文按 `section kind` 排序而表格绑定未同步的问题。规范器同步正文、绑定及 `selection marker`，保存原始和规范索引及双 SHA，歧义则拒绝。原始 TeX 颜色命令粘连数字也影响证据识别；Node/Python 修复后，交叉测试又发现命令外负号可能丢失，因此加入保守拒绝和负值回归，原文、引文与单位要求不变。

单位分列、千分位或精度变化、引文换行差异，需要修正文或引用本身，不能只追加含同值数字的引文。诊断开始给出真实正文路径、原表上下文和逐字原句，候选数字仍不能作为事实证明。

显式 `--refresh-reader-diagnostics` 只迁移同 run、同来源/模型/主提示词/预算的失败候选，不清零内容或完整生成次数，保留旧无进展状态审计。迁移后免费重跑完整解析器，付费请求仍受原限额约束。三个子代理为全部 30 篇完成原文事实核查清单，后续新稿须逐篇对照。

交叉审查注入归档 I/O 故障，复现并修正 save-new/rename-old 中断后的重入缺口。归档绑定完整旧 payload/envelope SHA，检查删改、symlink 和路径越界；真实失败候选均通过只读规范化重放，测试时未迁移生产候选。统一回归日志 `/private/tmp/fresh-diagnostics-verify-final.log` 记录 Hugo、JS/Python/Manual、全仓语法与严格只读数据检查通过，之后才显式恢复原 run。

### 20 篇通过程序检查、10 篇失败及文体修正故障

首轮恢复结束时，30 篇都有本轮分析，20 篇 Reader 通过程序检查，10 篇仍失败，尚未替换正式结果或发布。事实及原图复核仍发现指标方向、样本归属和未测因果错误，保存新稿 SHA 后再修订。

新 `patch` 阶段只允许修改同 run 活动失败候选的已有节点，完整生产解析器通过后才可作为失败恢复输入；预算不变，原字节和补丁可恢复归档。`analyze --ids` 只复验已修论文，最终状态仍按全批统计，不动未选论文或其预算。
