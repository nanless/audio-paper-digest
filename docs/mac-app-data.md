# 论文速递工作台 Mac 版：数据与恢复

客户端读取论文速递公开网站的目录、正文与引用资料。日更、会议和历史文章进入同一资料库，原评分、分类、来源和版本保持不变。数据读取由 [LibraryService](../apps/macos/Sources/LibraryService.swift) 实现；规划中的 [独立论文详情出口](desktop-data-contract.md)尚未部署。

## 网站资料与个人研究

当前源码先从站点前缀下的 `client/index.json` 读取目录入口，再取得相对于该入口的搜索分片。只有新入口明确返回 HTTP 404 或 410，才读取原来的 `index.json`。格式损坏、未知结构指纹、服务器错误和普通网络故障均不能改读旧入口。已发行的旧客户端继续使用原入口；1.4.3 已包含这组兼容读取。

分片就是将大目录拆成的若干小文件。应用核对每份文件的字节、大小、条数和 SHA 内容指纹，全部成功后才替换本机目录快照。快照表示某个时点的一份完整目录。取消或失败时，上一份完整目录继续可用，不把已经下载的一部分当作全站结果。新同步保存的本机目录也带结构指纹；已有目录按它实际保存的格式读取。未知或混用格式不能当成空目录重新保存。

分类资料也成对读取：优先使用 `client/data/tag-catalog-snapshot.json` 和 `client/data/tag-catalog-versions.json`，只有两份新地址都返回 404 时才读取原来的 `data/` 地址。新旧地址各自只接受该地址登记的格式；在错误地址收到另一种已知格式，也不会把它当成可用结果。新旧格式声明集中登记在 [`config/protocols/clients.json`](../config/protocols/clients.json)。当前格式使用稳定名称和 `schemaFingerprint`，后者是完整结构声明的内容指纹；旧格式按照原声明读取，不能因名称相同就替换成当前结构。

论文页给新客户端单独声明四份 `client/papers/` 附属文件及其 SHA：引用 JSON、BibTeX、RIS 和研究上下文。读取时核对同一页面、论文身份、日期、文件目录和实际响应字节。网页可见下载链接仍指向构建时生成的原 `data/papers/` 兼容地址，供已发行客户端使用。兼容文件不是新的科学来源证明；生成、审查和发布资格仍由原正常流程核验。

同一篇论文可能在多个日更或会议页面出现。应用依据明确的论文身份将这些出现记录关联起来，标题相似不作为合并依据；这样既保留各次导读，又避免把私人笔记误归给另一篇论文。

正文、图片、引用文件与 PDF 按需读取。目录移除的论文仍保留旧元数据及已有研究，并显示移除提示；目录缺失不直接判为论文撤稿。作者、机构、DOI 和论文日期以来源为准，缺项保持未知。

| 资料 | 保存范围 |
|---|---|
| 网站缓存 | `PublishedLibrary/` 下的目录、正文修订、图片、指定版本 PDF 与引用记录；Android 的 `PublishedLibrary/offline-index.json` 是启动用派生索引，可重建，不作为发布或阅读资格的权威 |
| 个人存储 | 笔记、标注、收藏、待读、阅读状态、任务及模型会话 |
| 模型材料 | `ModelUsage/` 下的实际输入、响应、来源、用量和恢复记录 |
| Zotero 记录 | 目标身份、选定材料、逐步结果与续传检查点 |
| 凭据 | 本应用自己的钥匙串；网盘密码也可仅本次保存在内存 |

个人资料根为 `~/Library/Application Support/PaperDigest/`，与生产仓库分开。网站同步不覆盖个人研究；客户端不读取生产 `.env`、账号池或运行账本。

现有共享目录的个人资料继续沿用原格式，更新后的客户端编辑时不改换格式。新建独立目录使用带结构指纹的稳定格式；旧版客户端不能把这种新格式当作空库打开。目录格式不替代备份的逐文件完整性核验。详见[收藏资料格式与两端兼容](favorite-collections.md#两端共用的个人资料)。

日更和会议汇总单独保存目录、原网页、可显示正文及图片。应用重新打开保存记录时，先按实际清单和分片核对目录，再以本机解析器重建正文。带图片的记录继续绑定原网页、每张图的位置、说明和实际字节；从另一平台恢复时也会以本机解析器重建，不直接把对方的派生正文当成本机结果。新记录使用稳定名称和结构指纹，旧记录仍从原目录核对，不改写旧清单或图片。保存了正文或部分图片不表示整页已经完整离线，也不提供单篇论文的研究或模型请求资格。

## 正文与 PDF 版本

正文仅提取已发布文章区域，清除脚本、表单、危险链接和外部实体，保留科学图、表、公式及原出处。引用导出读取实际发布的 BibTeX、RIS 或 JSON 原字节，缺失或身份错误会提示，不在本机拼造一份已发布引用。

正文和没有固定版本的 PDF 会按目录验证周期与六小时时限重新核对；主动刷新可以立即重试。读取失败时，已有副本仍可阅读，但界面保留原核对时间并说明可能陈旧。自动重试至少退避五分钟，避免在同一故障下连续请求。明确的 arXiv 版本固定保存，版本不符时停止下载。

PDF 保存实际字节 SHA、来源、版本和物理页数。原链接更新后，新旧 PDF 分开保存；旧回答、摘录和标注仍绑定原 SHA，不自动迁到新文件。扫描页能显示原件，但没有 OCR 或可提取文字时不能作为文字解析材料。

外部下载只接受规定的官方 HTTPS 来源，检查每次重定向与连接地址。arXiv 下载需要应用设置中的 HTTP CONNECT 代理。单张图片上限 16 MiB、单篇最多 32 张且累计 64 MiB；PDF 上限 100 MiB。取消一个任务只清理该任务未完成的传输，保留已有资料。

## 搜索与离线

资料库搜索覆盖标题、作者、编号、标签、已读导读和个人笔记。PDF 原文在阅读器内查找，不参与资料库全文搜索。

完整离线包保存指定版本的图文导读、科学图片、公式所需资源和原始 PDF。缺图或缺 PDF 时显示缺项。缓存管理先展示容量、引用关系和清理预览；私人研究、固定离线包及研究依赖版本受保护。

“打开过网页”和“完整离线”是两种状态：前者可能只有正文缓存，后者还要求同一版本的必要图片与原件齐全。准备在无网络环境阅读时，应查看完整离线状态，而不是仅看页面能否在当前窗口显示。

正式 `release` 包首次启动为空目录，不捆绑论文样稿。开发者可使用 `private-qa` 通道准备带 MiCLA 原件的测试包；该通道仅用于本机测试，不能用于正式发行。

## 模型记录与恢复

模型请求前，应用先保存不含 API 密钥的完整输入和待处理会话。服务返回后，无论成功还是失败，都先保存原始响应，再保存个人会话。重启恢复时从这些原文件重新核对来源、输入字节和本机响应校验；通过后可以恢复已有结果，不再请求一次模型。失败或中断仍保留实际状态与费用未知标记。

**响应校验密钥仅属于本机，不随备份迁移。** `ModelUsage/response-integrity.key` 和 `ModelUsage/response-integrity.android.key` 及其大小写别名在备份读取内容前排除。其他输入、响应、用量和恢复记录照常保存。迁移来的响应若不能通过目的端校验，不会被重新签成成功；原始研究材料仍保留。

## 备份与恢复

当前源码新建的本地和云端备份采用稳定合同 `paperdigest-backup` 与结构指纹；已有 `paperdigest-backup-v2` 备份仍按原格式读取。大小限制相同：最多 512 MiB 原文件、750 MiB 编码、100000 项，包含隐藏的普通研究文件，排除上述本机校验密钥及目录外资料。系统钥匙串不进入备份。

这是应用规定的资料包格式，不是普通 ZIP。原文件总量与编码后大小分别限制，因为原文件变成备份 JSON 后所占空间会增加。恢复会把研究空间退回到选定快照时点，不会自动合并两个时点的笔记；恢复前副本用于保留当前资料。

1. 下载或选择完整备份，先核对合同、路径、大小与全部原始 SHA。
2. 在原生窗口确认；取消时保留当前资料。
3. 保留恢复前副本，再完成暂存验证与替换，初始化失败时回滚。
4. 保留本机模型、协议、端点、网络和预算配置；已派发请求身份与时间合并保留，不因恢复旧版本清零次数。

旧备份仍先验证全部原字节，包括其中历史校验密钥条目的 SHA；恢复时不导入这些密钥，并保留目的端原本机密钥。含本机密钥的旧快照禁止继续上传或重新导出，原文件与检查点留在本机，可先保留旧快照再新建合规备份。来源、响应、费用和归档历史不为路径迁移改写；目录变化通过单独受限路径映射处理。

研究资料恢复到所选快照时点，之后的笔记、回答和原始费用可从恢复前副本找回。Zotero 原目标与授权继续核对，旧归档记录不取得新授权。云端操作见[坚果云保存与恢复](mac-app-cloud.md)。

## 开发接口与依据

下列接口供应用界面向本机服务请求操作，不是网页可以任意调用的公共网络 API：`library.status`、`library.sync`、`library.list`、`library.search`、`library.article`、`library.citationFile`、`library.downloadPDF`、`library.paperDetail`、`library.tagIndex`、`library.retryLoad`、`library.network` 与 `library.cancel`。读取论文、来源与版本时使用明确身份；进度返回实际阶段、完成数与总量。

`library.list` 默认返回完整行；传入 `compact: true` 时省略逐篇完整引用和官网分类记录，只保留浏览所需字段。省略的两部分由 `library.tagIndex` 按目录快照提供，`library.paperDetail` 按论文 id 返回完整行。分类证据按目录 `snapshotID` 与网页词表内容身份（`snapshotContentSHA256`、`versionsContentSHA256`）复用，个人资料变化不会重新发送；`library.paperDetail` 只按 id 取当前或已移除论文的完整行。

启动只在主线程同步解码 8 MiB 以内的小目录；超过 8 MiB 的 `current.json` 与全文索引都在后台任务中载入。就绪前 `library.status` 返回 `loading` 且不带 `snapshotID`，读取命令等待就绪，不会把尚未载入当成空目录。载入失败后由命令级 `library.retryLoad` 显式重试，其他命令不会因失败反复全量读取。备份恢复在暂存完成和替换完成后都等待目录就绪，替换失败时回滚到原目录。

实现依据：[BackupCodec](../apps/macos/Sources/BackupCodec.swift)、[RestoreLocalPolicy](../apps/macos/Sources/RestoreLocalPolicy.swift)、[ModelService](../apps/macos/Sources/ModelService.swift)。当前测试与实际操作范围见[验证说明](mac-app-validation.md)。
