# 论文速递工作台 Mac 版：Zotero 归档

工作台通过官方本地 API，将一篇论文和所选材料存入正在运行的 Zotero Desktop。当前支持本机个人文库；Android 使用独立的 Web API 配置，双方不共享本机许可。

## 使用顺序

1. 启动支持本地写入 API 的 Zotero Desktop 并开启本地 API，在工作台设置中点击“检查本机连接”。已实际使用的版本为 Zotero 10.0.6。
2. 打开论文，选择“归档当前论文”或“存入 Zotero”，核对目标分类，以及 PDF、图文导读、个人解析和笔记。
3. 需要写入时，在 Zotero 原生窗口决定是否授权。持续授权是文库范围，应用仍只处理本次选择的论文和分类；单次许可按实际能力处理。
4. 查看逐项结果。附件和笔记完成回读后才计入完整归档；部分失败时保留已保存对象和检查点，再次操作先核原结果、只补缺项。
5. 重启后可主动“检查已保存许可”。拒绝钥匙串访问时保留原条目，重新检查或授权由你决定。

网站汇总与说明页没有论文归档入口。打开设置、检查连接和读取分类不读取保存的许可；明确检查已保存许可或发起归档时才读取本应用当前实例下的凭据。单次许可留在内存，持久许可存入本应用钥匙串。

## 保存内容

| 内容 | 归档方式 |
|---|---|
| 书目 | 原题、作者顺序、摘要、论文日期、DOI/arXiv/会议身份、网址和来源字段 |
| 完整来源 | `source-metadata.json` 附件，保留结构化输入、机构、原评分及版本等信息 |
| 原始 PDF | 指定版本的存储附件，保存实际字节，不只是远程链接 |
| 图文导读 | 自包含 HTML，包含图片、表格、公式、来源与导读版本 |
| 个人材料 | 按选择保存个人解析、问题、模型、证据页、时间和笔记，独立于原摘要 |

作者机构等不适合标准字段的信息保存在完整来源记录中，缺失信息保持未知。没有个人解析或笔记时不生成空白替代内容。只有来源明确支持的条目类型才写入相应字段，复用已有书目不擅自改变用户类型或人工编辑。

## 账号、去重与冲突

归档同时绑定本机文库实例、Zotero 返回的正个人用户 ID、目标分类与论文身份。当前没有群组文库或账号选择器。无法识别个人账号时仍可阅读，但不创建新归档。

相同论文以明确的 DOI、arXiv 或规范会议身份核对，不按中文标题合并。附件和笔记有各自内容身份；丢失应答或重启后先回读已有结果。用户修改字段、笔记、标签或附件时，应用保留原版本并提示冲突，不覆盖或删除用户内容。

换账号、实例、分类或权限后重新核对目标，旧检查点不自动转向新文库。缺少账号绑定的旧完整记录可选择“仅只读回读”，只执行读取；旧部分记录保留断点，不继续写入。

## 本机与离线范围

固定本机服务为 `127.0.0.1:23119`。授权与附件上传限制在相同本机服务器，拒绝跳转；不直接读取或修改 Zotero SQLite。附件上传后回读实际条目与文件，核对内容和摘要值。

自包含导读可在不依赖工作台缓存的条件下从 Zotero 打开。本机归档回读不检查 Zotero 云端文件同步，后者由 Zotero 自己管理。

备份包含工作台中的归档材料和检查点，不包含 Zotero 数据库、钥匙串及本机响应校验密钥。异目录恢复先校验原字节，再按受限路径映射读取材料；原目标、输入身份及授权仍须核对。详见[数据与恢复](mac-app-data.md)。

## 实现与验证

[ZoteroService](../apps/macos/Sources/ZoteroService.swift)提供 `zotero.status`、`zotero.checkAuthorization`、`zotero.collections`、`zotero.authorize`、`zotero.archive` 和 `zotero.resume`。状态读取、许可请求、归档与续传分别处理。

已有已安装版本完成原生授权、真实书目和附件写入、逐项回读及 Zotero 中打开材料；模拟服务用于权限、冲突、篡改、丢失应答和部分失败测试。1.0.1 的实际检查范围见[验证说明](mac-app-validation.md)，项目清单见[验收矩阵](mac-app-acceptance.md)。

官方协议：[Local API](https://www.zotero.org/support/dev/web_api/v3/local_api)、[Write Requests](https://www.zotero.org/support/dev/web_api/v3/write_requests)、[File Uploads](https://www.zotero.org/support/dev/web_api/v3/file_upload)。
