# 标签体系实施与验收计划

本文记录 [标签设计](tag-system-design.md) 的第一批只读预览实施、当次验收，以及后续生产接入的状态。第一批保持日更、Reader、评分与已发布博客字节不变，交付共享词表、历史标签映射、预览索引和检索工作台。这个阶段没有执行正式语义重标或改写旧标签 URL。

后续已经把生产提示词、四行标签契约、分类核验阶段（`taxonomySeal`）和历史来源分类接入共享词表。新页面采用 `paper-taxonomy-flat-tags-compat-v1`：保留 Hugo `tags`，并记录词表、概念、分面、主任务和主方法。旧页和 URL 没有随预览批量改写，现有标签页明确显示为新旧混合索引。完整九分面网站导航、父级检索、全历史语义重标及旧 URL 迁移仍需独立实施和验收。

当前受跟踪的 `config/tag-catalog.json` 有 262 个概念、9 个分面，其中任务 108 个、方法 78 个。这是代码仓库配置的静态核对；下文 228 概念及历史页面数量属于原实施记录，不能当作今天的博客统计。

## 分工与依赖

第一批按以下接口和依赖实施：

| 阶段 | 负责范围 | 交付与验收 |
|---|---|---|
| P0，共享词表 | 词表及 Node 加载器 | 固定 ID、九分面、单父层级与严格别名，拒绝冲突、环和未知引用，保留不同概念的边界 |
| P1，Python 兼容与历史构建 | Python 加载器及只读 Hugo 扫描器 | 两端解析一致，来源 SHA 和构建前后输入一致；每个旧词都有映射或待核记录，不改源文件 |
| P2，检索界面 | 静态 HTML、CSS 与 JS | 同分面任一匹配（OR）、跨分面同时匹配（AND）、父级召回、别名搜索、清除与分页、可访问错误提示及安全链接 |
| 集成，主代理 | 命令、集中路径、受限本地服务、文档和验证 | 回放当次 4185 页样本，对照 Node/Python 结果，保持原正式分析和博客 SHA 不变，并完成项目回归 |

先固定 P0 接口，再让 P1/P2 使用相同快照契约。每个代理只修改分配文件，交付后由另一代理或主代理复核。失败应修正原因后重新验证，不能修改成功标记来消除问题。4185 是当时的样本数量，不是后续每次预览的固定门槛。

## 固定协议

词表版本是 `paper-taxonomy-v1`，概念字段为 `id`、`facet`、`preferredLabel{zh,en}`、`aliases`、`broaderId`、`definition`、`scopeNote`、`status` 和 `replacedBy`。九分面为 `task`、`method`、`setting`、`signal`、`application`、`research_focus`、`artifact`、`scientific_topic` 和 `model_family`。v1 每个概念最多一个父级，父级须有效、同分面且不能成环。别名不得把 PEFT 收窄为 LoRA、把数据增强改成预训练，或把说话人识别等同于验证。

新生产选择要求有效概念的首选标签、一个显式主任务和一个显式主方法，两个角色都在总计 3–5 个标签中。首选名采用中文，只有 `CNN/RNN/SFT/CTC/LoRA/Adapter/Transformer/Conformer` 这 8 个既定英文专名保留原形，每项必须配至少一条中文别名；参见 [设计中的选择规则](tag-system-design.md#1-核心决策) 及第 6.1 节。维护词表时必须遵守这项封闭例外。核心加载器检查名称、字段与层级，生产解析器精确匹配已登记的有效首选名；它们没有按汉字或八词清单自动判断首选名语言的检查。

预览版本是 `paper-taxonomy-preview-v1`，绑定词表原始字节 SHA、博客 Git 提交及页面 SHA。每条记录保留原 `tags`、全部 `mappedIds` 和 `unresolvedTags`；只有展示用的 `displayIds` 去除冗余祖先，原始证据不删除。主任务只能来自显式字段，并须唯一解析为任务概念，不能用首标签补齐。

预览的三种状态描述字面映射完整度：`legacy_mapped` 表示旧词全部可映射且没有显式主任务异常；`partial` 表示仍有未映射词或显式主任务无法核实；`unresolved` 表示尚无可用映射。三者都不是 `reviewed`，也不证明语义分类正确。缺少标签的页面仍保留记录。已知 arXiv ID 选最新页面为显示代表，并保留重复路径；未知 ID 按路径哈希独立保存，不能把全部显示记录称作唯一论文。

## 安全边界

预览构建器从项目配置读取真实 Hugo 仓库，只读扫描输入，结果写入独立的 `data/runtime/` 目录。构建前后核对输入状态与文件 SHA，拒绝路径逃逸和符号链接，不写博客或 `data/current/`。

网页快照不包含论文正文、凭据或用户绝对路径，只提供已发布的 HTTPS 论文链接。界面通过文本节点展示内容，不把论文文本拼成 HTML。本地服务只监听 `127.0.0.1`，开放首页、样式、脚本和快照四个固定路径，不提供运行目录列表或审计文件；同时限制 Host、Origin 与请求方法，并设置 CSP。

预览无需新依赖或论文模型请求，不重写全文。第一批实现保留了既有 Node/Python 历史解析行为，避免预览使已有生产凭证无关失效；后续生产接入则使用当前词表选择契约。不能把第一批“不切换生产”的范围延续为现状，也不能把历史别名解析当作新生产输出规则。

## 验收矩阵

| 验收项 | 需要确认的行为 |
|---|---|
| 词表结构 | ID、首选名、别名、父级、状态与说明合法，歧义、冲突和重复输入必须被拒绝 |
| 跨语言解析 | 逐项对照概念名称、别名、未知词及 PEFT/LoRA 等边界，原始字节 SHA 和解析结果一致 |
| 历史扫描 | 分别统计论文页、已知 ID、未知 ID 与重复 ID，每个旧标签有明确处置，未知词不会丢失 |
| 检索 | 父级包含自身及后代，同分面 OR、跨分面 AND；覆盖科学主题、缺主任务或标签、无结果、坏快照和恶意 URL |
| 输入保持 | 构建前后 Hugo 提交、工作区、全部页面 SHA、正式分析与已发布凭证保持不变 |
| 完整回归 | 在沙箱外运行 `npm run verify`，记录 Hugo、默认与 Manual JS/Python、语法及数据检查的实际结果 |

预览允许历史页没有主任务，不表示生产解析支持主任务为空。单元测试也不能替代论文语义准确率评估；真实博客样本与临时测试样例的结果须分别报告。

## 后续正式切换的前提

生产选择协议和历史来源语义分类入口已经实现。仍需独立验收历史分层语义评测、完整 Hugo 分面导航、正式索引切换及旧 URL 迁移。旧预览中的未知词可帮助安排补词和复核，不能为了提高覆盖率把歧义词硬映射到某个允许概念。

新的分类结果要有来源证据，并经过独立审查。发布时按正常生成、审查、推送流程处理改变的页面和资产，不能沿用不匹配的旧发布凭证。逐页审查按“相对路径 + 页面内容 SHA”复用，代码、模型或协议变化而页面字节不变时，仍须重跑当前批次检查并生成新发布凭证。远端 Git 核验之后，还要确认部署成功和正式页面的 HTTP 200、地址与标题；预览工具不完成这些上线检查。

## 执行记录

### 已实现的第一批

以下是原来第一批的实施记录，数量与状态没有在本次文档改写中重新测量：

- 当时 `config/paper-taxonomy.json` 有 228 概念、9 分面，其中任务 90、方法 72。词表补充众包、主观与用户评测、数据集构建与标注、基准设计、综述、形式化与统计分析及常见建模方法，并细化麦克风阵列、语音生物标志物和对抗鲁棒性。每个概念都有中英文名、严格别名、定义与范围说明。
- Node/Python 对名称、别名、祖先及展示去重逐项回放，结果一致。新映射层不再把 PEFT 收窄为 LoRA，也不混淆说话人识别与验证。
- 新 Python 路径集中在 `taxonomy_paths.py`，只引用既有项目根。当时 `path_config.py` 保持原字节，以免预览使已发布模板指纹变化。
- 构建器只读扫描 4490 个 Markdown 文件，得到 4185 个论文页、4069 条显示记录、2651 个已核唯一 arXiv ID 和 1418 个未定 ID 页面。全部 1243 种旧标签进入处置表，没有按题目猜测去重。
- 当次映射了 178 种标签，类型覆盖率为 14.32%；覆盖 13932/15774 次标签出现，即 88.32%，剩余 1065 种完整保留。2699 条记录完成字面映射，1044 条部分映射，326 条尚无映射。**当次语义审核记录为 0**，这些数字不是分类准确率。
- 构建器使用输出目录锁，核对全部源文件的前后 SHA 与 Git 状态，拒绝 ID 来源冲突并转义 CSV 公式；所有输出完成后才生成预览文件清单。服务启动时复验索引、报告、CSV 的全部字节以及词表和来源身份，拒绝不完整构建。
- 界面保留原标签和主任务异常，支持分面组合、祖先召回、别名搜索、分页与可访问错误提示。主任务不在标签卡片中重复显示，窄屏初始折叠分面。

### 实际验收

旧预览保存的索引、词表与博客提交 SHA 只证明当次输入和结果一致。词表新增或修订后，不能把旧值当作当前生产 SHA；当前值须由严格加载器从 `config/tag-catalog.json` 原始字节重新计算。预览输出位于 `data/runtime/taxonomy-preview/`，包含 `index.json`、`migration-report.json`、`tag-disposition.csv` 和 `bundle-manifest.json`，文件权限为 `0600`。

当次数据联验中，ASR 含子节点查询得到 600 条，AV-ASR 得到 4 条；LoRA 的 13 条包含在 PEFT 父查询的 178 条中。未映射或主任务待核筛选得到 1370 条，等于 1044 条部分映射加 326 条尚无映射。30 条显式主任务保留来源，4039 条缺失主任务没有用首标签填补。Edge 成功加载 4069 条真实记录，回归用例覆盖非空渲染、手机与桌面初始折叠及展示去重。

初次完整验证发现新 Python 库直接执行时缺少运行环境检查，修正后重新验证。隔离 Python 路径后，全套通过 **1178 项 JS、431 项默认 Python、24 项 Manual Python**，以及固定 Hugo、全仓语法和严格数据检查。原日志路径为 `/private/tmp/taxonomy-isolation-verify-final.log`。模拟模型和临时 Git 推送属于测试，原验收检查了模拟调用与临时仓库路径，没有把这些日志当成生产动作。

原验收还记录：正式分析 SHA `a450aa54f6a2b463b83409fe02f88c73f80d68d0146dfdd69e1d343429ef9925` 与四篇纠错安装凭据一致，博客 HEAD 保持原发布版本且工作区干净，`path_config.py` 相对实施前没有差异。隔离后的 npm 预览入口再次构建成功，统计相同；没有重写 Reader、改评分、改旧标签 URL 或推送博客，也没有发起付费论文分类请求。这些是当时的验收记录，没有在本轮重新检查博客、运行文件或日志；付费调用记录也不包含原会话及子代理本身用量，不能据此宣称整项工作零 Token。原临时预览服务在验收后停止。

### 使用方法

```bash
# 校验共享词表
npm run tags:validate
# 从项目 .env 指定的干净 Hugo 仓库读取输入并生成预览
npm run tags:preview
# 打开输出的本机 URL；按 Ctrl+C 停止服务
npm run tags:serve
# 可选指定端口，不支持绑定公网地址
npm run tags:serve -- --port 8999
```

这些入口必须在沙箱外运行。构建不联网，但需要真实 Hugo 输入。服务默认端口为 `8766`，可指定 `1024–65535` 范围内的端口。更改词表后先重新构建预览；旧预览结果的词表 SHA 与当前不符时会被拒绝。

没有 Hugo 仓库的干净 CI 可运行词表和临时样例测试，不能把无数据情况当作真实历史验收。预览是短时静态工作台，不是博客所依赖的本机 AI 服务，不会常驻或自动启动。
