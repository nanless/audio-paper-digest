# 论文标签体系设计：受控词表、任务层级与分面检索

共享词表、生产分类和只读历史检索预览已经接入。分析提示词读取同一份词表，Node 与 Python 解析器核对有效概念的首选标签；结构修复后，独立的分类阶段（`taxonomySeal`）检查并保存分类结果。新页面使用临时扁平兼容协议，保留 Hugo `tags`，同时记录词表版本、概念、分面、主任务和主方法。现有标签页混合展示新旧标签，并明确说明这一范围。

完整九分面网站导航、旧标签 URL 迁移和全历史语义重标尚未完成。历史页面要使用新版分类，仍须经过完整重写或有来源证据的重标流程。本文保留 2026-09-07 的调查与早期设计记录，并区分后续已经实现的功能；其中的采样数量和准确率目标是本站建议，并非学术界统一标准。

## 0. 全量历史盘点与证据边界

原调查以博客提交 `bf263b803bd353f1411d94f27c621edb33dbb898` 的干净工作区为基线，覆盖 2026-04-19 至 2026-09-04。扫描 4490 个 Markdown 文件，排除 305 个汇总、索引及会议方向列表，得到 **4185 个论文页面、1243 种实际标签和 290 个无标签页面**。以下数字描述这次调查，没有随词表后续更新重新测量。

其中 2767 页能够核实 arXiv ID，共有 2651 个唯一 ID；另有 1418 页没有可靠 ID，多为会议论文。对已知 ID 选取最新页面，再加上未定 ID 页面，得到 4069 条显示记录。它们不能全部算作已经确认身份的唯一论文，也不能仅凭题目相似合并。重复 ID 有 110 组，其中 96 组的历史标签集合不一致。

标签频数揭示了几种需要分别处理的问题：

- 885 种标签只出现一页，995 种至多出现两页。它们可能代表细分研究，也可能来自拼写差异或含义变化，不能一律删除。
- 125 种标签属于调查时的提示词分类表，1118 种不在表内。表外词未必无效，例如“数据增强”出现 247 页，却没有列入当时的白名单。
- 只有 30 页记录了显式主任务。473 页的首标签属于方法分面，42 页属于条件，119 页属于数据或评估，41 页属于应用，因此不能把首标签作为历史主任务的依据。
- “多模态模型”出现 790 页，“模型评估”出现 599 页，“基准测试”出现 470 页。这些频数不能直接表示研究任务分布。

调查还保留了 20 项逐页冲突证据，包括 CNN 与卷积神经网络、混合专家与混合专家模型、偏好优化的中英文名称分流、PEFT 与 LoRA 共标，以及把“未说明”写成标签。这些证据用来审查候选关系，没有证明历史论文已经逐篇完成语义重标。

本地审计文件位于 `data/runtime/tag-taxonomy-audit/`。`README.md` 解释统计口径，`all-tags.md` 和 `tag-frequencies.csv` 保存全部 1243 个词及频数，`pages.json` 保存页面清单和 SHA，`tag-cooccurrence.csv` 保存共现关系，`conflict-evidence.md` 保存上述 20 个例子。`pipeline-audit.md` 和 `reference-research.md` 分别记录代码与官方来源依据。这些私有运行文件不作为公开数据集提交。

## 1. 核心决策

每个概念使用一个稳定 ID。任务之间可以有父子关系，方法、条件、研究对象、应用和产物分别归入各自分面。

现行生产协议要求每篇论文恰有 1 个显式 `primaryTaskTag` 和 1 个显式 `primaryMethodTag`，两者都出现在总计 3–5 个标签中。主任务必须准确涵盖论文贡献，主方法必须支撑主要结论；不能用方法充当任务，也不能从标签顺序推导角色。新输出只接受词表中状态为 `active` 的首选标签。

首选标签采用中文，封闭例外是 `CNN / RNN / SFT / CTC / LoRA / Adapter / Transformer / Conformer` 这 8 个既定英文专名。它们保留原形，每项必须至少有一条中文别名，以支持中文检索。这个例外不扩展到其他英文名称。词表维护必须遵守这项内容规则；核心加载器检查字段、名称冲突和层级结构，并不自动按汉字或这份八词清单判断首选名的语言。

完整标签可以补充有独立证据的方法，但不得同时选择祖先与后代。数据集、基准、用户研究、综述和理论论文应选择实际采用的研究方法，例如数据集构建、评测协议、用户研究、系统综述或理论分析，不能硬贴一个没有贡献的模型架构。跨分支任务只有在存在独立论证或评测时才一并标记；理论研究无需虚构工程基准。

主任务应尽量选准确的具体节点。现行程序会对仍有更具体后代的主任务给出 `specificityWarning`，新分析会尝试局部修正；仅由这项告警触发的修正失败时，保留原有合法选择。告警不会使已经完成的旧阶段回放失效。同时选择祖先与后代则是必须纠正的错误。

论文提到某个模型或数据集，不自动表示它就是研究对象。中文名、英文名、缩写及明确的历史拼写指向同一概念 ID，改显示名不应改 ID 或丢失旧链接。词表覆盖面可以很广，每篇仍只选有证据的少量标签；后续阅读卡片设计拟显示主任务及最有区分度的 2–3 项，其余通过筛选器或展开信息查看。

上述关系借鉴 SKOS 对首选名称、别名、上下位和相关关系的区分。本站还要求任务层级无环，并为概念写明定义与范围；相关关系和上下位关系都不能直接当作同义关系。参见 [W3C SKOS Reference](https://www.w3.org/TR/skos-reference/)。

## 2. 为什么不能只“合并相似词”

| 情况 | 正确处理 | 不应该做的事 |
|---|---|---|
| 语音识别 / ASR / Automatic Speech Recognition | 同一概念，不同语言或缩写入口 | 建三个独立标签页 |
| 语音识别 / 音视频语音识别 | 下位任务继承上位检索 | 两者当同义词合并，或每篇重复贴两个 |
| 参数高效微调 / LoRA / Adapter | 上位方法与不同下位方法 | LoRA 和 Adapter 合并成一个词 |
| 流式 / 实时 | 分别记录分块处理与实测时延条件 | 只看到流式架构就声称实时 |
| 语音增强 / 主动降噪 / 回声消除 | 不同目标、信号与执行环路，分别定义 | 名称都有“噪声”就合并 |
| 数据集 / 基准 / 模型评估 | 产物、评测协议、研究活动分开 | 出现一个实验就贴“基准测试” |
| 语音克隆 / 语音合成 / 语音转换 | 克隆与合成、转换按目标建立相关关系 | 无条件把所有克隆归为文本到语音 |
| 模型集成 / 集成学习 / 模型融合 | 先区分预测组合与权重合并，旧记录待核 | 仅凭字面相近批量替换 |
| 音频分类 / 音频事件检测 | 片段类别与事件时间定位分开 | 标签合并后丢失时间定位能力 |

标签经常同时出现，也不证明它们含义相同。例如“低资源”和“多语言”回答不同问题，需要分别保留。

## 3. 数据结构与读者界面

### 3.1 分面

当前词表有九个分面：`task`、`method`、`setting`、`signal`、`application`、`research_focus`、`artifact`、`scientific_topic` 和 `model_family`。下表讨论论文分类记录与展示字段，既包含当前要求，也包含未来设计；它不是词表分面的逐项字段清单。`documentType` 和输入输出模态不属于上述九个分面。

| 字段 | 回答的问题 | 数量与适用范围 | 使用约束 |
|---|---|---|---|
| `primaryTaskTag` / 次任务 | 论文主要解决什么？ | 当前恰好 1 个主任务、0–2 个次任务 | 必须显式选择任务，并给出输入、输出、目标或评测依据，不能从首标签猜测 |
| `primaryScientificTopic` | 非任务导向研究主要解释什么现象？ | 拟议协议中为 0 或 1 | 主任务可为空的任务/科学主题分支尚未实现，需要新协议与迁移验证 |
| `primaryMethodTag` / 补充方法 | 核心改进或研究过程依靠什么？ | 当前恰好 1 个主方法；补充方法 0–若干，总标签仍为 3–5 个 | 主方法必须出现在完整标签中；其他方法须有独立证据，不罗列组件或重复祖先 |
| `settings` | 在什么运行或学习条件下？ | 建议 0–3 个 | 分别定义流式、低资源、零样本、多通道等条件 |
| `signals` 与 `inputModalities` / `outputModalities` | 研究什么信号，输入输出是什么？ | 据事实填写，也可不适用 | 区分语音、音乐、环境声与文本、视频、脑信号；描述性研究不必虚构输入输出接口 |
| `applications` | 主要面向什么场景？ | 建议 0–2 个 | 医疗、工业、助听、会议等场景须有依据，不能只凭一个测试集推断 |
| `researchFocus` | 主要研究哪种性质？ | 建议 0–2 个 | 公平性、隐私、鲁棒性、可解释性等须有专门实验或论证 |
| `artifacts` | 论文贡献了什么产物？ | 可有 0–多项 | 数据集、基准协议、工具或权重是否可用，仍由资源证据决定 |
| `documentType` | 这是哪类文章？ | 1 个 | 复用方法研究、理论研究、数据集与基准等既有类型，不另贴重复类型标签 |

界面不必把所有字段同时放在首页。只读预览已按“任务、方法、条件”优先组织分面，其他分面可以展开；窄屏初始折叠。领域分组用作导航，不要求每篇额外贴“语音”“音频”或“人工智能”。

同一分面内多选表示任一条件满足（OR），不同分面之间则要求同时满足（AND）。例如，查询可以选择“语音识别或语音翻译”，同时限定“LoRA”和“低资源”。当前预览搜索标题、ID、原标签、相关概念名称及别名，也保留未映射词和主任务异常供查询；搜索摘要是后续网站设计，并非预览已实现的功能。无法可靠确定主任务或主方法时，分类不能被标成成功。

### 3.2 父子关系如何实际工作

```text
语音内容识别与转写（导航分组）
├─ 语音识别
│  └─ 音视频语音识别
├─ 关键词检测
│  └─ 语音唤醒
└─ 强制对齐

模型适配（方法导航分组）
└─ 参数高效微调
   ├─ LoRA
   ├─ Adapter
   └─ 前缀微调
```

上图的领域名称是导航分组，实际概念及父关系以词表为准。“流式语音识别”通常用 `task.asr` 与 `setting.streaming` 组合表达，无需预先给每种组合建立新标签。音视频识别改变了输入和问题定义，因此可以保留专门任务，模态信息也可用于跨任务检索。

只读预览中，选择 LoRA 的论文也能通过“参数高效微调”父节点查询找到，卡片不会同时重复显示这两个概念。如果论文确实比较 LoRA 与 Adapter，可以选择两个有独立证据的叶节点，因为它们不在同一条父子链上。

一个主任务可以出现在多个导航专题，但专题链接不增加语义父任务。v1 与 `broaderId` 一致，每个概念最多有一个语义父级。未来若需要多父级，必须升级协议并逐条审查“是某种”的关系；“使用了”“发生在”或“服务于”不能用作父子关系。

### 3.3 统计口径

当前新页的“主任务分布”每篇只计显式主任务一次。未来若启用主任务可为空的科学主题协议，应把任务导向研究与科学主题分别统计，两类合计才是已分类论文总数；待分类记录另列。这个未来口径不能用来放宽当前生产要求。

“涉及任务、方法或条件”的数量可以重叠，不能相加当作论文总数。上级计数取本节点直接标记与全部后代标记的集合并集，不能简单相加子标签频数，也不能漏掉合法直接选择宽任务的论文。“直接标记数量”与“含子任务数量”应分别显示。

重复发布的同篇论文按已核 ID 去重；未知 ID 页面保留独立记录，并单列数量。当前历史预览按这些记录查询和计数，不能把每条未知身份记录都称作唯一论文。

## 4. 建议的任务覆盖目录

下表是候选覆盖目录，并不表示每个词都已经在本站出现或应该立即放上首页。分组名称用于导航。宽任务可用于有证据的多问题统一研究；若只是暂时缺少合适叶节点，则应明确留待复核。`needs_taxonomy_review` 是这类待核情况的建议标记，不能当作现行生产允许输出的新标签或已经实现的自动队列。

| 导航领域 | 任务与需要明确覆盖的子问题 | 重要边界 |
|---|---|---|
| 语音内容与语言 | 语音识别、音视频语音识别、关键词检测、语音唤醒、强制对齐、语言/方言识别、语音翻译、口语理解、口语意图与槽位、标点恢复、逆文本规范化 | 转写、翻译、语义理解与格式化不互为同义 |
| 说话人与会话结构 | 说话人识别、验证、说话人分离标注、说话人计数、语音活动检测、重叠语音检测、说话人追踪 | 说话人分离标注回答谁在何时说话；波形分离生成独立声音 |
| 对话与交互 | 语音对话、全双工交互、轮次切换、打断与应答时机、语音代理规划/工具使用 | “全双工”不是“低延迟”的同义词；纯语言对话不自动属于语音交互 |
| 语音生成与编辑 | 文本到语音、语音转换、语音克隆、语音编辑、语音配音、韵律/风格控制 | 配音与克隆可依赖合成或转换，不能强塞进某一实现路径 |
| 波形恢复与分离 | 语音增强、去混响、回声消除、语音分离、目标说话人提取、视觉辅助语音分离、通用声源分离、音乐源分离、带宽扩展、丢包修复、去削波、音乐增强 | 主动降噪另列；普通上采样不是已证明恢复缺失频带 |
| 声音感知与理解 | 音频分类、声学场景分类、声音事件检测、异常声音检测、音频问答、音频描述生成、时间定位/文本定位、声音关系与推理 | 事件类别本体与研究任务词表是两套东西 |
| 空间与声学 | 声源定位、声源追踪、联合检测定位、声场重建、声学参数/RIR 估计、房间声学建模、空间音频渲染、波束形成、主动声学控制 | “空间音频”是宽领域，不能长期包办所有空间任务 |
| 编码与传输 | 音频编码、语音编码、音乐编码、空间音频编码、码率控制、可感知压缩、语音/音频通信 | 研究压缩表示不等于任何使用编码器的模型都在研究编码任务 |
| 质量、可懂度与听觉 | 语音质量预测、音频质量预测、可懂度评估、主观听测方法、听觉建模、听觉辅助 | MOS 是特定质量评价形式；词错率、听感质量和可懂度分开 |
| 音乐分析与检索 | 音乐转录、音高/旋律提取、节拍/速度/下拍、和弦/调性、结构分析、乐谱对齐、曲目/翻唱识别、音乐检索、音乐文本检索、音乐推荐 | 音频波形、符号乐谱和文本查询应明确记录模态 |
| 音乐生成与表演 | 音乐生成、符号音乐生成、歌唱合成、伴奏生成、音乐续写/编辑、自动配器、表演控制 | 歌唱生成不是所有语音合成的同义词 |
| 音画与跨模态 | 视频到声音、音视频联合生成、音画同步、视觉辅助声源分离、音视频问答、音频字幕生成、跨模态检索 | 这里可以是跨域导航专题，复用已有任务 ID，不复制一份同名任务树 |
| 安全、身份与来源 | 语音/音频伪造检测、伪造片段定位、音频水印、音频指纹、声音来源验证、说话人匿名化、音频隐私攻击/防御 | 检测、定位、水印与指纹不同；防御研究与被攻击的原任务可分别标主次 |
| 非典型输入与应用任务 | 言语神经解码、静默语音接口、病理语音评估、健康声学检测、生物声学监测、工业故障声检测 | 脑信号词分类不能因为词输出就算声学 ASR；应用分面与具体输出任务联合使用 |

“语音”“音乐”“通用声音”等宽泛名称可以帮助检索，最终任务仍由论文目标和评测决定，不能只看题目关键词。

科学主题可覆盖发声与构音、音系与语音学、韵律、言语感知、听觉与音乐认知、语言习得与第二语言、言语障碍和社会语音学。这些概念不取消当前显式主任务要求。历史“蛋白质工程”“医学图像重建”等条目需要范围复核，不因此无限扩展本站词表，也不自动删除旧文章。

| [DCASE 2026，目录更新2026-07-01](https://dcase.community/challenge2026/index) | 补足异常声音、联合定位检测、空间语义分割、音频问答与长音频片段检索；年度挑战不是学科全集 |
| [ISMIR 2026 CFP](https://ismir2026.ismir.net/authors/call-for-papers) 及 [MIREX 2026任务目录](https://music-ir.org/mirex/wiki/MIREX_HOME) | 不让生成掩盖转录、对齐、节奏/和声、乐谱与音乐认知；目录不等于已完成的评测结果 |
| [ISCA Interspeech 2025 sessions](https://www.isca-archive.org/interspeech_2025/) | 补充语音科学与临床覆盖；未可靠取得 2026 完整投稿子领域表，不冒称当前年度标准 |
| [Google AudioSet](https://research.google.com/audioset/) | 借鉴稳定 ID 和定义；它是声音事件本体，不把数百种声音直接变成研究任务标签 |

具体分面、数量限制和迁移顺序仍是本站设计，并非上述机构的联合标准。

## 5. 方法、条件及别名的使用规则

### 5.1 方法分支

方法分面需要区分以下用途：

- 生成建模包括自回归、扩散、流匹配、生成对抗和变分建模。扩散与流匹配不能自动合并为同义词。
- 表示与结构包括 Transformer、卷积、循环、状态空间、图网络、混合专家及向量量化或神经编解码表示。它们用于说明结构贡献或关键对照，不能因为模型使用了组件就把组件列为主方法。
- 学习方法包括自监督、对比学习、半监督、弱监督、无监督、强化学习、偏好优化、蒸馏、元学习、多任务、持续学习和联邦学习。
- 适配方法包括领域适应、测试时适应、参数高效微调及其下位方法。测试时适应有具体更新条件，推理计算量增加不一定是适应。
- 效率方法包括剪枝、量化、低秩压缩、动态计算、早退和缓存。已选择具体方法时，不再重复贴“模型压缩”祖先。
- 推理与系统方法包括检索增强、工具增强、约束解码、搜索、规划，以及信号处理或优化方法。没有使用神经网络的研究也有实际方法。

大语言模型、音频语言模型和统一音频模型归入模型族分面。基座模型名称适合用作实体检索，不应无限扩成任务标签。“预训练”“后训练”优先表达训练阶段，“端到端”表达系统设计属性，不替代更具体的核心方法。SFT 表达监督微调，指令微调是使用指令样本的一种情形，两者不能无条件等同。

### 5.2 条件与可验证声明

流式处理能够逐段处理输入或陆续产生输出，无需先等完整序列。严格因果推理则不能使用未来输入；流式系统如果允许有限前视，须另记 `lookahead` 及单位，不能标为严格因果。

“实时”需要具体硬件、输入时长、吞吐或时延及测量条件。只有作者声明时，应保留 `claimed` 状态，不能当作已经 `measured`。在线与离线也要说明是在描述推理输入还是训练更新；未说明用途的历史“在线”标签须先消除歧义。

零样本与少样本必须说明相对于哪个任务、说话人、语言或域，不能因为测试集未见过就一律标零样本。多语言与跨语言、低资源与小数据、单通道与多通道、长序列与长音频、端侧与服务器分别有含义，不按共现强行合并。鲁棒性、公平性、隐私、安全或可解释性成为研究重点时，应有专门测试或论证，不能只依据引言中的愿景。

### 5.3 旧名称处置

每个旧标签必须记录一种处置结果：`keep`、`alias`、`broader`、`split_review`、`move_facet`、`deprecated` 或 `out_of_scope`。原值始终保留；无法确定含义时留待逐篇复核，不静默删除。

| 旧名或关系 | 建议 | 自动迁移条件 |
|---|---|---|
| ASR、自动语音识别、语音识别 | `task.asr`，中文首选“语音识别” | 原标签已确认为该含义 |
| TTS、文本转语音、文本到语音 | 同一个文本到语音概念 | 不能把含转换/克隆的宽“语音合成”全部无条件映入 |
| LLM、大语言模型 | 同一模型族 ID | 不据此推断音频理解能力 |
| 多语种、多语言 | 首选“多语言” | 与“跨语言”仍保留边界 |
| 自监督、自监督学习 | 首选“自监督学习” | 不与无监督学习做简单别名合并 |
| 说话人日志 | 首选“说话人分离标注”，别名保留原名和 diarization | 不并入说话人验证或波形分离 |
| 语音超分、音频超分辨、音乐超分辨 | 先规范显示名，再区分带宽扩展与其他超分任务 | 涉及语义细分时逐篇核查，不能只改字符串 |
| 音视频语音分离、音视频声源分离 | 语音与一般声源的上下位/适用范围关系 | 不互为无条件别名 |
| 理论分析、模型评估、模型比较 | 研究性质或文档类型/研究重点 | 保留原文章类型证据，不能代替主任务 |
| 数据集、基准测试、开源工具 | 转产物/文章类型与可用状态 | “开源”必须由资源与许可证据决定 |
| 音视频、多模态模型 | 分别为输入输出模态及模型角色 | 不因都带多模态含义而合并 |

## 6. 每篇如何选标签

选择从原文证据开始。先确认输入、输出和主要评测衡量的问题，再显式选择主任务；随后确认贡献是模型、方法、数据、评测协议、理论还是系统，保留文章类型与产物信息。主方法应与主要结论直接相关，明确写入 `primaryMethodTag`。非模型论文从数据构建、评测协议、用户研究、综述或理论分析等实际研究方法中选择，有独立证据的其他方法可以补充。

补充标签只保留有证据且能说明结论适用范围的条件和贡献。借用别的任务作为工具不形成次任务，例如用 ASR 评价增强不自动表示论文也研究 ASR。别名映射到同一 ID；同一祖先链只保留最具体选择，不同分面的合法标签可以共存。

缺少合适词时，先判断有效上位概念是否确实涵盖贡献，再明确记录需要复核的细分问题。不能吞掉未知词、随意改贴一个允许的方法，或借未来主任务可为空的设计宣称当前分类成功。没有可靠主任务或主方法的论文仍须按相应流程留待审查；建议标记 `needs_taxonomy_review` 不是可绕过生产解析的新标签。

<a id="61-判定判据60-篇分层抽检固化"></a>

### 6.1 分类判断规则（来自 60 篇分层抽检）

以下规则保留原来 60 篇分层抽检中发现的问题，现已写入 [主分析提示词](../prompts/deep-analysis.md) 和 [标签修复提示词](../prompts/taxonomy-tag-repair.md)。它们指导语义选择；标签数量、角色和父子关系还要由程序核验。

| 情况 | 如何选择 |
|---|---|
| 识别只是测量工具 | 社会语音学、韵律统计、发音评估或综述使用识别系统处理数据，并不自动构成识别任务。应按实际研究对象选择语音属性识别或适用科学主题；当前仍须有合法主任务，词表不能表达时留待复核 |
| 使用目标条件进行分离 | 视频、参考音频、嵌入或 DOA 指定提取目标时，按现行判据选择目标说话人提取；视觉输入可补充音视频信号。没有指定目标的视觉盲分离才选音视频语音分离 |
| 贡献核心不是骨干架构 | 核心贡献是表示、量化、数据或协议时，主方法不选 CNN、RNN、Transformer、注意力或状态空间等架构。架构可作补充标签 |
| 免训练流程或对抗攻击 | 不能因输入多模态就选择多模态学习；`scopeNote` 已区分输入模态与核心方法。优先选择实际起作用的信号处理等系统机制，缺项时检查有效上位概念，不凑数 |
| 应用与条件缺少正面证据 | 只在局限或未来工作提到的场景不选。实时处理必须有实测时延或吞吐及测量条件，作者自称不算测量 |
| 论文构造基准或语料 | 标题包含 benchmark、corpus、dataset，或正文明确构造基准、语料时，`conceptIds` 必须包含基准测试或数据集产物。在 3–5 标签预算内，优先于泛泛的条件或模型族 |
| 其他任务只是评测工具 | 次任务须有并列贡献或并列评测证据。用 WER 评测增强等工具用途不构成次任务 |

下面是记录结构的提案，版本为 `proposal-v1`，不是当前可安装的生产格式；其中 ID 示例不作为现行词表选择凭证：

```json
{
  "taxonomyVersion": "proposal-v1",
  "paperId": "2609.03622",
  "primaryTask": "task.speech-enhancement",
  "secondaryTasks": [],
  "primaryMethod": "method.test-time-adaptation",
  "methods": ["method.test-time-adaptation", "method.autoregressive"],
  "settings": [],
  "signals": ["speech"],
  "inputModalities": ["audio"],
  "outputModalities": ["audio"],
  "evidence": [
    {"field": "primaryTask", "sourceSha256": "需要填入实际原文SHA", "locator": "需要填入任务定义与主实验的位置"},
    {"field": "primaryMethod", "sourceSha256": "需要填入实际原文SHA", "locator": "需要填入适应目标和语音先验的位置"}
  ],
  "reviewStatus": "human_or_agent_review_required"
}
```

示例论文不会因为用了编解码器就标“语音编码”，也不会因辅助 WER 评价而变成 ASR 研究，或因提出停止预测就标“实时”。证据占位须替换为真实 64 位 SHA 与原文段落或 DOM 定位；若引用已有来源绑定的 Reader，还要保存 Reader SHA 和具体小节。示例本身不提供有效的生产凭证。

另外，LibriBrain100 的词分类输入是脑信号，应先检查言语神经解码，不能沿用声学 ASR。RIR 表征压缩研究编码，不能因测试混响就改为去混响。LoRA 语音识别只选择 ASR、LoRA 及有证据的条件，不再同时展示参数高效微调祖先。

## 7. 唯一词表与治理

[共享词表](../config/paper-taxonomy.json) 供 Node、Python、生产提示词和历史预览共同读取。别名及 `deprecated` 概念只能通过显式历史兼容模式（`legacy`）解释，不能直接写入新的正式分析结果。生产分类已接入，完整九分面网站导航仍需另行实现。

v1 概念字段为 `id`、`facet`、`preferredLabel`、`aliases`、`broaderId`、`definition`、`scopeNote`、`status` 和 `replacedBy`。名称、定义、范围、父级和弃用关系都有明确位置，正反边界写入 `scopeNote`。独立相关关系与逐概念引入版本尚属未来协议；当前各概念使用整份词表的版本。

ID 不得复用，每种语言只有一个首选名，同分面别名不能指向多个 ID。父级必须存在、有效且属于同分面，层级不得成环。弃用概念通过 `replacedBy` 指向有效的同分面替代概念；删除或拆分还须有迁移记录。新增叶节点应有定义，并至少提供正例、反例或排除条件。低频但有独立学术意义的任务可以保留，出现少不构成删除理由。

名称匹配采用 NFKC、首尾空白处理与 ASCII 大小写规范化，只接受明确登记的名称和别名，不用模糊相似度合并技术概念。新词维护建议先积累 3 篇明确同类论文再审议；有权威任务定义、现有树明显无法表达时，可审查单篇例外。按月检查候选、未知词、误分和冲突，升级时生成差异清单。这些是治理建议，不表示程序已自动建立或执行候选审批队列。

未来非任务型记录可考虑 `classificationKind=scientific_topic`，要求科学主题并允许主任务为空；未判定记录则保留 `classificationStatus=unresolved`。这两类不能混同。实施前必须同步升级当前非空主任务解析、发布校验和旧页面首标签兼容逻辑，不能只改 JSON 示例。

## 8. 分类的生成、审核与成本

当前主分析已经读取按协议生成、供分类提示词使用的完整有效概念清单，并输出首选标签和显式角色。结构修复完成后，`taxonomySeal` 检查分类；标签没有硬错误、也没有欠具体告警时无需额外请求；存在硬错误时局部修复标签节和机器摘要中的两个角色字段，并核验其余正文未变。修复模型以稳定 ID 返回选择，程序再转成首选标签。这项接入已经实现，不能再列为未来分类能力。

历史来源分类也有独立入口。它从已核验来源选择主任务、主方法及 3–5 个有效概念，每项附 20–1000 字符连续原文引文和理由，再经过独立语义审查。缓存绑定来源、词表、证据和决策，不能由旧博客标签推断角色，或冒充正文、Reader 和评分的生产证明。代码存在不代表全历史已经分类或发布。

后续可研究如何复用主分析证据、缩短适用领域候选词表，以及只传任务、方法、主要评测和争议概念的相关证据。候选必须保留跨域与低频任务，不能只靠标题关键词筛选。当前仍使用全部有效概念的清单，没有实施这种短名单，也没有测得节省比例。

成本评估应记录实际输入输出 token、调用次数、分类修正次数、人工与子代理审核负担及错误率。只比较提示词字符数，或减少有证据的标签数量，都不能证明整体成本下降。分类修复不得无故重写 Reader、重算评分或重新抓取全文。

## 9. 历史迁移与验收

### 9.1 按依赖顺序落地

| 阶段 | 当前实现与剩余工作 | 必须验证 |
|---|---|---|
| P0 | 共享词表已接入 [Node 解析](../scripts/utils.js)、[Python 解析](../scripts/utils.py) 及提示词 | 两端名称、别名和角色一致；PEFT 不变为 LoRA，数据增强不变为预训练，说话人识别不无条件变为验证 |
| P1 | 显式主任务、主方法、3–5 标签及独立 `taxonomySeal` 已实现；允许主任务为空的任务/科学主题协议尚未实现 | 历史兼容只显式启用；当前未知或歧义分类不能标为成功 |
| P2 | 扁平兼容发布已实现；完整 Hugo 分面搜索、父级查询和旧 URL 迁移仍待完成 | 新页绑定词表、概念、分面及角色；扁平计数不能当作九分面统计 |
| P3 | 只读历史预览和来源语义分类入口已实现；全历史分层评测、正式索引切换和分批发布仍需验收 | 待核项透明，分类维护保持无关正文和评分不变，发布经过正常检查 |

新的正式分类必须显式提供主任务与主方法。迁移网站模板（如 `research_metadata.html`）及统计代码时，应区分新分类与旧页兼容；新页不得从标签顺序猜角色，旧页缺失字段也不能直接被标成已完成语义审核。

### 9.2 迁移步骤

以下步骤是历史语义迁移与正式上线的设计，不能用一次字面预览代替：

1. 固定已发布页面清单，保留原页头元数据中的标签、显式主任务、论文 ID、日期和源文件 SHA，分别统计论文与页面。通过已核 arXiv、DOI 或 OpenReview 标识确认身份；无法核实的会议页独立保存，不按题目合并。选取最新代表页也不证明该页标签正确。
2. 输出全部旧词的处置表。明确同义词可提议自动映射，歧义、父子混用和跨分面项须逐篇检查。
3. 在独立附属记录中保存 `oldTags → proposedClassification → evidence → reviewStatus`，不改变历史正文、正式分析或评分。
4. 建立分层评测集，覆盖高频与低频、近期与历史、方法与数据集或理论、多任务及模态边界。建议起步至少 120 篇；这是采样设计，没有作为已完成验收数量。
5. 先用独立的新分类索引比较新旧检索结果，并保留切回旧索引的方式。确认后再进行独立标签发布。
6. 迁移旧标签 URL 时，Hugo aliases 在 GitHub Pages 上生成静态跳转页，不提供服务器 301。拆分标签应保留解释性聚合页，不能随意跳到某个子任务；所有旧入口须保持可达。
7. 新内容使用现行协议，历史迁移分批验收。分类版本变化影响分类、索引及相应发布凭证，不自动要求重写 30 篇或全站正文。附属记录须绑定来源、词表和分类结果的 SHA，并纳入受审发布内容。Reader 不变而页头元数据、搜索索引或标签页字节改变时，仍需重新生成并审查改变的文件。字节未变的页面按“相对路径 + 页面内容 SHA”复用逐页审查，但当前批次检查及新发布凭证不可省略，不能修改旧发布凭证。

发布还要核验基线、远端身份及允许变更集合。Git 远端 OID 只证明提交到达远端；宣布上线前，仍须确认对应部署成功，并人工核验正式页面地址、HTTP 200 和标题。当前分类工具不自动完成这些网页核验。

各项验收应分别报告：

| 指标 | 初始目标/判定 |
|---|---|
| 历史标签处置覆盖 | 100% 有明确处置，含待核项；这不等于语义分类 100% 正确 |
| 同义标签重复、同篇祖先冗余 | 规范化后为 0 |
| 无效 ID、别名冲突、层级环 | 0；构建遇到这些问题必须停止 |
| 独立抽样任务准确率 | 逐层统计并审查分歧，建议目标 ≥95%，达不到不批量上线 |
| 长尾召回 | 单独报告，不能用高频 ASR/TTS 准确率掩盖漏项 |
| 历史 URL 与链接 | 全量重放，无失效旧入口 |
| 不相关字段 | 原文、Reader、评分和原图 SHA 不变 |
| Token 用量与返工 | 报告总调用、完整用量与分类修正次数；不以少贴标签伪造低成本 |
