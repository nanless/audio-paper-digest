## 1. 核心决策

采用“一个概念一个稳定 ID、任务有父子关系、不同性质用不同字段”的体系，不继续扩张一张平面的标签白名单。

- 任务导向论文选择 **1 个主任务、0–2 个有独立证据的次任务**，选择能准确涵盖贡献的最具体概念。不为凑数添加任务。非工程任务导向的发声、感知、韵律研究允许 `primaryTask=null`，但必须提供一个有证据的 `primaryScientificTopic`，不能硬塞进ASR。
- 方法可以为 **0–2 个**。数据集、理论、评测论文没有新方法时允许为空，不能被迫贴一个模型架构。
- 条件、研究对象、应用、产物分别存放；正文中提到某个模型或数据集，不自动等于本文研究它。
- 父任务不与子任务重复存储；检索上级时自动包括下级。只有跨分支且有独立论证或评测的任务才同时标记；理论研究不强求工程基准。
- 中文名称、英文名称、缩写及历史拼写都指向同一 ID。改显示名不改 ID，也不丢旧链接。
- 词表覆盖面广，不等于每篇标签多。阅读卡片默认展示主任务和最有区分度的 2–3 项，其余放筛选器或展开信息。

这些关系借鉴 SKOS 对首选名称、别名、上下位和相关关系的区分；本站额外要求任务层级无环，并为每个概念定义范围与反例。**相关不等于同义，上下位也不等于同义。** [W3C SKOS Reference](https://www.w3.org/TR/skos-reference/)

## 2. 为什么不能只“合并相似词”

| 情况 | 正确处理 | 不应该做的事 |
|---|---|---|
| 语音识别 / ASR / Automatic Speech Recognition | 同一概念，不同语言或缩写入口 | 建三个独立标签页 |
| 语音识别 / 音视频语音识别 | 下位任务继承上位检索 | 两者当同义词合并，或每篇重复贴两个 |
| 参数高效微调 / LoRA / Adapter | 上位方法与不同下位方法 | LoRA 和 Adapter 合并成一个词 |
| 流式 / 实时 | 分别记录分块处理与实测时延条件 | 只看到流式架构就声称实时 |
| 语音增强 / 主动降噪 / 回声消除 | 不同目标、信号与执行环路，分别定义 | 名称都有“噪声”就合并 |
| 数据集 / 基准 / 模型评估 | 产物、评测协议、研究活动分开 | 出现一个实验就贴“基准测试” |
| 语音克隆 / 语音合成 / 语音转换 | 克隆与合成、转换按目标建立相关关系 | 无条件把所有克隆归为文本到语音 |
| 模型集成 / 集成学习 / 模型融合 | 先区分预测组合与权重合并，旧记录待核 | 仅凭字面相近批量替换 |
| 音频分类 / 音频事件检测 | 片段类别与事件时间定位分开 | 标签合并后丢失时间定位能力 |

标签共现高并不能证明重复。例如“低资源”和“多语言”经常同时出现，但回答的是不同问题。

## 3. 数据结构与读者界面

### 3.1 分面

| 字段 | 回答的问题 | 建议数量 | 使用约束 |
|---|---|---:|---|
| `primaryTask` / `secondaryTasks` | 论文主要解决什么？ | 任务型1 / 0–2 | 从任务树选择，有输入、输出、目标或评测证据；合法非任务型主任务为空 |
| `primaryScientificTopic` | 非任务导向研究主要解释什么现象？ | 0或1 | 已审非任务型必填；未判定记录不强迫造主题；发声、韵律、感知、认知等不是任务兜底词 |
| `methods` | 核心改进依靠什么？ | 0–2 | 只标贡献所依赖的方法，不罗列整个组件库 |
| `settings` | 在什么运行或学习条件下？ | 0–3 | 流式、低资源、零样本、多通道等分别有定义 |
| `signals` 与 `inputModalities` / `outputModalities` | 研究什么信号，输入输出是什么？ | 据事实或不适用 | 语音、音乐、环境声与文本、视频、脑信号等不要混淆；描述性研究无需虚构输入输出接口 |
| `applications` | 主要面向什么场景？ | 0–2 | 医疗、工业、助听、会议等，不能只凭一个测试集推断 |
| `researchFocus` | 主要研究哪种性质？ | 0–2 | 公平性、隐私、鲁棒性、可解释性等需专门实验或论证 |
| `artifacts` | 论文贡献了什么产物？ | 0–多项 | 数据集、基准协议、工具、权重；是否可用沿用资源证据，不由标签声称 |
| `documentType` | 这是哪类文章？ | 1 | 复用现有方法研究、理论研究、数据集与基准等字段，不再重复贴类型标签 |

底层字段可以多，首页不需要展示这么多分类按钮。第一屏默认只有“任务、方法、条件”，高级筛选展开其他分面。领域分类是导航入口，不是要求每篇额外贴“语音”“音频”“人工智能”。

同一分面内多选按OR，不同分面之间按AND。例如“语音识别或语音翻译” AND “LoRA” AND “低资源”。搜索框继续搜标题、摘要和别名；“未分类”和“无适用方法”分别显示，不能混同。

### 3.2 父子关系如何实际工作

```text
语音内容识别与转写（导航分组）
├─ 语音识别
│  └─ 音视频语音识别
├─ 关键词检测
│  └─ 语音唤醒
└─ 强制对齐

模型适配（方法导航分组）
└─ 参数高效微调
   ├─ LoRA
   ├─ Adapter
   └─ 前缀微调
```

“流式语音识别”通常表达为 `task.asr` + `setting.streaming`，不另建一个把所有组合预先展开的标签。反之，音视频识别改变输入及问题定义，可保留专门任务，同时由模态字段支持跨任务检索。

选了 LoRA，系统搜索“参数高效微调”时自动找得到，卡片不同时显示两枚标签。明确研究 LoRA 与 Adapter 对比时可以标两项叶节点，因为它们不是同一条父子链。

同一主任务可出现在多个导航专题，但专题链接不等于多个语义父任务。v1固定单语义父级，与 `broaderId` 一致；多专题用导航关联。未来确需多父级时另行升级schema并审查每条“是某种”的关系，禁止用“使用了、发生在、服务于”建立父子关系。

### 3.3 统计口径

- “主任务分布”每篇任务导向论文只计一次，使用固定主导航归属；非任务导向论文另列“科学研究主题”。两类相加才等于已分类论文总数；待分类另列，不能伪装成零相关性。
- “涉及任务/方法/条件”是多选覆盖数，可以重叠，明确注明不可相加得到论文总数。
- 上级计数是“本节点直接标记 ∪ 全部后代标记”的唯一论文ID集合并集，不能直接把子标签频次相加，也不能漏掉合法直接标宽任务的论文。同一篇重复发布按已核论文ID去重；未知ID保留独立记录并单列数量。
- “直接标记数量”和“含子任务数量”分别显示，避免用户误以为上级分类没文章。

## 5. 方法、条件及别名的使用规则

### 5.1 方法分支

- 生成建模：自回归、扩散、流匹配、生成对抗、变分建模。扩散和流匹配不是可自动合并的同义词。
- 表示与结构：Transformer、卷积、循环、状态空间、图网络、混合专家、向量量化/神经编解码表示；只在结构本身是贡献或关键对照时使用。
- 学习：自监督、对比学习、半监督、弱监督、无监督、强化学习、偏好优化、蒸馏、元学习、多任务、持续学习、联邦学习。
- 适配：领域适应、测试时适应、参数高效微调及其下位方法。测试时适应有其更新条件，不把所有推理时计算增加都算适应。
- 效率：剪枝、量化、低秩压缩、动态计算、早退、缓存；不要同时重复贴其“模型压缩”祖先。
- 推理与系统方法：检索增强、工具增强、约束解码、搜索、规划、信号处理/优化方法。无神经网络不代表没方法。
- 模型族（大语言模型、音频语言模型、统一音频模型）单独记录模型角色；基座模型名称留作实体检索，不无限扩成任务标签。

“预训练、后训练”优先作为训练阶段；“端到端”作为系统设计属性，不让它们抢占更具体的核心方法。SFT 表达监督微调，指令微调是以指令样本为目标的一种使用情形，不能无条件等同。

### 5.2 条件与可验证声明

- 流式：处理进行时可增量消费/输出，不必先等完整序列。
- 严格因果：推理不使用未来输入。流式可以有有限前视，另记 `lookahead` 及单位，不能把这种情况标为严格因果。
- 实时：需具体硬件、输入时长或吞吐/时延、测量条件支撑。仅作者使用“实时”字样时记录 `claimed`，不能升级为 `measured`。
- 在线/离线：必须注明是推理输入模式还是训练更新模式；历史裸“在线”进入消歧队列。
- 零样本/少样本：明确相对于什么任务、说话人、语言或域；不能因测试集未见过就一律零样本。
- 多语言/跨语言、低资源/小数据、单通道/多通道、长序列/长音频、端侧/服务器分别定义，不按共现强行合并。
- 鲁棒、公平、隐私、安全、可解释为研究重点时需有专门测试或论证；不能仅凭引言愿景贴标签。

### 5.3 旧名称处置

每个旧标签必须落入 `keep / alias / broader / split_review / move_facet / deprecated / out_of_scope` 之一，保留原值，不静默删除。

| 旧名或关系 | 建议 | 自动迁移条件 |
|---|---|---|
| ASR、自动语音识别、语音识别 | `task.asr`，中文首选“语音识别” | 原标签已确认为该含义 |
| TTS、文本转语音、文本到语音 | 同一个文本到语音概念 | 不能把含转换/克隆的宽“语音合成”全部无条件映入 |
| LLM、大语言模型 | 同一模型族 ID | 不据此推断音频理解能力 |
| 多语种、多语言 | 首选“多语言” | 与“跨语言”仍保留边界 |
| 自监督、自监督学习 | 首选“自监督学习” | 不与无监督学习做简单别名合并 |
| 说话人日志 | 首选“说话人分离标注”，别名保留原名和 diarization | 不并入说话人验证或波形分离 |
| 语音超分、音频超分辨、音乐超分辨 | 先规范显示名，再区分带宽扩展与其他超分任务 | 涉及语义细分时逐篇核查，不能只改字符串 |
| 音视频语音分离、音视频声源分离 | 语音与一般声源的上下位/适用范围关系 | 不互为无条件别名 |
| 理论分析、模型评估、模型比较 | 研究性质或文档类型/研究重点 | 保留原文章类型证据，不能代替主任务 |
| 数据集、基准测试、开源工具 | 转产物/文章类型与可用状态 | “开源”必须由资源与许可证据决定 |
| 音视频、多模态模型 | 分别为输入输出模态及模型角色 | 不因都带多模态含义而合并 |

## 6. 每篇如何选标签

依次回答以下问题，答案来自原文而不是旧标签：

1. 输入是什么，输出是什么，主要评测衡量什么？据此选主任务。非任务导向研究则明确科学问题，选择科学主题，不虚构工程任务。
2. 是谁的改进：新模型、新方法、数据、评测协议、理论还是系统？沿用文档类型并标产物。
3. 哪个方法与主结论直接相关？没有则留空，不能硬凑方法标签。
4. 哪些条件改变了结论适用范围？只保留最有检索价值且有证据的项。
5. 是否只是借用别的任务当工具？例如用 ASR 评价增强，不自动增加 ASR 为次任务。
6. 去重：别名映射到 ID；同一条祖先链只保留最具体项；不同分面正常共存。
7. 如果词表没有合适项：用可解释的上位任务加 `needs_taxonomy_review`；不得吞掉未知词或随意改贴一个允许的方法。

建议记录格式（提案，不是当前 production schema）：

```json
{
  "taxonomyVersion": "proposal-v1",
  "paperId": "2609.03622",
  "primaryTask": "task.speech-enhancement",
  "secondaryTasks": [],
  "methods": ["method.test-time-adaptation", "method.autoregressive-modeling"],
  "settings": [],
  "signals": ["speech"],
  "inputModalities": ["audio"],
  "outputModalities": ["audio"],
  "evidence": [
    {"field": "primaryTask", "sourceSha256": "需要填入实际原文SHA", "locator": "需要填入任务定义与主实验的位置"},
    {"field": "methods", "sourceSha256": "需要填入实际原文SHA", "locator": "需要填入适应目标和语音先验的位置"}
  ],
  "reviewStatus": "human_or_agent_review_required"
}
```

这篇不因为用了编解码器就标“语音编码”，不把辅助 WER 评价当成 ASR 研究，也不因提出停止预测就贴“实时”。示例中的证据占位必须替换为真实64位SHA和原文段落/DOM定位后才能验收；若引用已签Reader，还要保存Reader SHA及具体小节。该示例不是可安装的生产签名。

另三个边界示例：LibriBrain100 词分类输入是脑信号，应优先检查言语神经解码而不是沿用声学 ASR；RIR 表征压缩的主任务是编码，不能因为测试了混响就自动变为去混响；LoRA 语音识别只贴 ASR、LoRA 及有证据的条件，不再同时展示参数高效微调这个祖先。

## 7. 唯一词表与治理

建议未来新增一个共享 registry，供 Node、Python、Prompt 和 Hugo 导航共同读取；本轮仅设计，不先修改任一生产白名单。

每个概念至少含：`id`、`facet`、中英文 `preferredLabel`、`aliases`、`definition`、`includeExamples`、`excludeExamples`、`broaderId`、`relatedIds`、`status`、`introducedVersion`、`replacedBy`。别名规范化限制为已审核的语言、大小写、全半角与明确拼写，不用模糊字符串相似度自动合并技术概念。

规则：ID 永不复用；每个语言只有一个首选名；同一分面别名不能指向多个 ID；父级必须存在且同分面；层级无环；deprecated 词保留到新词的定向解释；删除和拆分必须有迁移记录。为每个新增叶子提供定义与至少一个正例、反例或排除条件。低频但有独立学术意义的任务可以保留，不用“出现少”作为删除理由。

新词进入候选区而非自动生效。通常先积累 3 篇明确同类论文再审议；有权威任务定义且现有树明显无法表达时允许单篇例外。按月检查新增候选、未知词、误分样本和别名冲突，版本升级生成差异清单。

合法非任务型记录和未判定记录分开：前者为 `classificationKind=scientific_topic`、科学主题必填、主任务为空；后者为 `classificationStatus=unresolved`，不得借“科学主题”绕过审查。当前强制主任务非空的门禁、发布字符串校验及Hugo首标签回退，必须在新协议中同步处理空值，不能只修改JSON示例。

## 8. 省 Token 的生成与审核路径

这部分是待实施方案，不宣称已经测得节省比例。

- 优先复用主分析已提取的任务、方法、输入输出及评测证据，避免另发一次全文分类调用。
- Prompt 先提供短的分面规则与适用领域候选词表；返回稳定 ID，而不是让模型反复抄写全部标签规则。
- 保留跨域候选与上位回退；候选选择不能只靠标题关键词，否则稀有任务会被漏掉。未知/冲突项进入队列，禁止静默过滤成“成功”。
- 正常化、别名、父子冗余、数量和角色检查在本地完成。结构错误只修 taxonomy JSON 的具体字段，不重写 Reader，不重算无关评分，不重抓全文。
- 确需二次语义分类时，只传任务/方法/主要评测相关证据与争议标签定义；缓存绑定论文来源、registry、规则和分类器版本 SHA。
- 标注成本同时记录输入/输出实报 token、调用次数、人工/Agent 审核负担与错误率；不能只比较 Prompt 字符数。

## 9. 历史迁移与验收

### 9.1 按依赖顺序落地

| 优先级 | 改动边界 | 必须验证 |
|---|---|---|
| P0 | 统一registry、别名与角色；梳理 `utils.js:1053`、`utils.py:193` 和Prompt三份词表 | Node/Python/Prompt逐项一致；PEFT不能变LoRA，数据增强不能变预训练，说话人识别不能无条件变验证 |
| P1 | 新分类schema与独立来源签名，修改 `analysis-contract.js` 四行/3–5/强制主方法约束及 `deep-analyzer.js` 语义补标签逻辑 | 旧契约保持原样，新契约明确分支；无适用方法/非任务主题/未知项都不伪造成功 |
| P2 | `publish_common.py`、`publish-to-blog.py`、封面统计与Hugo搜索/主题页读取同一分类投影 | tags顺序不改变主任务；父级查询、OR/AND、去重计数和旧URL均有回归 |
| P3 | 只读历史候选、分层评测、shadow索引、分批迁移 | 未决项透明；原正文/评分不变；每次发布仍经过generate/review与远端验证 |

当前已实测：同一合法 `#参数高效微调` 在Node保留原主方法，Python `utils.py:336/602` 却映成LoRA；`utils.py:304–317` 还有非严格等价映射。这些列为实施前阻挡项，本轮设计没有擅自修改已发布分类。Hugo `research_metadata.html` 与统计代码的首标签回退也应按新版分类状态显式停用，不能让空主任务又被方法标签填回去。

### 9.2 迁移步骤

1. 冻结已发布页面清单、原 frontmatter 标签、显式主任务、论文 ID、日期、源文件 SHA；论文级与页面级统计分开。先利用已核arXiv/DOI/OpenReview等标识建立身份；无法核实的会议页保留独立临时记录，不自动按题目归并。统计选最新页不意味着其标签就是事实真值。
2. 输出全量旧词处置表。明确同义词可提议自动映射；歧义、父子混用和跨分面项逐篇核查。
3. 在独立 sidecar 生成 `oldTags → proposedClassification → evidence → reviewStatus`，不改历史正文、canonical 或评分。
4. 建立分层评测集：高频/低频任务、近期/历史、方法/数据集/理论、多任务和模态边界均覆盖。建议起步至少 120 篇，按类别分层；该数字是采样设计，不是已完成验收数。
5. 先让论文库读取新分类的 shadow 索引，比较旧、新搜索结果，保留切回旧索引的开关。待确认后才执行单独的标签发布事务。
6. 迁移旧标签 URL：GitHub Pages 上 Hugo aliases 是静态跳转页，不是假称服务器 301。拆分标签保留解释性聚合页，不随意跳到某个子任务；旧 URL 全部可达。
7. 新内容先采用新版 schema；历史迁移分批做。分类版本变化只失效分类/索引/受影响的发布证明，不自动触发30篇或全站正文重写。sidecar也必须绑定source/registry/classification SHA并纳入发布投影；即使Reader不变，frontmatter、搜索索引或标签页字节改变仍须新generation/review，不可沿用旧receipt。

验收指标必须分别看：

| 指标 | 初始目标/判定 |
|---|---|
| 历史标签处置覆盖 | 100% 有明确处置，含待核项；这不等于语义分类100%正确 |
| 同义标签重复、同篇祖先冗余 | 归一后为0 |
| 无效ID、别名冲突、层级环 | 0，构建失败关闭 |
| 独立抽样任务准确率 | 逐层统计并审查分歧，建议目标≥95%，达不到不批量上线 |
| 长尾召回 | 单独报告，不能用高频ASR/TTS准确率掩盖漏项 |
| 历史URL与链接 | 全量重放，无失效旧入口 |
| 不相关字段 | 原文/Reader/评分/原图 SHA 不变 |
| Token与返工 | 报告总调用、完整用量与分类修正次数；不以少贴标签伪造低成本 |
